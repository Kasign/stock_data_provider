# 本地测试与使用说明（中文）

将本 Go 项目作为原 `daily_stock_analysis` 仓库里的独立 `go/` 子目录，例如 `daily_stock_analysis/go/`。所有以下命令都在含有该子项目 `go.mod` 的目录执行。

## 1. 当前可以运行什么

当前已补齐 `cmd/analysis-api` 正式启动入口。它会读取 `.env`，初始化 MariaDB/Redis，按配置执行迁移，装配 Python API 数据适配器和 Go 分析 Runner，并启动 HTTP 服务。

MariaDB 已用于运行记录、阶段事件、原始/标准化/组合快照与最终结果；Redis 已用于结果/快照缓存和就绪检查。`cmd/storage-check` 可单独检查 DB/Redis。

此版本是可用于完整工程链路测试的 MVP，并不是成熟的交易策略系统。基础趋势候选只根据日线与均线/收益做解释性筛选；因上游未提供可靠的 ST、停牌、涨跌停、可成交量，以及真实组合账本，候选信号会被可交易性/风险门禁拒绝，不生成仓位计划。`historical_replay` 因缺少逐条 available_at、provider 和复权口径，会被核心质量门禁阻断。

## 2. 环境与配置

要求 Go 1.22+。先确认 `.env` 中至少以下值正确：

```dotenv
HTTP_ADDR=:8092
ANALYSIS_TIMEOUT=3m
PYTHON_API_BASE_URL=http://127.0.0.1:8000
PYTHON_API_TIMEOUT=20s
PYTHON_API_HISTORY_DAYS=200
PYTHON_API_MAX_CONCURRENCY=4
PYTHON_API_MARKET_TIMEZONE=Asia/Shanghai

DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=stock_analysis
DB_PASSWORD=替换为真实密码
DB_NAME=stock_analysis
DB_AUTO_MIGRATE=true

REDIS_ADDR=127.0.0.1:6379
REDIS_PASSWORD=
REDIS_DB=0
```

DB 首次测试可设 `DB_AUTO_MIGRATE=true` 自动建表。迁移成功后，按正式发布规范决定是否切回 `false`。`.env` 已被 `.gitignore` 排除，不要提交真实凭据。

若进程运行在 Docker 容器内：`127.0.0.1` 指向 Go 容器自己。请使用同一 Docker 网络中的 MariaDB、Redis、Python 服务名，并确认这些服务实际加入该网络。

## 3. 完整测试顺序

在 Go 项目根目录（也就是 `go.mod` 所在目录）运行：

```bash
go mod download
go test ./...
go vet ./...
go test -race ./...
go run ./cmd/storage-check
```

含义：

- `go mod download` 下载 MySQL 和 Redis 客户端依赖。
- `go test ./...` 跑全部单元测试，包括 HTTP API、数据适配器、分析流程与存储相关包的编译。
- `go vet ./...` 检查常见代码问题。
- `go test -race ./...` 做竞态检测。
- `storage-check` 真实连接 MariaDB 和 Redis，校验三张必要表，对 MariaDB 执行事务内写入/读取/回滚，对 Redis 执行 SET/GET/DEL；若 `DB_AUTO_MIGRATE=true`，会先执行幂等表迁移。

数据库账号必须能连接目标数据库并拥有首次迁移所需的 DDL 权限。若使用 1Panel 容器，数据库主机名和端口要按实际 Docker 网络配置，不能仅凭服务显示名称猜测。

## 4. 启动 API

```bash
go run ./cmd/analysis-api
```

若启动失败，优先查看错误信息：

- `ping MariaDB`：检查 DB 地址、端口、库名、用户名和密码。
- `ping Redis`：检查 `REDIS_ADDR`、认证密码和 Docker 网络。
- `migrate schema`：检查数据库是否存在和当前账号的建表权限。
- Python API 配置错误：检查 `PYTHON_API_BASE_URL`、超时、时区与认证。

成功后应看到 `stock-analysis Go API listening on :8092`。另开终端执行：

```bash
curl -i http://127.0.0.1:8092/healthz
curl -i http://127.0.0.1:8092/readyz
```

`/healthz` 只表示 Go 进程存活；`/readyz` 必须同时连通 MariaDB 和 Redis。

## 5. 发起真实分析请求

默认请求：

```bash
curl -sS -X POST 'http://127.0.0.1:8092/api/v1/analysis/runs' \
  -H 'Content-Type: application/json' \
  -d '{"symbols":["600519"]}'
```

当前只注册了 `trend-following` 基线策略；若未填 `strategy_ids`，会自动使用该策略。支持 1–100 只六位 A 股证券代码；支持 `symbols`、`as_of`、`task_type`、`universe_id`、`portfolio_id`、`market_id` 和各版本字段。

默认分析时点为服务端当前 `Asia/Shanghai` 时间。若显式指定 `as_of`，应使用 RFC3339 时间格式，例如 `2026-10-20T15:00:00+08:00`。采集器会过滤晚于该时点的行情/日 K。

提交成功后会返回 `run_id`、核心数据质量报告、市场状态、因子、候选信号、风控判定、阶段事件和状态。如果返回 `partial`，应检查 `quality.issues`、`warnings` 与 `events`，不能仅凭 HTTP 200 判断数据完整。

## 6. 一键执行完整在线冒烟测试

Go API 成功启动后，在项目目录另开终端：

```bash
./scripts/full-smoke-test.sh
# 可换成你的自选股；逗号分隔
SYMBOLS=600519,000001 ./scripts/full-smoke-test.sh
```

脚本会检查进程健康、MariaDB/Redis 与表结构就绪状态，然后提交一次真实分析请求，并读取分析结果和阶段审计事件。脚本通过只代表本次工程链路可用，不代表策略具备预测优势或可以实盘交易。

## 7. 查询结果及审计事件

把 POST 返回 JSON 中的 `run_id` 替换到下方命令：

```bash
curl -sS 'http://127.0.0.1:8092/api/v1/analysis/runs/<run_id>'
curl -sS 'http://127.0.0.1:8092/api/v1/analysis/runs/<run_id>/events'
```

读取结果时 Redis 优先，未命中或缓存不可用时回退 MariaDB。写入事实数据以 MariaDB 为准；Redis 缓存写入失败会产生日志警告，不会把已落库结果改判为失败。

直接在 MariaDB 中检查：

```sql
SELECT run_id, status, task_type, as_of, started_at, finished_at
FROM analysis_runs ORDER BY started_at DESC LIMIT 10;

SELECT run_id, stage, status, event_at, duration_ms
FROM analysis_stage_events ORDER BY id DESC LIMIT 30;

SELECT run_id, snapshot_type, snapshot_id, as_of, created_at
FROM analysis_snapshots ORDER BY created_at DESC LIMIT 20;
```

## 9. Docker 运行

在 `1panel-network` 已存在且服务都接入该网络的前提下，按实际情况配置 Compose 环境变量：

```bash
export GO_DB_HOST='MariaDB 在该网络中的实际服务名'
export GO_REDIS_ADDR='Redis 在该网络中的实际服务名:6379'
export GO_PYTHON_API_BASE_URL='http://Python API 在该网络中的实际服务名:端口'
docker compose -f docker-compose.go.yml up -d --build
docker compose -f docker-compose.go.yml logs -f stock-analysis-go
```

示例服务名必须替换为 Docker 网络内真实可解析的名称。容器启动后用 `curl http://服务器地址:8092/readyz` 检查就绪状态。

## 10. 测试边界

真实 DB/Redis 和现有 Python 服务的端到端测试只能在你的服务器网络与凭据下完成；本地单元测试不等于已连接你的服务。当前工程不启用真实自动下单，不产生成交记录。策略是否有效还需要独立回测、成本建模、样本外验证和持续监控，不能根据一次成功执行认定分析准确。
