# 行情数据统一契约

本文定义 `services/market-data` 的标准化规则及 `go-core` 消费的数据契约。Provider 适配器必须先保留供应商原始值与原始单位，并在行情服务的规范化边界执行一次转换；分析服务不得再次猜测或重复换算。

## 标准单位

| 字段 | 标准含义 | 标准单位 |
|---|---|---|
| `current_price`、`open`、`high`、`low`、`prev_close`、`close` | 每股价格 | CNY/股 |
| `change` | 每股涨跌金额 | CNY/股 |
| `change_percent` | 涨跌百分比；数值 `1.25` 表示上涨 1.25% | 百分点（%） |
| `volume` | 成交量 | 股 |
| `amount` | 成交额 | CNY（人民币元） |
| `trade_date` | 交易所交易日，不是 UTC 零点时间戳 | `YYYY-MM-DD` |
| `quote_time` | 供应商报告的行情快照/更新时间；不保证是最近成交时间 | 带时区的 RFC3339 时间戳 |
| `quote_time_semantics` | 时间字段语义；当前供应商统一标记为 `provider_snapshot_time` | 枚举字符串 |
| `fetched_at` | 本服务接收到数据的时间 | UTC RFC3339 时间戳 |
| `normalized_at` | 本服务完成标准化的时间 | UTC RFC3339 时间戳 |

## 必须保留的来源信息

每条标准化行情或 K 线应保留实际的底层 Provider 名称、Provider 版本、抓取和标准化时间、可获得的原始值/单位、标准化单位、复权基准、质量状态和质量原因。`daily_stock_analysis_api` 这类传输/API 名称不能充当底层数据源名称。

供应商没有提供行情时间时必须保留为 null，不能用 `fetched_at` 冒充行情发生时间。同样，当前数据的抓取时间不等于它首次对市场参与者可用的时间；若分析依赖严格时点无前视条件，必须单独提供可审计的 `available_at` 或 publication time。

## 单位换算规则

- Provider 适配器必须注明原始成交量单位。只有源契约明确表示成交量为“手”时，才能按普通 A 股交易中 1 手 = 100 股换算；明确以股为单位的字段不得再乘 100。
- 成交额按供应商字段契约转换成 CNY。已经是人民币元的值不再换算。若成交额缺失，`amount` 必须保持 `null` 且该条记录的 `amount_unit` 必须为 `unknown`；接口整体的标准金额单位为 CNY 不代表缺失值具有该单位。
- 若数据源提供原始值，应在 `raw_volume`、`raw_volume_unit`、`raw_amount`、`raw_amount_unit` 等字段保留，供审计与差异定位。
- 不得仅凭数值大小猜测未知单位。无法证明单位时，应标记 unknown/degraded，并阻止依赖该字段的高风险分析。
- 腾讯实时行情字段 6 的成交量单位不稳定；只有在换手率与流通市值交叉校验能明确支持“股”或“手”时才允许标准化。交叉校验缺失或不一致时，该 Provider 必须返回错误并触发下一数据源兜底，不得继续把原始值默认乘以 100。旧 Redis 报价若带有历史原因 `volume_unit_assumed_without_turnover_crosscheck`，也必须拒绝命中并重新获取。
- 可以使用 `amount / volume` 对成交均价做合理性检查。若与 OHLC 明显矛盾，应拒绝该 Provider 结果并转向已配置的下一个 Provider；禁止自动执行未经来源证明的 x100 或 x0.01 修正。
- 实时行情的 `change` 必须与 `current_price - prev_close` 相差不超过 0.02 CNY；`change_percent` 必须与该差值换算的百分比相差不超过 0.15 个百分点，以容纳供应商展示精度的四舍五入。超出容差时拒绝该报价并走 Provider 兜底，不能只信任供应商单个字段。
- 估值快照的 `provider_report_date` 必须是有效日期且不能晚于中国市场当前日期；`provider_timestamp` 如存在，不允许为零值或明显晚于当前时间（超过 60 秒）。缺少报告日期或精确时间的估值不能标记为 valid。

## 复权规则

允许的历史行情复权基准为 `none`、`forward_adjusted`、`backward_adjusted` 和观测状态 `unknown`。其中 `unknown` 代表数据源无法确认口径，不能作为 API 的请求复权值。

同一技术指标序列中不得混用不同复权口径。实时行情标记为 `none`；若实时价与复权日 K 同时存在，组合结果必须降级并保留警告与原始报价，除非系统有已验证的换算因子可以统一口径。分析价格应以日 K 的口径为准。

供应商返回的前/后复权历史可能使用本次请求时已知的公司行动因子重新计算。当前版本没有保存严格时点的复权因子，因此对历史 `as_of` 请求要返回显式警告；不得声称这些数据可用于无前视偏差历史回测。未来需要建设时点复权因子与快照存储。

Tushare 日 K 的复权实现使用其独立 `adj_factor` 接口（参见[复权因子接口](https://tushare.pro/document/2?doc_id=28)与[A 股复权行情说明](https://tushare.pro/document/2?doc_id=146)）：
- `forward_adjusted` 按 `raw_ohlc × adj_factor(交易日) / adj_factor(请求范围内最新参考日期)` 计算；每根日 K 记录 `adjustment_method=tushare_adj_factor_qfq_v1` 及参考日期。
- `backward_adjusted` 按 `raw_ohlc × adj_factor(交易日)` 计算，记录 `adjustment_method=tushare_adj_factor_hfq_v1`。
- 成交量、成交额及原始单位/来源字段不因价格复权而改变。因子缺失、重复、非正/非有限、证券身份错配或上游权限失败时，整次复权候选必须失败并继续 Provider 回退，不能把未复权价格标注成复权结果。
- 该换算依赖本次请求可取得的 Tushare 因子和请求结束日期，只补齐常规 qfq/hfq 计算；不构成历史时点因子归档，也不意味着支持严格的历史 `as_of` 回放。Tushare 账户必须具备 `adj_factor` 权限。 数据库日 K 回退若存在多个来源/版本分组，依次按覆盖条数、最新交易日、最新采集时间择优；完全打平时按分组 key 字典序稳定决胜，不依赖 Go map 遍历顺序。

## 时间语义与未完成 K 线

- `trade_date` 是日期，不是时间戳。
- `quote_time` 由供应商提供或为空，当前表示供应商报告的行情快照/更新时间，不保证等于最近一笔成交时间；`quote_time_semantics=provider_snapshot_time` 显式标注该语义。`fetched_at` 只表示本地采集时刻，分析任务的排队/执行时长不能改变供应商原始时间。
- 盘中供应商行情超过新鲜度门限时应标记 `stale`；明显超前于本机时间的供应商时间应标记 `degraded`。缓存命中同样必须做新鲜度检查。
- 如果在本地市场收盘前获取当日 K 线，应标记为 partial。对收盘前时点的历史 `as_of` 查询，应排除该日期后来才形成的完整 K 线。目前用 `Asia/Shanghai` 时钟估算收盘，并未接入权威交易所交易日历，因此节假日/临时休市等情况仍是已知限制。
- 龙虎榜和涨停池属于已发生交易日的结果，服务与 Provider 层都拒绝晚于中国市场当前日期的请求；未来日期不能被解释成“当前没有记录”的 unknown 空快照。 东方财富与 Tushare 的涨跌停池 Provider 均在发起上游请求前执行该门禁，不能只依赖服务层拦截。 同花顺龙虎榜还必须检查响应返回的 `trade_date`；即使请求未指定日期，源端返回未来日期也必须拒绝，不能标记为已确认报告。 对 Tushare 的龙虎榜/涨跌停池，`provider_report_date` 仅在实际收到并核验过源端该交易日记录后填写；空的 unknown 响应不得将请求日期伪装成已确认的源端报表日期。交易日历查询本身仍允许请求未来日期。
- 对仅提供当前快照的筹码、财务或板块数据，当请求的 `as_of` 是历史时点时，不得将当前结果倒灌至过去；应显式说明该字段缺失/不适用。 Python 兼容桥的 `fetch_stock_bundle` 与辅助数据单独入口都必须执行该门禁：当历史时点无法重建时，不调用最新筹码、财务或板块 Provider，返回空值并带稳定 warning。财务指标有数据时，`publication_date` 缺失必须降级；标记为 valid 的基本面分区必须带有效公告日期，且日期不能晚于当前中国市场日期。未来公告日期必须拒绝，不能缓存为可用快照。

## 质量状态

允许的质量状态包括 `valid`、`degraded`、`stale`、`invalid` 和 `unknown`。质量是否可用取决于下游目的：行情可以满足展示需求，但如果成交量单位未知，则不能用于依赖成交量的分析。

指数行情必须有有限且大于零的最新价，非空的开高低/昨收价也必须为正数；非空数值不得为 NaN/Inf，成交额非空时必须是非负人民币元。 指数日 K 父快照缺少可核验的源端快照时间时必须降级，不能标记为 `valid`；服务层还必须对新响应与缓存执行同一门禁。缺少供应商报价时间的单项不能标记为 `valid`，只要有单项降级，快照整体也不能标记为 `valid`。这些约束由服务层在新 Provider 响应和缓存命中时统一执行。 板块排行的 `total` 必须为正数且不小于返回条目数；条目必须包含有效涨跌幅、正排名和正确的成交额单位，数值不得是 NaN/Inf，快照不能在单项降级时仍声明 `valid`。 同时要求返回列表按 `rank` 递增；`direction=up` 时涨跌幅应非递增，`direction=down` 时应非递减。顺序不一致的结果必须拒绝并尝试后备 Provider。 同样，市场广度不能忽略非原子成交额采集/来源快照时间未暴露的质量原因；个股板块、龙虎榜、热度榜和公告快照的父级质量也不能高于其任一条目质量。

缺失成交额必须保持 null。经过 Go bridge 进入历史 Python 消费者的 map 时，也必须继续表示为 null，而不是 0。 Tushare 普通股票日 K 的 `daily.amount` 原始单位为千元，标准化 `amount` 必须乘以 1000 后以人民币元输出；原始数值同时保留在 `raw_amount`，并标注 `raw_amount_unit=thousand_CNY`，禁止将原始千元数直接作为 CNY 暴露。 Tushare 指数日 K 的 `index_daily.amount` 也必须乘以 1000 转为 CNY；指数成交量仍保留 `hands` 单位，不得误套用个股日 K 的股数转换。

市场广度的涨停/跌停计数若存在必须非负且不能超过已覆盖证券数；越界计数表示供应商统计口径与本次覆盖集合不一致，应拒绝该快照并回退。市场广度的成交额是聚合字段：
- 对可取得逐证券行情时间的来源，快照必须报告 `quote_timestamp_coverage_count`、`oldest_quote_time` 与 `newest_quote_time`，并确保两端时间与 `provider_report_date` 属于同一中国市场日期。覆盖数表示有效源时间戳数量；最早时间是保守的快照时间下界，不得误解为所有行情在同一时刻生成。
- 若有效时间戳覆盖不完整，快照必须为 `degraded`。即使覆盖数量完整，只要最早和最新报价时间跨度超过 10 分钟，也必须降级并记录 `provider_quote_timestamp_spread_exceeds_10_minutes`。服务层会拒绝缺少完整源时间覆盖却标为 `valid` 的快照；东方财富未提供逐证券可核验行情时间时继续保持降级。

东方财富涨跌停池中的板数、炸板次数等计数字段必须解析为非负整数，不能把小数静默截断。服务层还会拒绝涨跌停池条目的非有限数值、负计数/金额与“条目降级但快照 valid”的质量矛盾，避免错误值经缓存重新返回。当 `amount_coverage_count` 小于 `covered_securities` 时，`total_amount_cny` 必须为 `null`，且快照质量必须是 `degraded`，不能因涨跌分类覆盖完整而标记为 `valid`。服务层必须同时校验该约束，避免错误质量状态进入缓存或 API。返回条数还必须不超过供应商声明的 `total`；若 `total` 小于 `items` 条数，应拒绝该快照并触发回退，不允许通过缓存保留矛盾计数。

补充数据（如 MX 的筹码分布和个股资金流）还应保留 Provider 版本、快照日期、金额单位和质量原因。若无法证明精确发布时间/可用时间，即使表格字段完整，也不能标记为完全 valid。

指数日 K 的父快照即使包含行情条目，只要质量为 `unknown`，也不得抢先结束 Provider 回退链；只有回退耗尽后才返回带明确原因的 unknown 快照并短缓存。 当多个 unknown 候选返回条目数相同时，按非空成交量、成交额、涨跌幅和源端时间字段覆盖择优；覆盖相同才按来源优先级保留候选。多 Provider 场景中的旧 unknown 缓存若没有回退耗尽标记，不得跳过后备来源。

### 结构化快照的来源版本与缓存契约

所有数据域的 `source_version` 都必须是可识别的供应商/字段映射契约版本；空值或大小写不敏感、去除首尾空白后等于 `unknown` 的占位值均视为缺失，Provider 回包必须拒绝并继续回退，旧缓存不得直接命中。

- **指数报价、热度榜**：父快照必须提供非空 `source_version`，每条记录的版本必须与父快照一致。指数报价的 `symbol` 必须为标准六位指数代码加交易所后缀，且 `code` 必须与 `symbol` 一致。缺失/错配版本或证券身份不合法的响应/缓存不能通过契约校验，避免混合字段映射或错误证券被输出。
- **个股公告分页**：父快照和公告条目必须使用一致的来源版本，防止新旧公告字段与旧父快照拼接。
- **涨跌停池、龙虎榜、行业/概念排行、个股所属板块**：父快照与每条记录的 `source_version` 必须非空且一致；涨跌停池与龙虎榜还必须校验 A 股 `symbol` 为规范代码，且 `code` 与其代码段一致。旧缓存或 Provider 版本错配、证券身份冲突时拒绝候选并回源。
- **指数目录与指数/板块成分**：父快照必须提供非空来源版本。**指数日 K** 还要求每根 K 线的版本与父快照一致。
- **市场广度、证券搜索、个股基础资料**：必须提供非空 `source_version`；缺失时拒绝缓存或 Provider 结果并继续回退。个股基础资料和所属板块快照即使允许上游省略交易所后缀，服务返回前也必须统一规范为 `symbol`（例如 `600519.SH`），缓存命中路径同样规范化输出。个股基础资料若同时有 `total_shares` 和 `float_shares`，两者必须为有限值，总股本必须为正，流通股本不得为负且不能超过总股本；流通市值不能超过总市值。上市和退市日期同时存在时，退市日期不能早于上市日期。缓存的 `normalization_version` 必须匹配当前版本。
- **实时行情**：Provider 响应和缓存都必须带非空 `source_version`，且 `normalization_version` 必须与当前规范一致；旧版本缓存失效，旧版本 Provider 响应应被拒绝并触发回退。
- **日 K**：每根记录都必须带非空来源版本，同一响应、缓存或数据库回退序列必须保持来源与 `source_version` 一致。缺失版本、混用版本或显式旧 `normalization_version` 时拒绝整批 Provider 响应。数据库只选择单一来源、单一来源版本和单一归一化版本的连续候选序列。
- **财务指标/报表、交易日历**：聚合快照必须带非空 `source_version`；缺失时拒绝缓存或 Provider 响应并尝试其他国内数据源。 每个财务分区的指标 `key` 必须唯一，`key/name/unit/source_field` 必须有非空内容，数值必须是有限值；重复键或空白元数据需要拒绝该候选，以免下游字典化时发生静默覆盖。
- **资金流与筹码分布**：按证券返回的结果也必须有非空且可识别的来源版本；不得以字面值 `unknown` 冒充真实字段映射版本，缺失时不能进入缓存或 API。 服务层统一拒绝大小写不敏感、去除首尾空白后等于 `unknown` 的版本值，触发 Provider 回退。
- **批量估值**：父快照和条目必须提供一致且非空的 `source`、`source_version`，并要求非零 `fetched_at`。元数据缺失或版本不一致时继续回退，不能把混合版本输出给 API 或写入缓存。

### Unknown 回退与候选择优规则

- 人气榜/飙升榜和批量估值的父级质量为 `unknown` 时，即使有条目也要先尝试后备 Provider；回退耗尽后才返回 unknown，并带明确原因短缓存。估值在证券覆盖相同时，按 PE、PB、PS、PCF、换手率、量比和股息率等全部标准化数值字段的非空数量择优，不能遗漏新增字段。
- 换手率、量比和股息率等比例字段必须为有限非负值；负值使估值候选不符合契约。PE、PB 等可能因财务状况而为负的估值倍数不使用非负约束。
- 人气榜每条记录的名次必须为正、唯一，且返回数组中的名次必须递增；重复名次或顺序错乱会使排名含义不明确，必须拒绝候选并继续回退。候选覆盖相同时，还要比较最新价、涨跌额、涨跌幅、热度、排名变化与趋势等非空字段；覆盖仍相同才按 Provider 注册顺序稳定保留。
- 财务、资金流和筹码分布在回退耗尽后，按已填充分区/指标数择优保留 unknown 候选，不能让最后一个 Provider 的低覆盖记录覆盖较完整结果。
- 证券搜索中，未知目录即使返回匹配条目也要继续回退；所有来源耗尽后才返回 `unknown`，并记录 `stock_search_fallback_exhausted_with_unconfirmed_quality`。若所有来源均只有过期匹配，则保留覆盖较完整的候选；匹配数相同时选择抓取时间较新的快照。
指数目录在 unknown 回退耗尽时按条目数与源端快照时间择优；指数成分在回退链耗尽时按成分数、权重覆盖、源端时间及报告日保留更完整的 unknown 候选；筹码 Provider 列表中的 nil 项必须被安全忽略。

资金流与筹码等补充数据即使包含数值，只要质量为 `unknown`，也不得抢先结束 Provider 回退链。仅当回退耗尽后，才返回带明确耗尽原因的 unknown 快照并短缓存；多 Provider 场景必须跳过未记录回退耗尽标记的旧 unknown 缓存。用于同一能力的 Provider 列表按去除首尾空白、忽略大小写后的名称去重，避免同一来源因配置写法不同而重复请求。

## 当前实现边界

目前实现：东方财富/腾讯的实时行情与日 K、新浪实时行情兜底、Provider 优先级与兜底、有限重试、按 Provider/能力隔离的熔断、单位规范化与校验、JSON HTTP 契约、Redis 缓存、可选 MariaDB 持久化、Go-core HTTP 适配器、Python 辅助 bridge，以及默认关闭的 MX 筹码/资金流补充接口。

尚未完整实现：所有原 Python Provider 的迁移、完整指数/全市场广度、行业/概念板块、财务、涨停池、龙虎榜、新闻公告、严格时点公司行动因子/交易日历、基于部署目标 MariaDB/Redis 与实时供应商的端到端集成测试。不能仅因某个数据域已经有 HTTP 路由，就认定其已具备生产质量的数据来源和口径。


## Go-core 个股辅助数据映射

Go 分析核心在行情与日 K bundle 获取成功后，并发请求基本面、所属板块、筹码分布和资金流。任一辅助接口不可用都不会丢弃已获取的报价与日 K；失败会以稳定 warning 暴露，质量状态和质量原因随数据进入上下文。

- **基本面**：请求最近一个已结束季度；保留分区、报告期、公告日期、指标单位、Provider 来源和质量信息。兼容指标键只在全局不重复时平铺，完整指标另以分区前缀存于 `metrics`，避免同名指标互相覆盖。
- **所属板块**：只有 Provider 明确返回 `has_data=true` 才作为有效列表；含义不明的空结果不解读成“该股没有所属板块”。
- **筹码分布**：只映射契约明确的平均成本、获利比例和集中度；90%/70% 成本区间与日期、来源、质量原因保存在 `raw`，不误作中位成本。
- **资金流**：保留人民币元单位的主力净流入、5/10 日合计、观测数量、来源版本和质量原因；缺失值继续保持 null。
- **历史时点边界**：这些接口没有统一的 `as_of` 读取能力；显式 `as_of` 的个股请求不会附加当前辅助快照。完整 PIT 财报版本与辅助数据历史快照仍未实现。


### 基本面默认报告期选择

Go-core 请求基本面时，默认选择最近一个定期报告披露截止日已过的季度，而不是简单选择前一个自然季度：一季报截止日后选择当年 Q1，半年报截止日后选择当年 Q2，三季报截止日后选择当年 Q3；年报截止日前沿用上一年 Q3。这样在披露窗口内不把尚未公开的报表视为数据缺失。此规则是默认查询策略，不替代每个分区的公告日期、质量状态与严格 PIT 校验。


配置化端点必须是绝对 HTTP(S) URL，不含凭据、查询串或 fragment；即使 URL 以空的 `?` 或 `#` 结尾也应拒绝，防止后续拼接请求参数时产生错误地址。

时间边界：市场广度必须提供格式正确且不晚于中国市场当日的 `provider_report_date`；指数 `quote_time` 不能为零或显著晚于采集时间；热度榜缺少源端时间时不可标记为 `valid`；公告 `published_at` 若存在，不能是零时间或未来时间。`fetched_at` 是采集时间，不得替代源端时间。

个股所属板块：`has_data=false` 与 `quality_status=unknown` 表示源端尚未确认归属，不代表确认没有板块。此类空响应缓存 5 分钟；有板块数据的响应缓存 12 小时。

财务快照缓存按完整性和质量分级：有效且有数据的快照最多缓存 12 小时；有数据但质量为 `degraded` 或 `unknown` 的快照最多缓存 1 小时；无数据的未知结果最多缓存 5 分钟。 财务 API 可包含六组标准指标以及可选的利润表、资产负债表、现金流量表分区；报表按精确报告期匹配，只取合并报表类型并校验已公告日期。 三张报表分区应覆盖常用财务科目，包括收入成本/利润与费用、银行保险专属科目、应收应付组合项、租赁相关资产负债，以及经营/投资/筹资现金流小计、税费返还、处置资产现金和自由现金流；每项保留原始 `source_field` 与明示单位，不把缺失科目补零。 分区质量以关键汇总科目的完整性为门槛；可选明细科目缺失时保持字段缺失，不单独导致分区降级。 利润表和现金流量表一季度使用 `report_type=1`，第二至第四季度使用 `report_type=2` 的单季合并数据；资产负债表始终使用 `report_type=1` 的期末合并报表，不能混用累计期间值与单季值。某张报表接口不可用时只降级该分区，不丢弃其他可用指标。 若六组指标端点不可用，但独立报表端点返回可用数据，也必须返回包含报表分区的 `degraded` 快照；只有指标和报表均无可用字段时才返回整体错误。 指标端点无记录与指标端点请求失败会分别在父级 `quality_reasons` 中以稳定原因区分。此能力不提供严格历史 `as_of` 版本重建，不能据此宣称完全满足 point-in-time 财报。不能因为 `has_data=true` 就把质量未知的财务字段按有效数据长缓存。

证券主数据的 Provider 未提供质量状态时归为 `degraded` 并记录 `provider_quality_status_missing`；明确返回 `unknown` 时继续尝试后备来源，链路耗尽后保留 unknown 候选并附加 `stock_basic_fallback_exhausted_without_usable_quality`，以短 TTL 缓存，不会把未知质量静默变成可用的 degraded 结果。

筹码分布和个股资金流在缓存命中时也必须执行与上游回包相同的字段校验。筹码成本区间需为有限正数、获利比例/集中度需在 `[0,1]`；资金流的 5 日/10 日合计分别要求至少 5/10 条观测。契约不通过的缓存应被忽略并触发上游刷新。

由于筹码分布和资金流模型没有精确的来源可用时间字段，服务层不会接受 Provider 直接标记的 `valid`；这种返回会降级为 `degraded` 并附加 `publication_availability_timestamp_unverified`，直到契约能证明数据在何时对市场可见。

升级兼容：旧版 Redis 中若存在将筹码分布或资金流标为 `valid` 的缓存，因当前契约没有精确来源可用时间字段，新版本会拒绝这类缓存并回源，避免部署升级后继续暴露过高质量等级。

财务快照还必须拒绝未来报告期：即使 `publication_date` 看起来不在未来，`report_date` 也不能晚于中国市场当前日期。季度报告期末与发布日期分别校验，不能仅依据发布日期判断该期报表是否已经结束。

财务字段的日期顺序约束：`report_date` 必须对应请求季度的期末，不能晚于中国市场当前日期；若 `publication_date` 存在，则必须是有效日期且不早于 `report_date`，也不能在未来。两者语义不同，不能互相替代。

财务快照必须包含六个标准指标分区（盈利、营运、成长、偿债、现金流、杜邦）；同花顺还可附带 `income_statement`、`balance_sheet`、`cash_flow_statement` 三类独立报表分区。服务层允许六个标准分区加最多三个报表分区。若同花顺未返回某个标准指标分区，适配器会补充 `unknown` 空分区并记录 `provider_fundamental_ability_missing:<category>`，不补零；重复或未知指标能力会在适配器发起三张报表请求前被拒绝；错误报告期、非法日期与不一致的 `has_data/metrics` 也仍拒绝。报表分区的降级状态不能被父快照提升为 `valid`。

财务 API 的 `year`/`quarter` 只定位报告期，不代表历史时点查询。当前 Provider 对该报告期返回请求时可获得的版本，尚不能重建指定历史时刻之前已发布的修订版本；`GET /api/v1/stocks/{symbol}/fundamentals` 若传入 `as_of` 参数（包括空值）会返回 HTTP 400 `VALIDATION_ERROR`，不会静默忽略。历史回测必须依据可审计的公告/可用时间做 point-in-time 门禁；在历史版本存储与回放能力完成前，不得将当前修订值当作历史时点财务数据。

指数数据契约：指数目录无项目或质量未知时只缓存 5 分钟；指数成分的报告日期不能晚于中国市场当日，源端时间不得为零或显著晚于当前时间。指数日 K 必须校验涨跌幅有限性、成交量/成交额数值与单位的一致性；未知单位不能与非空数值共存，`provider_defined` 成交额只能处于降级质量，且单项降级不得被父快照标为 `valid`。 Tushare 指数日 K 的成交量转为 `int64` 前必须拒绝达到 `2^63` 的浮点边界，避免 `float64(math.MaxInt64)` 舍入后仍被误判为可表示整数。

指数日 K 的服务层查询范围必须截止于中国市场当前日期或更早；不依赖某一个 Provider 拒绝未来日期，避免自动切换到另一个 Provider 后意外接受同一请求。

浮点数量在转换成 `int64` 前必须使用严格上界：`float64(math.MaxInt64)` 会舍入为 `2^63`，所以等于该值也必须拒绝。该规则适用于 Tushare/同花顺指数及个股成交量、同花顺财报时间戳和 TickFlow 整数解析；成交量无法安全转换时应保留为未知并降级，不得产生负数或伪造日期。

补充数据与财务快照的 `fetched_at` 由行情服务在收到 Provider 成功回包后统一写入 UTC 接收时刻，不沿用上游携带的同名字段，以免上游时钟或错误字段污染缓存时效与响应时间语义。筹码分布的 `date` / `provider_date` 必须是有效日期且不得晚于中国市场当前日期；未来日期视为不可信回包，拒绝该 Provider 结果并继续尝试兜底。


核心实时行情与日 K 的时间字段也由服务边界统一维护：`fetched_at` 在收到成功 Provider 响应后盖章，`normalized_at` 在服务完成字段规范化和质量处理后盖章。Provider 返回的这两个字段不作为可信时间输入；供应商原始行情时间仍单独保存在 `quote_time` / `provider_timestamp`，不能与服务时间互相替代。


服务时间的缓存校验同样适用于旧 Redis 条目：实时行情和日 K 缓存中的 `fetched_at` 或 `normalized_at` 缺失、或明显晚于当前时间时，不能直接返回缓存，必须忽略该条目并重新获取 Provider 数据。历史 K 线可以因历史日期而较旧，但服务采集/规范化时间本身不能缺失或来自未来。


日 K 请求的 `start_date` / `end_date` 和 Provider 回包的 `trade_date` 必须严格符合 `YYYY-MM-DD`，且解析后重新格式化必须与原始字符串一致。服务后续依赖日期字符串做范围过滤、排序和缓存键计算，因此不能只验证“可解析”就接受非规范日期。



东方财富个股基本资料在原有动态 PE/PB、行业、市值、板块编号及盈利指标之外，补充总股本与流通股本（单位均为股，来自行情资料字段 `f84`/`f85`）。缺失值保留为 null；非正总股本、负流通股本以及流通股本大于总股本时会拒绝对应异常值并追加质量原因。此类扩展资料没有独立可核验的源端快照时间，整体质量仍保持 `degraded`，不能当作 point-in-time 财务记录。


批量估值的 Tushare `daily_basic` 适配器除 PE/PB/PS 外，还保留换手率、流通换手率、量比、股息率和 TTM 股息率。换手率及股息率以百分点表示；量比是源端比率，不是百分比。缺失值保持 null，不补零；这些字段与 PE/PB/PS 一样没有精确可核验的源端快照时间，不能据此把估值质量提升为 `valid`。静态 PE 仍放在 `pe_static`，`pe_mrq` 和 PCF 在此来源不支持时保持 null。

## 涨跌停池默认返回数与总数语义

- `GET /api/v1/market/limit-pools` 未提供 `limit` 时默认返回最多 100 条；显式 `limit` 允许 1–100。接口不公开页码/游标参数；东方财富 Provider 内部按每页最多 30 条、`Pageindex=0,1,...` 拉取，直到获取 `min(total, limit)` 条、源端空池，或发现分页契约异常。每页原始 `pool` 条数必须精确等于 `min(page_size, max(tc - Pageindex × page_size, 0))`；即使返回数没有超过 `pagesize`，只要超过 `tc` 推导出的预期条数，也必须拒绝，不能通过按调用方 `limit` 截断掩盖源端总数与行数矛盾。分页期间 `tc` 总数和 `qdate` 必须保持一致；若在达到目标覆盖前出现短页、空页或源端计数/报告日期漂移，则拒绝该候选并触发后备 Provider。最终 `total` 仍表示供应商报告的池子总数，`len(items)` 表示本次实际返回条数；当 `total > len(items)` 时，说明受调用方 `limit` 上限或来源覆盖限制影响，不得把响应解释为完整池子。
- Provider 侧默认值与 HTTP/Service 层保持一致，避免内部调用在未指定条数时意外退回 30 条。来源报告日期必须来自可信的供应商时间戳，不能用请求日期填充；格式错误或晚于中国市场当前日期的报告日期会被服务层拒绝。
- 只要 `total > len(items)`，服务层就将涨跌停池快照降级为 `degraded`，附加 `provider_limit_pool_response_truncated`；新 Provider 回包和旧 Redis 缓存采用相同规则。即使条目本身字段有效，也不能把未返回的池子数据视为完整。
- 提高默认返回条数只减少常见池子被默认截断的情况，并不保证任意数据源/交易日都完整；供应商总数、实际条数、质量状态和单位限制仍需由调用方共同判断。


## 指数成分来源覆盖计数

- `total` 与 `items` 表示规范化后实际返回的成分数量；`provider_returned` 表示来源在去重/名称补全前返回的候选成分条数；`excluded_count` 记录因重复或缺少可核验名称而被排除的候选条数。若 `provider_returned > 0`，必须满足 `provider_returned = total + excluded_count`。
- 只要 `excluded_count > 0`，快照质量不得为 `valid`。旧缓存或旧 Provider 没有来源覆盖计数时，非空且原本为 `valid/degraded` 的快照必须降级并附加 `provider_constituent_source_coverage_unreported`；原本为 `unknown` 的快照保持 `unknown`，只补充覆盖原因，不能通过补元数据变成已确认数据。缓存命中与新 Provider 回包必须调用同一处理逻辑。这些字段描述当前来源快照的覆盖情况，并不代表历史成分生效日期已知。

## 指数成分 as_of 查询契约

- GET /api/v1/market/indices/{symbol}/constituents?as_of=YYYY-MM-DD 为可选的历史报告日查询；不传 as_of 时维持原有当前/最近成分快照行为。
- 历史查询只选择实现 HistoricalIndexConstituentProvider 的 Provider，不允许将仅支持当前成分的来源作为历史查询的后备。当前接入的 Tushare 按月向前查询 index_weight，最多检索 120 个月，并只接受不晚于请求日期的源报告行。
- 响应中的 as_of_date 表示请求日期，provider_report_date 表示源端实际权重报告日，两者不可混用。数据原因 provider_as_of_uses_latest_index_weight_report_not_effective_membership_interval 明确表明该实现是“指定日期之前最近一份权重报告”，并未证明每只证券的真实纳入/剔除生效区间。
- 该接口不等于完整严格的 point-in-time 回放：查询仍依赖请求时上游可返回的数据，尚未持久化历史报告版本，也无法证明上游从未回补或修正报告。不得仅凭 as_of 参数宣称历史回测无前视偏差。
- /api/v1/data-sources 的 historical_index_constituents_capable 只表示 Provider 实现了历史报告日查询契约，不代表已具备成员生效区间或历史修订归档。


## A 股证券名称/代码搜索

- `GET /api/v1/stocks/search?q=贵州茅台&limit=10` 使用已启用的 `StockSearchProvider` 链，当前优先腾讯 Smartbox、再尝试东方财富证券目录；查询长度为 1–64 个字符，返回条数为 1–50，默认 10。
- `items` 中 `symbol`、`code`、`name` 与 `exchange` 必须一致；搜索结果只是证券目录候选，不应当作实时行情。`fetched_at` 是服务获取目录结果的时间，不是报价时间。
- 若 Provider 未报告完整候选总量，或搜索结果质量不能确认，响应通过 `quality_status` / `quality_reasons` 显式降级；调用方不得根据搜索结果为空就断言证券不存在。
- 东方财富全量证券目录分页必须复用第一页 `total` 作为本次抓取的边界；后续页 `total` 漂移，或单页原始行数超过该总数推导出的剩余容量时，拒绝该 Provider 目录并触发后备源。短页仍按不完整目录降级，去重/无效行导致的覆盖损失也必须显式降级，不能把 `len(items) > total` 的矛盾结果标记为有效。
- 只有快照质量明确为 `stale` 时响应才提供 `X-Market-Data-Cache: STALE`；非 stale 响应不声明服务层缓存命中，因为搜索服务没有独立缓存命中标志。

### 非空 unknown 快照的回退规则

涨跌停池和龙虎榜即使已返回结构完整的记录，只要父快照质量仍为 `unknown`，服务层就必须继续尝试后备 Provider。只有所有启用来源均无法提供非 unknown 结果时，才可择优保留非空 unknown 候选并记录对应的回退耗尽原因；这类结果只能短缓存。空 unknown 结果继续使用“未确认数据”的原因，不能被解释成零事件。

个股所属板块与公告列表同样遵循非空 unknown 回退：即使 Provider 返回结构完整的条目，只要父级质量为 `unknown`，就必须尝试后续数据源；只有回退链耗尽后才以对应的 `*_fallback_exhausted_with_unconfirmed_quality` 或 `*_fallback_exhausted_without_usable_quality` 原因返回并短缓存。公告行本身仍需通过发布时间、来源链接、日期和分页契约校验，不能因为允许父级 unknown 而放宽行级检查。


## 公告与龙虎榜的分页完整性

- 公告 total / pages 表示本次查询范围的源端匹配总数与总页数。对于非空查询，当前页 returned 必须等于 min(page_size, total - (page-1)*page_size)；不足页或超额页视为源端计数/分页契约异常，拒绝该 Provider 并继续回退，不把部分记录当作完整有效页。total=0 仍表示尚未确认的空结果，不能据此证明没有公告。
- 龙虎榜的 total/pages 保留源端报表总行数；source_returned 是当前页未过滤的源端行数，returned 是过滤非 A 股品种后的规范行数，excluded_non_a_share_count 只统计当前页被排除的行。因此 source_returned = returned + excluded_non_a_share_count，且 pages = ceil(total/page_size)、当前页源端原始行数必须等于总数推导的预期条数。仅条目质量为 degraded 并不能替代分页完整性校验；新 Provider 响应与缓存都必须经过相同的服务层门禁。


## 腾讯 Smartbox 证券类型过滤

- 腾讯 Smartbox 搜索使用 t=all，市场标记仅说明交易所，不能独立证明记录是普通 A 股股票。适配器需同时校验交易所与普通股票代码段，过滤 ETF、指数、可转债及其他不支持品种；若过滤后无匹配股票，应返回 Provider 错误，让服务层尝试东方财富全量股票目录。腾讯搜索未报告完整匹配总数，因此非空结果继续标记为 degraded，不得提升为 valid。


## 行业/概念排行返回覆盖度

- 行业/概念 CLIST 请求第一页时，期望原始返回条数为 min(limit, total)。源端 total 大于零但实际原始条数少于期望值时，Provider 应失败并触发后备源；原始条数超额也属于契约错误。解析后因缺少必填代码、名称或涨跌幅而丢弃条目时，服务层以同一覆盖度约束拒绝不完整候选，继续尝试后备 Provider。
- 当来源未提供可用 total 时，只能用已解析条数作为返回下界，并附加 provider_total_missing_using_returned_count；这不代表完整榜单，也不能改变缺少源端快照时间时的 degraded 状态。


### 涨跌停池的源端报告日期门禁

非空涨跌停池若要声明 `quality_status=valid`，必须提供可核验且与请求交易日一致的 `provider_report_date`。报告日期缺失时，服务层必须拒绝 valid 候选并尝试后备 Provider；仅当日期存在时再校验格式、不能晚于中国市场当日且必须匹配请求日期。缓存命中复用同一校验，不能让旧 valid 缓存绕过该门禁。当前东方财富与 Tushare 的非空实现仍因源端精确时间/单位等边界保持 degraded。


### 公告响应分页身份校验

东方财富公告响应若提供 `page_index` 或 `page_size`，必须分别与请求页码及页大小一致；不一致时拒绝当前 Provider 并触发回退。源端缺失这两个字段时不伪造其响应值，仍按既有总数、预期条数及公告行契约校验。该检查既适用于非空查询，也适用于源端返回空结果对象前的响应门禁。


### 龙虎榜源端显式失败状态

东方财富龙虎榜响应若明确提供 `success=false`，即使 `result` 中仍带有 `count/data`，也必须拒绝该响应并继续 Provider 回退；不能只因条目可解析就忽略源端失败标志。若源端未提供 `success` 字段，继续按现有 `result/count`、交易日、页数及行数契约验证，不把缺失字段当成失败或成功证据。


### Tushare 公告重复行质量原因

Tushare 公告端点返回完全重复的记录时，适配器按规范化的证券、公告日期、标题和来源 URL 生成稳定 ID 并去重，但必须增加 `provider_duplicate_announcement_rows_deduplicated` 质量原因，使聚合快照保持 degraded；去重后的 `total/returned` 表示唯一公告记录数，不伪装成源端未去重行数。


### 热度榜重复记录与补充行情覆盖

东方财富热度榜中，同一个榜单出现重复 `sc` 证券身份时，Provider 应拒绝该候选并触发后备源，而不是跳过重复行后将榜单继续作为有效候选。批量补充行情返回中，同一个 `f12` 代码重复时必须拒绝该回包，不能用后出现的行静默覆盖此前价格、名称或涨跌幅；`f12` 为空的行或不属于本次请求榜单代码集合的额外行情行也必须拒绝，避免无身份数据被忽略或把另一只股票的报价混入结果。补充行情代码不得超出请求代码集合，已返回行的身份必须明确且唯一。对于请求代码在补充行情中缺失的情况，仍按现有规则保留榜单条目并标记行情补充缺失，不能把缺失误当作零价格/零涨跌幅。

### 热度榜源端计数缺失与返回下界

当热度榜 Provider 没有提供权威的总数/分页元数据时，`total` 仅代表本次响应中经过规范化后输出的条数，不能解释为完整排行榜总数。Eastmoney 与同花顺快照必须将 `total_is_lower_bound` 置为 true、使用 `provider_returned` 保留原始榜单行数，并为实际被过滤的重复行增加 `excluded_rows`。请求的 `limit` 截断与源端返回数量是两种不同边界：前者限制 `items`，后者只描述实际收到的源响应。由于 Eastmoney 当前固定请求单页、同花顺响应不带分页总数，不能从当前响应推导完整热度排名的总条数。


### 热度榜数值完整性

热度榜的非空价格、涨跌额、涨跌幅和热度分值都必须是有限数值；`NaN`/`Inf` 不能进入响应或缓存。热度分值即使不是所有 Provider 都提供，也必须在存在时执行同一有限性校验，不能因只校验行情价格字段而绕过。


### 热度榜证券身份范围

东方财富热度榜仅接受普通沪深 A 股代码段。市场标记和六位数字本身不足以证明是股票；ETF、指数、可转债、B 股及无法映射到已支持普通股票代码段的记录必须拒绝当前榜单候选并触发后备源，不能把它们标准化成个股。北交所暂不在该东方财富热度榜适配器支持范围内。


### 行业/概念排行的显式总数与覆盖账本

东方财富行业/概念排行响应若提供 `total`，该值必须为正且与本页原始返回条数满足 `len(diff)=min(limit,total)`；显式 `total=0` 但同时返回条目属于源端矛盾，必须拒绝并回退。只有 `total` 字段确实缺失时，才允许使用已解析返回数作为下界，并附加 `provider_total_missing_using_returned_count`，保持 degraded。不能将缺失字段与显式零值混为一谈。

行业排行快照统一提供 `provider_returned`、`excluded_rows` 和 `total_is_lower_bound`：

- Eastmoney 的 `provider_returned` 为本次 CLIST 响应的原始 `diff` 行数；必填字段无效而未输出的行计入 `excluded_rows`。显式 `total` 被保留为来源计数；若缺失，则 `total` 只能使用已解析输出数，且必须设置 `total_is_lower_bound=true`。
- TickFlow 的 `provider_returned` 为完整发现并校验过的 SW1 行业池数；由于没有任何成分报价可用于计算涨跌幅而被跳过的行业计入 `excluded_rows`。源端行业池总数已完整校验时 `total_is_lower_bound=false`，但缺失行业仍必须通过质量原因显式披露。
- 请求 `limit` 只限制 `items`，不能覆盖原始返回数或源端总数。若必填字段过滤导致候选不完整，服务层应拒绝当前 Provider 并继续回退；覆盖字段用于诊断源端差异，不表示允许不完整榜单直接进入分析主流程。


### 热度榜排名连续性

热度榜快照应返回从 1 开始连续递增的排名序列（1, 2, 3...）。排名虽递增但出现缺号时，说明榜单候选可能缺失；服务层必须拒绝当前 Provider 候选并继续回退，而不是把不完整榜单静默当成完整排名。此规则适用于新 Provider 响应与缓存。

### 交易日历多来源择优与冲突处理

交易日历服务会验证所有已配置 Provider 的完整日期覆盖后，再按证据质量选择结果，而不是直接返回列表中的第一个结构完整响应。明确逐日返回完整日期范围的来源优先于仅返回交易日、再将缺席日期推断为非交易日的来源；缺少源端时间戳会降低证据分，但不等价于日期覆盖不完整。

如果两个或多个有效 Provider 对同一日期的交易状态给出不同结论，服务返回按证据优先级选出的候选，但必须将整体质量降级并加入 `provider_trading_calendar_sources_disagree`。该冲突标记不能替代后续对权威交易所日历、临时休市及特殊交易安排的整体验收。

### 雪球榜单请求上限与可选名次变化

雪球榜单适配器单次最多请求 50 条。调用方请求 51–100 条时，适配器仍只能请求 50 条，父快照必须附加 `provider_request_limit_capped_at_50`，不能把内部请求上限隐藏为普通结果。可选 `rank_change` 缺失属于允许情况；若源端提供非空值但无法解析为整数或超出 `[-1000000, 1000000]`，应省略该字段，并同时在父快照和对应条目的质量原因中记录 `provider_rank_change_invalid_or_out_of_range`。

### 涨跌停池非 A 股记录过滤

涨跌停池 Provider 过滤非 A 股证券时，必须在父快照的 `quality_reasons` 中记录 `provider_non_a_share_security_rows_excluded`。过滤可以避免 ETF 等非目标证券进入个股涨跌停池，但不能让上游返回行与标准化输出之间的差异静默消失；即使接受的 A 股条目仍可展示，快照也应保持降级。

### 指数成分最新报告日与源记录覆盖

选择指数成分快照时，应先依据源端 `trade_date` 确定最新报告日，再过滤不受支持的证券类型。不能因为最新报告日仅包含不受支持的证券而悄悄退回较旧报告日。`provider_returned` 应统计所选最新报告日的源记录；`excluded_count` 必须覆盖不受支持证券及名称无法核验的记录。最新报告日没有任何可用 A 股成分时，应返回带报告日与排除计数的 `unknown` 候选，让服务层继续尝试其他来源。

Tushare `index_weight` 适配器按月独立查询，以避免跨多月结果被总行数限制截断。若被选月度响应达到 5000 行，必须保留 `provider_monthly_index_weight_result_is_large_and_may_be_truncated`，并将 `total_is_lower_bound=true` 暴露给调用方；此时 `total` 不能被解释为权威成分总数。该标记只描述来源覆盖边界，并不代表已获得成分股真实纳入/剔除生效区间。

### 雪球榜单源端状态码校验

雪球响应若包含 `error_code`，必须能够解析为整数；非法、空或无法识别的状态码必须拒绝该响应，即使 `data.items` 同时存在，也不能忽略状态字段并继续接纳数据。合法的非零错误码继续按源端失败处理，并进入 Provider 回退。

### 龙虎榜单页证券身份唯一性

同一龙虎榜分页内的普通 A 股 `symbol` 必须唯一。若源端返回重复证券记录，Provider 应拒绝当前分页并触发后备来源，不得将重复项重复计入条目、静默去重后仍宣称覆盖完整，或让重复证券进入下游个股统计。过滤非 A 股证券的规则仍独立生效。

### 单只证券基础资料的唯一记录约束

按唯一证券代码查询基础资料时，源端必须恰好返回一条匹配记录。缺失结果应报错；重复记录或返回与请求不符的证券代码也应拒绝该 Provider，而不是只取第一条记录，以免把源端重复或身份冲突隐藏为正常基础资料。

### 涨跌停池源端总数与实际返回覆盖

涨跌停池快照使用三个覆盖字段与一个明确标记表达来源完整性：

- `total` 是调用方条数上限截断之前的最佳可用总数；当 `total_is_lower_bound=true` 时，它只是已观察到的下界，不能当作权威全量计数。
- `provider_returned` 记录本次为构造候选而实际收到的源端原始行数，分页源按已获取的页累计；它可能大于最终 `items` 条数，因为调用方上限会截断列表。
- `excluded_non_a_share_count` 记录被普通 A 股证券门禁排除的源端行。过滤数量必须可对账，不能静默从源端返回数中消失。
- `total_is_lower_bound` 只有在来源的行数上限造成总数无法确认时置为 true；同时父快照质量原因必须说明上限及下界语义。

东财涨跌停池若源端总数 `tc` 大于当前响应 `pool` 条数，必须记录 `provider_total_exceeds_returned_rows`。其内部分页要在源端总数稳定、报告日期一致且每页原始行数与预期相符的前提下继续取数；请求上限导致的截断仍需显式暴露。

Tushare `limit_list_d` 未提供独立的权威总数，返回达到 2500 行时必须附加 `provider_response_may_be_capped_at_2500_rows` 和 `provider_limit_pool_total_is_lower_bound`，将 `total_is_lower_bound` 设为 true，并保留 `provider_returned` 与 `excluded_non_a_share_count`。不能把过滤后的数量宣称为权威源端总数。

### 涨跌停池证券唯一性

同一 Tushare 涨跌停池响应中，普通 A 股 `symbol` 必须唯一。重复代码应拒绝当前 Provider 候选并触发回退，不能将同一股票重复计入涨跌停池或依赖服务层事后过滤来掩盖源端重复记录。

### 个股公告查询证券范围

个股公告接口只接受受支持代码段内的普通 A 股股票。ETF、指数、可转债、B 股及其他非普通股票证券必须在请求上游之前拒绝，不能仅因代码可规范化就按个股公告查询，也不能将接口空结果解释为该证券没有公告。此规则在东方财富与 Tushare 公告 Provider 中保持一致。

### 龙虎榜非 A 股记录过滤

龙虎榜分页过滤 ETF、可转债、B 股等非普通 A 股证券时，父快照必须追加 `provider_non_a_share_security_rows_excluded`，并保留源端返回数、已接受数和排除数之间的可对账关系。不能只统计排除计数而隐藏质量原因。

### 东方财富股票专用接口的证券类型门禁

东方财富普通股票报价、日 K、基础资料、所属板块、筹码分布和个股资金流接口，必须在上游请求前校验证券属于受支持的普通 A 股代码段。ETF、指数、可转债、B 股及其他非普通股票证券不能只凭格式可标准化就进入股票数据链路；指数必须使用独立指数接口。

### 东方财富涨跌停池的普通 A 股证券门禁

东方财富涨停、跌停和炸板池必须在生成证券标识后校验其属于受支持的普通 A 股代码段。ETF、指数、B 股及市场字段与证券代码不一致的记录必须拒绝，不能仅根据接口返回的市场字段直接拼接后写入事件池。测试源码覆盖 ETF、指数、B 股、交易所不一致，以及沪市和北交所普通 A 股的正反例；尚待统一运行验收。

### 东方财富证券搜索目录的市场与证券类型校验

证券目录必须使用响应中的市场字段确定交易所，并将 ETF、指数、B 股及市场字段与代码段不一致的记录排除在普通 A 股搜索目录之外。发生过滤时，目录质量必须降级并记录 `provider_non_a_share_security_rows_dropped`，不能静默把格式可标准化的代码当作普通股票。HTTP fixture 覆盖沪深/北交所正例、ETF、指数、B 股和交易所字段不一致的负例；尚待统一运行验收。

### 涨跌停池触板时间字段有效性

东方财富涨跌停池的首次触板时间和最后触板时间必须是有效的 24 小时时刻：小时范围为 00–23，分钟和秒范围为 00–59。非空但不符合时刻范围的值必须输出为空，并在单条记录和父快照中追加 `provider_limit_pool_touch_time_invalid`；不能将例如 `24:60:00` 作为有效时间保留。

### 东方财富指数行情的计数与价格一致性

东方财富核心指数行情应校验源端 `total` 与返回行数的一致性：负数总量、返回行存在时总量为零、或总量小于实际返回行数均视为契约错误；源端总量大于返回行数时保留可用行但将快照降级并记录 `provider_total_exceeds_returned_rows`。指数最新价及提供的开盘/最高/最低/昨收价必须为正数；最高价不得低于最低价，最新价和开盘价在上下界齐全时必须落在区间内。成交额为负数时不能保留为人民币金额，应置空并降级说明。

### 指数行情涨跌额与涨跌幅一致性

当指数行情同时提供最新价和昨收价时，涨跌额必须与 `最新价 - 昨收价` 一致（容差 0.05 个指数点），涨跌幅必须与 `(最新价 - 昨收价) / 昨收价 × 100` 一致（容差 0.15 个百分点）。超出容差的记录必须排除并使快照质量降级，记录 `provider_index_change_fields_inconsistent`；无法验证昨收价时不推断或伪造交叉校验结果。

## 日 K 请求日期边界

- 显式的日 K 起始日期和结束日期必须是有效的 `YYYY-MM-DD`；当两者均提供时，起始日期不得晚于结束日期。
- 显式起始日期或结束日期均不得晚于 `Asia/Shanghai` 的当前日期。未来日期边界与反向区间必须在 Provider 发起上游请求前拒绝，不能依赖上游报错或在收到回包后才发现参数错误。
- 未提供日期边界时可按各 Provider 已声明的默认范围查询；无论请求如何设置，实际返回的每根日 K 仍必须处于有效的请求范围内，并经过交易日期与数值契约校验。



### 日 K 修订版本留存与观察时点查询

`market_data_daily_bars` 继续作为每个来源当前规范值的便捷表；另由 `market_data_daily_bar_versions` 追加留存每个来源、证券、交易日、周期和复权口径的不同内容版本。版本内容指纹不包含 `fetched_at` 和 `normalized_at`，因此仅重复抓取同一数据不会不断生成重复版本；OHLC、成交量/额、复权元数据、来源版本或质量字段变化则会生成新版本。版本写入与当前表 UPSERT 位于同一数据库事务中。

仓储方法 `ListBarsAsOf` 按系统记录时间 `recorded_at` 查询在给定时点之前已观察到的版本，并对每个来源/交易日返回当时最新版本；多个来源仍分别返回，由服务层按数据质量和 Provider 优先级决定是否及如何选用。该能力为 PIT 重放提供存储基础，但不等于已恢复供应商在历史时点的真实可用数据，也不能替代公司行动、复权因子和指数成分生效区间的独立版本化。版本表目前没有自动清理策略，部署方应在制定保留周期前关注磁盘增长。

### 财务快照修订留存与 `as_of` 查询

`market_data_fundamental_versions` 按证券、报告期与来源追加保存不同内容版本。版本指纹不包含 `fetched_at` 或 `system_observed_at`，同一来源仅在最新版本内容变化时追加一条；内容变更后再次恢复为旧值也会形成新的观察版本。它与日 K 历史版本一样，使用系统记录时间而非上游报告期来判断“当时本服务已经观察到什么”。

财务接口 `GET /api/v1/stocks/{symbol}/fundamentals?year=YYYY&quarter=Q&as_of=RFC3339` 使用版本表，不请求实时 Provider。返回值是每个来源在 `as_of` 之前已记录的最新版本，再按质量择优；`system_observed_at` 表示该版本被系统记录的时刻。每个有数据的分区必须有可核验的披露日期，且其 `publication_date` 必须早于 `as_of` 在 `Asia/Shanghai` 时区对应的自然日。由于源端通常只给出披露日期而没有披露时刻，同日披露不能被证明在请求时刻前可用，因此保守剔除；披露日期缺失的分区也会被剔除，并将结果质量降级。不存在可用版本时返回 `404 PIT_REVISION_NOT_FOUND`；未配置本地版本存储时返回 `503 PIT_STORAGE_UNAVAILABLE`，不会悄悄回退到当前值。

PIT 版本只能重建启用版本化后实际记录过的快照。迁移前未留存的财务历史修订无法凭当前最新快照补造；`as_of` 也不等于上游的真实发布时间，来源优先级和公司行动/复权因子历史仍需独立处理。

### 指数/板块目录的来源覆盖账本

指数/板块目录快照额外提供 `provider_returned`、`excluded_rows` 与 `total_is_lower_bound`。目前同花顺目录将原始 `item` 数记录为 `provider_returned`，重复代码被剔除时计入 `excluded_rows`；因此在非截断响应中必须满足 `provider_returned = total + excluded_rows`。若原始返回恰好达到本地 30000 项安全边界，无法证明上游没有截断，服务会标记 `total_is_lower_bound=true` 并降级质量。无效代码/名称仍视为当前 Provider 响应不可信，触发服务层回退，而不会把格式错误的条目计入正常目录。

### 个股所属板块列表的来源覆盖账本

`StockBoardSnapshot` 提供 `provider_returned`、`excluded_rows` 和 `total_is_lower_bound`。东方财富所属板块接口每次请求最多 1000 行，`provider_returned` 记录实际收到的原始行数；当源端总数恰为 1000 时，响应可能已经触及请求上限，因此必须置 `total_is_lower_bound=true` 并保持降级，不能把 1000 当作已证明的完整板块数。当前适配器遇到无效代码/名称或重复板块会拒绝该 Provider 候选并触发服务层回退，不静默过滤，因此成功结果的 `excluded_rows` 为 0，并要求 `provider_returned = total + excluded_rows`。空列表仍是未确认的 unknown，不能解释为该证券确定没有板块归属。

### 市场统一交易时段判定

`GET /api/v1/market/session?at=RFC3339`（省略 `at` 时使用服务端当前时间）先通过已配置交易日历 Provider 确认 `Asia/Shanghai` 本地日期是否为交易日，再依据固定时段输出 `phase`、`is_trading_session`、`is_continuous_trading` 与 `is_auction`。时段边界按左闭右开区间计算：09:15–09:25 开盘集合竞价；09:25–09:30 竞价间隔；09:30–11:30 上午连续交易；11:30–13:00 午间休市；13:00–14:57 下午连续交易；14:57–15:00 收盘集合竞价。其余交易日时刻为开盘前或收市后；非交易日优先返回 `non_trading_day`。

这是市场级计划时段，而非个股能否下单的最终判断。该接口尚不感知个股临时停牌、ST/退市整理状态、证券各板块不同的涨跌幅限制、交易所临时停市或特殊交易安排；使用方不能只凭 `is_trading_session=true` 推断具体证券当前可交易。若日历 Provider 质量降级，结果会保留其降级状态和原因。
