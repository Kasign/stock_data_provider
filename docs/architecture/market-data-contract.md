# 行情数据统一契约

本文定义 `services/market-data` 的标准化规则及 `go-core` 消费的数据契约。Provider 适配器必须先保留供应商原始值与原始单位，并在行情服务的规范化边界执行一次转换；分析服务不得再次猜测或重复换算。

## 标准单位

| 字段 | 标准含义 | 标准单位 |
|---|---|---|
| `current_price`、`open`、`high`、`low`、`prev_close`、`close` | 每股价格 | CNY/股 |
| `change` | 每股涨跌金额 | CNY/股 |
| `change_percent` | 涨跌百分比；数值 `1.25` 表示上涨 1.25% | 百分点（%） |
| `volume` | 成交量 | 股 |
| `amount` | 成交额 | CNY（人民币元） |
| `trade_date` | 交易所交易日，不是 UTC 零点时间戳 | `YYYY-MM-DD` |
| `quote_time` | 供应商报告的行情快照/更新时间；不保证是最近成交时间 | 带时区的 RFC3339 时间戳 |
| `quote_time_semantics` | 时间字段语义；当前供应商统一标记为 `provider_snapshot_time` | 枚举字符串 |
| `fetched_at` | 本服务接收到数据的时间 | UTC RFC3339 时间戳 |
| `normalized_at` | 本服务完成标准化的时间 | UTC RFC3339 时间戳 |

## 必须保留的来源信息

每条标准化行情或 K 线应保留实际的底层 Provider 名称、Provider 版本、抓取和标准化时间、可获得的原始值/单位、标准化单位、复权基准、质量状态和质量原因。`daily_stock_analysis_api` 这类传输/API 名称不能充当底层数据源名称。

供应商没有提供行情时间时必须保留为 null，不能用 `fetched_at` 冒充行情发生时间。同样，当前数据的抓取时间不等于它首次对市场参与者可用的时间；若分析依赖严格时点无前视条件，必须单独提供可审计的 `available_at` 或 publication time。

## 单位换算规则

- Provider 适配器必须注明原始成交量单位。只有源契约明确表示成交量为“手”时，才能按普通 A 股交易中 1 手 = 100 股换算；明确以股为单位的字段不得再乘 100。
- 成交额按供应商字段契约转换成 CNY。已经是人民币元的值不再换算。若成交额缺失，`amount` 必须保持 `null` 且该条记录的 `amount_unit` 必须为 `unknown`；接口整体的标准金额单位为 CNY 不代表缺失值具有该单位。
- 若数据源提供原始值，应在 `raw_volume`、`raw_volume_unit`、`raw_amount`、`raw_amount_unit` 等字段保留，供审计与差异定位。
- 不得仅凭数值大小猜测未知单位。无法证明单位时，应标记 unknown/degraded，并阻止依赖该字段的高风险分析。
- 腾讯实时行情字段 6 的成交量单位不稳定；只有在换手率与流通市值交叉校验能明确支持“股”或“手”时才允许标准化。交叉校验缺失或不一致时，该 Provider 必须返回错误并触发下一数据源兜底，不得继续把原始值默认乘以 100。旧 Redis 报价若带有历史原因 `volume_unit_assumed_without_turnover_crosscheck`，也必须拒绝命中并重新获取。
- 可以使用 `amount / volume` 对成交均价做合理性检查。若与 OHLC 明显矛盾，应拒绝该 Provider 结果并转向已配置的下一个 Provider；禁止自动执行未经来源证明的 x100 或 x0.01 修正。
- 实时行情的 `change` 必须与 `current_price - prev_close` 相差不超过 0.02 CNY；`change_percent` 必须与该差值换算的百分比相差不超过 0.15 个百分点，以容纳供应商展示精度的四舍五入。超出容差时拒绝该报价并走 Provider 兜底，不能只信任供应商单个字段。
- 估值快照的 `provider_report_date` 必须是有效日期且不能晚于中国市场当前日期；`provider_timestamp` 如存在，不允许为零值或明显晚于当前时间（超过 60 秒）。缺少报告日期或精确时间的估值不能标记为 valid。

## 复权规则

允许的历史行情复权基准为 `none`、`forward_adjusted`、`backward_adjusted` 和观测状态 `unknown`。其中 `unknown` 代表数据源无法确认口径，不能作为 API 的请求复权值。

同一技术指标序列中不得混用不同复权口径。实时行情标记为 `none`；若实时价与复权日 K 同时存在，组合结果必须降级并保留警告与原始报价，除非系统有已验证的换算因子可以统一口径。分析价格应以日 K 的口径为准。

供应商返回的前/后复权历史可能使用本次请求时已知的公司行动因子重新计算。当前版本没有保存严格时点的复权因子，因此对历史 `as_of` 请求要返回显式警告；不得声称这些数据可用于无前视偏差历史回测。未来需要建设时点复权因子与快照存储。

## 时间语义与未完成 K 线

- `trade_date` 是日期，不是时间戳。
- `quote_time` 由供应商提供或为空，当前表示供应商报告的行情快照/更新时间，不保证等于最近一笔成交时间；`quote_time_semantics=provider_snapshot_time` 显式标注该语义。`fetched_at` 只表示本地采集时刻，分析任务的排队/执行时长不能改变供应商原始时间。
- 盘中供应商行情超过新鲜度门限时应标记 `stale`；明显超前于本机时间的供应商时间应标记 `degraded`。缓存命中同样必须做新鲜度检查。
- 如果在本地市场收盘前获取当日 K 线，应标记为 partial。对收盘前时点的历史 `as_of` 查询，应排除该日期后来才形成的完整 K 线。目前用 `Asia/Shanghai` 时钟估算收盘，并未接入权威交易所交易日历，因此节假日/临时休市等情况仍是已知限制。
- 龙虎榜和涨停池属于已发生交易日的结果，服务与 Provider 层都拒绝晚于中国市场当前日期的请求；未来日期不能被解释成“当前没有记录”的 unknown 空快照。交易日历查询本身仍允许请求未来日期。
- 对仅提供当前快照的筹码、财务或板块数据，当请求的 `as_of` 是历史时点时，不得将当前结果倒灌至过去；应显式说明该字段缺失/不适用。财务指标有数据时，`publication_date` 缺失必须降级；标记为 valid 的基本面分区必须带有效公告日期，且日期不能晚于当前中国市场日期。未来公告日期必须拒绝，不能缓存为可用快照。

## 质量状态

允许的质量状态包括 `valid`、`degraded`、`stale`、`invalid` 和 `unknown`。质量是否可用取决于下游目的：行情可以满足展示需求，但如果成交量单位未知，则不能用于依赖成交量的分析。

指数行情必须有有限且大于零的最新价，非空的开高低/昨收价也必须为正数；非空数值不得为 NaN/Inf，成交额非空时必须是非负人民币元。缺少供应商报价时间的单项不能标记为 `valid`，只要有单项降级，快照整体也不能标记为 `valid`。这些约束由服务层在新 Provider 响应和缓存命中时统一执行。 板块排行的 `total` 必须为正数且不小于返回条目数；条目必须包含有效涨跌幅、正排名和正确的成交额单位，数值不得是 NaN/Inf，快照不能在单项降级时仍声明 `valid`。 同样，市场广度不能忽略非原子成交额采集/来源快照时间未暴露的质量原因；个股板块、龙虎榜、热度榜和公告快照的父级质量也不能高于其任一条目质量。

缺失成交额必须保持 null。经过 Go bridge 进入历史 Python 消费者的 map 时，也必须继续表示为 null，而不是 0。

## 当前实现边界

目前实现：东方财富/腾讯的实时行情与日 K、新浪实时行情兜底、Provider 优先级与兜底、有限重试、按 Provider/能力隔离的熔断、单位规范化与校验、JSON HTTP 契约、Redis 缓存、可选 MariaDB 持久化、Go-core HTTP 适配器、Python 辅助 bridge，以及默认关闭的 MX 筹码/资金流补充接口。

尚未完整实现：所有原 Python Provider 的迁移、完整指数/全市场广度、行业/概念板块、财务、涨停池、龙虎榜、新闻公告、严格时点公司行动因子/交易日历、基于部署目标 MariaDB/Redis 与实时供应商的端到端集成测试。不能仅因某个数据域已经有 HTTP 路由，就认定其已具备生产质量的数据来源和口径。


## Go-core 个股辅助数据映射

Go 分析核心在行情与日 K bundle 获取成功后，并发请求基本面、所属板块、筹码分布和资金流。任一辅助接口不可用都不会丢弃已获取的报价与日 K；失败会以稳定 warning 暴露，质量状态和质量原因随数据进入上下文。

- **基本面**：请求最近一个已结束季度；保留分区、报告期、公告日期、指标单位、Provider 来源和质量信息。兼容指标键只在全局不重复时平铺，完整指标另以分区前缀存于 `metrics`，避免同名指标互相覆盖。
- **所属板块**：只有 Provider 明确返回 `has_data=true` 才作为有效列表；含义不明的空结果不解读成“该股没有所属板块”。
- **筹码分布**：只映射契约明确的平均成本、获利比例和集中度；90%/70% 成本区间与日期、来源、质量原因保存在 `raw`，不误作中位成本。
- **资金流**：保留人民币元单位的主力净流入、5/10 日合计、观测数量、来源版本和质量原因；缺失值继续保持 null。
- **历史时点边界**：这些接口没有统一的 `as_of` 读取能力；显式 `as_of` 的个股请求不会附加当前辅助快照。完整 PIT 财报版本与辅助数据历史快照仍未实现。


### 基本面默认报告期选择

Go-core 请求基本面时，默认选择最近一个定期报告披露截止日已过的季度，而不是简单选择前一个自然季度：一季报截止日后选择当年 Q1，半年报截止日后选择当年 Q2，三季报截止日后选择当年 Q3；年报截止日前沿用上一年 Q3。这样在披露窗口内不把尚未公开的报表视为数据缺失。此规则是默认查询策略，不替代每个分区的公告日期、质量状态与严格 PIT 校验。


配置化端点必须是绝对 HTTP(S) URL，不含凭据、查询串或 fragment；即使 URL 以空的 `?` 或 `#` 结尾也应拒绝，防止后续拼接请求参数时产生错误地址。

时间边界：市场广度必须提供格式正确且不晚于中国市场当日的 `provider_report_date`；指数 `quote_time` 不能为零或显著晚于采集时间；热度榜缺少源端时间时不可标记为 `valid`；公告 `published_at` 若存在，不能是零时间或未来时间。`fetched_at` 是采集时间，不得替代源端时间。

个股所属板块：`has_data=false` 与 `quality_status=unknown` 表示源端尚未确认归属，不代表确认没有板块。此类空响应缓存 5 分钟；有板块数据的响应缓存 12 小时。

财务快照缓存按完整性和质量分级：有效且有数据的快照最多缓存 12 小时；有数据但质量为 `degraded` 或 `unknown` 的快照最多缓存 1 小时；无数据的未知结果最多缓存 5 分钟。不能因为 `has_data=true` 就把质量未知的财务字段按有效数据长缓存。

证券主数据的 Provider 若未提供质量状态或返回 `unknown`，服务层将其归为 `degraded` 并记录 `provider_quality_status_missing_or_unknown`，不会自动提升为 `valid`。这避免下游把未知来源质量当作经过验证的主数据。

筹码分布和个股资金流在缓存命中时也必须执行与上游回包相同的字段校验。筹码成本区间需为有限正数、获利比例/集中度需在 `[0,1]`；资金流的 5 日/10 日合计分别要求至少 5/10 条观测。契约不通过的缓存应被忽略并触发上游刷新。

由于筹码分布和资金流模型没有精确的来源可用时间字段，服务层不会接受 Provider 直接标记的 `valid`；这种返回会降级为 `degraded` 并附加 `publication_availability_timestamp_unverified`，直到契约能证明数据在何时对市场可见。

升级兼容：旧版 Redis 中若存在将筹码分布或资金流标为 `valid` 的缓存，因当前契约没有精确来源可用时间字段，新版本会拒绝这类缓存并回源，避免部署升级后继续暴露过高质量等级。

财务快照还必须拒绝未来报告期：即使 `publication_date` 看起来不在未来，`report_date` 也不能晚于中国市场当前日期。季度报告期末与发布日期分别校验，不能仅依据发布日期判断该期报表是否已经结束。

财务字段的日期顺序约束：`report_date` 必须对应请求季度的期末，不能晚于中国市场当前日期；若 `publication_date` 存在，则必须是有效日期且不早于 `report_date`，也不能在未来。两者语义不同，不能互相替代。

指数数据契约：指数目录无项目或质量未知时只缓存 5 分钟；指数成分的报告日期不能晚于中国市场当日，源端时间不得为零或显著晚于当前时间。指数日 K 必须校验涨跌幅有限性、成交量/成交额数值与单位的一致性；未知单位不能与非空数值共存，`provider_defined` 成交额只能处于降级质量，且单项降级不得被父快照标为 `valid`。 Tushare 指数日 K 的成交量转为 `int64` 前必须拒绝达到 `2^63` 的浮点边界，避免 `float64(math.MaxInt64)` 舍入后仍被误判为可表示整数。

指数日 K 的服务层查询范围必须截止于中国市场当前日期或更早；不依赖某一个 Provider 拒绝未来日期，避免自动切换到另一个 Provider 后意外接受同一请求。

浮点数量在转换成 `int64` 前必须使用严格上界：`float64(math.MaxInt64)` 会舍入为 `2^63`，所以等于该值也必须拒绝。该规则适用于 Tushare/同花顺指数及个股成交量、同花顺财报时间戳和 TickFlow 整数解析；成交量无法安全转换时应保留为未知并降级，不得产生负数或伪造日期。
