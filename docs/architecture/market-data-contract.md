# 行情数据统一契约

本文定义 `services/market-data` 的标准化规则及 `go-core` 消费的数据契约。Provider 适配器必须先保留供应商原始值与原始单位，并在行情服务的规范化边界执行一次转换；分析服务不得再次猜测或重复换算。

## 标准单位

| 字段 | 标准含义 | 标准单位 |
|---|---|---|
| `current_price`、`open`、`high`、`low`、`prev_close`、`close` | 每股价格 | CNY/股 |
| `change` | 每股涨跌金额 | CNY/股 |
| `change_percent` | 涨跌百分比；数值 `1.25` 表示上涨 1.25% | 百分点（%） |
| `volume` | 成交量 | 股 |
| `amount` | 成交额 | CNY（人民币元） |
| `trade_date` | 交易所交易日，不是 UTC 零点时间戳 | `YYYY-MM-DD` |
| `quote_time` | 供应商报告的行情快照/更新时间；不保证是最近成交时间 | 带时区的 RFC3339 时间戳 |
| `quote_time_semantics` | 时间字段语义；当前供应商统一标记为 `provider_snapshot_time` | 枚举字符串 |
| `fetched_at` | 本服务接收到数据的时间 | UTC RFC3339 时间戳 |
| `normalized_at` | 本服务完成标准化的时间 | UTC RFC3339 时间戳 |

## 必须保留的来源信息

每条标准化行情或 K 线应保留实际的底层 Provider 名称、Provider 版本、抓取和标准化时间、可获得的原始值/单位、标准化单位、复权基准、质量状态和质量原因。`daily_stock_analysis_api` 这类传输/API 名称不能充当底层数据源名称。

供应商没有提供行情时间时必须保留为 null，不能用 `fetched_at` 冒充行情发生时间。同样，当前数据的抓取时间不等于它首次对市场参与者可用的时间；若分析依赖严格时点无前视条件，必须单独提供可审计的 `available_at` 或 publication time。

## 单位换算规则

- Provider 适配器必须注明原始成交量单位。只有源契约明确表示成交量为“手”时，才能按普通 A 股交易中 1 手 = 100 股换算；明确以股为单位的字段不得再乘 100。
- 成交额按供应商字段契约转换成 CNY。已经是人民币元的值不再换算。若成交额缺失，`amount` 必须保持 `null` 且该条记录的 `amount_unit` 必须为 `unknown`；接口整体的标准金额单位为 CNY 不代表缺失值具有该单位。
- 若数据源提供原始值，应在 `raw_volume`、`raw_volume_unit`、`raw_amount`、`raw_amount_unit` 等字段保留，供审计与差异定位。
- 不得仅凭数值大小猜测未知单位。无法证明单位时，应标记 unknown/degraded，并阻止依赖该字段的高风险分析。
- 腾讯实时行情字段 6 的成交量单位不稳定；只有在换手率与流通市值交叉校验能明确支持“股”或“手”时才允许标准化。交叉校验缺失或不一致时，该 Provider 必须返回错误并触发下一数据源兜底，不得继续把原始值默认乘以 100。旧 Redis 报价若带有历史原因 `volume_unit_assumed_without_turnover_crosscheck`，也必须拒绝命中并重新获取。
- 可以使用 `amount / volume` 对成交均价做合理性检查。若与 OHLC 明显矛盾，应拒绝该 Provider 结果并转向已配置的下一个 Provider；禁止自动执行未经来源证明的 x100 或 x0.01 修正。
- 实时行情的 `change` 必须与 `current_price - prev_close` 相差不超过 0.02 CNY；`change_percent` 必须与该差值换算的百分比相差不超过 0.15 个百分点，以容纳供应商展示精度的四舍五入。超出容差时拒绝该报价并走 Provider 兜底，不能只信任供应商单个字段。
- 估值快照的 `provider_report_date` 必须是有效日期且不能晚于中国市场当前日期；`provider_timestamp` 如存在，不允许为零值或明显晚于当前时间（超过 60 秒）。缺少报告日期或精确时间的估值不能标记为 valid。

## 复权规则

允许的历史行情复权基准为 `none`、`forward_adjusted`、`backward_adjusted` 和观测状态 `unknown`。其中 `unknown` 代表数据源无法确认口径，不能作为 API 的请求复权值。

同一技术指标序列中不得混用不同复权口径。实时行情标记为 `none`；若实时价与复权日 K 同时存在，组合结果必须降级并保留警告与原始报价，除非系统有已验证的换算因子可以统一口径。分析价格应以日 K 的口径为准。

供应商返回的前/后复权历史可能使用本次请求时已知的公司行动因子重新计算。当前版本没有保存严格时点的复权因子，因此对历史 `as_of` 请求要返回显式警告；不得声称这些数据可用于无前视偏差历史回测。未来需要建设时点复权因子与快照存储。

## 时间语义与未完成 K 线

- `trade_date` 是日期，不是时间戳。
- `quote_time` 由供应商提供或为空，当前表示供应商报告的行情快照/更新时间，不保证等于最近一笔成交时间；`quote_time_semantics=provider_snapshot_time` 显式标注该语义。`fetched_at` 只表示本地采集时刻，分析任务的排队/执行时长不能改变供应商原始时间。
- 盘中供应商行情超过新鲜度门限时应标记 `stale`；明显超前于本机时间的供应商时间应标记 `degraded`。缓存命中同样必须做新鲜度检查。
- 如果在本地市场收盘前获取当日 K 线，应标记为 partial。对收盘前时点的历史 `as_of` 查询，应排除该日期后来才形成的完整 K 线。目前用 `Asia/Shanghai` 时钟估算收盘，并未接入权威交易所交易日历，因此节假日/临时休市等情况仍是已知限制。
- 龙虎榜和涨停池属于已发生交易日的结果，服务与 Provider 层都拒绝晚于中国市场当前日期的请求；未来日期不能被解释成“当前没有记录”的 unknown 空快照。 东方财富与 Tushare 的涨跌停池 Provider 均在发起上游请求前执行该门禁，不能只依赖服务层拦截。 同花顺龙虎榜还必须检查响应返回的 `trade_date`；即使请求未指定日期，源端返回未来日期也必须拒绝，不能标记为已确认报告。 对 Tushare 的龙虎榜/涨跌停池，`provider_report_date` 仅在实际收到并核验过源端该交易日记录后填写；空的 unknown 响应不得将请求日期伪装成已确认的源端报表日期。交易日历查询本身仍允许请求未来日期。
- 对仅提供当前快照的筹码、财务或板块数据，当请求的 `as_of` 是历史时点时，不得将当前结果倒灌至过去；应显式说明该字段缺失/不适用。 Python 兼容桥的 `fetch_stock_bundle` 与辅助数据单独入口都必须执行该门禁：当历史时点无法重建时，不调用最新筹码、财务或板块 Provider，返回空值并带稳定 warning。财务指标有数据时，`publication_date` 缺失必须降级；标记为 valid 的基本面分区必须带有效公告日期，且日期不能晚于当前中国市场日期。未来公告日期必须拒绝，不能缓存为可用快照。

## 质量状态

允许的质量状态包括 `valid`、`degraded`、`stale`、`invalid` 和 `unknown`。质量是否可用取决于下游目的：行情可以满足展示需求，但如果成交量单位未知，则不能用于依赖成交量的分析。

指数行情必须有有限且大于零的最新价，非空的开高低/昨收价也必须为正数；非空数值不得为 NaN/Inf，成交额非空时必须是非负人民币元。 指数日 K 父快照缺少可核验的源端快照时间时必须降级，不能标记为 `valid`；服务层还必须对新响应与缓存执行同一门禁。缺少供应商报价时间的单项不能标记为 `valid`，只要有单项降级，快照整体也不能标记为 `valid`。这些约束由服务层在新 Provider 响应和缓存命中时统一执行。 板块排行的 `total` 必须为正数且不小于返回条目数；条目必须包含有效涨跌幅、正排名和正确的成交额单位，数值不得是 NaN/Inf，快照不能在单项降级时仍声明 `valid`。 同样，市场广度不能忽略非原子成交额采集/来源快照时间未暴露的质量原因；个股板块、龙虎榜、热度榜和公告快照的父级质量也不能高于其任一条目质量。

缺失成交额必须保持 null。经过 Go bridge 进入历史 Python 消费者的 map 时，也必须继续表示为 null，而不是 0。

东方财富涨跌停池中的板数、炸板次数等计数字段必须解析为非负整数，不能把小数静默截断。服务层还会拒绝涨跌停池条目的非有限数值、负计数/金额与“条目降级但快照 valid”的质量矛盾，避免错误值经缓存重新返回。当 `amount_coverage_count` 小于 `covered_securities` 时，`total_amount_cny` 必须为 `null`，且快照质量必须是 `degraded`，不能因涨跌分类覆盖完整而标记为 `valid`。服务层必须同时校验该约束，避免错误质量状态进入缓存或 API。

补充数据（如 MX 的筹码分布和个股资金流）还应保留 Provider 版本、快照日期、金额单位和质量原因。若无法证明精确发布时间/可用时间，即使表格字段完整，也不能标记为完全 valid。

指数日 K 的父快照即使包含行情条目，只要质量为 `unknown`，也不得抢先结束 Provider 回退链；只有回退耗尽后才返回带明确原因的 unknown 快照并短缓存。 当多个 unknown 候选返回条目数相同时，按非空成交量、成交额、涨跌幅和源端时间字段覆盖择优；覆盖相同才按来源优先级保留候选。多 Provider 场景中的旧 unknown 缓存若没有回退耗尽标记，不得跳过后备来源。

人气榜/飙升榜与批量估值同样适用 unknown 回退规则：即使快照已有条目，只要父级质量为 `unknown`，就必须先尝试后备 Provider；回退耗尽时保留覆盖更完整的候选，并以明确原因短缓存。 指数报价和热度榜还必须提供非空父级 `source_version`，每条记录的 `source_version` 必须与父快照一致；版本缺失或错配的回包/缓存不通过契约校验，不能混合字段映射版本。 个股公告分页也必须遵守同一规则，防止公告记录字段随来源版本变化后与旧父快照混合。 涨跌停池、龙虎榜、行业/概念排行和个股所属板块同样要求父快照与每条记录的 `source_version` 非空且一致，旧缓存或 Provider 版本错配必须触发拒绝/回源，不得保留拼接结果。 指数目录与指数/板块成分虽没有逐条版本字段，也必须要求父快照来源版本非空；指数日 K 还必须保证每根 K 线的版本与父快照一致。 市场广度和证券搜索必须要求非空快照 `source_version`；个股基础资料作为单条返回数据也必须带有非空版本，缺失时拒绝该候选并继续回退。 实时行情缓存命中和 Provider 回包也必须带非空 `source_version`；否则跳过旧缓存或拒绝该 Provider，并尝试其他行情源。日 K 每条记录同样必须带非空版本，同一响应、缓存或数据库回退序列必须使用一致的来源和 `source_version`；缺失或混合版本时拒绝整批 Provider 回包，数据库仅读取单一来源、单一版本和单一归一化版本的连续候选序列。 财务指标/报表聚合快照和交易日历快照也必须提供非空 `source_version`；缺失版本时拒绝缓存或 Provider 回包，继续尝试其他国内数据源。 个股筹码分布和资金流虽然按证券逐条返回，但同样必须保留非空且可识别的来源版本；不得用字面值 `unknown` 冒充真实字段映射版本，版本缺失时不能进入缓存或 API。估值父快照必须提供非空 `source`、`source_version` 与 `fetched_at`；每条记录的 `source`、`source_version` 也必须非空且与父快照一致。元数据缺失或版本不一致视为候选契约错误并继续回退，禁止混合来源版本进入 API 或缓存。 换手率、量比和股息率等比例字段必须是有限非负值；负值会使该候选违反数据契约并触发 Provider 回退。PE、PB 等可能因财务状况而为负的估值倍数不使用这条非负约束。批量估值在证券覆盖相同时，按 PE、PB、PS、PCF、换手率、量比和股息率等全部标准化数值字段的非空数量择优；评分不得遗漏新增字段，否则会在覆盖相同的情况下错误保留信息更少的来源。 人气榜候选覆盖相同时，还要比较最新价、涨跌额、涨跌幅、热度、排名变化与趋势等非空字段；覆盖仍相同时才按 Provider 注册顺序稳定保留。 财务、个股资金流和筹码分布也以已填充分区/指标数择优保留回退耗尽后的 unknown 候选；不会因最后一个 Provider 的字段更少而覆盖更完整的数据。 证券搜索也遵循这一规则：未知目录即使返回匹配条目也要继续回退，只有所有来源耗尽后才以 `unknown` 返回，并记录 `stock_search_fallback_exhausted_with_unconfirmed_quality`。 若所有来源均只返回过期匹配，保留覆盖更完整的候选；匹配条数相同时选择抓取时间较新的快照。
指数目录在 unknown 回退耗尽时按条目数与源端快照时间择优；指数成分在回退链耗尽时按成分数、权重覆盖、源端时间及报告日保留更完整的 unknown 候选；筹码 Provider 列表中的 nil 项必须被安全忽略。

资金流与筹码等补充数据即使包含数值，只要质量为 `unknown`，也不得抢先结束 Provider 回退链。仅当回退耗尽后，才返回带明确耗尽原因的 unknown 快照并短缓存；多 Provider 场景必须跳过未记录回退耗尽标记的旧 unknown 缓存。用于同一能力的 Provider 列表按去除首尾空白、忽略大小写后的名称去重，避免同一来源因配置写法不同而重复请求。

## 当前实现边界

目前实现：东方财富/腾讯的实时行情与日 K、新浪实时行情兜底、Provider 优先级与兜底、有限重试、按 Provider/能力隔离的熔断、单位规范化与校验、JSON HTTP 契约、Redis 缓存、可选 MariaDB 持久化、Go-core HTTP 适配器、Python 辅助 bridge，以及默认关闭的 MX 筹码/资金流补充接口。

尚未完整实现：所有原 Python Provider 的迁移、完整指数/全市场广度、行业/概念板块、财务、涨停池、龙虎榜、新闻公告、严格时点公司行动因子/交易日历、基于部署目标 MariaDB/Redis 与实时供应商的端到端集成测试。不能仅因某个数据域已经有 HTTP 路由，就认定其已具备生产质量的数据来源和口径。


## Go-core 个股辅助数据映射

Go 分析核心在行情与日 K bundle 获取成功后，并发请求基本面、所属板块、筹码分布和资金流。任一辅助接口不可用都不会丢弃已获取的报价与日 K；失败会以稳定 warning 暴露，质量状态和质量原因随数据进入上下文。

- **基本面**：请求最近一个已结束季度；保留分区、报告期、公告日期、指标单位、Provider 来源和质量信息。兼容指标键只在全局不重复时平铺，完整指标另以分区前缀存于 `metrics`，避免同名指标互相覆盖。
- **所属板块**：只有 Provider 明确返回 `has_data=true` 才作为有效列表；含义不明的空结果不解读成“该股没有所属板块”。
- **筹码分布**：只映射契约明确的平均成本、获利比例和集中度；90%/70% 成本区间与日期、来源、质量原因保存在 `raw`，不误作中位成本。
- **资金流**：保留人民币元单位的主力净流入、5/10 日合计、观测数量、来源版本和质量原因；缺失值继续保持 null。
- **历史时点边界**：这些接口没有统一的 `as_of` 读取能力；显式 `as_of` 的个股请求不会附加当前辅助快照。完整 PIT 财报版本与辅助数据历史快照仍未实现。


### 基本面默认报告期选择

Go-core 请求基本面时，默认选择最近一个定期报告披露截止日已过的季度，而不是简单选择前一个自然季度：一季报截止日后选择当年 Q1，半年报截止日后选择当年 Q2，三季报截止日后选择当年 Q3；年报截止日前沿用上一年 Q3。这样在披露窗口内不把尚未公开的报表视为数据缺失。此规则是默认查询策略，不替代每个分区的公告日期、质量状态与严格 PIT 校验。


配置化端点必须是绝对 HTTP(S) URL，不含凭据、查询串或 fragment；即使 URL 以空的 `?` 或 `#` 结尾也应拒绝，防止后续拼接请求参数时产生错误地址。

时间边界：市场广度必须提供格式正确且不晚于中国市场当日的 `provider_report_date`；指数 `quote_time` 不能为零或显著晚于采集时间；热度榜缺少源端时间时不可标记为 `valid`；公告 `published_at` 若存在，不能是零时间或未来时间。`fetched_at` 是采集时间，不得替代源端时间。

个股所属板块：`has_data=false` 与 `quality_status=unknown` 表示源端尚未确认归属，不代表确认没有板块。此类空响应缓存 5 分钟；有板块数据的响应缓存 12 小时。

财务快照缓存按完整性和质量分级：有效且有数据的快照最多缓存 12 小时；有数据但质量为 `degraded` 或 `unknown` 的快照最多缓存 1 小时；无数据的未知结果最多缓存 5 分钟。 财务 API 可包含六组标准指标以及可选的利润表、资产负债表、现金流量表分区；报表按精确报告期匹配，只取合并报表类型并校验已公告日期。 三张报表分区应覆盖常用财务科目，包括收入成本/利润与费用、银行保险专属科目、应收应付组合项、租赁相关资产负债，以及经营/投资/筹资现金流小计、税费返还、处置资产现金和自由现金流；每项保留原始 `source_field` 与明示单位，不把缺失科目补零。 分区质量以关键汇总科目的完整性为门槛；可选明细科目缺失时保持字段缺失，不单独导致分区降级。 利润表和现金流量表一季度使用 `report_type=1`，第二至第四季度使用 `report_type=2` 的单季合并数据；资产负债表始终使用 `report_type=1` 的期末合并报表，不能混用累计期间值与单季值。某张报表接口不可用时只降级该分区，不丢弃其他可用指标。 若六组指标端点不可用，但独立报表端点返回可用数据，也必须返回包含报表分区的 `degraded` 快照；只有指标和报表均无可用字段时才返回整体错误。 指标端点无记录与指标端点请求失败会分别在父级 `quality_reasons` 中以稳定原因区分。此能力不提供严格历史 `as_of` 版本重建，不能据此宣称完全满足 point-in-time 财报。不能因为 `has_data=true` 就把质量未知的财务字段按有效数据长缓存。

证券主数据的 Provider 未提供质量状态时归为 `degraded` 并记录 `provider_quality_status_missing`；明确返回 `unknown` 时继续尝试后备来源，链路耗尽后保留 unknown 候选并附加 `stock_basic_fallback_exhausted_without_usable_quality`，以短 TTL 缓存，不会把未知质量静默变成可用的 degraded 结果。

筹码分布和个股资金流在缓存命中时也必须执行与上游回包相同的字段校验。筹码成本区间需为有限正数、获利比例/集中度需在 `[0,1]`；资金流的 5 日/10 日合计分别要求至少 5/10 条观测。契约不通过的缓存应被忽略并触发上游刷新。

由于筹码分布和资金流模型没有精确的来源可用时间字段，服务层不会接受 Provider 直接标记的 `valid`；这种返回会降级为 `degraded` 并附加 `publication_availability_timestamp_unverified`，直到契约能证明数据在何时对市场可见。

升级兼容：旧版 Redis 中若存在将筹码分布或资金流标为 `valid` 的缓存，因当前契约没有精确来源可用时间字段，新版本会拒绝这类缓存并回源，避免部署升级后继续暴露过高质量等级。

财务快照还必须拒绝未来报告期：即使 `publication_date` 看起来不在未来，`report_date` 也不能晚于中国市场当前日期。季度报告期末与发布日期分别校验，不能仅依据发布日期判断该期报表是否已经结束。

财务字段的日期顺序约束：`report_date` 必须对应请求季度的期末，不能晚于中国市场当前日期；若 `publication_date` 存在，则必须是有效日期且不早于 `report_date`，也不能在未来。两者语义不同，不能互相替代。

财务快照必须包含六个标准指标分区（盈利、营运、成长、偿债、现金流、杜邦）；同花顺还可附带 `income_statement`、`balance_sheet`、`cash_flow_statement` 三类独立报表分区。服务层允许六个标准分区加最多三个报表分区。若同花顺未返回某个标准指标分区，适配器会补充 `unknown` 空分区并记录 `provider_fundamental_ability_missing:<category>`，不补零；重复或未知指标能力会在适配器发起三张报表请求前被拒绝；错误报告期、非法日期与不一致的 `has_data/metrics` 也仍拒绝。报表分区的降级状态不能被父快照提升为 `valid`。

财务 API 的 `year`/`quarter` 只定位报告期，不代表历史时点查询。当前 Provider 对该报告期返回请求时可获得的版本，尚不能重建指定历史时刻之前已发布的修订版本；`GET /api/v1/stocks/{symbol}/fundamentals` 若传入 `as_of` 参数（包括空值）会返回 HTTP 400 `VALIDATION_ERROR`，不会静默忽略。历史回测必须依据可审计的公告/可用时间做 point-in-time 门禁；在历史版本存储与回放能力完成前，不得将当前修订值当作历史时点财务数据。

指数数据契约：指数目录无项目或质量未知时只缓存 5 分钟；指数成分的报告日期不能晚于中国市场当日，源端时间不得为零或显著晚于当前时间。指数日 K 必须校验涨跌幅有限性、成交量/成交额数值与单位的一致性；未知单位不能与非空数值共存，`provider_defined` 成交额只能处于降级质量，且单项降级不得被父快照标为 `valid`。 Tushare 指数日 K 的成交量转为 `int64` 前必须拒绝达到 `2^63` 的浮点边界，避免 `float64(math.MaxInt64)` 舍入后仍被误判为可表示整数。

指数日 K 的服务层查询范围必须截止于中国市场当前日期或更早；不依赖某一个 Provider 拒绝未来日期，避免自动切换到另一个 Provider 后意外接受同一请求。

浮点数量在转换成 `int64` 前必须使用严格上界：`float64(math.MaxInt64)` 会舍入为 `2^63`，所以等于该值也必须拒绝。该规则适用于 Tushare/同花顺指数及个股成交量、同花顺财报时间戳和 TickFlow 整数解析；成交量无法安全转换时应保留为未知并降级，不得产生负数或伪造日期。

补充数据与财务快照的 `fetched_at` 由行情服务在收到 Provider 成功回包后统一写入 UTC 接收时刻，不沿用上游携带的同名字段，以免上游时钟或错误字段污染缓存时效与响应时间语义。筹码分布的 `date` / `provider_date` 必须是有效日期且不得晚于中国市场当前日期；未来日期视为不可信回包，拒绝该 Provider 结果并继续尝试兜底。


核心实时行情与日 K 的时间字段也由服务边界统一维护：`fetched_at` 在收到成功 Provider 响应后盖章，`normalized_at` 在服务完成字段规范化和质量处理后盖章。Provider 返回的这两个字段不作为可信时间输入；供应商原始行情时间仍单独保存在 `quote_time` / `provider_timestamp`，不能与服务时间互相替代。


服务时间的缓存校验同样适用于旧 Redis 条目：实时行情和日 K 缓存中的 `fetched_at` 或 `normalized_at` 缺失、或明显晚于当前时间时，不能直接返回缓存，必须忽略该条目并重新获取 Provider 数据。历史 K 线可以因历史日期而较旧，但服务采集/规范化时间本身不能缺失或来自未来。


日 K 请求的 `start_date` / `end_date` 和 Provider 回包的 `trade_date` 必须严格符合 `YYYY-MM-DD`，且解析后重新格式化必须与原始字符串一致。服务后续依赖日期字符串做范围过滤、排序和缓存键计算，因此不能只验证“可解析”就接受非规范日期。



东方财富个股基本资料在原有动态 PE/PB、行业、市值、板块编号及盈利指标之外，补充总股本与流通股本（单位均为股，来自行情资料字段 `f84`/`f85`）。缺失值保留为 null；非正总股本、负流通股本以及流通股本大于总股本时会拒绝对应异常值并追加质量原因。此类扩展资料没有独立可核验的源端快照时间，整体质量仍保持 `degraded`，不能当作 point-in-time 财务记录。


批量估值的 Tushare `daily_basic` 适配器除 PE/PB/PS 外，还保留换手率、流通换手率、量比、股息率和 TTM 股息率。换手率及股息率以百分点表示；量比是源端比率，不是百分比。缺失值保持 null，不补零；这些字段与 PE/PB/PS 一样没有精确可核验的源端快照时间，不能据此把估值质量提升为 `valid`。静态 PE 仍放在 `pe_static`，`pe_mrq` 和 PCF 在此来源不支持时保持 null。

## 涨跌停池默认返回数与总数语义

- `GET /api/v1/market/limit-pools` 未提供 `limit` 时默认返回最多 100 条；显式 `limit` 允许 1–100。当前接口没有公开页码/游标参数，因此 `total` 表示供应商报告的池子总数，`len(items)` 表示本次实际返回条数；当 `total > len(items)` 时，不得把响应解释为完整池子。
- Provider 侧默认值与 HTTP/Service 层保持一致，避免内部调用在未指定条数时意外退回 30 条。来源报告日期必须来自可信的供应商时间戳，不能用请求日期填充；格式错误或晚于中国市场当前日期的报告日期会被服务层拒绝。
- 只要 `total > len(items)`，服务层就将涨跌停池快照降级为 `degraded`，附加 `provider_limit_pool_response_truncated`；新 Provider 回包和旧 Redis 缓存采用相同规则。即使条目本身字段有效，也不能把未返回的池子数据视为完整。
- 提高默认返回条数只减少常见池子被默认截断的情况，并不保证任意数据源/交易日都完整；供应商总数、实际条数、质量状态和单位限制仍需由调用方共同判断。


## 指数成分来源覆盖计数

- `total` 与 `items` 表示规范化后实际返回的成分数量；`provider_returned` 表示来源在去重/名称补全前返回的候选成分条数；`excluded_count` 记录因重复或缺少可核验名称而被排除的候选条数。若 `provider_returned > 0`，必须满足 `provider_returned = total + excluded_count`。
- 只要 `excluded_count > 0`，快照质量不得为 `valid`。旧缓存或旧 Provider 没有来源覆盖计数时，非空快照降级并附加 `provider_constituent_source_coverage_unreported`。这些字段描述当前来源快照的覆盖情况，并不代表历史成分生效日期已知。


## A 股证券名称/代码搜索

- `GET /api/v1/stocks/search?q=贵州茅台&limit=10` 使用已启用的 `StockSearchProvider` 链，当前优先腾讯 Smartbox、再尝试东方财富证券目录；查询长度为 1–64 个字符，返回条数为 1–50，默认 10。
- `items` 中 `symbol`、`code`、`name` 与 `exchange` 必须一致；搜索结果只是证券目录候选，不应当作实时行情。`fetched_at` 是服务获取目录结果的时间，不是报价时间。
- 若 Provider 未报告完整候选总量，或搜索结果质量不能确认，响应通过 `quality_status` / `quality_reasons` 显式降级；调用方不得根据搜索结果为空就断言证券不存在。
- 只有快照质量明确为 `stale` 时响应才提供 `X-Market-Data-Cache: STALE`；非 stale 响应不声明服务层缓存命中，因为搜索服务没有独立缓存命中标志。

### 非空 unknown 快照的回退规则

涨跌停池和龙虎榜即使已返回结构完整的记录，只要父快照质量仍为 `unknown`，服务层就必须继续尝试后备 Provider。只有所有启用来源均无法提供非 unknown 结果时，才可择优保留非空 unknown 候选并记录对应的回退耗尽原因；这类结果只能短缓存。空 unknown 结果继续使用“未确认数据”的原因，不能被解释成零事件。

个股所属板块与公告列表同样遵循非空 unknown 回退：即使 Provider 返回结构完整的条目，只要父级质量为 `unknown`，就必须尝试后续数据源；只有回退链耗尽后才以对应的 `*_fallback_exhausted_with_unconfirmed_quality` 或 `*_fallback_exhausted_without_usable_quality` 原因返回并短缓存。公告行本身仍需通过发布时间、来源链接、日期和分页契约校验，不能因为允许父级 unknown 而放宽行级检查。
