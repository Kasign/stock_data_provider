# 东方财富公开数据接口待集中处理的问题

更新日期：2026-10-23  
状态：**暂缓集中处理；本轮继续其他国内 Provider 迁移，不把本页列出的问题伪装成已解决。**

## 已观察到的现象

- 一些 `push2.eastmoney.com` 请求会返回 HTTP 302，随后跳转至 `push2delay.eastmoney.com` 并得到 HTTP 200 JSON。两跳状态都应保留在诊断报告中；不得把 HTTP 302 当作业务失败，也不得丢掉最终响应细节。
- `/api/qt/clist/get` 行业/概念板块榜曾成功返回分页列表，但 GitHub Runner 的其他轮次出现过 HTTP 502。相同接口在不同时刻结果不稳定。
- `/getTopicZDFenBu` 全市场涨跌分布、涨停/跌停/炸板池及 `/api/qt/ulist.np/get` 指数行情有过单次 HTTP 200 的真实返回，但单轮成功不等于长期稳定。
- 指数返回字段 `f86` 不能稳定解析为可验证的精确报价时间；没有源端时间时应保持 `quote_time=null`、质量降级，不得把 `fetched_at` 冒充为报价时间。
- 板块、指数等某些接口不暴露可校验的源端快照时间；抓取时间、交易日和报告日期含义不同，不能互相替代。
- 实时 Provider Probe 是多能力汇总任务。板块榜偶发 502 可造成 job failure，即使其他能力本轮已返回有效数据，验收必须检查每个 `LIVE_PROVIDER_RESULT`，而不只是看整体 job 结论。

## 已记录的 GitHub Issue

[Issue #6：记录并延期处理东方财富公开接口的间歇性 502、302 跳转与数据质量降级](https://github.com/Kasign/stock_data_provider/issues/6)

## 统一修复计划

1. 按当前分支 HEAD 连续运行多轮真实探测，汇总每个能力的 HTTP 状态码、重定向链、耗时、错误类型、返回数量、数据日期和质量原因。
2. 分别验证主域名与 delay 域名；在确认接口差异前，不全局替换 Endpoint。
3. 核对市场广度、涨跌停池、行业/概念榜和指数的分页总量、字段单位、缺失值、交易日归属与源端时间语义。
4. 评估受控重试、指数退避、请求间隔、并发限制和按能力隔离故障；不得以弱化断言、吞掉失败、误记为 skipped 的方式让 CI 变绿。
5. 为公开接口准备独立备用源或明确的不可用降级策略，并继续让生产开关默认关闭。
6. GitHub Runner 多轮复验后，在目标 NAS/Docker 中完成端到端验收，再决定是否启用配置。

## 暂缓原则

本轮不再反复修改东方财富请求实现或解析细节；若再次遇到相关问题，只追加证据到 Issue #6，除非它直接阻断其他代码编译或基础 CI。优先完成独立国内 Provider 能力迁移。
