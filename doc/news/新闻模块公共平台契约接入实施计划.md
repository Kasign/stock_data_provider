## 2. 当前基线与真实差距

### 2.1 已进入当前分支的平台原语

| 能力 | 当前代码 | News 尚缺 |
|---|---|---|
| Config / Secret | `internal/platform/config` | News Config Schema、Secret 注入和启动校验 |
| Security | `internal/platform/security` | News 生产路由目前不新增；可信 caller 从上层 Application Context 注入 |
| Fault | `internal/platform/fault` | News 领域错误到 Fault 的边界映射和公开错误 DTO 映射证据 |
| Request ID | `internal/platform/observability` | News 业务执行与出站调用的传播验证 |
| HTTP Client | `internal/platform/httpclient.Client.Do(ctx, request, DestinationPolicy)` | News 侧按 Provider/Source endpoint 创建独立策略适配器；Client 生命周期由组合根持有 |

### N5：公共平台消费者接入

**N5-1 Config / Secret**
- News 定义独立、不可变的 Config 结构；环境变量只在 Bootstrap 边界读取。
- Provider API Key 使用 Platform Secret 或等价安全类型注入；不得进入 News 表、日志、Fault、Diagnostics Attributes。
- 缺失/非法配置按必需/可选 Provider 分类；必需配置错误启动失败，可选 Provider 显式 not_configured/skipped。
- 不实现热更新、远程配置中心或 News 专属凭证管理。

**N5-2 Platform HTTP Client 策略适配**
- 当前实际 API 为 `httpclient.Client.Do(ctx, request, DestinationPolicy)`；不再使用不存在的 `Client.Bind()` / `BoundDoer` 描述。
- Platform Client 生命周期由 Server 组合根持有；News 只创建轻量适配器，不创建/关闭 Client。
- 每个 Provider API endpoint 独立调用 `provider.NewPlatformHTTPDoer(client, endpoint, dependency)`，得到独立 `app.HTTPDoer` 和精确 Host/Port allowlist。
- Provider 默认禁止重定向，`Idempotent=false`，不触发平台通用重试；Provider 查询可能消耗配额，重试策略必须由 News 业务层显式决定。
- HTTP 仅在 endpoint 明确使用 `http://` 时将 `AllowHTTP=true`；平台仍会拒绝私网/保留 IP、DNS 解析到非公网 IP 的目标。不能为 SearXNG 内网地址绕过平台安全策略。
- Provider endpoint allowlist 与 News Source/Endpoint 授权是两层策略，不能共用 Doer。
- 禁止生产注入裸 `http.Client`、默认 Transport 或 fake Doer。
- Provider 配额、来源访问频率、授权和业务并发仍由 News 决定；DNS/IP、代理、重定向、响应大小、Deadline 和通用网络重试由 Platform 执行。
- PLAT-002 未冻结前只做接口适配准备与测试，不将当前包内 API 宣称为稳定跨模块契约；生产真实抓取必须等待 PLAT-002/PLAT-008 对应门禁和部署出口验收。

**N5-3 Request ID / Fault**
- 保留 ProviderOutcome 的 success/empty/partial/failed/skipped 语义，不压成单一 Fault。
- 仅在应用/传输边界映射 Platform Fault；cause 不进入公开响应或日志。
- Request ID 从可信 Context 传播；不得将 Request ID 当作 caller 身份、授权或幂等键。
- 业务质量状态、授权状态和平台 Check 状态分别表达。

退出条件：News Config/Secret/Transport 适配测试、Fault 映射和 Request ID 传播测试通过；平台契约状态仍按项目登记簿维护，不擅自改为 frozen。

### N6：News 持久化与授权 Owner

**N6-1 Migration / Repository**
- MariaDB 是事实存储；Redis 不作为首期强制依赖。
- News 自有 Repository、SQL、表、索引、事务边界和 Migration；namespace 使用 `news`，版本单调且已发布内容不可修改。
- 复用 Platform Storage 的连接生命周期和 Migration Runner；OpenSQL 不自动执行 Migration。
- Repository 借用 Server 共享 `*sql.DB`，不得另建连接池或自行 Close 共享资源。
- 由 Server 组合根统一注册 News Migration；本分支只提供 News Migration 清单，不改根注册入口。

**N6-2 身份/Observation/版本/关系**
- 落库 Identity、Identifier、Observation、News Item、Version、Relation Assertion/Evidence 等领域事实。
- 身份唯一键、全局 Observation idempotency key、`(news_id, version_no)` 唯一约束落到数据库。
- 同 Source 身份解析使用跨进程事务/锁；版本追加按 NewsID 协调写入；唯一键冲突必须回滚并重跑完整事务，不只重试单条 INSERT。
- 覆盖事务回滚、并发首次创建、同 key 同载荷重放、同 key 不同载荷冲突、同指纹复用、版本连续性和跨 NewsID 并发。

**N6-3 授权快照与当前策略复核**
- News 是 Provider Output + Source + Endpoint 组合授权的唯一 Owner。
- 保存不可变 PolicySnapshot、AuthorizationRef 和策略版本；resource_ref 指向精确不可变 Evidence/Version 资源，不使用可变 news_id 代替。
- 只有显式 allowed 且 requested_content_level 被授权覆盖才允许内容读取；conditional 必须由 Owner 验证条件并重新签发 allowed，不能直接放行。
- 每次受限内容读取重新检查当前策略、用途、内容级别、过期和撤销；授权检查与内容读取必须位于同一一致性边界。无法证明策略版本一致时 fail closed。
- 过期边界为 `now >= expires_at`；expires_at=null 只代表没有固定过期时间，不代表永久授权。
- JCS 指纹复算依赖项目公共 Verifier；该实现未确认前，不实现自有 canonicalization。

退出条件：真实 MariaDB Repository/Migration、事务/唯一约束/并发测试通过；NEWS-CTR-002 仍须补齐 Owner/Read/Race 契约证据后才可申请 A2。

### NEWS-CTR-001：ResearchEvidenceQuery Facade

依赖 N6 持久化和 N6-3 当前授权复核。

- 在 `internal/news/app` 提供公开 GetEvidence/ListEvidence Port 与 DTO。
- 只查询已持久化证据；不隐式触发搜索、Provider 请求或抓取。
- 请求字段严格遵循项目契约：caller_ref、purpose_code、requested_content_level、system_as_of、受控 filters、page_size=1..100、cursor。
- PIT 先按 system_as_of 过滤 Observation、Version、Identity、Classification、Relation，再解释业务时间；available_at 无来源证据时保持 unknown/null，严格 PIT 排除，不从 published_at/fetched_at 推导。
- 固定排序 `news-evidence-v1`：system_observed_at DESC、news_id ASC、version_id ASC。
- 首屏固定不可变 snapshot_ref；Cursor 绑定 caller_ref、purpose_code、requested_content_level、filters fingerprint、system_as_of、snapshot_ref、排序版本和稳定唯一键。
- Cursor 使用 HMAC-SHA256、防篡改和 key_id 轮换；Cursor/Snapshot TTL 15 分钟。HMAC 密钥由 Server Secret 注入。
- 不新增 News HTTP API；Research/Researchflow 只依赖公开 Application DTO。

退出条件：DTO Schema/Golden、Cursor HMAC/TTL/轮换测试、真实 MariaDB PIT/跨页稳定性和授权读取测试通过。

## 7. P0 前置核对记录（2026-11-06）

本轮基于当前 News 分支文件和项目级权威契约目录完成静态核对。以下结论只表示代码/文档可见证据，不代表运行验收。

### 7.1 已核实的实现入口

- Platform 配置原语实际位于 `internal/platform/config/env.go`，不是单独的 `config.go`。已提供 `NewEnv`、`NewEnvWithLookup`、`String`、`RequiredString`、`Bool`、`Int`、`Duration`、`Secret`、`RequiredSecret` 和基础校验函数。
- `config.Secret` 通过 `Value()` 显式取明文；String、GoString、fmt、slog、JSON、Text 均输出脱敏标记。News 应直接复用该类型，不定义第二套 Secret。
- Provider Adapter 的构造入口为 `NewBocha(endpoint, apiKey, doer)`、`NewTavily(endpoint, apiKey, doer)`、`NewBrave(endpoint, apiKey, doer)`、`NewSearXNG(baseURL, doer)`。前三者要求 endpoint 与 API Key；SearXNG 只要求 endpoint。
- News `app.HTTPDoer` 与 Platform `httpclient.BoundDoer` 的 `Do(*http.Request)` 形状兼容；Source 侧已有 `EndpointTransport`，按 `SourceID + EndpointID` 精确选择绑定，缺失时失败关闭。
- Platform Request ID 出站传播从已验证 Context 读取，并覆盖/清除请求预置的 `X-Request-ID`；News 不应自行读取或信任任意请求 Header。

### 7.2 P0 仍未解除的外部依赖

1. **GOV-CTR-006 Runtime Verifier：** 项目契约已规定完整 PolicySnapshot tuple 进入 RFC 8785 JCS + SHA-256 指纹输入，并提供 Golden 规则；当前 News 合并基线的代码核查未发现可直接调用的公共 Runtime Verifier。News 不复制 canonicalization 算法。需要 Platform/项目 Owner 给出唯一 package/API、测试入口及版本归属。
2. **Server 组合根：** 当前根启动入口、共享 SQL/HTTP Client 生命周期、News Migration 总注册和统一诊断路由仍未装配。需要 Server/集成 Owner 确认具体负责人、目标集成分支及可接受的装配接口；本分支不修改 `cmd/**`、根 DI 或全局路由。
3. **CollectionRunID：** 尚无真实采集触发入口和 ID 所有者。需要业务触发 Owner 明确触发来源、Run 生命周期、重试边界及 ID 生成责任；确认前不新增无调用方 Orchestrator/Worker/Task，也不借用 Analysis RunID。

### 7.3 N5-1 可独立推进的配置实现约束

- News 自己定义不可变 Config Schema/loader，环境读取仅发生在 Bootstrap 边界；使用 Platform `config.Env` 与 `config.Secret`。
- Bocha/Tavily/Brave 的 endpoint 与 API Key 必须成对配置：两者均未配置时表示 optional/not_configured；只配置其中一个视为配置错误并启动校验失败。
- SearXNG 只使用 endpoint；未配置时为 optional/not_configured。
- 配置错误只报告环境变量键名和错误类别，不包含 endpoint query、API Key 或 Secret 明文。
- Config loader 不创建 HTTP Client、不执行网络请求、不做 DNS 检查，也不直接实例化 Provider；BoundDoer 和 Provider 构造由后续注入边界完成。
- Provider endpoint 与 Source/Endpoint 是不同安全目的地，必须使用独立 DestinationPolicy/BoundDoer，不能共用宽泛 allowlist。

## 8. N5-2 实现记录（2026-11-06）
