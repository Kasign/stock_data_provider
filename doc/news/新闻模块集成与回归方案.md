# 新闻模块集成与回归方案

> 状态：设计基线，待 N1 结合仓库实际 CI、迁移和测试约定补全

## 1. 分支策略

- 专项分支：`feat/research-news-ingestion`。
- 基线/目标集成分支：`feat/full-go-data-providers-api-switch`。
- 不修改 WebUI、整体规划和 main。
- 不在专项开发期间直接改公共数据侧文档。
- 未经明确授权不创建 PR、不合并、不关闭 PR。

## 2. 文件范围

允许：
- 新闻模块专属 Go 代码。
- 新闻模块专属测试。
- `doc/news/**`。

原则上禁止：
- `web/**`。
- 行情、财务、估值业务代码。
- 公共模型或公共 API 的非必要变更。
- 现有 Python Bridge 和旧新闻调用删除。
- 无关重构、临时文件和调试代码。

确需跨模块修改时，先说明必要性、影响面和替代方案，获得批准后再实施。

## 3. 数据库集成

- 首阶段只新增新闻专属表、索引和迁移。
- 迁移应幂等，明确升级检查和恢复方式。
- 不修改、不删除、不重建其他模块表。
- 验证空库安装、已有库升级和重复执行。
- 回滚策略必须考虑已写入新闻数据，不能默认直接 DROP 丢弃数据。

## 4. 测试策略

- 单元测试：标准化、时间解析、去重、版本和关联规则。
- Adapter 契约测试：固定 Provider 响应样本。
- Repository 测试：唯一约束、事务、幂等和分页。
- API 测试：参数、认证、分页、错误和部分失败。
- 质量测试：来源可信度、时间可信度、内容完整度和历史可追溯性。
- 集成测试：新闻模块与现有服务、诊断和数据库迁移协作。
- Live Probe：仅受控执行，不作为普通 CI 必需步骤。

## 5. 集成前检查

- [ ] 当前分支和基线 SHA 已确认。
- [ ] 变更仅限批准范围。
- [ ] 无敏感信息和密钥。
- [ ] OpenAPI 与 Handler/DTO 一致。
- [ ] 数据库迁移已验证。
- [ ] Python 兼容链路未被提前删除。
- [ ] 测试结果和未执行项有记录。
- [ ] 文档状态与实际实现一致。
- [ ] 目标分支同期变更和冲突已检查。
- [ ] 回滚方案明确。

## 6. 集成后回归

验证现有行情、财务、估值、分析任务、诊断和 Python Bridge 行为不受影响。新闻模块异常不得阻断非新闻业务。若新闻能力不可用，应返回明确降级状态，而不是伪造成功或影响其他模块可用性。

## 7. 提交约定

按完整功能或阶段集中提交，不为每个文件单独提交。提交前检查 diff、测试和文件范围。提交信息使用中文或仓库现有约定格式，避免混入无关变更。
