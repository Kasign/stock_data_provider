# 新闻模块集成与回归方案

> 状态：设计基线，待 N1 结合仓库实际 CI、迁移和测试约定补全

## 1. 分支策略

- 专项分支：`feat/research-news-ingestion`。
- 基线/目标集成分支：`feat/full-go-data-providers-api-switch`。
- 不修改 WebUI、整体规划和 main。
- 不在专项开发期间直接改公共数据侧文档。
- 未经明确授权不创建 PR、不合并、不关闭 PR。

## 2. 文件范围

允许：
- 新闻模块专属 Go 代码。
- 新闻模块专属测试。
- `doc/news/**`。

原则上禁止：
- `web/**`。
- 行情、财务、估值业务代码。
- 公共模型或公共 API 的非必要变更。
- 不为旧 Python Bridge 或 go-core 新闻调用新增兼容代码；独立旧服务不在本专项删除范围。
- 无关重构、临时文件和调试代码。

确需跨模块修改时，先说明必要性、影响面和替代方案，获得批准后再实施。

## 3. 公共基础设施依赖（当前延期）

- 新闻模块当前不创建 MariaDB 连接、连接池、SQL Repository、事务封装、Schema Migration 或 Redis 客户端。
- DB、Redis 和通用诊断统一由公共服务提供；新闻模块不得另建平行实现。
- 当前阶段仅定义业务所需的最小 Repository 端口，并使用 fake/内存测试替身验证业务规则。
- 物理表结构、事务/幂等实现、缓存策略、迁移升级和恢复方案均放到公共服务契约稳定后的集成阶段。
- 公共服务接入时只增加新闻所需的业务存储，不修改、不删除、不重建其他模块表。

## 4. 测试策略

- 单元测试：标准化、时间解析、去重、版本和关联规则。
- Adapter 契约测试：固定 Provider 响应样本。
- 业务端口测试：fake Repository 下的调用顺序、业务幂等语义和冲突处理；数据库唯一约束、SQL 事务、持久化幂等和数据库分页延期至公共服务接入阶段。
- Application 契约测试：用例参数校验、错误分类、分页查询语义（如内部查询需要）、部分 Provider 失败和配额约束。
- 既有 Server API 集成测试：仅当该 API 实际接入新闻 Application 并对外提供能力时，验证该 API 自身认证、授权、限流和响应契约；当前不新增新闻 HTTP API。
- 质量测试：来源可信度、时间可信度、内容完整度和历史可追溯性。
- 集成测试：当前验证新闻模块与现有搜索能力、同进程 Application 的协作；公共诊断和数据库迁移协作延期至公共服务接入阶段。
- 边界测试：验证新闻模块没有独立 HTTP Server、新闻专属 Handler、公开路由或独立认证机制。
- 内部调用测试：验证分析模块直接调用新闻 Application，不依赖内部 HTTP 或新闻专属 Token；来源管理和主动采集只能由受控内部运维入口触发。
- 若未来既有 Server API 对外接入新闻能力，再在该 API 的测试范围验证认证、授权和限流，不将其作为当前新闻模块交付项。
- 当前不建设或执行新闻主动 Probe；公共诊断服务就绪后再按其统一规则开展受控 Probe。

## 6. 集成后回归

验证根服务现有行情、财务、估值和分析任务不受新闻模块变更影响。旧 Python Bridge/go-core 不属于新新闻模块兼容验收范围。新闻模块异常不得阻断非新闻业务。若新闻能力不可用，应返回明确降级状态，而不是伪造成功或影响其他模块可用性。

## 7. 提交约定

按完整功能或阶段集中提交，不为每个文件单独提交。提交前检查 diff、测试和文件范围。提交信息使用中文或仓库现有约定格式，避免混入无关变更。


## 8. 2026-11-05 公共服务延期决策

DB、Redis 和通用诊断由公共服务统一提供。新闻专项当前阶段的验收不得要求数据库迁移、Redis 缓存、Probe 或诊断历史；也不得以 fake/内存测试替身替代生产基础设施验收。N6/N7 公共服务接入后再补齐对应集成和回归。


## 10. 最终架构与回归范围更新（2026-11-05）

- 新闻模块直接在根 Go Module 实现；不创建共享 Provider Go Module，不调整 go-core Docker 构建上下文。
- 不以 go-core 旧 Searcher 或 Python Bridge 作为运行时依赖；旧实现仅供协议行为参考。
- 回归重点是根服务、新闻 Domain/Application、Provider Adapter 与其他根模块的边界；不要求旧 go-core/Python 新闻链路兼容。
- 不删除独立旧服务，不修改与本新闻专项无关的 go-core 功能。只有在确认旧新闻集成不再被任何目标调用方使用后，才清理相应代码。
- DB/Redis/通用诊断仍延期；不得将内存测试替身描述为生产存储或诊断验证。


## 9. 公共平台接入与持久化所有权补充（2026-11-05）

Platform 负责连接生命周期、通用事务基础能力和 Migration Runner；News 负责新闻 Repository、SQL、业务表、索引和数据保留策略。不得把“接入公共 DB 能力”误解为“公共平台替 News 实现业务 Repository”。

- N2/N3/N4 可使用注入式 Port、fake Transport 和 fake Repository 开发；不得创建新闻专属生产 DB/Redis/HTTP Client/Diagnostics。
- 真实网络执行等待 PLAT-002 冻结及 PLAT-008 可用，并通过新闻来源授权和 SSRF 安全门禁。
- 新闻 SQL Repository 和 Migration 内容由 News 实现，接入公共连接与 Migration Runner；统一注册入口由根服务集成分支负责。
- Redis 首期非必需；不因平台提供 Redis 能力而自动引入新闻缓存。
- 诊断 Check 由 News 提供领域实现，注册和执行由 PLAT-007 提供；News 不自建诊断历史。
- 只有需要定时/长耗时/可恢复执行时才接入 PLAT-010；Task 不取代 Observation。

## 2026-11-06 N3-02 Observation 幂等闭环审查

- feed_ingest_test.go 已在离线固定样本中手工串联 Feed 映射、IngestCandidate 和 ResearchUpdate；证明字段与内容层可贯通，不证明生产调用方已存在。
- CollectSource 当前只返回 transient Entry；IngestCandidate 只接收 Candidate、策略和上游 IdempotencyKey；ResearchUpdate 要求已持久化 ObservationID/NewsID。尚无本分支可确认的生产编排将三者连接。
- 幂等键必须包含由触发器拥有的 CollectionRunID，并结合 SourceID、EndpointID 和稳定 Entry 身份。相同 Run 重试复用 key；不同 Run 使用新 key。未找到真实触发器前，不引入无调用方的 key builder 或虚构 RunID。
- Feed 原生 ID 与经过 allowlist 的规范 URL 是身份凭据；无凭据时保留 unidentified Observation，不使用标题/数组序号构造身份。
- PolicyTrace 由 CollectSourceResult 同次授权评估产生，应原样传入 IngestCandidate；不得重新查询 Catalog 生成新版本快照。
- ContentLayers 与 Candidate/Observation 分层；只有持久化授权明确允许时才将 ContentLayers 交给 ResearchUpdate。当前 CollectSource 的 StorageMode 固定 transient，不能把该路径视为已获准的正文持久化路径。
- 修正了一个身份边界缺陷：有效 SourceItemID 不再因同条目 RawURL 未通过 allowlist 而被整体丢弃；不合规 URL 不产生 URL 凭据，若无原生 ID 则仍拒绝该 URL 身份。新增 Domain 单测。
- 生产 Repository、数据库全局幂等唯一约束、跨实例锁和并发冲突重试仍延期至 N6；当前内存替身不代表生产验收。
- 判定：Domain/Application 离线组件链路部分通过；生产编排、CollectionRunID、授权允许持久化的在线路径均未验收。下一步先确认真实触发器/调用方，再实现薄编排，不预先扩张接口。
