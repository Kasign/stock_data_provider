# 新闻 API 契约

> 版本：设计草案 v0.2  
> 状态：部署归属与认证责任边界已确认；具体路由、分页和 DTO 仍待 N1 冻结

## 1. 基本原则

- 对外 HTTP 路由统一挂载在 `stock-analysis-server:8092`，复用 Server 统一认证、授权、错误响应、分页和日志规范；新闻模块不实现独立认证。
- 新闻 Application 供同进程内部模块直接调用，不经过内部 HTTP，不使用新闻专属 Token。
- Server 当前尚未发现认证中间件；管理类 HTTP 操作在 Server 级认证和管理员授权落地前不得无保护开放。
- 新闻专项契约以本目录 `openapi.yaml` 为机器可读草案。
- API 只返回系统实际掌握的数据，不伪造发布时间、正文或关联结果。
- 数据结果与质量、来源和时间元信息一起返回。
- 查询接口不得隐式触发无限制外部抓取。

## 2. 候选接口

| 方法 | 路径 | 目的 |
|---|---|---|
| GET | `/api/v1/news` | 按条件查询已入库新闻 |
| GET | `/api/v1/news/search` | 搜索/聚合候选新闻；是否入库需明确 |
| GET | `/api/v1/news/{id}` | 新闻详情、内容和版本信息 |
| GET | `/api/v1/news/sources` | 来源目录和状态 |
| GET | `/api/v1/news/diagnostics` | 新闻来源和采集质量诊断 |

以上是候选接口，不表示当前已实现。所有路由如最终保留，均由根 Server 统一注册；新闻模块不单独监听端口。来源管理、主动采集和外部 URL 测试等管理操作必须要求 Server 管理员权限。

## 3. 查询语义

需要明确支持范围：
- 起止时间及其字段语义。
- 证券标准 ID、行业 ID。
- 来源及来源类别。
- 内容完整度、质量状态。
- 分页、排序和最大 page size。
- 发布时间可信度与数据新鲜度。
- 是否包含摘要、正文、版本和关联证据。

分页必须有稳定排序键，避免同一时间戳导致翻页重复或遗漏。

## 4. 响应信息

新闻记录应尽可能返回：
- 新闻 ID、标题、摘要、规范 URL。
- 来源标识和来源类别。
- published_at、available_at、fetched_at、system_observed_at。
- 时间可信度和缺失状态。
- 内容类型/完整度。
- 证券/行业关联及关联证据状态。
- 质量状态和降级原因。
- 内容版本标识。

具体字段名和通用响应 envelope 以 N1 对现有代码规范核实后为准。

## 5. 错误语义

区分参数错误、未找到、未授权、Provider 部分失败、限流、内部错误和数据质量降级。部分 Provider 失败时，需明确是返回部分结果还是整体失败，不得静默吞掉错误。

## 6. 安全边界

- 第一阶段不提供任意 URL 抓取接口。搜索、采集和刷新动作必须受来源白名单、权限、限流和任务策略约束。
- 新闻模块是根 Server 内部业务模块，不独立暴露服务、不独立认证；对外 HTTP 请求统一由 Server 认证与授权中间件处理。
- 同进程 Application 调用不走 HTTP，不使用新闻专属 Service Token；内部调用仍需遵守业务级来源白名单、配额和任务约束。
- 查询、搜索、诊断、来源管理和主动采集按 Server 的业务权限分级；来源 CRUD、主动采集、批量刷新、外部 URL 测试和授权策略修改至少要求管理员权限。
- 根 Server 当前静态盘点未发现认证中间件。认证/授权未实际部署前，管理类新闻路由不得对公网开放；不能把“新闻模块不独立部署”解释为“Server 的公网接口没有风险”。
- 未来若新闻模块拆成独立进程，再单独设计服务间认证，不在当前阶段提前引入新闻专属密钥体系。

## 7. N1 对现有 API 的核对补充（2026-11-05）

统一部署的主分析 API 当前仅注册 runs/tasks 路由，尚无新闻接口；其 request ID、日志、recoverer 和错误响应格式可复用。用户已确认新闻模块随根 `stock-analysis-server:8092` 部署，由根 Server 统一注册对外新闻路由。market-data 与 go-core 各有独立认证和错误 envelope，不复制其认证机制。

现有任务事件查询使用 after_sequence 和 limit，但这不是通用新闻列表分页规范。新闻列表应在 N1 最终评审时明确稳定排序键、游标/offset 方案和最大页大小。

候选 /api/v1/news、/search、/{id}、/sources、/diagnostics 仍为设计候选，不是现有路由，也未冻结。尤其要明确 /search 是否只返回候选、是否触发采集入库、外部 Provider 部分失败如何返回，以及调用权限和配额策略。

## 8. N1 HTTP 安全边界补充（2026-11-05）

根 Go `internal/platform/httpapi.Server.Handler()` 当前挂载 request-id、请求日志和 panic recoverer，但未发现 API 认证中间件。用户已确认新闻模块不单独认证，统一依赖根 Server 的认证与权限边界；内部 Go Application 调用不经过 HTTP。来源 CRUD、外部 URL dry-run/fetch、手动采集、批量刷新和授权策略修改必须要求 Server 管理员权限。在 Server 级认证/授权中间件实际落地前，这些管理路由不得无保护地对公网开放。新闻模块不另建 Service Token 或专属 API Key。
