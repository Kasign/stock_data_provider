# 新闻 API 契约

> 版本：设计草案 v0.1  
> 状态：待 N1 核对现有路由规范并冻结

## 1. 基本原则

- 统一使用现有服务 API 的认证、错误响应、分页和日志规范。
- 新闻专项契约以本目录 `openapi.yaml` 为机器可读草案。
- API 只返回系统实际掌握的数据，不伪造发布时间、正文或关联结果。
- 数据结果与质量、来源和时间元信息一起返回。
- 查询接口不得隐式触发无限制外部抓取。

## 2. 候选接口

| 方法 | 路径 | 目的 |
|---|---|---|
| GET | `/api/v1/news` | 按条件查询已入库新闻 |
| GET | `/api/v1/news/search` | 搜索/聚合候选新闻；是否入库需明确 |
| GET | `/api/v1/news/{id}` | 新闻详情、内容和版本信息 |
| GET | `/api/v1/news/sources` | 来源目录和状态 |
| GET | `/api/v1/news/diagnostics` | 新闻来源和采集质量诊断 |

以上是候选接口，不表示当前已实现。N1 需要核对现有 API 路由、认证、响应封装和诊断 API，避免重复建设。

## 3. 查询语义

需要明确支持范围：
- 起止时间及其字段语义。
- 证券标准 ID、行业 ID。
- 来源及来源类别。
- 内容完整度、质量状态。
- 分页、排序和最大 page size。
- 发布时间可信度与数据新鲜度。
- 是否包含摘要、正文、版本和关联证据。

分页必须有稳定排序键，避免同一时间戳导致翻页重复或遗漏。

## 4. 响应信息

新闻记录应尽可能返回：
- 新闻 ID、标题、摘要、规范 URL。
- 来源标识和来源类别。
- published_at、available_at、fetched_at、system_observed_at。
- 时间可信度和缺失状态。
- 内容类型/完整度。
- 证券/行业关联及关联证据状态。
- 质量状态和降级原因。
- 内容版本标识。

具体字段名和通用响应 envelope 以 N1 对现有代码规范核实后为准。

## 5. 错误语义

区分参数错误、未找到、未授权、Provider 部分失败、限流、内部错误和数据质量降级。部分 Provider 失败时，需明确是返回部分结果还是整体失败，不得静默吞掉错误。

## 6. 安全边界

第一阶段不提供任意 URL 抓取接口。搜索、采集和刷新动作必须受来源白名单、权限、限流和任务策略约束。
