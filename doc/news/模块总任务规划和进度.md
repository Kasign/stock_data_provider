## 2. 模块边界

- News 是 Server 进程内业务模块，不建设独立对外 HTTP API。
- News 负责新闻来源、Provider、采集、身份、内容、版本、Observation、来源策略和 Research/PIT Evidence。
- Platform 提供通用技术原语；Server 是组合根，负责共享资源、Migration 汇总、Diagnostics 注册和进程级组件装配/启停。
- Researchflow 负责 Run/Stage/Attempt/Worker 执行和 StageOutput 生命周期。
- News 不负责新闻与证券/行业关系，不负责新闻转载关系，不建设独立 Scheduler/Queue/Worker/Orchestrator，不开发人工导入能力。

## 3. 当前能力收敛目标

1. `news_items` 保存当前完整新闻主体。
2. 规范 URL 全局唯一；来源原生 ID 仅在来源范围内唯一。
3. 多来源发现同一规范 URL 时复用一个 news_id。
4. RSS/Atom 和被研究流程选中的 Provider 候选共用一个正式入库事务。
5. 内容变化才追加不可变版本；Research/PIT 的 Version/Observation/Availability 证据链保持有效。
6. Feed 采集具备真实 Server 生产装配和可验证执行路径。
7. 移除旧关系表、旧身份历史能力、双阶段写入和失效文档规则。

## 5. 已锁定的领域决策

- 一篇文章是一个新闻主体，不按新闻事件聚合。
- 完全相同的规范 URL 全局只对应一条新闻。
- 不同 URL 默认不同文章，不自动识别转载、重定向或相似内容。
- 来源原生 ID 唯一范围为 source_id；多个来源身份可以指向同一 news_id。
- URL 和来源原生 ID 命中不同主体时返回 identity_conflict，不自动合并。
- `news_items` 保存当前内容；`news_item_versions` 保存历史内容快照。
- Observation 保存发现/采集记录，不长期复制完整正文。
- Provider 搜索候选默认留在 Researchflow StageOutput；只有明确选中后才正式入库。
- RSS/Atom 正式采集走同一入库事务。
- News 不负责证券/行业关系、转载关系和人工导入。
- 不兼容旧 Schema/数据，不迁移、不双写、不保留兼容视图；数据库由用户在验收后手动清理。
