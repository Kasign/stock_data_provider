## 1. 模块目标与边界

News 负责新闻 Provider 搜索、来源目录、授权策略、Feed/HTML 解析、身份识别、去重、内容版本、证券/行业关系、Observation/Evidence、PIT 查询、Retention 和领域诊断。新闻模块不建设独立对外 HTTP API；内部能力通过公开 Application Port 供 Server/Researchflow 使用。

- Provider/Source/Endpoint 授权必须分层评估；未授权或用途不明时 fail closed。
- Provider 搜索摘要不能替代来源摘要或正文；不从 URL 推断发布者身份。
- published_at、fetched_at、observed_at 不得推导 available_at。
- News 拥有自己的 Repository、SQL、Migration 内容和领域质量规则。
- Platform 提供受控 HTTP Client、Secret、Fault、Diagnostics Runner 等公共原语。
- Server 负责共享资源、Migration 注册、Provider/Source Transport 注入、Diagnostics 注册和 Worker/Lifecycle。
- Research 通过只读 Evidence Query 消费 News 证据；授权复核必须在精确内容读取的一致性边界内。

## 4. News→Research Evidence 的准入状态

- A 组：真实 MariaDB 授权复核、PIT/分页、Key 轮换验签和 Importer fail-closed 零落库已通过历史 Integration 精确 SHA 验收。
- B 组：Research Evidence 成功写入保持 shelved。当前搜索 Provider 无法提供合格的首次公开可获取时间证据；已有来源审查确认符合准入条件的时间字段仅可能存在于法定披露类来源形态，须经产品/来源准入决策后才可重新启动。
- available_at 必须来自真实、可追溯、可授权的来源字段和证据，不得由 published_at、fetched_at、observed_at 推导或回填。
- News 已实现字段级授权写入、Decision 追加、PIT Resolver、原子复核和独立 Retention；这些内部机制不构成真实来源准入，也不产生生产 Evidence。

## 5. Researchflow Stage 边界

- 已有 Stage：news.search_candidates@1.0.0。
- Stage 使用现有 SearchCandidates Application，不改变 News 领域归属，不依赖 Researchflow 私有包。
- Integration Server 将 Stage Adapter、Payload/QualitySummary Registry 和 Worker Runtime 组合装配；真实 Tavily 单/双 Worker 执行已有 Live Workflow 证据。
- Stage 搜索候选不是持久化新闻 Observation，也不是已授权 Research Evidence。
- Provider 详细 Outcome 需按现有 Stage Output/错误契约处理；不得伪造 DiagnosticRefs。
