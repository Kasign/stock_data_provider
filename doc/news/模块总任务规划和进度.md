### 5.1 NEWS-POST-01：Feed 生产触发场景与执行生命周期边界

- 跨模块代码核对结论：Researchflow 拥有 Run/Stage/Attempt；Server 负责 IDGenerator 适配、可信 RequestIdentity 注入和 Worker/Scheduler 生命周期；Platform 提供 RequestID。News 当前拥有 NewsItem/Observation/版本等领域身份及业务幂等键，不拥有通用工作流执行身份。
- News 的 CollectSource 是单次受控调用，返回内存采集结果；IngestCollectedSource 使用调用方提供的 IdempotencyPrefix，不创建或持久化 CollectionRun 实体。
- 当前没有证据表明 News Feed 采集已被定义为独立长期任务，也没有真实生产触发方。因此不新增 CollectionRunID 字段、表、Repository 或生成器。
- 若未来 Feed 采集作为 Researchflow Stage 执行，使用 Researchflow RunRef/StageRef/AttemptRef 作为编排上下文；News 只保留自身领域身份和幂等语义。当前 `news.search_candidates` Stage 仅执行搜索候选，不等于 Feed 采集已接入该 Stage。
- 若未来确有独立于 Researchflow 的持续 Feed 采集任务，Server 负责 Worker/Scheduler/Lifecycle；是否需要持久化采集运行实体，应根据重试、恢复、审计和跨进程关联的真实要求另行设计，不预设字段。
- 退出条件：确认 Feed 生产调用场景和触发方；在此之前保持无独立 CollectionRunID 的现状，不增加接口或存储。

### 5.2 NEWS-POST-02：生产组合与真实网络

- Provider 与每个 Source Endpoint 必须独立创建精确 DestinationPolicy 的 BoundDoer；Provider 与 Source 不得共用宽泛 Doer。
- Platform Client、Secret 和共享资源由 Server 持有；News 不创建第二套 HTTP Client/连接池。
- Provider Output Policy、Source Policy、Endpoint Policy 按现有授权模型求交集；未授权、unknown、pending、revoked 均 fail closed。
- 先做受控环境验证，再对已确认许可的真实 Provider/Source 做 DNS、出口、重定向、响应体限制、Deadline、解析、身份、Observation 和持久化端到端验收。
- 缺凭证、无授权、未配置或无可比较样本标记 skipped/not_comparable，不得标成通过；不得为验收故意修改真实凭证制造故障。
- 不增加 News 对外 HTTP API；不修改 `cmd/**`、`internal/server/**` 或公共 Platform 代码。

### 5.3 NEWS-POST-03：Diagnostics 注册

- 当前 Server 已注册 ParserChecks、ProviderConfigChecks；News 另有 SourceEndpointCheck、ProviderOutputPolicyCheck/ResolverCheck、StorageChecks、ObservationRetentionCheck 和单条 BusinessQualityCheck 工厂。
- 只有对应 Repository、SourceCatalog、Policy Resolver 等真实依赖已装配，才注册依赖型 Check；不注入 nil/fake 以制造绿色状态。
- Provider/Source 未配置或没有许可时使用 skipped/not_comparable；依赖不可用或 Check 执行异常按失败；有数据但业务质量/新鲜度不满足阈值时按降级或领域 invalid 记录，不能把平台 Runner failed 与业务数据 invalid 混为一谈。
- BusinessQualityCheck 是单条 Evidence 的质量评估，不默认注册为全局 Readiness Check。
- 每个 Check 必须记录调用场景、数据来源、reason_code、safe_message、attributes 白名单和四态判定：通过、降级、失败、不可比较。

### 5.4 NEWS-POST-04：Cleaner 周期生命周期

- 现有 ObservationRetentionCleaner、EvidenceSnapshotRetentionCleaner 等用例只执行一次有界清理，不负责调度。
- Server 负责启动角色、周期、批次上限、超时、并发互斥、错误退避、指标/诊断和 Shutdown 等生命周期。
- 不在 News 内新建 Scheduler/Task Queue；不在 API 请求路径同步执行大批清理。
- 验收必须使用真实 MariaDB 验证到期边界、批次上限、重复执行、并发执行、失败重试、Context 取消和关闭行为；没有执行记录不得称周期 Worker 已通过。

### 5.5 NEWS-POST-05/06：available_at 与 Research B 组

- available_at 必须来自经授权来源明确声明的首次公开可获取时间，保留字段路径、原始值、证据 URL、策略版本、内容版本、采集时间和解析器版本。
- 普通 published_at/published_date、RSS pubDate、Atom published/updated、HTTP Date/Last-Modified、Provider 索引时间、fetched_at、observed_at 均不能替代。
- 证据缺失、冲突、授权不明或语义不清时保持 NULL/不可比较并从严格 PIT 结果排除。
- 在 POST-05 获得合格来源证据前，POST-06 不启动，不产生生产 Research Evidence 成功写入。

## 6. 验收状态统一定义

- **通过（PASS）**：精确 SHA 的代码/契约测试通过；需要真实数据或网络时，必须有对应真实 Provider/Source、授权、持久化和运行证据。
- **降级（DEGRADED）**：检查能够执行，但覆盖、新鲜度或业务质量不满足完整门槛；必须保留稳定 reason_code 和证据。
- **失败（FAIL）**：配置/依赖/数据完整性/安全边界违反要求，或 Check 自身执行异常；说明失败责任层，不把 Provider 业务失败误映射为 Platform Check 失败。
- **不可比较（NOT_COMPARABLE）**：缺凭证、未授权、未配置、没有真实样本或缺少可比基准；不得折算为通过或失败。
- 测试替身只证明测试路径；真实数据验收必须说明来源、样本范围、采集时间、授权状态、持久化结果和精确 SHA。
- 新增字段必须在任务记录中给出来源、语义、时间口径、可空条件和授权要求；新增接口必须给出真实调用方和调用场景。
