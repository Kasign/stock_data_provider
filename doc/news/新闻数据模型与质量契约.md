# News 数据模型与质量契约

更新时间：2026-11-25  
适用分支：repair_all  
权威执行任务：NEWS-POST-08

本文是 News 当前数据模型和质量语义的唯一契约。旧版 N1/N3/N4 设计口径不再适用；与本文或 NEWS-POST-08 实施计划冲突的旧字段、旧身份规则和旧关系规则全部废止，不作为兼容要求。

## 1. 新闻主体

- 一条 `news_items` 表示一篇文章，不表示新闻事件。
- `news_items` 保存当前可直接读取的完整新闻内容：规范 URL、标题、发布者、作者、发布时间、内容层 JSON、内容指纹及创建/更新时间。
- 完全相同的规范 URL 全局唯一，不受来源 ID 限制。
- 不同 URL 默认是不同文章。不得按标题相似、正文相似、事件相同、跨站转载或重定向关系自动合并。
- 不创建 URL 缺失且没有可信来源原生文章 ID 的正式新闻主体。
- URL 与来源原生 ID 分别命中不同主体时返回身份冲突，不自动合并既有主体。

## 2. 身份与 URL

### 2.1 规范 URL

- URL 使用现有 Source URL Policy 的校验和规范化结果。
- 规范 URL 保存在 `news_items.canonical_url`，允许 NULL。
- 非 NULL URL 同时保存 SHA-256 `canonical_url_hash`，并建立全局唯一约束。
- Hash 只用于索引和快速定位；命中后必须比较完整规范 URL 原文。Hash 相同但原文不同属于冲突。
- 不追踪复杂重定向链，不推断跟踪参数语义，不做跨站转载识别。

### 2.2 来源原生身份

- `news_identifiers` 只保存来源原生文章 ID，不保存 URL 类型身份。
- 唯一范围为 `source_id + identifier_hash`；Hash 命中后比较 `identifier_value` 原文。
- 同一规范 URL 被多个来源发现时复用同一 `news_id`，每个来源分别保留自己的来源原生身份和 Observation。
- 删除 `identifier_type`、`identifier_status` 和身份状态历史能力；不保留历史 URL 别名兼容。

## 3. 内容与版本

- `news_items` 保存当前内容；`news_item_versions` 保存不可变历史快照。
- 首次正式入库创建初始版本。
- 内容指纹只反映来源侧内容和元数据；规范 URL、来源原生 ID、Provider 摘要和采集时间不属于内容指纹。
- 当前内容指纹未变化时不新增版本；内容实质变化时，在同一事务内更新主体并追加版本。
- A→B→A 属于真实内容变化，恢复到 A 时仍追加新版本。
- 纯采集时间、观察时间、Provider 来源变化不构成内容版本变化。
- 版本至少保留 Research/PIT 所需的版本号、指纹、标题、发布者、作者、发布时间、content_json、observed_at 和 observation_id。
- 当前新闻读取不要求先关联版本表。

## 4. Observation 与采集入口

- Observation 表示一次发现或采集记录，不是新闻主体，也不长期保存完整正文副本。
- Observation 保留来源/Provider、采集时间、策略版本、身份处理结果、必要候选元数据、质量原因和短期候选载荷。
- RSS/Atom 成功采集后进入统一正式入库用例。
- Provider SearchCandidates 默认只作为 Researchflow StageOutput 候选；只有研究流程明确选中/确认后才进入正式 News。
- StageOutput 生命周期由 Researchflow 管理，不由 News Cleaner 管理。
- 不开发人工导入 UI、API、表或写入路径。

## 5. 正式入库事务

RSS/Atom 与被选中的 Provider 候选共用唯一正式入库用例。一个 MariaDB 事务内完成策略复核、主体解析/创建、来源身份写入、Observation 写入和必要版本写入。

固定锁顺序：

1. 按固定类型顺序锁定并读取当前 Source/Endpoint/Provider 策略指针。
2. URL 存在时，按 canonical_url_hash 获取跨实例 URL 命名锁。
3. 获取来源原生身份的 source_id 命名锁。
4. 全局解析 URL、来源原生 ID；命中不同主体则返回 identity_conflict。
5. 锁定或创建 news_items。
6. 锁定最新版本并比较指纹。
7. 写入来源身份和 Observation。
8. 提交事务后释放命名锁。

唯一索引是最终并发防线，进程内 Mutex 不能替代数据库约束或跨实例协调。所有正式写入路径必须遵守同一锁顺序。

## 6. 最终 News V1 表清单

保留 10 张表：

1. `news_items`
2. `news_identifiers`
3. `news_observations`
4. `news_item_versions`
5. `news_authorization_snapshots`
6. `news_evidence_snapshots`
7. `news_policy_versions`
8. `news_current_policy_versions`
9. `news_version_availability_evidence`
10. `news_version_availability_decisions`

删除 4 张表及其专属 Domain/Application/Repository/DTO/测试：

- `news_relation_assertions`
- `news_relation_evidence`
- `news_item_relations`
- `news_identifier_status_history`

News 不负责新闻与证券/行业关系，也不负责新闻转载关系。相关关系分析如有真实需求，由对应业务模块实现。

## 7. 时间与 PIT

- `published_at` 仅表示来源声明的发布时间。
- `observed_at` 表示一次 Observation 被系统观察到的时间。
- `fetched_at` 仅表示真实响应体读取完成时间。
- `normalized_at` 表示解析和标准化完成时间。
- `available_at` 只有在存在绑定具体内容版本、可追溯且符合授权要求的首次公开可获取时间证据时才允许填写。
- 不得由 published_at、Provider 索引时间、HTTP Date、Last-Modified、fetched_at 或 observed_at 推导 available_at。
- PIT/Research 继续通过 Version、Observation 和 Availability Evidence/Decision 建立可追溯证据链。

## 8. 质量与诊断

- 新闻业务质量与技术执行状态分离。
- 数据缺失、内容降级、身份冲突、策略拒绝和依赖故障使用各自稳定的 reason_code，不混成单一状态。
- 缺凭证、未配置来源、未授权或没有可比较样本时标记 skipped/not_comparable，不伪造通过。
- 诊断必须可定位到来源、策略版本、Observation、内容版本或具体依赖；不以空结果掩盖失败。
- 不为个人研究系统增加没有真实调用方的质量评分、自动转载推断或复杂治理流程。

## 9. 不兼容原则

最终 V1 直接替换旧 Schema 和旧逻辑。不做旧数据迁移、旧逻辑兼容、双写、兼容视图或旧字段保留。用户在最终 Schema 验收后手动清理旧 News 数据；本任务不远程清库。
