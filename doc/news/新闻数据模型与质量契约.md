# 新闻数据模型与质量契约

> 版本：设计草案 v0.1  
> 状态：待 N1 盘点现有模型、数据库和证券主数据后冻结

## 1. 设计原则

- 原始来源证据与标准化业务字段分离。
- 新闻记录、正文内容、内容版本、来源和关联事实职责清晰。
- 所有重要字段保留来源、采集时间和可信度。
- 区分 NULL、未知、未采集、明确为空和采集失败。
- 复用现有证券标准 ID，不重复建设证券主数据。
- 不将搜索摘要等同于原文正文。
- 不将模型推断写入来源事实字段。

## 2. 时间语义

| 字段 | 含义 | 约束 |
|---|---|---|
| `published_at` | 来源声明的原始发布时间 | 必须记录来源及可信度；无法确认则为空 |
| `available_at` | 信息实际可被市场参与者获取的时间 | 无可靠证据不得推算或伪造 |
| `fetched_at` | 系统从来源获取记录的时间 | 系统生成，统一 UTC 存储 |
| `normalized_at` | 系统完成标准化的时间 | 系统生成 |
| `system_observed_at` | 系统首次观察到该记录的时间 | 首次写入后不可被后续采集覆盖 |
| `source_version` | 来源侧版本或内容版本标识 | 无来源版本时使用内部版本策略，不伪造来源版本 |

禁止将搜索引擎更新时间冒充原始发布时间，禁止将当前采集时间冒充历史可用时间。时区、原始时区、解析方式和时间可信度需要可追溯。

历史研究和回测必须遵循 point-in-time 原则：只使用当时已经可获得且系统有证据证明可用的数据。

## 3. 逻辑实体候选

以下为逻辑实体，不是已冻结的物理表结构；最终命名、字段和关系须结合仓库 ORM、迁移和索引规范确定。

### news_sources

来源目录和来源配置：来源类型、权威等级、基础地址、启用状态、访问策略、授权/保留策略、能力和诊断状态。

### news_items

新闻主记录：内部 ID、来源引用、来源原始 ID、标题、规范 URL、摘要、语言、发布时间、首次观察时间、标准化状态和质量摘要。

### news_contents

正文或内容载体：内容类型、原始/规范化内容引用、内容指纹、采集状态、长度、格式和保留策略。正文缺失不能伪装成完整。

### news_versions

同一新闻内容的版本历史：版本号、来源版本、内容指纹、观察时间、变化类型和证据引用。不得用新内容覆盖后丢失历史。

### news_relations

新闻与证券、行业等实体的关联事实：实体类型与标准 ID、关联类型、关联来源、置信度/状态、证据片段或证据引用、生成方式和版本。

## 4. 去重和版本识别

不能只按标题去重。候选信号包括：

1. 来源原始 ID（同一来源内优先）。
2. 规范 URL。
3. 来源标识与规范 URL 的组合。
4. 正文/原始内容指纹。
5. 标题、发布时间、来源等辅助相似度。

必须区分：
- 同一条新闻的重复抓取。
- 不同来源转载同一内容。
- 同一新闻后续修订。
- 标题相似但内容不同的独立新闻。

去重决策需要保留匹配依据，避免误合并造成证据丢失。

## 5. 来源和内容质量

质量至少覆盖：

- 来源身份是否明确。
- 来源权威等级。
- 发布时间可信度。
- 内容完整度（仅标题、摘要、正文、附件等）。
- 正文可访问性。
- 规范 URL 有效性。
- 重复判断及匹配依据。
- 证券/行业关联质量。
- 采集延迟和数据新鲜度。
- 内容版本变化和历史可追溯性。

质量状态不能只用布尔 success 表示；需要区分成功、部分成功、降级、跳过、失败和未知，并与项目现有质量状态契约保持一致。

## 6. 来源分级

至少区分：
- 官方披露：监管机构、交易所、法定信息披露平台、上市公司公告。
- 新闻媒体和行业来源。
- 搜索引擎或聚合 Provider：例如 Bocha、Tavily、Brave、SearXNG。

不同类别采用不同的权威性、时间可信度和完整度评价规则。搜索结果只能作为发现入口，不天然等同于权威原始来源。

## 7. 数据库约束

- 首阶段只新增新闻专属表。
- 不修改或重建行情、财务、估值、证券主数据表。
- 迁移必须可重复执行，包含启动检查和明确的回滚/恢复策略。
- 评估唯一索引、查询索引、历史版本增长和数据保留成本。
- 正文存储策略须遵守来源授权和保留限制。
- 物理表结构须经 N1 评审后冻结。

## 8. 验收要点

固定样本覆盖时间缺失、时区、重复抓取、跨来源转载、内容修订、正文缺失、错误证券关联、来源不可用和历史可追溯场景。不得以新闻数量或接口 HTTP 200 作为唯一验收标准。
