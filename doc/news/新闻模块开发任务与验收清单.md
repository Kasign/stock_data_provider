### N1 任务编号映射核对（来源：feat/design_doc / doc/整体任务规划/整体任务规划总览.md）

| 编号 | 原始任务边界 | 本新闻专项的关系 |
|---|---|---|
| DATA-016 | 新闻/公告来源接入契约、原始记录与来源时间、去重索引、证券/行业关联基础数据、事件存储与历史版本；不含 LLM 解释和前端展示 | 本专项承接新闻基础数据、来源、去重、证券/行业关联和内容版本；事件存储仅作为基础数据契约评估，不做事件研究逻辑 |
| MIG-005 | Go 新闻源/搜索适配、采集、标准化、去重、来源/时间元数据、原始证据和失败分类 | 本专项主要迁移任务 |
| MIG-006 | 事件识别/聚合/生命周期、事实与推断分离、证券/行业关联、版本化和事件后价格验证 | 完整事件处理不在本专项实施范围；只预留新闻关联和事件存储基础边界 |
| MIG-008 | Go Repository、事务、幂等、任务/研究结果/历史版本写入，核对旧 Python 表、迁移、保留和回滚 | 本专项只迁移新闻专属数据和旧新闻/情报表；其他业务 Repository 不在范围内 |
| RESEARCH-004 | 新闻与事件生命周期：采集、去重、来源可信度、事实核验、事件分类、证券/行业/产业链关联、影响方向/时效/不确定性、价格验证 | 属于上层完整研究能力，不在新闻基础设施专项实现；新闻模块只提供可追溯来源事实和关联证据 |

任务边界结论：新闻基础设施可以提供事件研究所需的事实数据、来源证据、时间、关联和版本基础，但不负责 LLM 解释、事件生命周期判断、影响方向推断或事件后收益验证。不得把 DATA-016 的“事件存储基础”扩张成完整 RESEARCH-004，也不得把 MIG-006 全部并入新闻采集模块。
