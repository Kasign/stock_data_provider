用户已明确整体服务尚未投入使用，按最终架构直接建设，不为旧服务保留兼容层。此前 N1-A 中关于共享 Provider Module、go-core 双调用方、旧 NewsSearcher、Python fallback 和旧 DTO 转换的设计全部由本节替代。

### N1-A 已确认的架构冻结项
- [x] 不创建独立 `shared/newsprovider` Go Module；Provider Adapter 直接归属根模块 `internal/news/adapters/provider/`。
- [x] 不调整 go-core Docker 构建上下文，不引入跨 Go Module 本地 replace。
- [x] 不保留旧 NewsSearcher/Python Bridge fallback/旧 NewsItem DTO 兼容层。

- [x] 不为旧 go-core/Python 调用链设置兼容、双写或双运行验收。

### N2 实施顺序调整
1. 在根模块建立新闻 Domain、Application 端口和 Provider 候选/执行结果模型。
2. 将现有 Provider 协议能力按新契约迁移到根模块 Adapter；只迁移必要协议处理，不复制旧 Searcher 聚合、缓存和 fallback。

4. 为 Bocha/Tavily/Brave/SearXNG 建立固定响应契约测试；对未获准留存的 Provider 验证策略拦截。

6. 后续按 N3/N4 推进来源抓取、解析、身份、版本和证券关联；DB/Redis/通用诊断仍按公共服务计划延期。

### N5 调整

- 无新闻专属 DB/Redis/通用诊断实现；不新增新闻 HTTP 路由。
