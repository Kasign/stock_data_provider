# 新闻来源授权矩阵

> 核查日期：2026-11-05
> 状态：第一轮公开条款核查；不是法律意见，不等于已取得任何来源的书面授权
> 适用范围：个人低频 A 股研究助手；不默认对外分发、商业转售或向多租户提供新闻内容

## 1. 使用原则

必须将两类授权拆开判断：

1. **Provider 输出使用权**：新闻搜索/聚合 API 是否允许使用、缓存、保存或再分发它返回的候选结果。
2. **原始发布来源内容权利**：新闻发布者、监管机构、交易所或信息披露平台是否允许抓取、保存摘要/正文、建立历史数据库及向用户展示。

Provider 允许保存输出，不代表原始发布者允许保存其文章全文；Provider 不允许保存结果，也不能通过随后抓取原始 URL 来绕过 Provider 自身的使用限制。

来源可访问、存在 RSS、内容公开或用于投资研究，都不能单独推导出自动抓取、长期保存、再分发或训练模型的授权。

### 1.1 个人研究用途的判断口径（2026-11-25 校准）

- 本项目是个人使用的 A 股研究工具，不对外提供新闻服务，不转售、不向多租户共享新闻内容。没有商业合同或书面商业授权，不再作为所有来源接入的统一前置条件；应依据具体来源公开条款、访问方式、内容类型和个人研究目的分别判断。
- 个人非商业浏览/下载与服务端脚本采集、批量抓取、长期保存、全文建库是不同动作。来源条款明确允许个人浏览或临时下载时，可先采用人工访问/人工导入路径；不能据此自动启用 RSS 轮询、脚本抓取或全文长期保存。
- 条款明确禁止自动化访问、系统性收集或 text/data mining 的来源，不进行自动采集，不绕过登录、验证码、访问控制、限速或反爬措施。
- 个人学习/研究对已发表作品的使用仍须逐项满足适用法律条件并保留作者、作品名称和来源；这不是对批量复制、完整数据库建设、自动化访问或任意留存的概括许可。
- 首期默认本地、单用户、低频、最小必要留存；不对外展示或分发第三方全文。人工取得的内容也必须记录来源链接、作者/发布者、取得方式和取得时间。
- available_at 是独立的数据事实门禁：人工取得时间、系统 observed_at、网页 published_at 均不能自动替代首次公开可获取时间。缺少可验证证据时仍为 unknown，不进入 Strict PIT。

### 2.1 Provider 规则的实现含义

- Provider 结果和发布来源内容必须有独立策略判断，不能用一个 `persist_allowed` 布尔值概括。
- 搜索候选可临时进入当前请求的内存处理流程；是否允许持久化 observation、标题、摘要、URL、全文，按 Provider 输出条款和来源内容权利分别判断。
- 对 Brave，持久化 Search Results 不允许；对博查，存储权利未明确前不持久化；对 Tavily，Provider 层存储许可不能覆盖第三方发布者版权。
- 不允许将“先从受限 Provider 搜到 URL，再抓取原文”的路径作为规避 Provider 结果限制的手段。若使用第三方搜索结果进行跳转，须确保仅作必要的临时定位，并由独立来源策略决定是否可形成新闻事实记录。
- Provider 条款、套餐、Order Form 或企业补充协议可能变化；上线前应核对实际账号适用版本，而不是只依赖公共网页。

## 4. 媒体、行业站点和聚合源

- 媒体/行业网站必须逐个记录发布者、服务条款、版权声明、robots 规则、允许访问方式、内容类型、留存范围和复核日期。
- RSS/Atom 只说明存在订阅格式，不自动授予服务端长期保存全文、建立数据库或再分发的权利。
- robots.txt 是自动化访问规则信号，不等同于版权许可或合同授权；两者都要检查。
- NewsNow 等聚合器必须进一步追溯实际上游发布者；聚合器可访问不代表聚合器拥有第三方内容授权。
- 没有明确许可的来源，默认只保留必要的来源名称/链接等最小定位信息是否可行也需逐源确认；不能把“只存 URL”当成无条件免责方案。
- 不把摘要改写、提取事实或模型生成摘要视为自动脱离原始内容权利约束。

## 5. 建议的策略状态与默认动作

| 状态 | 含义 | 默认动作 |
|---|---|---|
| approved | 已核验具体协议/授权，覆盖指定访问方式、字段、保存用途和期限 | 仅在授权范围内采集和保存 |
| restricted | 有明确限制，例如禁止长期保存或禁止自动化访问 | 按限制缩小为临时使用/禁止抓取/禁止持久化 |
| pending | 条款不明确、未找到条款或需要书面确认 | 禁止自动化抓取和持久化内容 |
| revoked | 授权撤销、到期或来源要求停止 | 停止新增采集，按约定清理受影响载荷并保留必要审计记录 |

策略至少按以下维度表达，不得仅按来源名称设置一个总开关：

- 访问方式：manual / official_api / rss / scripted_web / licensed_feed。
- 可采集内容：metadata / title / snippet / abstract / full_text / attachment。
- 可保存内容：none / transient / persistent_metadata / persistent_excerpt / persistent_full_text。
- 用途：internal_personal_research / internal_business / public_display / redistribution / model_training。
- 保留期限、缓存期限、删除要求、署名要求和来源链接要求。
- 授权依据 URL、协议版本/日期、核验人、核验时间、适用账号/套餐及复核时间。

同一来源的访问许可和内容保存许可必须分别判断；Provider 许可和发布者许可必须同时满足。

## 10. NEWS-CTR-002 AuthorizationRef 签发与读取验收

News 是 Provider 输出策略、Source 策略、Endpoint 策略交集的唯一授权决策 Owner。Research/Researchflow 只消费不透明 AuthorizationRef，不复制策略判断。

### 10.1 签发绑定

- `policy_version` 必须逐字等于 `PolicySnapshot.snapshot_ref`，表示完整策略组合快照；Provider Output/Source/Endpoint 的具体版本只放入 `PolicySnapshot.policies`，不得将单个 News Registry 版本写入该字段。

- `subject_ref` 必须等于可信调用上下文中的 caller_ref；禁止从请求体、Query、任意 Header 或 Evidence 字段读取未经认证的主体。
- `resource_ref` 必须使用唯一规范格式 `news_evidence_version:{news_id}:v{version_no}`，精确绑定不可变 News Item Version；`version_id` 继续作为独立不透明 ID，不参与 resource_ref 拼接。
- `purpose_code` 必须等于本次受控请求用途：research_analysis、risk_review、user_display。不得将未识别用途映射为默认用途。
- `content_level` 是本次实际允许访问的最高内容级别；metadata/summary/snippet/full 只按枚举顺序表达级别，不代表自动降级许可。请求级别高于策略允许级别时拒绝本次请求，不得静默返回较低级别内容。
- PolicySnapshot 必须包含本次决策实际适用的全部策略版本：Provider Output Policy（若该 Evidence 由 Provider 输出形成）、Source Policy、Endpoint Policy（若该入口存在独立策略）。不存在独立 Endpoint Policy 时必须明确按 Source Policy 继承，不得虚构 Endpoint 版本。
- Endpoint Policy 默认只能收紧 Source Policy；扩大权限必须有独立、可审计的书面许可。任一适用策略为 pending/restricted/revoked 或用途/内容级别不满足时，最终决策不得为 allowed。
- conditional 仅用于可满足的明确条件（如 attribution_required）；条件满足后重新评估并签发新的 allowed 引用。旧 conditional 引用永远不能直接用于读取。
- 授权快照是审计事实，不是 bearer token；每次读取按当前策略重新授权。策略检查与内容读取之间策略版本变化，必须重新授权；无法证明一致性则丢弃正文并拒绝返回。

- `golden/NEWS-CTR-002-authorization-binding.golden.json`：将 NEWS 绑定字段与 GOV-CTR-006 News conditional 向量组合，验证 caller/resource/purpose/content_level 与 AuthorizationRef 及 PolicySnapshot 的跨对象绑定。

| NEWS002-RACE-01 | 授权检查后、正文读取前策略版本发生变化 | 重新授权；无法证明版本一致则丢弃正文并 fail closed | 无正文 |
| NEWS002-FAIL-01 | 策略服务/策略存储不可用或决策 unknown | 受限内容默认拒绝，不回退历史 allowed 或缓存正文 | unavailable + 无正文 |

NEWS-CTR-002 的项目级定义已在 PLAT-002 登记簿中冻结（L1）。本表列出的 Schema/Golden、News Owner 绑定、当前策略读取和并发竞态证据属于后续 L2 实现符合性门禁；在运行时 JCS Verifier、可信策略 Resolver 和授权/内容一致性边界未验收前，不得宣称 News 的 L2/L3 已通过。

## 9. Source/Endpoint 策略继承规则

- Source 级策略为默认规则，适用于该发布者所有入口。
- Endpoint 级策略只在某入口有独立条款/授权/访问限制时建立，不复制相同内容。
- Endpoint 级规则默认只能收紧 Source 级权限；扩大权限必须有单独书面许可及明确适用范围。
- 未配置 endpoint 级策略时继承 source 级策略；source 级策略 pending 时不得自动采集。
- 最终权限是 Provider 输出策略、Source 策略、Endpoint 策略、使用目的和保留期限的交集。


## 11. 个人研究接入决策（2026-11-25）

本项目没有商业用途，也没有对外分发场景。后续接入按“先人工、后自动；先元数据、后正文；先单条、后批量”推进：

- 不因缺少商业书面授权而冻结全部公开来源。
- 公开条款允许个人浏览/临时下载的来源，优先建设人工取得、人工确认出处的入口；不自动推导为服务端抓取许可。
- 自动化采集只针对访问方式和内容留存范围均有明确依据的来源；不明确的来源保持自动化关闭，但不妨碍用户人工查阅。
- 首批人工入口不得将人工取得时间伪装为 available_at。严格 PIT 仍要求来源字段语义、精确版本绑定、原始证据和审核 Decision 全部成立。
- 当前代码尚无 Server 生产装配的 SourceCatalog/CollectSource/IngestCollectedSource 链路；因此本节是接入策略调整，不代表人工导入功能或真实来源采集已经实现。
