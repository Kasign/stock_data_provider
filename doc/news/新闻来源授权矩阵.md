# News 来源接入策略

更新时间：2026-11-25  
适用范围：个人研究系统  
当前规则：不以商业授权或多用户 SaaS 场景作为 News 自动采集的前置门槛。

## 1. 使用边界

- 系统仅供用户个人研究使用，不建设公共新闻平台，不向第三方提供新闻数据服务。
- 不按商业许可、转授权或多租户治理要求阻断个人研究流程。
- 不在 News 中实现面向外部用户的新闻分发、销售或开放 API。
- 数据源是否可用以真实访问结果、凭证、接口稳定性和用户配置为准，不因旧文档中的商业许可推断自动关闭来源。

## 2. 保留的技术策略

Source、Endpoint、Provider Policy 只承担可执行的技术配置和研究数据边界：

- 是否启用来源/Provider。
- Endpoint 的协议、主机、端口和安全访问范围。
- API 凭证是否配置、请求超时、响应体大小、配额和重试预算。
- 本次采集允许保存的内容层级、保留时间和策略版本。
- 内容字段的来源、观察时间、标准化结果和质量状态。

这些策略用于保证采集可控、结果可追溯，不作为商业授权审核系统。

## 3. 内容保存规则

- 标题、发布者、作者、发布时间等元数据随正式新闻主体保存。
- Feed 来源摘要按当前 Source/Endpoint Policy 的内容层级保存。
- 未识别类型的正文不自动升级为全文；解析器明确识别内容类型后，才能按对应策略保存。
- Provider SearchCandidates 默认只进入 Researchflow StageOutput；被研究流程选中后才进入正式 News。
- Provider 返回的摘要不冒充原始发布者的 SourceSummary。
- Observation 保存发现过程和必要候选元数据；不长期复制完整正文。
- 内容发生变化时追加版本，不覆盖历史版本。

## 4. PIT 时间证据

- `published_at` 是来源声明的发布时间。
- `observed_at` 是系统观察时间。
- `available_at` 只有在来源明确提供首次公开可获取时间，且能绑定具体内容版本和原始证据时才填写。
- 不从 RSS pubDate、Provider 索引时间、HTTP Date/Last-Modified 或系统采集时间推导 `available_at`。
- 缺少合格证据时保持 NULL；严格 PIT 排除该记录，不伪造时间。

## 5. 当前执行边界

- 不开发人工导入 UI/API/表或独立写入路径。
- RSS/Atom 走 Feed 采集和统一正式入库事务。
- Provider 候选通过 Researchflow 选择后走统一正式入库事务。
- Source/Endpoint/Provider 策略版本保留用于复现采集决策；不再保留旧文档中的逐供应商商业许可拦截规则。
- 缺少凭证、来源未配置或没有可比较样本时，诊断为 skipped/not_comparable，不伪造通过。
