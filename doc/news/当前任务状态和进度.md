## 3. NEWS-POST-01 任务边界

### 目标

明确是否存在独立 Feed 生产触发场景，以及触发方与生命周期责任。跨模块核对已确认：Researchflow 管理 Run/Stage/Attempt，Server 管理 Worker/Scheduler 生命周期，Platform 提供 RequestID；News 不默认拥有通用执行身份。

### 本任务允许范围

- 只读核对 `internal/news/app`、`internal/news/domain` 与 Server/Researchflow 现有调用路径。
- 明确 Feed 采集是否作为 Researchflow Stage，或作为 Server 管理的独立 Worker 用例；区分请求追踪、工作流执行身份、新闻领域身份和业务幂等键。
- 明确一次采集执行的触发方、批次边界、重放/幂等作用域、失败/取消语义和 Worker 传播方式。
- 形成依赖/决策文档，更新模块总规划和当前任务状态。

### 本任务禁止范围

- 不新增 CollectionRunID 字段、接口、表或 Migration，除非真实场景证明需要持久化独立采集生命周期。
- Researchflow Run/Stage/Attempt 只作为工作流编排身份，不复制为 News 领域身份；RequestID 只用于请求追踪。
- 不新建通用 Scheduler、Task Queue、独立 HTTP API 或 Service Key。
- 不修改 `cmd/**`、`internal/server/**`、`internal/platform/**` 或其他模块。
- 不以固定 Fixture 或 Stage 搜索候选冒充 Source Feed 真实采集验收。

### 退出条件

1. 是否需要独立 Feed 生产任务有明确业务场景和调用方。
2. 触发入口及 Server/News/Researchflow 的责任边界明确。
3. 优先复用 RequestID、Researchflow Run/Stage/Attempt 和现有业务幂等键。
4. 只有存在独立持久化生命周期需求时，才定义新增身份的来源、语义、幂等范围和保留期限。
5. 对应设计与依赖文档完成评审；没有真实调用场景时不增加代码。
