### NEWS-POST-08-FIX-02：Schema 外键运行时校验

- 问题证据：原 `ValidateSchema` 只检查表集合、必需列和索引；Migration 虽然定义了外键，但启动校验无法发现外键被人工删除、改指其他表或列顺序漂移。
- 修复：从 MariaDB `information_schema.key_column_usage` 读取外键定义，校验 11 个外键的名称、所属表、本地列顺序、引用表和引用列顺序，并拒绝缺失或额外外键。
- 测试：增加外键缺失、引用表错误、复合列顺序错误的单元测试；Migration 测试核对全部外键声明；MariaDB 集成测试在应用 V1 后直接执行 `ValidateSchema`。

### NEWS-POST-08-FIX-01：来源身份补充规范 URL 的持久化

- 问题证据：统一入库用例在来源原生 ID 命中已有新闻后，会在内存主体上补充规范 URL；但 Repository 更新原先仅发生在内容指纹变化时，导致内容未变化时 URL 身份补充没有落库。
- 回归测试：`TestIngestCandidatePersistsCanonicalURLWhenNativeIdentityAlreadyExists`，验证同一来源原生 ID 后续补充 URL 后，主体 ID 不变、URL/hash 已持久化且不增加内容版本。
- 修复：将“内容是否变化”和“身份字段是否变化”分开判断；内容变化追加版本，内容变化或规范 URL 身份补全时更新当前主体。仅补全身份不增加版本。
