### 7. NEWS-POST-02 News 侧初步代码核对

| 核验项 | 当前代码事实 | 结论/缺口 |
|---|---|---|
| Provider 配置与装配 | News Config 支持 Bocha/Tavily/Brave/SearXNG；Platform ProviderSet 为每个 Provider 独立绑定目的地址；Server 已将 ProviderSet 注入 News Search Stage | 搜索 Provider 生产组合已存在，不重复建设 |
| Source Catalog | Application 有 SourceCatalog Port；当前只有 StaticSourceCatalog 启动快照实现 | 尚无权威 Source/Endpoint 注册数据的生产装配；News Config 没有 Source 注册配置，Migration 也没有 Source/Endpoint 目录表 |
| Source Transport | NewPlatformEndpointTransport 按每个 Source/Endpoint 创建独立 Platform DestinationPolicy 适配器 | 适配器构造能力存在，但 Server 没有实际构造/注入 |
| CollectSource | 使用已登记 Source/Endpoint，执行授权预检、RSS/Atom 获取和解析；结果是 transient，不写 DB | 单次采集用例存在，无生产调用路径 |
| IngestCollectedSource | 独立复核当前 Source/Endpoint 策略并写 Observation 元数据；需要调用方提供 IdempotencyPrefix | 持久化用例存在，未与 CollectSource 形成生产组合 |
| 策略新鲜度 | CollectSource 根据 StaticSourceCatalog 内嵌策略快照做采集前判断；Ingest 才在 DB 事务内锁定当前策略版本 | 策略运行期替换时可能先按旧快照发起网络请求、后在入库阶段被拒绝；生产接入前必须补齐采集前当前策略校验/原子快照刷新或明确受控重启约束 |
| Server 组合根 | 当前 News Search Stage 只装配 ProviderSet；Research News Composition 只装配 Evidence Query/Importer | 未装配 SourceCatalog、SourceTransport、CollectSource、IngestCollectedSource |

**当前缺口不是缺少一个 News Scheduler。**真正缺少的是可信 Source/Endpoint 注册数据来源、真实调用方，以及 Collect → Ingest 的组合调用路径。先确定注册数据来源和调用方，再判断静态启动快照是否足够；没有证据前不新增持久化目录、Orchestrator、Worker 或调度器。

**授权一致性风险：**CollectSource 在网络请求前只基于 StaticSourceCatalog 的内存策略快照执行授权判断；数据库当前策略版本的锁定复核发生在 IngestCollectedSource 的 Observation 写事务中。现有测试分别证明快照未授权时不发请求、数据库策略版本变化时不落库，但没有证明运行期数据库撤销会阻止采集前的网络请求。需要先确定策略更新是否强制重启刷新 Catalog/Transport，或增加采集前当前策略校验及原子快照机制。不得把“最终拒绝入库”当作“采集前已拒绝访问”。

**幂等约束：**IngestCollectedSource 通过调用方 IdempotencyPrefix 与条目指纹生成 Observation 幂等键；现有测试证明部分提交后复用同一 Prefix 可以安全重试。调用方必须让同一逻辑执行的所有重试复用 Prefix，新逻辑执行使用新 Prefix；不应按每次 Attempt 重新生成 Prefix。
