## 1. 迁移原则

Go 替代能力验收前，不删除 Python Bridge、旧服务、旧调用方或兼容配置。

Python 旧实现可以作为固定样本对照基准，但不能将旧实现的缺陷视为 Go 的正确行为。

## 3. 迁移步骤

1. 完整搜索 Python 代码和所有调用方。
2. 为每条链路建立输入输出契约和固定样本。
3. 实现 Go 替代能力，保留旧链路。
4. 对比功能、时间语义、来源证据、质量和异常行为。
5. 运行单元、契约、集成和真实环境验证。
6. 通过受控开关灰度切换。
7. 观察日志、指标和业务结果。
8. 确认无旧调用后，提出退役方案。
9. 经明确批准后再删除旧实现和配置。
