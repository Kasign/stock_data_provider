## 1. 结论摘要

新闻模块与公共平台采用“平台提供横切技术能力、新闻模块保留领域所有权”的方式协作。平台能力不是一个替新闻实现业务 Repository 的数据库服务，也不是要求 News 等待全部平台任务完成后才能开发。

- N2/N3/N4 的纯 Domain、协议 DTO、离线解析、身份/版本/关系规则可先行开发。
- 生产网络调用等待 PLAT-002 契约冻结、PLAT-008 可用，以及新闻自身的授权和 SSRF 安全门禁。
- 新闻持久化等待 PLAT-009 的 DB 生命周期和 Migration Runner；Repository、SQL、新闻表和 Migration 内容仍由 News 实现。
- 通用诊断框架由 PLAT-007 提供；新闻质量规则和领域 Check 实现仍由 News 提供。
- Redis、异步 Task、Audit 均非新闻首期强制依赖，必须由真实场景驱动。

## 2. 所有权矩阵

| 能力 | 公共平台负责 | 新闻模块负责 |
|---|---|---|
| Config / Secret | 类型化装载、校验、Secret Provider、脱敏 | Provider/Source 配置结构、凭证引用、业务策略 |
| Identity / Security | Principal、Scope、认证授权 Middleware、Service Key | 新闻操作所需的授权意图；当前同进程调用不创建 Service Key |
| Logger / Fault / Trace | slog 约定、通用错误包装、Request ID、Trace 传播和脱敏 | 新闻领域错误 Code、ProviderOutcome、部分成功语义 |
| HTTP Client | 连接池、TLS、总 Deadline、响应体上限、通用 Retry Policy、Trace 传播 | Provider 协议、配额、业务并发、Provider 错误分类、来源 URL/SSRF 授权策略 |
| Diagnostics | Check、Registry、Runner、超时/并发、状态聚合和受保护查询 | 新闻来源/Provider/解析/身份/质量等领域 Check 和质量算法 |
| Storage / Migration | DB/Redis 连接生命周期、通用事务/健康能力、Migration Runner/排序/互斥 | 新闻 Repository、SQL、领域表、索引、数据保留、Migration 内容 |
| Task | 通用任务生命周期、Actor 快照、租约/重试/恢复 | 新闻采集业务输入、Observation、内容版本和业务结果 |
| Audit | 通用审计事件模型、Writer、访问约束 | 未来来源策略变更等领域管理动作发出审计事件 |
| Metrics | 指标命名、低基数标签和 Exporter | 新闻业务指标定义及统计口径 |

## 4. 平台已接受的三项契约评审及实施门禁

News 于本轮向 feat/platform-foundation 提交三项跨分支评审意见。平台分支已在 `98f561ec812b8b27fee5b4fb9d35b1accade93d8` 正式接受并更新文档：

### 4.1 HTTP Client / SSRF（接受，P0 安全门禁）

- News 负责 source/endpoint 授权、用途策略和 host/port allowlist。
- Platform HTTP Client 负责 DNS/IP 特殊地址拦截、受控 DialContext、校验 IP 与实际 TCP 连接绑定、默认禁止重定向及逐跳复核、默认禁用环境代理。
- 每次 Redirect 重新验证 scheme、host、port、来源 allowlist 和 DNS/IP；禁止 HTTPS 降级。
- 未通过 SSRF/DNS rebinding/重定向/代理绕过测试前，不开放任意来源真实抓取。
- 平台当前已实现安全 HTTP Client 与 `BoundDoer`，并有受控回归测试；这不代表 News 已完成领域注入或生产公网 SSRF 验收。新闻 Adapter 不得自行复制一套生产 HTTP Client。

### 4.2 Diagnostics 字段（接受，进入正式契约）

- `reason_code`：非 healthy 结果必须提供的稳定机器原因标识，由领域维护词汇。
- `safe_message`：必填脱敏摘要。
- `evidence_ref`：可选不透明引用，由 News 解释和授权；Platform 只透传，不读取、不拥有新闻 Observation。
- `attributes`：有界、白名单、低敏感结构化标量，不得承载正文、snippet、原始响应或 Secret。
- 新闻质量、Freshness、授权状态仍由 News 判断；平台只负责 Check 执行和聚合。

### 4.3 Fault 字段（接受，进入正式契约）

- `retryable`：默认 false，只表示技术上可作为重试候选，不自动触发重试。
- `dependency`：可选稳定逻辑依赖标识，不得包含原始 URL、IP 或凭证。
- 实际重试仍受请求幂等、HTTP Retry Policy、剩余预算和总 Deadline 约束。
- Provider 级部分成功、配额、候选拒绝和业务重试判断继续保留在 News 的 ProviderOutcome/领域结果中。

### 4.4 当前状态边界

平台分支 `PLAT-002` 仍为待评审，公共契约尚未冻结。PLAT-008 已有安全 Client、DNS/拨号/重定向/代理/响应体约束及 `BoundDoer` 策略绑定实现，并有平台专项测试证据；但 News 尚未在组合根按 endpoint 注入独立 BoundDoer，也未完成生产 DNS/出口与来源授权验收。当前仍只进行固定样本、fake Transport 和离线解析，不执行任意来源真实抓取。


## 5. 新闻业务状态与平台诊断状态映射原则

以下维度必须并列保留，不能互相覆盖：

| 新闻领域状态 | 语义 | 平台 Check 表达建议 |
|---|---|---|
| quality=valid | 新闻数据满足业务质量规则 | Check 执行正常时 healthy |
| quality=degraded | 有数据但字段/时间/覆盖不完整 | degraded，并保留 quality=degraded |
| quality=invalid | Check 成功执行，但新闻内容不满足质量规则 | degraded，并保留 quality=invalid；不能把平台 failed 当作内容 invalid |
| quality=unknown | 证据不足，无法判断 | degraded 或按具体场景 skipped；必须保留 unknown 原因 |
| freshness=stale | 数据超过业务新鲜度阈值 | degraded，并保留 freshness=stale |
| authorization=pending/restricted/revoked | 不允许执行某些采集/留存用途 | skipped/unavailable 视策略而定，保留授权状态和原因 |
| Check 实现 panic/非法结果 | 平台 Check 自身异常 | failed |
| 未配置可选 Provider | 本次没有执行该能力 | skipped/not_configured |

Platform failed 表示 Check 自身执行异常，不表示新闻数据 invalid。Provider 请求 empty、partial、failed、skipped 仍是 SearchCandidates 的业务结果，不由一个 Diagnostics 状态代替。

## 6. 调整后的新闻阶段路线

### N2：Domain / Application / Provider 协议
- 实现独立 Domain、Application Ports、Provider DTO 和执行结果。
- Provider Adapter 通过注入式窄 Transport Port 发送请求；不创建生产 Client。
- 使用固定响应样本和 fake Transport；不要求真实 Key 或实时网络。

### N3：来源安全、解析和标准化
- 实现来源授权决策、URL 规范化、Feed/HTML 解析、编码和时间标准化。
- 设计逐跳 Redirect 与 DNS/IP 安全校验。
- 离线解析可先做；真实网络抓取等待 PLAT-008、SSRF 安全钩子和来源许可确认。

### N4：身份、版本和关系规则
- 实现 Identity、Hash 原文核验、跨来源转载隔离、版本指纹和关系断言。
- 使用 fake Repository/内存替身验证业务规则，不实现生产 SQL。

### N5：公共平台基础能力接入
- PLAT-002 正式冻结后，接入 PLAT-005/006/008 的稳定 API。
- 不引入新闻专属认证、Secret 管理、HTTP Client、日志或通用错误框架。

### N6：新闻持久化
- PLAT-009 提供可用 DB 生命周期和 Migration Runner 后，News 实现自己的 SQL Repository、新闻表和 Migration。
- MariaDB 是首选事实存储；Redis 暂不列为首期依赖。
- 历史 Python 数据不自动导入。

### N7：诊断及可选任务/审计
- PLAT-007 可用后注册新闻领域 Check。

- Audit 当前无独立 PLAT 任务编号；只有未来出现来源策略管理等敏感管理操作时，再评估最小审计事件接口。

### N8：集成验收
- 按 PLAT-011 完成跨模块契约、DI、Migration、运行和数据质量验收。
- 按 PLAT-012 计划执行必要故障演练。
- Provider/Source 真实验收必须满足授权条件；未确认许可保持 skipped/restricted。

### H1：历史 Python 数据价值评估（可选）

- 只有确认历史数据具有明确价值后，另立一次性导入任务。

## 2026-11-06 NEWS-CTR-002 方案与实现 Review

### Review 结论

当前架构边界成立：News 是授权决策 Owner；Platform 只提供通用技术原语；AuthorizationRef 是审计引用而非访问令牌；历史 allowed 不替代读取时当前授权检查。当前不新增 News 独立服务、HTTP 路由、Service Key、数据库/Redis 私有框架或无真实调用方的采集编排。

### 本轮修正与实现范围

- Binding DTO 对 `provider_ref`、`endpoint_ref`、`expires_at` 均增加显式存在性判断，避免把字段缺失误认为合法 null；允许显式 null 表达无 Provider/无独立 Endpoint 策略继承。
- Validator 校验 trusted caller/resource/purpose 绑定、内容级别、decision/conditions、UTC 时间、fingerprint 格式、Snapshot 版本引用和策略 tuple 绑定；同一 Source/Provider/Endpoint 只允许一个实际生效版本。
- 修正策略快照负例：按 `policy_type=provider_output` 精确移除策略，不依赖数组下标；此前 CI 失败来自该测试用例误删 endpoint 策略，不是生产 Validator 失败。
- 当前仅校验 fingerprint 格式；公共 GOV-CTR-006 JCS Verifier 尚未进入 News 共同基线，禁止在 News 内复制 canonicalization 算法。
- 本次 Validator 仅证明 DTO/快照内部一致性；不代表授权签发、当前策略查询、内容读取门禁、TOCTOU 竞态或跨模块联调已完成。

### Review 遗留项

1. 等公共 GOV-CTR-006 JCS Verifier 进入共同基线后，接入 Golden 指纹复算；不得自行实现第二套算法。
2. 为每个 News 内容读取点定义 Owner 当前策略复核接口，并验证历史 allowed、撤销、过期、授权服务不可用时 fail closed。
3. 明确授权检查与正文读取之间的策略版本一致性边界，补竞态保护；不可证明一致时丢弃正文。
4. 将 Provider Output Policy、Source Policy、可选 Endpoint Policy 的实际生效版本接入真实授权决策调用链；不得从候选 DTO 自报策略版本。
5. 生产授权签发、不可变快照保存和 AuthorizationRef 生命周期需要真实 Repository/组合根条件；当前不得提前虚构持久化或编排调用方。
6. 通过 NEWS-CTR-002 适用的 Schema、Golden、Owner Contract、READ/RACE 测试并形成 CI 证据后，才能申请升级契约状态。
