## 1. 结论摘要

新闻模块与公共平台采用“平台提供横切技术能力、新闻模块保留领域所有权”的方式协作。平台能力不是一个替新闻实现业务 Repository 的数据库服务，也不是要求 News 等待全部平台任务完成后才能开发。

- N2/N3/N4 的纯 Domain、协议 DTO、离线解析、身份/版本/关系规则可先行开发。
- 生产网络调用等待 PLAT-002 契约冻结、PLAT-008 可用，以及新闻自身的授权和 SSRF 安全门禁。
- 新闻持久化等待 PLAT-009 的 DB 生命周期和 Migration Runner；Repository、SQL、新闻表和 Migration 内容仍由 News 实现。
- 通用诊断框架由 PLAT-007 提供；新闻质量规则和领域 Check 实现仍由 News 提供。
- Redis、异步 Task、Audit 均非新闻首期强制依赖，必须由真实场景驱动。

## 2. 所有权矩阵

| 能力 | 公共平台负责 | 新闻模块负责 |
|---|---|---|
| Config / Secret | 类型化装载、校验、Secret Provider、脱敏 | Provider/Source 配置结构、凭证引用、业务策略 |
| Identity / Security | Principal、Scope、认证授权 Middleware、Service Key | 新闻操作所需的授权意图；当前同进程调用不创建 Service Key |
| Logger / Fault / Trace | slog 约定、通用错误包装、Request ID、Trace 传播和脱敏 | 新闻领域错误 Code、ProviderOutcome、部分成功语义 |
| HTTP Client | 连接池、TLS、总 Deadline、响应体上限、通用 Retry Policy、Trace 传播 | Provider 协议、配额、业务并发、Provider 错误分类、来源 URL/SSRF 授权策略 |
| Diagnostics | Check、Registry、Runner、超时/并发、状态聚合和受保护查询 | 新闻来源/Provider/解析/身份/质量等领域 Check 和质量算法 |
| Storage / Migration | DB/Redis 连接生命周期、通用事务/健康能力、Migration Runner/排序/互斥 | 新闻 Repository、SQL、领域表、索引、数据保留、Migration 内容 |
| Task | 通用任务生命周期、Actor 快照、租约/重试/恢复 | 新闻采集业务输入、Observation、内容版本和业务结果 |
| Audit | 通用审计事件模型、Writer、访问约束 | 未来来源策略变更等领域管理动作发出审计事件 |
| Metrics | 指标命名、低基数标签和 Exporter | 新闻业务指标定义及统计口径 |

平台不拥有新闻业务表、新闻 Repository 或新闻质量规则；News 不创建第二套连接池、通用 HTTP Client、诊断 Runner 或任务框架。

## 4. 当前契约需要平台分支评审澄清的差异

本节是新闻接入方的 Review 意见，不代表平台分支已经接受修改。

### 4.1 HTTP Client 安全策略

平台详细设计列出 Proxy/TLS/Redirect/并发策略，但 PLAT-002 的 httpclient.Policy 示例没有明确：

- Redirect 是否默认禁止或逐跳验证；
- DNS 解析结果如何与实际 Dial 绑定，如何阻止 DNS rebinding；
- 私网、回环、链路本地、保留地址和 IPv4-mapped IPv6 如何阻断；
- 每个依赖的并发限制是否由 Client Factory 统一承载。

新闻 Source Fetcher 可能访问外部 URL，必须对初始地址和每次重定向重新执行 URL、DNS/IP、协议和来源策略校验。仅在请求前解析一次 DNS 不足以防 DNS rebinding。未确认安全钩子前不执行任意来源真实抓取。

### 4.2 Diagnostics Observation 字段差异

平台详细设计提到 reason_code、safe_message、evidence_ref；PLAT-002 的 Observation 示例目前只有 status、summary、checked_at、duration、attributes。新闻接入需要稳定 reason code 和受控 evidence reference。建议平台契约明确：
- reason_code 是否为正式字段；
- evidence_ref 是否允许引用新闻 Observation 或受控业务证据；
- Attributes 的允许字段、大小和敏感级别。

不能把正文、snippet、完整 Provider 响应塞入 Attributes。

### 4.3 Fault 字段差异

平台详细设计列出 retryable/dependency，PLAT-002 的 fault.Error 示例目前主要是 Class/Code/Message/Cause。新闻侧 Provider 重试判断仍放在 ProviderOutcome 和 HTTP Policy，不把可重试业务结果压缩进通用 Fault。平台需明确通用 Fault 是否承载 retryable/dependency，避免详细设计和契约稿继续不一致。

### 4.4 契约与实现状态

平台当前代码树可见 dotenv、局部 HTTP API 和历史 taskqueue 实现，但 PLAT-002 仍待接入方评审，PLAT-003~012 在任务表中仍未开始/未验收；PLAT-004 为条件任务且暂缓。代码存在不等于公共契约实现完成；News 不直接依赖尚未冻结的内部路径。

## 5. 新闻业务状态与平台诊断状态映射原则

以下维度必须并列保留，不能互相覆盖：

| 新闻领域状态 | 语义 | 平台 Check 表达建议 |
|---|---|---|
| quality=valid | 新闻数据满足业务质量规则 | Check 执行正常时 healthy |
| quality=degraded | 有数据但字段/时间/覆盖不完整 | degraded，并保留 quality=degraded |
| quality=invalid | Check 成功执行，但新闻内容不满足质量规则 | degraded，并保留 quality=invalid；不能把平台 failed 当作内容 invalid |
| quality=unknown | 证据不足，无法判断 | degraded 或按具体场景 skipped；必须保留 unknown 原因 |
| freshness=stale | 数据超过业务新鲜度阈值 | degraded，并保留 freshness=stale |
| authorization=pending/restricted/revoked | 不允许执行某些采集/留存用途 | skipped/unavailable 视策略而定，保留授权状态和原因 |
| Check 实现 panic/非法结果 | 平台 Check 自身异常 | failed |
| 未配置可选 Provider | 本次没有执行该能力 | skipped/not_configured |

Platform failed 表示 Check 自身执行异常，不表示新闻数据 invalid。Provider 请求 empty、partial、failed、skipped 仍是 SearchCandidates 的业务结果，不由一个 Diagnostics 状态代替。

## 6. 调整后的新闻阶段路线

### N1-A：架构和契约评审
- 已完成内部收敛；本矩阵加入后等待用户评审确认。
- 评审平台所有权、PLAT-002 接入方意见和新闻阶段门禁。

### N2：Domain / Application / Provider 协议
- 实现独立 Domain、Application Ports、Provider DTO 和执行结果。
- Provider Adapter 通过注入式窄 Transport Port 发送请求；不创建生产 Client。
- 使用固定响应样本和 fake Transport；不要求真实 Key 或实时网络。

### N3：来源安全、解析和标准化
- 实现来源授权决策、URL 规范化、Feed/HTML 解析、编码和时间标准化。
- 设计逐跳 Redirect 与 DNS/IP 安全校验。
- 离线解析可先做；真实网络抓取等待 PLAT-008、SSRF 安全钩子和来源许可确认。

### N4：身份、版本和关系规则
- 实现 Identity、Hash 原文核验、跨来源转载隔离、版本指纹和关系断言。
- 使用 fake Repository/内存替身验证业务规则，不实现生产 SQL。

### N5：公共平台基础能力接入
- PLAT-002 正式冻结后，接入 PLAT-005/006/008 的稳定 API。
- 不引入新闻专属认证、Secret 管理、HTTP Client、日志或通用错误框架。

### N6：新闻持久化
- PLAT-009 提供可用 DB 生命周期和 Migration Runner 后，News 实现自己的 SQL Repository、新闻表和 Migration。
- MariaDB 是首选事实存储；Redis 暂不列为首期依赖。
- 历史 Python 数据不自动导入。

### N7：诊断及可选任务/审计
- PLAT-007 可用后注册新闻领域 Check。
- PLAT-010 仅在定时/长耗时/可恢复采集需求成立时接入。
- Audit 当前无独立 PLAT 任务编号；只有未来出现来源策略管理等敏感管理操作时，再评估最小审计事件接口。

### N8：集成验收
- 按 PLAT-011 完成跨模块契约、DI、Migration、运行和数据质量验收。
- 按 PLAT-012 计划执行必要故障演练。
- Provider/Source 真实验收必须满足授权条件；未确认许可保持 skipped/restricted。

### H1：历史 Python 数据价值评估（可选）
- 不属于主路径，不做兼容、双写或在线切换。
- 只有确认历史数据具有明确价值后，另立一次性导入任务。

## 7. 关键决策

1. 不等待整套公共平台全部完成才开发纯领域能力。
2. 不为赶进度复制平台 HTTP/DB/Redis/Diagnostics 实现。
3. 不把平台 DB 连接能力误解为平台替新闻实现 Repository。
4. 不因平台提供 Redis/Task/Metrics 就默认引入新闻依赖。
5. 不把新闻业务质量、Provider 执行结果和平台诊断状态混为一个状态。
6. 不修改 feat/platform-foundation；平台契约意见仅作为新闻分支评审材料，待平台负责人确认。


## 8. 2026-11-05 最新平台分支规划对齐

本轮只读核对 feat/platform-foundation 最新检查 HEAD 44d10cd6197ca446b4bbf29dff9f62408b32bbfe，阅读 doc/platform/README.md、00 至 09 相关架构/路线图/契约文档。没有对该分支执行写操作。

### 8.1 最新变化

- PLAT-003 首期采用 owner Token + 每个调用方独立环境 Secret；不建设数据库凭证管理系统。
- PLAT-004 动态 Service Key 已降为 P2 条件任务并暂缓，不应作为新闻接入依赖。
- PLAT-011 是 Data/News/Research 按需接入；PLAT-012 是关键故障演练与运行手册。
- Metrics/Audit 没有独立任务编号，不得把它们映射成 PLAT-011/012 或虚构 PLAT-013/014。
- PLAT-002 仍是 v1.0.0-review；平台设计强调只为真实调用方抽取 package，不预建公共 Storage、Task 等抽象。

### 8.2 News 的依赖策略修订

1. 同进程 Application 不经过 HTTP，不需要 Service Key；若未来由既有 Server API 暴露，认证由该 API 和根服务统一处理。
2. N2/N3/N4 的纯 Domain、Provider DTO/协议样本、离线解析、身份/版本/关联规则可先行，不等待平台运行时代码。
3. 真实 Provider/Source 网络调用必须等 PLAT-002 冻结、PLAT-005/006/008 对应能力可用，并通过新闻来源授权与 SSRF 门禁。
4. PLAT-009 不能被解释成 Platform 替 News 实现 Repository。News 负责 Repository、SQL、表和 Migration 内容；连接生命周期、事务入口和 Migration Runner 是否抽为公共 package，以 PLAT-009 最终契约和实际调用方数量为准。若不抽公共包，由根服务组合根注入已有 DB 资源并由集成分支协调 Migration 注册；News 不自行另建连接池或私有 Migration Runner。
5. Redis、PLAT-010 Task、Metrics、Audit 均不作为新闻首期强制依赖。
6. PLAT-007 可用后再注册新闻领域 Check；新闻质量、Freshness、授权和内容有效性始终由 News 定义。

### 8.3 PLAT-002 冻结前的待解决契约问题

- **安全 HTTP：** 明确 Redirect 默认策略；每跳重做 URL、DNS/IP 和来源授权检查；将 DNS 校验结果绑定实际 Dial，防 DNS rebinding；明确私网/回环/链路本地/保留地址和 IPv4-mapped IPv6 的处理。
- **并发预算：** 明确每依赖连接/请求并发上限由 Client Policy 还是调用方控制；News 仍负责 Provider 配额、来源抓取频率和业务并发。
- **Diagnostics：** 明确稳定 Reason Code、受控 Evidence Reference、Attributes 白名单/大小上限/敏感级别；不得放入新闻正文、snippet、完整响应或 Secret。
- **Fault：** 通用 Fault 与 ProviderOutcome 分离。Provider 可重试性和部分成功保留在新闻业务结果/调用策略中，不压成单一平台错误。
- **Storage/Migration：** 明确 PLAT-009 是可直接注入的 DB 生命周期与 Runner，还是仅提供治理约定；不要为抽象而抽象，也不能让 News 被迫自建重复连接池。

### 8.4 执行门禁

平台文档“已规划”不等于实现“可用”。News 接入某项能力前至少核对：契约已冻结、目标 package/API 已实现、单测/契约测试通过、根服务集成方式明确。真实 Provider/Source 还需授权许可核实；测试替身不作为线上连通性或持久化验收证据。
