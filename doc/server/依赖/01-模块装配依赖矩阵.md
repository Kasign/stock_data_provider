## 2. 本轮新增的 News Root 装配

- Root 使用 Server 自己持有的 MariaDB，构造 News MySQL Repository；不创建第二套连接池。
- API/All 角色注册 News 存储连接和 News-owned 表结构检查；不把领域对象质量检查误当作进程 Readiness。
- Worker/All 角色启动 News Retention Cleaner，周期执行：
  - 到期 Observation / Availability Evidence 载荷清理；
  - 到期 Evidence Pagination Snapshot 清理。
- 清理使用 News 模块已有 Application Cleaner 和 Repository Port；Server 只负责调度、时间源、批次配置和生命周期。
- Root 真实 MariaDB 集成测试已验证 Observation 到期载荷清理：批次 2 的 2+1 续跑、重复执行幂等、未到期载荷保留；精确 SHA `f5821a356e23691d9738f4b3808abf8e0e3494d8` 的 Server CI 全项通过。该测试不覆盖真实 Provider 采集，也不将 Fixture 视为市场数据证据。
- 默认间隔 5 分钟、批次 100；可通过 `NEWS_RETENTION_INTERVAL`、`NEWS_RETENTION_BATCH_SIZE` 调整。只在 Worker/All 角色读取该配置。
- 当前不装配 RSS/Atom 来源采集 Worker：仓库虽有 `CollectSource`、`IngestCollectedSource` 和 `StaticSourceCatalog`，但没有生产 Source/Endpoint 目录配置和受治理的完整采集调用链。不能凭空生成来源记录或把任意 URL 作为采集入口。

## 3. Migration 统一管理边界

Root Registry 内部执行 News、Research、Researchflow、Notification、Platform Security、Server Security Audit 等静态 Migration。Data 当前公开的是模块自有 `MigrationRunner.Migrate(ctx)`，并未公开完整静态 Migration 定义。

本轮 Server 增加显式 `RegisterExternalNamespace("market_data")`：
- Data Migration 仍由 Data Module 自己调用 Platform Runner；Root Registry 不执行空 Migration，也不复制 Data SQL。
- Root 只读校验要求 `market_data` 至少有一条历史记录，且所有记录版本均为非零、状态均为 `applied`。
- 此外部命名空间检查不验证预期版本集合和 checksum；不能等同最终统一 Migration Registry。
- Data Store 在 Platform ApplyMigrations 锁释放后仍执行兼容索引/补列 DDL，锁外并发竞态仍待 Data Owner 修复。
- 最终方案仍是 Data 提供静态不可变 Migration 定义、兼容 DDL 版本化，Platform 提供只读 checksum 校验，Server 统一注册/调度。

## 4. Diagnostics 装配边界

当前 Root Diagnostics 包含：
- Platform MariaDB/Redis/Schema Registry Checks；
- Data Module Readiness Check；
- News Storage Connection/Schema Checks；
- News RSS/Atom Parser Self-check；
- News Provider Configuration Checks；
- 其他真实进程级检查（若模块正式提供）。

不自动注册：
- Research Context/Event/Claim/Evidence 质量评估：必须绑定具体对象与 `run_as_of`；
- Researchflow StageAssessment：属于单次 Run/Stage，不代表进程健康；
- Quant 指标/因子有效性：属于具体计算输入和结果；
- Notification 投递成功率：必须有真实渠道与实际 Delivery；
- LLM 模型能力：必须有绑定 Provider/Model/Gateway 版本和有效期的实测 Evidence。

不创建空 Check、恒 true Check、无真实依赖的诊断字段。Required Check 不健康必须影响 Readiness；可选 Provider 未配置应明确 skipped，不冒充 PASS。

## 5. 跨模块调用规则

1. Server 是唯一应用组合根，不成为领域数据的第二所有者。
2. 同进程调用使用模块公开 Application Port，不通过 localhost、内部 HTTP 或伪造 API Key 绕行。
3. 事件通知使用冻结 Outbox/Inbox 契约；Relay 成功只代表接收/入箱，不代表渠道发送。
4. HTTP 路由只注册已批准且已有正式契约的 Handler；SRV-CTR-001 deferred 时不开放 Researchflow 公网 API。
5. 每项新依赖必须明确真实调用场景、接口提供方、字段来源、错误/超时和诊断判定。
6. 不因模块目录存在就推断它已具备生产服务；没有持久化、授权、真实 Provider 或调用方的能力保持未装配。
