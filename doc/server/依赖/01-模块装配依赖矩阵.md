## 3. Diagnostics 装配边界

当前 Server 注册共享 MariaDB/Redis/Schema Checks，以及 News Parser/Provider Configuration Checks。

- Data 的 Module Diagnostics.Ready 是可用于 Root Readiness 的模块公开入口，待 SRV-009 接入。
- Research 的 Context/Event/Claim/Evidence Checks 是针对具体领域对象和 run_as_of 的质量评估，不自动注册为全局进程健康检查。
- Researchflow StageAssessment 是单次 Stage 的 pass/degraded/fail/not_comparable，不自动注册为全局进程健康检查。
- 其他模块只有提供真实、稳定、可调用的进程级 Check 时，才由 Server 适配到 Platform Runner。
- 不创建空 Check、恒 true Check 或无真实依赖支撑的诊断字段。

## 4. 跨模块调用规则

1. Server 是组合根，不成为领域数据的第二所有者。
2. 同进程调用使用模块公开 Application Port，不通过 localhost、内部 HTTP 或伪造 API Key 绕行。
3. 事件通知使用已冻结 Outbox/Inbox 契约；Relay 成功只代表接收/入箱，不代表渠道发送。
4. HTTP 路由只注册已批准且有正式契约的 Handler；SRV-CTR-001 deferred 时不开放 Researchflow 公网 API。
5. 每项新依赖必须明确真实调用场景、接口提供方、字段来源、错误/超时和诊断判定。
