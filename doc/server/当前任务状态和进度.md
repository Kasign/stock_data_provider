## 3. 实施前置问题

以下问题必须在代码实施前明确，不得靠临时增加接口或复制公共能力绕过。

### 3.1 Data MigrationRunner 与 Server Registry 对接

- Data Module 的公开 MigrationRunner 只有 Migrate(ctx) error。
- Server Registry 当前接收 []platformstorage.Migration，并通过 ValidateApplied 做只读版本校验。
- Data Module 没有向 Server 暴露完整 Migration 定义；Store.Migrate 内部调用 Platform ApplyMigrations，但调用结束后还有兼容索引/补列 DDL。
- Data Store.Migrate 中版本化 Migration 由 Platform ApplyMigrations 执行，但后续兼容索引/补列逻辑在该调用之后继续执行。

**复核结论：不建议 Server 适配当前的 Migrate(ctx) error，也不建议 Root 直接调用它。**

建议采用唯一迁移链路：
1. Data 在自己的公开 Bootstrap API 暴露完整的 `Migrations() []platformstorage.Migration`（或等价只读定义接口），供 Server 在构造 Data Module 前注册；迁移 SQL 仍由 Data 拥有。
2. Root 将 namespace `market_data` 和 Data Migration 定义注册到现有 Server Registry，由 Platform ApplyMigrations 统一执行。Server 不创建第二套 Runner，不访问 Data 私有 SQL。
3. 保持已发布版本 1～3 的 Statement 内容和 checksum 不变；把当前 Runner 外的兼容索引/补列操作迁为后续新版本（4+），所有 DDL 必须在同一 namespace 锁内执行。不得修改旧版本内容来“顺便修复”。
4. 兼容操作必须同时覆盖全新库和历史库。先核验目标 MariaDB/MySQL 版本对条件 DDL 的支持；若静态 SQL 无法跨目标版本安全表达条件操作，应由 Platform Migration Runner 提供受锁的条件迁移能力，不得保留当前 Runner 外的 information_schema 检查与 ALTER 竞态。
5. `MIGRATION_ENABLED=true` 走 Root Registry + Platform Runner；false 走只读校验，未应用、失败、未知版本或 checksum 不一致均 fail-closed。

**额外发现：Server Registry 当前的 ValidateApplied 只读取 namespace/version/status，没有读取或比较 platform_schema_migrations.checksum。** 它的注释称 checksum 校验由 Platform Runner 负责，但 `MIGRATION_ENABLED=false` 时并不会调用 ApplyMigrations，因此此路径实际上漏掉 checksum 校验。建议 Platform 提供与 ApplyMigrations 共用 prepare/checksum 逻辑的只读 `ValidateAppliedMigrations` 公共方法，Server Registry 只负责逐 namespace 调用；不要在 Server 重写 SHA-256 算法。

因此 SRV-009 的 Migration 子项有两个外部前置：Data 提供可注册定义并消除 Runner 外 DDL；Platform 提供只读 checksum 校验（或经评审的等价公共能力）。在这两个前置完成前，不接入旧 `MigrationRunner.Migrate`，也不宣称迁移接入完成。

## 5. 验收标准

- PASS：Data Module 使用唯一 Root 共享资源；启用 Provider 的 HTTP/TCP 出口均有明确受控执行器；Migration 可重复且并发安全；Data Readiness/路由/Lifecycle 正常；真实 MariaDB/Redis 测试通过。
- DEGRADED：仅可选 Provider 被明确标记 skipped/degraded，必需资源、Schema 和核心路由仍健康；诊断必须给出 reason_code 和证据引用。
- FAIL：必需资源或 Schema 不可用、受控出口缺失、Migration 失败/并发不安全、身份上下文不可信、Lifecycle 无法安全关闭；启动或 Readiness 必须 fail-closed。
- NOT_COMPARABLE：Provider 未配置、没有真实样本或无法核对真实上游行为；只能记录不可比较，不能记为真实 Provider 验收通过。
