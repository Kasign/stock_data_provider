## 3. Migration 未完成项与风险

当前 Root 在 `MIGRATION_ENABLED=true` 时调用 Data Module 公开的 `MigrationRunner.Migrate(ctx)`，随后执行 Server Registry 中其他模块的 Migration。该方式复用了 Data/Platform 现有实现，但还不是最终统一注册方案。

仍存在两个代码事实：

1. Data Store.Migrate 在 Platform ApplyMigrations（版本 1～3）返回后，仍在锁外执行 `ensureNonUniqueHistoryIndex`、`ensureColumn`。多 API/Worker 实例可能并发观察到同一索引/列缺失并执行 DDL，存在真实竞态风险。
2. `MIGRATION_ENABLED=false` 时 Server Registry.ValidateApplied 只验证已注册 namespace/version/status，不比较 Data Migration checksum；Data Diagnostics.Ready 当前检查 DB/Redis Ping，不验证 Data Schema。因此不能把该分支日志理解为 Data Schema/checksum 已通过。

最终方案仍为：Data 公开不可变 Migration 定义并将兼容 DDL 纳入版本 4+；Platform 提供共用 checksum preparation 的只读校验能力；Server 只负责注册和调度。在前置合入前，Migration 子项维持 IN_PROGRESS，不宣称多实例启动安全。

## 5. 验收口径

- PASS：共享资源唯一；启用 Provider 的 HTTP/TCP 出口均受控；Application/HTTP/Diagnostics/Lifecycle 真实集成通过；Migration 执行和只读校验并发安全；精确 SHA CI 和真实 MariaDB/Redis Bootstrap 测试通过。
- DEGRADED：仅可选 Provider 明确 skipped/degraded，必需存储、Schema、路由和生命周期仍健康，且有 reason_code/evidence。
- FAIL：必需资源/Schema 不可用、受控出口缺失、Migration 失败或存在未控制的并发 DDL 风险、认证上下文不可信、无法安全关闭。
- NOT_COMPARABLE：无真实 Provider 样本或没有可比较来源；不能将 CI Fixture/Mock 记为真实行情验收。
