## 1. 模块目标与边界

Server 是唯一应用组合根和对外 HTTP 宿主，负责配置 Bootstrap、共享资源创建、模块构造与依赖注入、路由注册、认证接入、Migration 汇总、Worker 生命周期、Health/Readiness/Diagnostics 和优雅关闭。

Server 不实现 Data/News/Research/Quant/Researchflow/LLM/Notification 的领域规则，不复制 Platform 的 HTTP Client、Fault、Security、Storage、Migration Runner 或 Diagnostics Runner，不直接访问其他模块私有 Repository/SQL/Domain。

## 6. 生产装配准入与诊断标准

- 只装配模块已公开且可构造的 Application Port、Handler、Worker、Migration 和 Check。
- 所有 Config 在 Bootstrap 读取并校验，作为不可变快照注入。
- 共享资源由 Server 创建并拥有；模块借用，不提前关闭。
- 关闭顺序：先停止消费者/Worker/Relay/模块后台任务，再关闭共享 HTTP Client、Redis、DB。
- 业务模块之间通过公开 Application Port 或冻结 Outbox/Inbox 契约交互，不直接访问彼此数据库。
- 模块没有真实 Provider、Schema 或消费者时，不创建空 Registry、空 Adapter 或占位 Worker。
- 诊断统一使用 Platform Diagnostics Runner；Server 只做模块 Check Adapter，不复制 Runner。

每项新增诊断必须在任务设计中明确：
- PASS：必需依赖和必需检查均 healthy，且有当前检查时刻的真实证据。
- DEGRADED：必需链路仍可用，但可选 Provider/能力被明确跳过或部分不可用；必须保留 reason_code/evidence，不得包装成 PASS。
- FAIL：必需依赖、Schema、受控出口或必需检查失败；Required 检查不健康时 Readiness 必须拒绝流量。
- NOT_COMPARABLE：未配置可比较来源、无真实样本或缺少可验证证据；不得将其记为健康或真实数据验收通过。

进程 Readiness 与领域数据质量分开：Provider 无配置/无样本不必然导致进程不可启动，但不能据此宣称数据质量 PASS。Required/Optional 必须在每个 Check 注册时说明。

## 7. Owner Session 专项边界

- Owner Bearer 与 Owner Session 必须独立验证；浏览器只使用 HttpOnly Cookie Session，不下发 Bearer。
- Platform 提供 CredentialStore、SessionStore、CSRF、Login RateLimit、Hasher 和安全原语。
- SRV-CTR-002 定义 Owner Session 登录/登出/轮换/密码修改 HTTP DTO、路由和安全边界；当前项目契约状态仍以 PLAT-002 登记簿为准。
- 当前已完成 Schema/Golden/OpenAPI、真实 MariaDB/Redis HTTP 生命周期和 WebUI 消费代码；剩余是目标环境部署/浏览器验收和契约治理冻结，不重复开发已有 Handler。
- 不新增匿名初始化或匿名密码重置接口；生产 Argon2id 参数必须经目标硬件基准。
