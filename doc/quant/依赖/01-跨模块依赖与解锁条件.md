# Quant 跨模块依赖与解锁条件

更新时间：2026-11-18  
维护范围：Quant 模块依赖登记；项目级契约状态以 `doc/contract/PLAT-002-项目级契约冻结登记簿.md` 为准。

## 1. Data 依赖

| 依赖项 | Quant 用途 | 当前状态 | 责任方/解锁条件 |
|---|---|---|---|
| DailyBars v2 Decimal | Indicator/Factor 价格序列精确输入 | DATA-CTR-005 deferred；当前 v1 为 HTTP JSON number / InProcess float64 | Data Owner 完成精度可保真的 v2 DTO、scale/舍入、单位/缺失语义、interval、交易日历版本和真实 DTO/Golden |
| Snapshot 与 Evidence Locator | 输入快照身份、内容寻址和可追溯引用 | DATA-CTR-007 deferred | Data Owner 完成 Manifest、Snapshot 引用和访问契约 |
| PIT/复权 | 防止未来数据泄漏，保证价格口径一致 | 需按冻结 Data 契约验收 | Data 提供 available_at、source_version、adjustment_basis/reference_date 等权威元数据 |
| 交易日历/停牌 | 确认序列连续性和有效样本数 | 当前生产输入未闭环 | Data 提供版本化交易日历、交易状态及停牌/缺失区分 |
| 证券/行业主数据 | Market/Industry/Stock 分析 | 未满足对应分析输入 | Data 提供历史有效期、版本和稳定引用 |

Data v1 代码核验（只读 `feat/data`，HEAD `4fb13f3b9c2904b6a3a976075539c5d86a1b92ab`）：`internal/marketdata/app/port.go` 的 DailyBar OHLC/Amount/ChangePercent 为 float64，QuoteSnapshot 价格/金额/比率为 *float64，Volume 为 *int64；`internal/marketdata/httpapi/openapi.yaml` 对价格/金额/百分比使用 JSON number，对 Volume 使用 integer/int64。该链路是现有兼容基线，不代表十进制精度保真。把 float64 格式化成 String 不构成 Decimal v2，也不能恢复源值精度。

Quant 不得复制 Data Provider、行情标准化、Snapshot 存储或交易日历权威事实。DATA-CTR-005/007 未解锁前，相关真实数据链路标记 blocked/not_comparable，不发布伪真实结果。

## 2. Server / Platform 依赖

| 能力 | 当前 Quant 代码 | 责任方与缺口 |
|---|---|---|
| 可信 Principal | PrincipalResolver Port | Server 注入真实认证上下文，不接受请求自报主体 |
| 授权复核 | Quant Policy Owner 负责规则、不可变版本、当前策略复核和撤销一致性；GetResult 只验证 Owner 返回的授权证明 | Server 注入可信 Principal 并装配 Quant Owner；Platform 只提供公共 Fingerprint/Storage 原语，不拥有 Quant 业务策略 |
| Storage | Save Port、MemoryRepository、Quant 自有 MySQLRepository 和 quant namespace Migration | Quant 拥有结果 SQL Adapter 与 Migration 内容；Server 负责 Root 注册/注入；Platform 提供连接生命周期和 Migration Runner |
| Access Audit | AccessAuditor Port、MySQLAccessAuditor、quant_access_audit Migration v2 | Quant 拥有审计事件和持久化 Adapter；Server 注入 DB/Clock；审计保留期限、归档和生产权限仍待明确 |
| Clock | Application 注入边界 | Server 提供可信 UTC Clock；不得由 Domain 调用 time.Now |
| Diagnostics/Fault | 复用 Platform 公共语义 | Quant 只定义领域 Check 和判定，不新增第二套通用诊断/故障框架 |

Quant 只维护领域端口、调用时机和必要契约测试；不在 `internal/quant/**` 内创建 SQL、Redis、通用 Storage、Authorization 或 Diagnostics 框架。

## 3. Researchflow 依赖

- Researchflow 是 Quant 计算 Application 的首要消费者。
- Quant 提供强类型 Application Facade、稳定请求/响应、ResultRef/Envelope 和授权读取用例。
- Researchflow 负责生成/传播 request_id、correlation_id、可信 CallerRef，调用公开 Application Port，校验并消费已注册 Payload。
- Research 不直接 import Quant；需要量化结果时由 Researchflow 编排并传递授权引用/结果上下文。
- 目前 Quant Application 只有 GetResult，没有 Indicator/Factor 计算 Facade；不得把纯函数串接为伪生产 Provider。
- 只有完整 Payload Schema/Golden/Validator 和 Registry 注册项均存在的 result_type 才允许跨模块发布。

## 4. 当前解锁顺序

1. Quant 内部：QNT-001 Registry Entry → QNT-002 Indicator Payload → QNT-014 计算 Facade。
2. Data：DATA-CTR-005/007 满足登记簿重新进入条件后，Quant 才执行 QNT-015 真实输入 Adapter；Factor 同时等待 QNT-CTR-003 状态变化。
3. Server/Platform：完成生产 Reader/Storage/Auditor/Principal/Clock 注入后，QNT-013 才能通过生产持久化与授权验收。
4. Researchflow：在 Quant Facade、Payload Registry、CallerRef 和授权读取均具备后，执行实际 Stage Provider 消费验收。
5. Trend/Market/Industry/Stock/Strategy/Backtest 按各自真实输入和算法决议推进，不因当前联调完成而提前开放。

## 5. 诊断判定边界

| 状态 | Quant 依赖判定 |
|---|---|
| pass | 依赖契约已冻结、真实输入可读、快照/授权/质量证据完整 |
| degraded | 依赖明确允许降级，且缺失字段不影响本用例的必要计算语义 |
| fail | 必需依赖不可用、授权拒绝、数据完整性/PIT/复权门禁失败 |
| not_comparable | 契约版本、复权基准、交易日历、时间窗口或样本集合不一致 |

skipped 不计为 pass；不可比较不能降级为“基本通过”。诊断状态不替代 Quant 的 quality_status/result_status。


### 统计指标精度证据补充（2026-11-18）

Quant 现有 256-bit 参考测试通过 `big.Float.SetFloat64` 接收同一 float64 输入，只能证明算法运算阶段的数值误差，不能证明 Provider 原始十进制输入精度。Data v1 DailyBar OHLC 仍为 float64，DATA-CTR-005 仍 deferred。因此生产 Return/Volatility/RSI 的 tolerance、scale 与 rounding_mode 仍不可定；不重复增加只比较相同 float64 输入的参考测试。待 Data v2 提供原始精度、scale、舍入和真实 DTO/Golden 后，再由 Quant 建立端到端误差预算。


## 6. QNT-013 授权策略当前契约缺口（2026-11-20）

GOV-CTR-006 已冻结 Quant 的基础映射：policy_owner=quant；MVP subject_ref 来自可信调用主体且示例为 service:researchflow；resource_ref 精确对应 Quant result_id；purpose_code=quant_analysis；content_level=full；每次读取必须按当前策略复核；历史 allowed、expires_at=null 均不能绕过撤销；授权检查与结果读取必须具有可证明的一致性边界。

但 GOV-CTR-006 Quant Golden 仅是指纹/结构测试向量，不是生产 Allow 规则。当前缺少以下规则与治理定义，因此不得直接写入默认 allow-list：

1. Policy Payload 的机器 Schema 和字段：如何表达主体范围、结果归属/资源范围、用途/内容级别、条件、有效期及显式拒绝。
2. 生产判定规则：service:researchflow 是否可读取全部 Quant result_id，还是仅可读取指定 Run/调用链创建的结果；资源创建主体/调用链与结果之间的绑定事实由谁持有。
3. Policy Owner 发布治理：谁有权创建、发布、替换、撤销策略版本；更新是否需要审批/审计；如何防止普通业务调用者签发策略。
4. SnapshotRef 版本规则：不可变策略版本的命名/内容寻址、当前策略指针更新和历史版本保留规则。
5. 撤销并发边界：读取事务与撤销事务锁定同一当前指针；撤销成功后新读取不能使用旧版本；在途读取线性化点需明确。
6. Access Audit 的保留、查询、归档、删除授权和生产访问控制策略。当前 v2 表只追加事件，不自行设置保留期限或清理任务。

**当前已实现：** 结果不可变 MariaDB Repository/Migration v1；MySQLAccessAuditor 和审计表 Migration v2；审计写入失败由 GetResult 既有 fail-closed 语义阻断结果释放。  
**当前未实现：** Policy Owner 的策略 Payload/规则/版本签发与撤销、AuthorizedResultReader 线性化读取、Server Root 对 Repository/Reader/PrincipalResolver/Auditor 的完整装配。  
**执行门禁：** 项目契约 Owner 冻结上述规则/治理输入后，Quant 才实现 Policy Owner 与撤销竞态；不得以 Golden 代替生产规则。Researchflow Quant Stage 暂不接入。

### 7. QNT-013 当前 Run 结果访问范围决议（2026-11-20）

项目 Owner 已明确选择：**`service:researchflow` 只能读取当前 Researchflow Run 自己创建或明确关联的 Quant 结果**。服务主体身份本身不授予跨 Run 或全量 Quant 结果读取权。

执行约束：

1. 每次 Quant 结果读取必须同时具备可信 `subject_ref=service:researchflow`、可信当前 `run_ref`、目标 `result_id`；`run_ref` 不得来自普通请求体、任意 Header 或调用方自报字段。
2. 只有存在可验证的持久化关联，且关联记录的 `run_ref` 与本次可信当前 Run 完全一致，才允许读取。仅凭同一服务主体、相同 correlation_id、已知 result_id 或历史 AuthorizationRef 均不得推断关联。
3. 现有 Researchflow `researchflow_stage_output_resources` 已持久化不可变 Stage Output 内容及 `run_ref/stage_ref/attempt_ref`。优先复用该权威资源承载并验证明确的 Quant result_id 关联；先核实当前 Quant Stage 输出 Schema/Registry 是否已经表达该引用，不得假设所有 Stage Output 都已包含它，也不得另建重复关联表。
4. Run/Stage/Attempt 与 Stage Output 的事实由 Researchflow 持有；Quant Policy Owner 负责授权判定。Quant 不得直接查询 Researchflow 私有 SQL 表；通过明确的 Application Port 由 Server 组合根注入 Researchflow 关联读取适配器，或由 Researchflow 暴露等价的只读应用端口。
5. 缺少可信 run_ref、关联不存在、关联指向其他 Run、关联资源无法读取或校验失败，一律 fail-closed；不得退化为按 service principal 全局放行。
6. 不把 run_ref 塞入 Quant Manifest/QuantResultRef，也不改变 GOV-CTR-006 AuthorizationRef 公共字段；当前 Run 是读取时可信上下文与策略条件，除非后续正式契约评审明确要求公开 DTO 变更。

验收必须覆盖：同 Run 明确关联允许；同一主体读取另一 Run 结果拒绝；无关联拒绝；伪造/篡改 RunRef 或 ResultID 拒绝；缺失可信 Run 上下文拒绝；关联读取故障拒绝；授权撤销与结果读取并发边界仍保持线性化。当前 `GetResult.Execute(ctx, resultID)` 尚未接收可信 Run 上下文，`AuthorizedResultReader` 也未实现，因此本决议已确定授权范围，但生产实现仍 OPEN，不能把它记为 QNT-013 完成。
