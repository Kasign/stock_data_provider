## 1. 模块目标与边界

Quant 负责确定性、可复算的数值分析和风险判断。输入来自 Data 的证券主数据、行情、财务、估值、交易日历、历史行业成分、PIT 与质量契约；输出由 Researchflow 编排消费。Research 不直接 import Quant，也不直接调用 Quant 内部实现。

Quant 不调用 LLM，不负责研究编排，不直接访问 Provider/HTTP/SQL/Redis；不把指标输出自动解释为投资建议或交易指令。硬风险门禁不能被分数或模型覆盖。

- Quant Domain：算法、指标/因子定义、质量策略、Risk 规则和强类型结果。
- Quant Application：面向明确调用方的用例入口、幂等、输入校验、结果保存/读取编排。
- Quant 不拥有根 Server 组合根、Platform 公共基础设施、Data Provider 或 Researchflow Worker。
- 模块 CI、Fixture/Golden、真实 Data、生产 Storage/授权、Researchflow 消费分别验收，不互相替代。

### 阶段 A：模块内契约与确定性算法闭环（P0）

2. QNT-002：完成 IndicatorResultPayload 的 Go 强类型校验、Schema、Golden 和 Envelope 注册。未具备完整 Registry Entry 的指标不得进入 Envelope。
3. QNT-010：补齐 Risk 规则清单、RuleSet 完整性与规则版本加载策略；block 规则必须 required，输入 unknown 不得 pass。
4. QNT-014：实现公开 Application Facade、请求规范化、可信 Caller、幂等作用域和结果引用返回；只暴露有明确 Researchflow 调用场景的接口。

阶段 A 验收：公式和边界可复算；Schema/Golden/Go Validator 一致；未知类型/版本 fail closed；当前 SHA Quant 专项 CI 通过。Fixture 只证明确定性，不证明真实数据。

### 数值精度和输入类型约束（QNT-001 的实施门禁）

- 项目级 QuantMetric 已允许 `value` 按 `metric_code` 固定为 `string/number/null`；金额和价格采用明确 Decimal 精度策略，使用 float64 的统计指标必须声明误差容忍、舍入策略和固定样本。
- Data 当前 v1 的 DailyBar/Quote Application DTO 使用 float64，HTTP OpenAPI 使用 JSON number；Volume 使用 int64/integer。JSON 层改成 String 不会修复进入 float64 时已经发生的精度损失。
- 因此不得全量 String 化，不得静默修改 Data v1；价格派生指标的 Decimal 计算/输出必须等待 DATA-CTR-005 v2 提供精度可保真的输入 DTO。统计指标可独立完成逐项误差策略审计，但不得用 Golden tolerance 代替生产误差预算。
- 每个 Registry Entry 必须固定自己的 value_type；同一 metric_code 不得在不同接口、Schema 或版本中混用 String/Number。无来源的 precision、rounding_mode、range、error_budget 不得猜测。

#### QNT-001 统计指标审计阶段结论

- Return：算法为 simple/log 两种收益；输出类型候选 number，单位 ratio；N 个收益需要 N+1 个正数 close。simple 收益数学下界为 -1（严格大于），log 收益无有限上下界。
- Volatility：末尾 N 个收益的样本标准差乘以 sqrt(annualization_factor)；类型候选 number，单位 ratio，数学下界为 0。年化因子必须与 bar interval/交易日历依据绑定，不得默认 252。
- RSI：Wilder 初始均值 + 后续递推；输出范围 [0,100]，类型候选 number；unit 尚未有权威决议，不得猜测。sample_count 为当前实现实际处理的相邻 close_change 数，即输入 close 数减一。
- 以上只收敛算法语义与候选字段。GOV-CTR-001 要求 number 字段具备生产 precision/tolerance/rounding；Golden tolerance 不得充当生产误差预算。三项仍缺完整输入要求和 quality_policy，暂不创建正式 Entry。
- Registry NumericRange 当前只支持双边界或全 unbounded，无法表达 Return/Volatility 的单边数学边界；不得填任意上限。若采用 unbounded，需由算法边界测试单独保证已知不变量。
- Indicator Payload Schema 的 sample_count 目前 optional；DEC-PLAT-002-052 要求 Registry required_in_metric 与专属 Metric Schema 对齐。正式 Entry 前须核实生产 Metric 构造是否保证字段存在。
- QNT-CTR-002 的 annualization_factor 参数 Schema 1.0.0 未声明 maximum；Registry ValidateParameters 已对 volatility.annualization_factor 增加 GOV-CTR-001 安全整数运行时门禁。Metric.Validate 同样限制 sample_count。冻结 Schema 未修改，Schema 层 maximum 仍待后续版本演进。

## 6. 统一验收标准

- **公式与算法**：公式、窗口、seed、warm-up、缺失/异常、单位、精度、舍入、误差和算法版本可复算。
- **输入质量**：PIT、复权、交易日历、停牌/缺失、覆盖率和有效样本数有独立门禁。
- **结果身份**：Manifest 指纹、result_id、Payload Schema、Envelope 元数据一致；未知类型/版本 fail closed。
- **风险**：硬门禁优先于评分和模型；block 不可被覆盖；unknown 不得作为 pass。
- **授权**：可信主体来自 Server；当前策略复核、撤销、审计和记录读取具备一致性边界。
- **持久化**：相同 result_id/相同内容幂等成功；相同 result_id/不同内容冲突；并发写入由唯一约束/原子写入保证。
- **跨模块**：Researchflow 只调用公开 Application Port；Research 不直接依赖 Quant 内部包。

### 诊断判定

诊断四态与业务 quality_status/result_status 分开：

| 诊断状态 | 判定 |
|---|---|
| pass | 必需输入、契约、快照、时间、单位、质量和计算证据全部满足 |
| degraded | 仅存在 Registry 明确允许的非关键缺失/降级，且结果限制被显式记录 |
| fail | 必需输入缺失、PIT/授权/完整性违反、硬风险规则失败或计算不安全 |
| not_comparable | 数据口径、复权基准、交易日历、时间窗口、版本或共同样本不一致，无法进行有效比较 |

不得将 skipped 视为 pass；不得将 not_comparable 伪装成 degraded；业务质量状态不由诊断状态覆盖。
