任务前缀：QNT

## 1. 模块目标与边界

Quant 负责确定性、可复算的数值分析和风险判断。输入来自 Data 的证券主数据、行情、财务、估值、交易日历、历史行业成分、PIT 与质量契约；输出由 Researchflow 编排消费。Research 不直接 import Quant，也不直接调用 Quant 内部实现。

Quant 不调用 LLM，不负责研究编排，不直接访问 Provider/HTTP/SQL/Redis；不把指标输出自动解释为投资建议或交易指令。硬风险门禁不能被分数或模型覆盖。

## 4. 结果类型注册边界

当前完整 Envelope 仅注册：
- `trend/1.0.0`
- `risk/1.0.0`

IndicatorResultPayload 的容器 Schema/Golden/结构 Validator 已有，但逐指标 Registry Entry 的单位、精度、值域、质量策略和 sample_count 语义未齐，不得注册为完整 Envelope。FactorResultPayload 尚缺完整 Schema/Golden/Validator，并受 DATA-CTR-005 deferred 门禁约束。Market/Industry/Stock/Strategy/Backtest/Evaluation 仍为预留类型，必须 fail closed。

## 6. 核心验收门禁

1. 公式、窗口、seed、缺失/异常、单位、精度、舍入和误差均有可复算测试。
2. PIT、复权、交易日历和输入质量有独立门禁。
3. 真实数据验收记录 Provider、证券、日期、样本数、快照和质量；Fixture 不冒充真实数据。
4. unknown/null 不转为零或有效排序值；诊断状态不得替代业务 quality/result 状态。
5. 风险输入 unknown 必须 fail-closed；硬风险规则优先于评分。
6. Envelope 只允许已注册的强类型 Payload；未知类型/版本 fail closed。
7. 生产授权、审计和结果读取必须有可证明的一致性边界。
8. CI 必须关联精确 SHA；模块 CI、真实数据、生产 Storage 和跨模块消费分别记录。
