## 执行批次

1. Q0：先完成旧资产盘点、契约核对和 Golden 设计；Q0 未完成前不批量迁移旧代码。
2. P0：QNT-001~003；QNT-003 与 QNT-002 不建立强制串行依赖。
3. P1：QNT-004~010；市场/行业/个股按契约并行，策略和回测后置。
4. P2：QNT-011/012，等待足够历史样本和回测验收。
5. 存储可与对应领域能力并行设计；QNT-013 不得修改根 Migration 注册入口。

## 完成门禁

- 单测覆盖公式、窗口边界、缺失/异常、单位、精度和时区。
- 固定样本可重复运行，差异有解释。
- PIT/复权有独立测试。
- 回测交易制度和成本假设有边界测试。
- 真实数据验收记录 Provider、证券、日期、样本数、快照和质量。
- CI 精确关联当前 SHA；Mock/Fixture/构建通过不能代替真实数据验收。
- 诊断结果至少区分 PASS、DEGRADED、FAIL、INSUFFICIENT_DATA、NOT_COMPARABLE、UNKNOWN；具体规则由指标/因子契约定义，不允许把 unknown/null 转为零或有效排序值。

### 本模块可独立开工边界

- QNT-001~003 可先使用固定输入样本和内存实现完成领域算法及契约测试。
- QNT-003 与 QNT-002 不建立强制串行依赖；Factor 可以消费标准化输入序列，不必依赖 Indicator Engine。
- Data OpenAPI/Go DTO 修复只影响对应 Data Adapter 字段，不阻断 Quant Domain。
- QNT-013 拆分为 Repository Port/Schema 设计、模块 Repository 实现、真实 Storage/根 Migration 接入三个验收项；不得要求所有 Quant 能力完成后才开始存储设计。
