## 执行批次

1. Q0：先完成旧资产盘点、契约核对和 Golden 设计；Q0 未完成前不批量迁移旧代码。
2. P0：QNT-001~003；QNT-003 与 QNT-002 不建立强制串行依赖。
3. P1：QNT-004~010；市场/行业/个股按契约并行，策略和回测后置。
4. P2：QNT-011/012，等待足够历史样本和回测验收。
5. 存储可与对应领域能力并行设计；QNT-013 不得修改根 Migration 注册入口。

## 完成门禁

- 单测覆盖公式、窗口边界、缺失/异常、单位、精度和时区。
- 固定样本可重复运行，差异有解释。
- PIT/复权有独立测试。
- 回测交易制度和成本假设有边界测试。
- 真实数据验收记录 Provider、证券、日期、样本数、快照和质量。
- CI 精确关联当前 SHA；Mock/Fixture/构建通过不能代替真实数据验收。
- 诊断结果至少区分 PASS、DEGRADED、FAIL、INSUFFICIENT_DATA、NOT_COMPARABLE、UNKNOWN；这些是诊断分类，不得直接扩展或映射替代 quality_status、metric_status、result_status。对外诊断字段须由对应 DTO Schema/Golden 明确，不允许把 unknown/null 转为零或有效排序值。

### 本模块可独立开工边界

- QNT-001~003 可先使用固定输入样本和内存实现完成领域算法及契约测试。
- QNT-003 与 QNT-002 不建立强制串行依赖；Factor 可以消费标准化输入序列，不必依赖 Indicator Engine。
- Data OpenAPI/Go DTO 修复只影响对应 Data Adapter 字段，不阻断 Quant Domain。
- QNT-013 拆分为 Repository Port/Schema 设计、模块 Repository 实现、真实 Storage/根 Migration 接入三个验收项；不得要求所有 Quant 能力完成后才开始存储设计。

### QNT-CTR-005 / GOV-CTR-006 Quant Owner 授权绑定复核（2026-11-09）

本轮对照项目级机器契约、Quant/Research DTO 字段表、Quant Result Manifest 与当前代码，确认以下边界：

1. `Manifest.ResultID` 是由 Manifest 内容指纹派生的 `quant_result:sha256:<64位小写SHA-256>`，是 GOV-CTR-006 Quant 授权 `resource_ref` 的唯一目标；不得使用业务别名、请求 ID、快照 ID 或 Envelope 临时 ID。
2. Quant 授权必须由 Quant Owner 签发：`policy_owner=quant`、`subject_ref` 来自已认证的 Researchflow service principal、`resource_ref=Manifest.ResultID`、`purpose_code=quant_analysis`、`content_level=full`。调用请求体/Header 中的主体声明不得作为可信主体来源。
3. 只有 `decision=allowed` 且 `conditions=[]` 的授权快照可进入结果发布/读取流程。conditional 不是许可；denied/unknown 必须 fail closed。expires_at=null 不代表永久许可。
4. `authorization_ref` 是审计引用，不是 bearer token。BuildRef 当前只检查其非空文本并原样保存；它没有验证授权快照内容、Owner、主体、资源、用途、内容级别、策略快照或 fingerprint。这是有意保留的信任边界，不得把 BuildRef 成功解释为授权通过。
5. 当前 `result.Repository` 仅有 Save，没有 Get/Query；这是正确的安全限制。不能在授权复核、撤销/过期、TOCTOU 一致性和结果引用归属尚未实现前增加读取 API。
6. QNT-CTR-004 字段表定义了 QuantResult Envelope，但当前实现只有 Manifest、Ref 及部分强类型 payload DTO；不得把 Manifest 当 Envelope，也不得将 Ref 当完整结果响应。
