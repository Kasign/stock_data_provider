## 完成门禁

- 单测覆盖公式、窗口边界、缺失/异常、单位、精度和时区。
- 固定样本可重复运行，差异有解释。
- PIT/复权有独立测试。
- 回测交易制度和成本假设有边界测试。
- 真实数据验收记录 Provider、证券、日期、样本数、快照和质量。
- CI 精确关联当前 SHA；Mock/Fixture/构建通过不能代替真实数据验收。
- 诊断结果至少区分 PASS、DEGRADED、FAIL、INSUFFICIENT_DATA、NOT_COMPARABLE、UNKNOWN；具体规则由指标/因子契约定义，不允许把 unknown/null 转为零或有效排序值。

#### 已发现的契约待澄清项

以下属于总规划契约解释/机器 Schema 一致性问题。本模块只登记，不擅自修改项目级文档或 QNT Schema：

1. **use_case 幂等作用域缺少显式映射。** QuantAnalysisRequest 字段表没有 use_case，但幂等作用域和指纹定义使用 use_case。若由 AnalyzeStock/AnalyzeMarket 等 Facade 路径隐式确定，必须形成稳定的 Facade→use_case 映射和测试；否则需要总规划决定是否增加显式字段。不能由 Quant 私自扩展 DTO。
2. **QuantResultRef 与 QuantResult Envelope 字段重叠。** 两者均定义 result_id、result_type、scope、system_as_of、period、algorithm_version、parameter_fingerprint、input_snapshot_refs、quality_status、result_status、authorization_ref。需明确 QuantResultRef 是 Envelope 的引用投影/索引视图，还是独立 DTO；避免两份 Schema 演进分叉。
3. **纯函数无输入引用规则与 QNT-CTR-005 Manifest Schema 不一致。** Envelope 允许白名单纯函数的 input_snapshot_refs 为空，但当前 Manifest Schema 对 input_snapshot_refs 设置 minItems=1。需要总规划明确：纯函数是否允许生成可持久化/可引用的 QuantResult；若允许，Manifest Schema 应以白名单条件表达，否则删除 Envelope 例外。当前不得自行放宽 Schema。
4. **请求与结果 scope 范围不同。** QuantAnalysisRequest 为 stock/market/industry；QuantResultRef 为 stock/market/industry/portfolio。portfolio 可能对应 QNT-012 后续能力，首批不开放，需在 Facade/Schema 中标记 deferred，避免误以为请求已支持组合分析。
5. **连续有效交易日的判定依赖交易日历。** Factor 决议中的 21/61/21 个连续有效交易日不能只按自然日期相邻或数组连续判断；必须使用 Data 交易日历版本识别应有交易日，并把缺失交易日视为窗口不完整，不填充。
6. **ATR 初始 True Range 的样本边界需在 Golden 固定。** 已有公式和 Wilder/SMA 初始化决议，但首个 TR 依赖前一日 close；Golden 必须明确窗口 N 对应 N 个 TR 还是 N+1 根 OHLC bar，避免不同实现产生一日偏差。
7. **NOT_COMPARABLE 缺少 DTO 状态落点。** 诊断需要显式区分复权/时间/单位不可比较，但 QuantMetric.metric_status 当前枚举没有 not_comparable，QuantResult.result_status 也没有该状态。需要明确使用 rejected + reason_code，还是扩展状态枚举；不能静默映射成 unknown 或 insufficient_data。

#### 算法决议转成 Golden 的固定检查点

- EMA：首 window 个 close 的 SMA seed，之后 alpha=2/(window+1)。
- RSI：首 window 个变化的平均涨跌幅 SMA seed，之后 Wilder 平滑；需要 window+1 个 close。
- MACD：fast/slow/signal EMA 均按 SMA seed；fast_window < slow_window；histogram=2*(DIF-DEA)。
- Volatility：window 个收益样本、ddof=1；年化因子必须显式提供；首批 Factor volatility_20d 不年化。
- Bollinger：middle=SMA；总体标准差 ddof=0；multiplier>0。
- ATR：TR=max(high-low, abs(high-prev_close), abs(low-prev_close))；Wilder 平滑，初始 SMA；样本边界待 Golden 明确。
- Factor：动量 close_t/close_(t-N)-1；volatility_20d 为 20 个 simple daily return 的样本标准差；不前向/后向填充。
- 全部价格窗口：同一 adjustment_basis/reference_date；复权或参考基准不一致判 NOT_COMPARABLE；缺样本判 INSUFFICIENT_DATA；无法确认质量判 UNKNOWN；输入违反硬约束判 FAIL；仅允许且符合 code 规则的 degraded 数据才可 DEGRADED。

#### 2. Registry 元数据规则

- 一个 Registry 条目必须能唯一定位到 code + schema_version + algorithm_version；注册顺序不得影响序列化或计算结果。
- `value_type` 只允许 decimal_string / integer / number；单位、precision、range、tolerance 必须与类型一致。
- `parameters_schema` 本身是受版本控制的 JSON Schema；Registry Schema 校验其结构，运行时再按对应 code 的参数 Schema 校验请求。
- `quality_policy` 必须声明 minimum_coverage、缺失处理、允许的质量状态和不可用条件；具体字段形状在 Schema 实现前复核总规划，不自行发明跨模块 DTO。
- SMA/EMA/ATR/Bollinger 属价格量纲；Return/Volatility/Factor 动量及波动率使用 ratio；RSI、MACD 子输出的具体单位与 value_type 必须在 Registry 逐 code 冻结，禁止根据名称猜单位。
- 多输出指标（MACD 的 DIF/DEA/Hist、Bollinger 的 upper/middle/lower）必须有稳定子 metric_code 映射，不允许用无约束 map 承载。

|---|---|---|
| normal | 完整有效窗口，固定参数 | PASS，数值与独立参考计算一致 |
| minimum_window | 恰好满足最小窗口 | PASS，验证 seed 和首个输出位置 |
| insufficient_window | 少于最小窗口 | INSUFFICIENT_DATA，value=null |
| missing_session | 交易日历显示应有交易日但输入缺失 | INSUFFICIENT_DATA，不填充 |
| invalid_price | 非正数、NaN/Inf 或 OHLC 不一致 | FAIL，禁止输出有效值 |
| adjustment_mismatch | adjustment_basis/reference_date 不一致 | NOT_COMPARABLE，不混算 |
| degraded_input | 质量 degraded | 仅当 Registry quality_policy 明确允许时 DEGRADED，否则拒绝 |
| deterministic_repeat | 相同输入/参数/版本重复计算 | 输出字节级稳定或在声明 tolerance 内稳定 |

算法特定补充：
- EMA/RSI/MACD：固定 seed、warm-up、首个有效输出索引。
- Return：simple/log 两种口径、正价格约束、window 起止索引。
- Volatility：ddof=1、年化因子显式传入；不年化与年化分开编码。
- ATR：明确 N 个 TR 所需 OHLC bar 数、首个 TR 的 previous_close 来源和 Wilder 初始 SMA。
- Bollinger：ddof=0、multiplier 边界和 upper/middle/lower 顺序。
