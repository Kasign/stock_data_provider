## 0. 结论摘要

阶段 2.3 **不是"把报告读出来"，而是"在不伪造完整报告的前提下，为 WebUI 建立一条可授权、可追溯、不绕过 Repository 的正式结果读取路径"**。

全仓事实核查得到三个互相制约的结论：

1. **完整报告资源确实不存在**。`ComposedResearchResult` 无持久化 Store/ResultRef（`Researchflow模块卡点.md:92` RF-BLOCK-007 **OPEN**）；报告正文的两个生产者证据仍缺——LLM Gateway 生产消费者与 News 可验证 `available_at`。因此 2.3 不能凭空定义"完整报告 DTO"。
2. **领域结果授权读取已经打通，但零生产消费者**。阶段 2.2 接通的 `readQuantResultForRun` / `readNewsEvidenceForRun`（`researchflow_execution_composition.go:349-377`）目前只在 L3 集成测试与单测被调用，无 HTTP 或 Worker 生产读取点。这与 2.2 实施前的"对象图存在、行为从未发生"是同一类缺口，只是层级上移到 Server。
3. **契约边界明确禁止当前做法**。SRV-CTR-001 `FROZEN` 1.0.0 首期只开放三条 Run 路由，明确"不开放 Stage Output 内容读取、Quant/Research 独立 API"（`:25`），GET 响应"首期不返回 Attempt 明细、Stage Output 内容或内部 Domain/Storage 字段"（`:107`）。任何新读取端点都必须走独立的契约演进决策，不能就地改冻结契约。

**推荐路线（D1–D6 全部按推荐项）**：把 2.3 精确定义为「**领域结果授权读取**」——Server 在 Owner Session 鉴权后，以进程内可信身份调用 2.2 已接通的领域 Owner 授权读取入口，返回**强类型公开投影 DTO**（Quant `Envelope` 的受限视图 / News `ResearchEvidenceRecord` 的受限视图 + Run/Stage 聚合），**明确不冒充完整报告**；另立 DEC 对 SRV-CTR-001 做 additive 契约演进（新增独立结果读取端点与 Schema，1.0.0 字节不动），本轮不改 WebUI 页面，只交付 Server 契约 + 真实 L3 读取断言 + 契约测试。RF-BLOCK-007 与完整报告正文外部阻塞如实保留 OPEN。

> 关键提醒：不得因为"Run/Stage 聚合已能返回 `ResultSummary`"就把它当报告读取完成。`ResultSummary` 是执行摘要（迁移盘点 `:215-217`、SRV-CTR-001 `:107`），清单 2.3 明确禁止"Run/Stage 聚合冒充完整报告"。

## 3. 问题定义：2.3 真正要闭环什么

清单退出条件为「WebUI 有正式结果读取路径；UI 不访问模块 Repository」。拆成可验证语义：

| 验收语义 | 现有覆盖 | 精确空白 |
|---|---|---|
| 入站身份只认 Owner Session | SRV-CTR-001 `:29-35` 与 `researchflow_http.go:84-90` 已实现于三条 Run 路由 | 新结果读取端点的鉴权矩阵需沿用同一适配器，不得另开 Bearer/Service Token 入口 |
| 先由领域 Owner 做资源级授权 | `GetRunService.GetRun`（`get_run.go:38-48`） | 新端点必须先经 `GetRun` 授权拿可信 `run_ref`，再进入结果读取；不得用路径参数直接查 Repository |
| 结果读取经领域 Owner，不经 Repository | `readQuantResultForRun` / `readNewsEvidenceForRun` 已接通 | 无任何 Server handler 调用；需在 HTTP 层建立消费者并完成 DTO 投影 |
| 返回内容不冒充完整报告 | `ResultSummary` 是执行摘要（`result-summary-1.0.0.schema.json`） | 需定义独立的"领域结果读取 DTO"及其 Schema/Golden，明确 `result_kind`/`content_level`/`source` 语义 |
| 不开放 Stage Output 内容 | SRV-CTR-001 `:107` | 新 DTO 不得包含 `StageOutputResource.Content` 或 `domain.Run` 内部字段 |
| WebUI 可迁移 | 前端 Researchflow 函数零调用 | 本轮交付契约与测试；页面切换属 3.1/3.2，不提前改 UI |

**一句话**：2.3 的交付物是**让领域 Owner 的授权读取在 Server HTTP 边界上真实发生，并以不冒充报告的公开 DTO 暴露给 WebUI，同时保持冻结契约的边界不被就地破坏**。

```
2.1 已完成（四 Stage + L3 种子闭环）

   ↓
3.1/3.2 WebUI 迁移 → 4 删除与清表 → 5 最终验收
```

- **硬顺序依据**：退役清单 `:20-32` 依赖图与迁移盘点 `:374,381-382`——必须先有 Server 正式读取契约再切 WebUI，删除门禁要求前置全过。
- **2.3 → 2.4 的关系**：2.4 要冻结「可信 CallerRef / SystemAsOf / Deadline 贯穿读取」与「RiskDecision 唯一来源」。2.3 的 DTO 若提前固化这些字段，会与 2.4 的语义冻结冲突。因此本轮 DTO **只承载已有领域结果的可信投影与来源引用**，不自行定义 RiskDecision 或上下文语义。
- **RF-BLOCK-007 的位置**：它是阶段 3 页面迁移"完整报告正文"展示能力的阻塞，不是 2.3 领域结果读取的阻塞。二者必须分开，否则会把"结果可读"误判为"报告已具备"。
- **报告正文阻塞**：LLM Gateway 生产消费者与 News `available_at` 真实来源证据缺失，按用户既定口径如实保留，不用空壳报告资源替代。

## 9. 风险提示与常见坑（dev / prod 差异）

1. **DSN 门控测试陷阱**：改迁移/Schema 时必须逐个 grep 检查 `SERVER_RELAY_TEST_MYSQL_DSN` / `MARKET_DATA_TEST_MYSQL_DSN` 门控测试，本地 SKIP 不等于通过（`cb11af410` 修复记录）。
2. **CI 只跑单个 L3 函数名**：新增断言必须写在 `TestQuantResearchMariaDBRedisL3` 函数体内，新建独立测试函数不会在 CI 的该步骤执行。
3. **Principal 注入陷阱**：Quant `GetResult` 只认 `service:researchflow`（`get_result.go:233-238`）；HTTP 侧若忘记进程内身份注入，会以"未授权"失败而非编译错误，单测直调容易掩盖。
4. **契约指纹漂移**：模板/契约 Schema 新增字段必须 `omitempty` 或有基线回归断言；阶段 2.1 曾因去掉 `omitempty` 导致指纹从 `0e57907d…` 漂到 `6aa73fe7…`。
5. **白名单测试反例**：遍历规格表的测试在"整条漏登记"时不会失败（表变短、遍历跟着变短），必须对每个应有登记做独立存在性断言（DEC-062 变异 5 的教训）。
6. **dev / prod 差异**：dev 可用内存 Store 跑通 DTO 投影，但授权策略锁、`FOR UPDATE` 撤销竞态、审计落库必须在真实 MariaDB 验证；Owner Session 的 HTTPS/Secure Cookie 只在目标环境成立，本地 HTTP 不能冒充浏览器验收。
