# Quant 量化引擎总体设计

## 1. 目标与非目标

Quant 是确定性、可复算的数值引擎。同一输入快照、参数、交易日历和算法版本应得到一致结果。它不调用 LLM、不编排研究任务、不连接 Provider/HTTP/SQL/Redis、不下单。

## 2. 目标包结构

```text
internal/quant/
  domain/
  indicator/
  factor/
  trend/
  market/
  industry/
  stock/
  strategy/
  backtest/
  risk/
  evaluation/
```

模块内部按 domain/application/ports/adapters 分层。不要为目录齐全而先创建大量空包；按实际能力和依赖边界逐步建立。

## 3. 依赖与输入

只依赖 Data 和 Platform 的稳定契约。输入至少包括证券身份、system_as_of、trade_date、交易日历版本、复权方法/参考基准、snapshot_ref、source_version、available_at、provider_time、fetched_at、质量/覆盖率、字段单位和计算参数。历史研究必须使用当时可用的证券主数据、行业成分、财务和复权版本。

unknown/null 不得转零；不同时点、不同复权基准或不可比较质量的数据不得混算。Data v1 百分比字段使用 percentage_point，Quant 内部收益率使用 ratio；Data Adapter 必须显式转换并提供 Golden。真实 PIT 复权按总规划 DATA-CTR-002 执行，不得回退 Provider 当前复权行情。

## 4. 子系统

- Indicator：收益、均线、波动、量价和统计函数；公式、单位、窗口边界、精度、空值语义固定。
- Factor：因子计算、异常值处理、横截面标准化和因子版本；明确统计母体和时点。首批固定 momentum_20d、momentum_60d、volatility_20d。
- Trend：方向与阶段分离，按短/中/长周期计算；结合价格结构、动量、波动调整强度、量价和反转观察；周期冲突显式表达。
- Market：指数、全市场涨跌分布、宽度、新高新低、成交活跃度、波动、涨跌停和风险偏好；明确全集、分母、停牌/ST/退市/新股规则及覆盖率。
- Industry：分类和历史成员版本化；收益、相对强度、广度、成分贡献、持续性和轮动分开计算。
- Stock：多周期趋势、量价、波动、相对强度、流动性、价格结构、财务估值可用性和交易状态。
- Strategy：策略规则、入场/失效/退出条件和版本；输出 SignalCandidate，不输出交易指令。
- Backtest：交易模拟与绩效统计分离；覆盖 T+1、涨跌停、停牌、ST、上市/退市、费用、滑点、公司行动、容量和成交假设。
- Risk：硬门禁、风险预算和拒绝原因；block 优先于分数和模型。
- Evaluation：样本外、walk-forward、概率校准、漂移、参数敏感性和失败案例。

## 5. 结果契约

Metric/Factor/Trend/Signal/Backtest/Risk/Evaluation 结果均需包含 system_as_of、输入快照引用、来源、算法版本、参数摘要、质量和限制。趋势 direction 与 phase 分开；概率必须附样本数、区间和校准信息；样本不足返回 insufficient_sample/unknown。DTO 的 JSON 类型、精度、scale、舍入和空值语义以 QNT-CTR-001～005 的机器契约及 Golden 为准；未完成证据的契约不得标记 frozen。

## 6. 旧代码迁移盘点与决策

盘点基线：`0cb99a525de00d3c340891caa029b716c4d2f749`。本节记录源码事实和迁移方向，不代表相关能力已进入 Quant。

### 6.1 go-core Indicator

源码：`go-core/internal/indicators/technical.go`；测试：`go-core/internal/indicators/technical_test.go`。

| 能力 | 现状与证据 | 决策 |
|---|---|---|
| MA5/10/20/60 | 按有效 Close 序列末尾窗口计算；MA60 不足时回退 MA20 | rewrite：保留均值公式；新契约窗口不足返回 insufficient_data，不复用 MA20 冒充 MA60 |
| EMA | EMA 首值作为 seed，alpha=2/(period+1)；当前仅供 MACD 使用 | reuse formula + rewrite API：固定 seed、period 和输出窗口 |
| RSI14 | Wilder alpha=1/period 平滑，但平均涨跌从 0 初始化；与历史 pandas EWM 兼容 | rewrite：先冻结算法版本和 seed；不能笼统称为所有平台通用 Wilder RSI |
| MACD | 12/26/9；快慢 EMA 和 DEA 均以首值初始化；hist=(DIF-DEA)*2 | rewrite：明确 seed、warm-up、参数和 histogram 倍数 |
| MA Bias | (close-MA)/MA*100，输出百分数数值 | reuse formula：Registry 明确单位为 percentage_point，禁止与 ratio 混用 |
| MA Alignment/TrendStatus | 只比较 MA5/10/20，输出 bullish/bearish/mixed 和 uptrend/downtrend/sideways | defer：属于 Trend 表达，不作为 Indicator 核心计算输出 |

当前测试只覆盖 MA 窗口值、无有效 Close、平盘 RSI、一个 RSI 历史样本。未覆盖 RSI/MACD warm-up、不足窗口、重复/乱序日期、缺失交易日、异常值、复权基准和数值精度。Calculate 本身会排序并过滤无效 Close，但不负责交易日去重和质量审查；不得把过滤后的稀疏序列自动视为连续有效交易日。

### 6.2 go-core 行情预处理与时段

- `go-core/internal/marketdata/normalize.go`：校验 ISO 日期和 OHLC，丢弃无效行，重复日期保留最后一个有效行并升序输出；还提供交易所时区日期、截止日期过滤和盘中日 K 标记。决策：不迁入 Quant Domain；作为旧工作流输入预处理资产，Data Adapter 应消费 Data 已标准化 DTO，不重复实现 Provider 归一化。
- `go-core/internal/application/stock_flow.go`：先过滤未来 K 线，再通过 completedBarsForIndicators 只保留同一 source、normalization_version、adjustment_reference_date、adjustment_basis 且质量 valid/degraded 的连续后缀。决策：质量/快照一致性约束应沉淀为输入校验策略，不把整个 StockFlow 搬入 Quant。
- `go-core/internal/market/phase.go`：只按 Asia/Shanghai 时钟推断交易时段，显式标记 trading_calendar_status=not_checked；外部市场返回 unknown。测试覆盖外部市场 unknown 和 A 股上午时段。决策：reuse 时钟映射逻辑，但交易日/节假日/特殊时段必须依赖 Data 交易日历，禁止把 clock phase 当作真实开市状态。

### 6.3 Data 已有均线计算

`services/market-data/internal/service/moving_average.go` 已计算 MA5、MA20、MA120、MA250，要求完整窗口、有效 Close、同一复权基准，并拒绝 invalid/unknown 质量；测试覆盖窗口不足、无效 Close 和混合复权基准。

该能力属于 Data 行情服务当前输出能力，不等同于 Quant Indicator Engine。Quant 需要为可复算算法维护自己的版本化计算定义，但不得为了重复展示而新增 Data API，也不得把 Data 计算结果未经契约映射直接作为 Quant 算法结果。后续需先明确实际消费者和字段契约，再决定是否复用 Data 已计算字段。

### 6.5 Python 与其他候选资产

当前仓库 Python 文件主要位于 `python_bridge/**`，`python_bridge/capabilities/market_data.py` 是 Provider API 包装和旧数据适配，不是独立 Quant 算法库。没有发现可直接迁入的独立 Python Indicator/Factor 模块。后续如发现 Python 公式实现，必须以原始公式、依赖版本、固定输入输出样本为证据，不凭报告文本推定算法。

### 6.6 盘点结论

1. 旧 Indicator 有可复用公式，但算法初始化、窗口不足和质量语义必须重定。
2. 旧 Market 时段只提供时钟推断，真实交易日历由 Data 提供。
3. Data 已有 MA5/20/120/250 计算，Quant 不新增重复展示 API；Quant 自身的版本化算法计算仍需独立契约。
4. Analysis 的 Registry、Factor 执行校验和 Risk AND 门禁有复用价值；Runner、数据采集、交易计划和执行评估不属于 Quant。
5. 本次只完成源码盘点，没有代码迁移、算法实现或真实数据验收。

## 7. 开发与迁移原则

- 逐项标记 reuse/rewrite/retire/defer，提供公式、边界、调用方和测试证据；未评估前不得批量搬迁/删除。
- 先完成 QNT-CTR-001～005 对应子契约的字段核对和 Golden，再实现对外 DTO；未冻结的跨模块调用点保持隔离。
- QNT Domain 可使用固定 Fixture 独立开发；真实 Data Adapter、真实 Storage 和根 Migration 分开验收。
- 不为 WebUI 展示提前增加 API；每个新增接口必须有明确调用方和场景。
