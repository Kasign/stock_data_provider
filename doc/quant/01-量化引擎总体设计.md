# Quant 量化引擎总体设计

## 1. 目标与非目标

Quant 是确定性、可复算的数值引擎。同一输入快照、参数、交易日历和算法版本应得到一致结果。它不调用 LLM、不编排研究任务、不连接 Provider/HTTP/SQL/Redis、不下单。

## 2. 目标包结构

```text
internal/quant/
  indicator/ factor/ trend/ market/ industry/
  stock/ strategy/ backtest/ risk/ evaluation/
```

模块内部按 domain/application/ports/adapters 分层。不要为目录齐全而先创建大量空包。

## 3. 依赖与输入

只依赖 Data 和 Platform 的稳定契约。输入至少包括证券身份、as_of、交易日历版本、复权方法/参考基准、snapshot_ref、source_version、available_at、provider_time、fetched_at、质量/覆盖率、字段单位和计算参数。历史研究必须使用当时可用的证券主数据、行业成分、财务和复权版本。

unknown/null 不得转零；不同时点、不同复权基准或不可比较质量的数据不得混算。

## 4. 子系统

- Indicator：收益、均线、波动、量价和统计函数；公式、单位、窗口边界、精度、空值语义固定。
- Factor：因子计算、异常值处理、横截面标准化和因子版本；明确统计母体和时点。
- Trend：方向与阶段分离，按短/中/长周期计算；结合价格结构、动量、波动调整强度、量价和反转观察；周期冲突显式表达。
- Market：指数、全市场涨跌分布、宽度、新高新低、成交活跃度、波动、涨跌停和风险偏好；明确全集、分母、停牌/ST/退市/新股规则及覆盖率。
- Industry：分类和历史成员版本化；收益、相对强度、广度、成分贡献、持续性和轮动分开计算。
- Stock：多周期趋势、量价、波动、相对强度、流动性、价格结构、财务估值可用性和交易状态。
- Strategy：策略规则、入场/失效/退出条件和版本；输出 SignalCandidate，不输出交易指令。
- Backtest：交易模拟与绩效统计分离；覆盖 T+1、涨跌停、停牌、ST、上市/退市、费用、滑点、公司行动、容量和成交假设。
- Risk：硬门禁、风险预算和拒绝原因；block 优先于分数和模型。
- Evaluation：样本外、walk-forward、概率校准、漂移、参数敏感性和失败案例。

## 5. 结果契约

Metric/Factor/Trend/Signal/Backtest/Risk/Evaluation 结果均需包含 as_of、输入快照引用、来源、算法版本、参数摘要、质量和限制。趋势 direction 与 phase 分开；概率必须附样本数、区间和校准信息；样本不足返回 insufficient_sample/unknown。

## 6. 旧代码迁移

`internal/analysis/**` 和 `go-core/internal/indicators/**`、`market/**`、`application/**` 是候选资产，不是目标架构。逐项标记 reuse/rewrite/retire/defer，提供公式、边界、调用方和测试证据；未评估前不得批量搬迁/删除。
