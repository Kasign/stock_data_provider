### Data v1 数值精度链路核验（只读证据）

本轮只读核对 `feat/data`，没有修改 Data 分支：

- `internal/marketdata/app/port.go`（blob SHA：`40c0c1576de597383f8aefc6f09adccf7d1fb9f9`）：DailyBar 的 OHLC、Amount、ChangePercent 使用 `float64`；QuoteSnapshot 的价格/金额/比率字段使用 `*float64`；Volume 使用 `*int64`。FundamentalMetric.Value 也是 `float64`。
- `internal/marketdata/httpapi/openapi.yaml`（blob SHA：`95c6ee71850c4e50f3265e78fd979f5fd409b4a1`）：Quote、DailyBar 的价格、金额和百分比字段声明为 JSON `number`；Volume 声明为 `integer/int64`。
- 这与项目登记簿中 DATA-CTR-005 的现状一致：当前 v1 HTTP number / InProcess float64；DailyBars Decimal v2 尚未形成 Schema/Golden，DATA-CTR-005 仍为 deferred。

#### 对 Quant 的直接影响

1. JSON number 进入 Go `float64` 后，精度限制已经存在于应用 DTO；即使后续把结果格式化为 JSON String，也不能恢复已丢失的十进制信息。
2. SMA、EMA、MACD、ATR、Bollinger 等价格派生指标若要求精确十进制结果，必须等输入链路提供可保真的 Decimal 值；不能把现有 float64 结果转字符串后标记为 Decimal。
3. Return、Volatility、RSI 等统计指标可以评估 Number 路径，但必须逐 `metric_code` 明确误差预算、舍入规则和固定样本；不能因为它们是小数就统一决定类型。
4. 成交量/样本数继续使用整数语义；标识符、证券代码继续使用 String。不得将所有字段统一改成 JSON String。
5. 现有 v1 契约保持不变。Decimal v2 需要由 Data Owner 按 DATA-CTR-005 重新进入条件定义原始精度保留、Decimal scale、舍入、单位、缺失语义、bar interval 和交易日历版本引用。

**本轮结论：** Quant 采用项目已冻结的按 `metric_code` 固定 JSON 类型策略；价格/金额精确十进制与统计 Number 分流。价格派生指标的 Decimal 正式 Entry/计算路径受 DATA-CTR-005 阻断；不在 Quant 分支复制 Data DTO，也不做 float64→String 的表面转换。

#### 当前不能凭现有证据填写的字段

1. **value_type**：项目决议规定精确价格/金额使用 decimal string、统计数值使用 number；但各 metric_code 的最终分类和可执行转换仍须逐项确定。当前 Indicator/Factor 纯算法输出 float64，价格类指标不能未经精度策略就直接宣称满足 decimal string。
2. **unit**：项目字段契约列举了 CNY/share、percentage_point、ratio 等可用单位，但明确要求逐 metric_code 注册；RSI、ATR、MACD、Bollinger 的具体单位仍有待确认，不能把 Go float64 或公式名称当作单位决议。
3. **precision**：Golden tolerance 是测试断言容差，不是生产 max_fraction_digits、rounding_mode 或误差预算。
4. **range**：synthetic Golden 的样本极值不是合法值域。数学边界必须逐指标证明，价格类范围还依赖输入与算法约束。
5. **input_requirements**：算法函数只接收数值数组，不掌握 Data 字段版本、Decimal 精度、复权参考日期、PIT、交易日历和真实快照质量。DATA-CTR-005/007 仍 deferred。
6. **quality_policy**：纯计算函数不能识别停牌、缺失交易日、Provider 覆盖率或数据新鲜度；不能统一假设 minimum_coverage=1 或 missing_handling=reject 后冒充业务决议。
7. **parameters_schema**：全局 QNT-CTR-002 Schema 和 Golden 已存在，但 Entry.parameters_schema 要求单个 code 对应的封闭对象 Schema；需要从冻结子契约形成逐 Entry 映射，并确认 Registry 接受的对象层级。
8. **sample_count.required_in_metric**：计数单位/规则可由算法与契约推导，但是否对每个输出字段强制存在仍应与对应 Payload Schema 保持一致；当前 Metric Go 字段为可选指针，Validator 只按 Entry 检查字段存在，尚未验证实际计数与 counting_rule 一致。

#### QNT-001 当前结论

当前完成的是代码/契约盘点，不是正式 Registry Entry 注册。没有可靠来源的元数据保持空缺；不生成“看起来完整”的默认 Entry。下一步优先按输入可保真程度拆分指标：统计类指标继续核验 Number 的误差预算/舍入/固定样本；价格派生指标等待 DATA-CTR-005 Decimal v2 后再冻结精确 Decimal Entry。Factor 继续受 QNT-CTR-003、DATA-CTR-005/007 deferred 阻断。
