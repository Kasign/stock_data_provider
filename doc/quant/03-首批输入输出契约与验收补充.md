# Quant 首批输入输出契约与验收补充

- 适用任务：QNT-001～003
- 契约范围：QNT-CTR-001～005；公共语义遵循 GOV-CTR-001～006
- 状态：实现输入基线；不代表 Schema、Golden、Contract Test 或 L2 已通过
- 权威关系：项目级契约目录登记编号、状态和公共语义；本文件细化 Quant 生产方/消费者边界，不改变已接受的项目级契约

## 1. 依赖方向

Quant 是确定性计算模块。领域层不依赖其他业务模块；Application 通过端口读取 Data 快照并调用 Platform 公共原语。

- Data 拥有行情、证券主数据、交易日历、行业历史成分、财务和估值事实。
- Quant 只通过自己的 Data Adapter 消费公开 DTO/API，不 import Data Domain、Repository、SQL Model、Provider Adapter 或 HTTP DTO。
- Researchflow 是 Quant Application 的主要编排消费者；Quant 不依赖 Research/Researchflow 内部类型，不调用 LLM、不下单、不执行策略动作。
- Quant 风险事件在本地事务写入 Outbox，按 INT-CTR-001 投递 Notification；不直接依赖 Notification 领域包、Repository 或发送接口，发布失败不得回滚已提交风险事实。

## 2. 计算上下文规范

跨模块 DTO 使用 snake_case，时间字段遵循 GOV-CTR-002。首批请求至少包含 schema_version、request_id、correlation_id、scope、security_id（按场景必需）、system_as_of、trade_date、period、input_snapshot_refs、adjustment_basis（按场景必需）、typed parameters、quality_policy、idempotency_key。

system_as_of 是系统知识截止，不是交易日。Data 旧 API 的 as_of 仅允许在 Data Adapter 内显式映射；Quant 对外 DTO、结果和跨模块调用统一使用 system_as_of。当前分支 services/market-data/openapi.yaml 仍登记 v1 DailyBar（数值字段为 JSON number，PIT 查询参数为 as_of，行级时间字段为 system_observed_at）；未发现已发布的 Data v2 Decimal/system_as_of OpenAPI 路由或 Schema。DATA-CTR-005 仍为 pending_evidence，真实 Data Adapter 不得宣称已接入 v2。

历史输入必须满足：
1. snapshot_ref 不可变，保存来源和 source_version。
2. 严格 PIT 的 available_at 必须有来源证据且不晚于 system_as_of；不得用 published_at、fetched_at 或当前时间推导。
3. 交易日、复权基准/参考日期、证券主数据版本、行业成分版本必须一致。
4. 不同 system_as_of、adjustment_basis、单位或不可比较质量的数据不得混算。
5. null/unknown/unavailable 不得转成 0、false 或空字符串。

## 3. 数值与 Metric Registry

每个 Registry entry 以 `(code, schema_version)` 标识，必须声明 `value_type`、`unit`、`precision`（最大整数位、fractional digits/scale、rounding mode、tolerance）、`range`、`algorithm_version`、`input_requirements`（输入字段、interval、adjustment、PIT、quality、snapshot 要求）、`parameters_schema`、`quality_policy`（coverage、missing handling、quality states、unavailable conditions）和 `supports_interval`。Registry 是指标语义的唯一权威来源；消费者不得自行推断单位、精度或算法版本。

- 精确价格/金额使用 decimal string；禁止 float64 转字符串伪装无损。
- 统计量仅在明确允许浮点误差时使用 JSON number，并声明 tolerance 和舍入策略。
- 百分比区分 percentage_point 与 ratio；转换必须位于明确 Adapter/计算边界并有 Golden。
- 计数使用 integer，遵循 GOV-CTR-001 安全整数上限。
- value=null 时 metric_status 必须说明原因；metric_status=available 时 value 必须非 null。
- quality_status=invalid/unknown 时不得 available；上下界必须同时存在或同时为 null，类型与 value 一致。

SMA/EMA/Return/Volatility/RSI/MACD/ATR/Bollinger 参数 Schema 固定窗口、最小样本、seed、缺失处理、复权要求和精度。首批 Factor 仅为单证券时间序列 momentum_20d、momentum_60d、volatility_20d；不做横截面排序、行业中性化、winsorize/zscore/rank 或其他因子扩展，这些均延期。Factor 不隐式依赖 Indicator Engine。

## 4. 结果与风险契约

QuantResult 使用 result_type + schema_version 判别的强类型 payload，禁止任意 map。Envelope 至少包含 schema_version、result_id、result_type、scope、security_id（按场景必需）、system_as_of、trade_date、period、algorithm_version、parameter_fingerprint、input_snapshot_refs、quality_status、result_status、authorization_ref、payload。

result_status 与 quality_status 独立；completed 不代表 valid。insufficient_data、insufficient_sample、rejected、failed 不得伪装为 completed。未知 result_type/schema_version 必须拒绝，不回退旧版本。

Quant Result Manifest 不可变，直接绑定 result_type、schema_version、system_as_of、input_snapshot_refs 和 result_fingerprint；result_fingerprint 对强类型 payload 计算，payload 内的 algorithm_version/parameter_fingerprint 由该摘要间接绑定。调用主体不属于 Manifest 字段，由 Quant 签发的 GOV-CTR-006 AuthorizationRef 单独绑定 subject_ref 和 resource_ref=result_id：policy_owner=quant、subject_ref 来自可信认证 Context、resource_ref=result_id、purpose_code=quant_analysis、content_level=full。读取时仍须检查当前授权；历史 allowed 不能覆盖当前 denied/expired/unknown。

RiskDecision 只表达 pass/reject/unknown、规则版本、评估时间、system_as_of、输入引用和原因。数据缺失、规则无法评估或质量不足时不得 pass；硬风险结论不能被评分或 LLM 覆盖。风险事件仅在首次形成或 status/硬阻断原因集合实质变化并持久化后发布，遵循 INT-CTR-001。

### 6.2 仍待项目级确认的语义

以下问题只登记在 Quant 专项文档，不擅自修改项目级契约或现有 QNT Schema。已经由最新契约明确的 Registry 字段、首批算法和延期范围不再重复列为待决项。

1. **算法活动版本选择。** Registry 已要求区分 `code`、`schema_version`、`algorithm_version`，但尚未明确同一 code/schema_version 存在多个算法版本时的活动版本切换和历史复算规则。建议公开请求只传 code/schema_version/parameters，由服务端显式选择活动 algorithm_version，结果记录实际版本；历史版本保留供内部复算。不得依赖注册顺序或允许客户端任意指定算法版本。该建议需项目级确认。
2. **use_case 幂等作用域。** QuantAnalysisRequest 字段表没有 use_case，但幂等作用域和请求指纹使用 use_case。建议由 AnalyzeStock/AnalyzeMarket 等 Facade 路由稳定映射内部 use_case，不增加客户端可控字段；需要补充同一键跨用例冲突/隔离测试。
3. **QuantResultRef 与 QuantResult Envelope 关系。** 两者字段高度重叠，需要明确 Reference 是 Envelope 的引用投影/索引视图还是独立 DTO，并明确 GetResult 返回完整 Envelope、引用或受授权的结果投影。
4. **纯函数空快照引用冲突。** Envelope 描述允许白名单纯函数的 input_snapshot_refs 为空，但 QNT-CTR-005 Manifest Schema 当前 minItems=1。需明确纯函数是否能生成可持久化/可引用结果；未决前不放宽 Manifest Schema。
5. **NOT_COMPARABLE 状态落点。** 诊断要求显式不可比较，但 QuantMetric.metric_status 和 QuantResult.result_status 当前枚举没有 not_comparable。需明确映射为 rejected + reason_code 或扩展状态，不能静默映射成 unknown/insufficient_data。
6. **ATR 首个 TR 边界。** TR 公式、Wilder 平滑和初始 SMA 已明确；仍需通过 Golden 明确 N 个 TR 所需 OHLC bar 数及首个 previous_close 的来源。
7. **交易日历版本绑定。** 首批 Factor 需要 21/61/21 个连续有效交易日；必须按 Data 交易日历版本判定，不能按自然日或数组连续性推断。需确认交易日历版本从 Snapshot Manifest/输入元数据的哪个字段取得，并补缺失交易日负例。
8. **Data v2 真实输入证据。** 当前 Data OpenAPI v1.0.2 的 DailyBar 数值字段为 JSON number，PIT 参数为 `as_of`，尚不能证明 Decimal string/`system_as_of` v2 Adapter。DATA-CTR-005 证据完成前，只允许 Fixture 或明确标记的 v1 兼容输入，不得宣称真实 v2 接入。
9. **QNT-CTR-005 运行时证据。** 项目级 Manifest Schema/Golden 和测试矩阵已存在；Quant 仍需补模块内 Schema/Manifest Validator、可信 principal 到 AuthorizationRef 的绑定、结果读取当前授权复核，以及策略变更竞态下 fail-closed 的 CI 证据。

明确不再作为待决项：
- 首批范围为 stock/market/industry；portfolio 属 QNT-012 后续能力。
- 首批 Factor 仅为单证券时间序列 momentum_20d、momentum_60d、volatility_20d；横截面排序/中性化/标准化延期。
- Metric Registry 属 Quant 领域能力，放在 `internal/quant/**`；不新增 Platform 通用 Registry，也不要求复用 `internal/analysis/registry`。

### 6.4 首批算法口径

- SMA：最近 N 个有效 close 的算术平均。
- EMA：首 window 个 close 的 SMA seed，之后 alpha=2/(window+1)。
- Return：按显式参数计算 simple/log return。
- Volatility：window 个收益样本的样本标准差 ddof=1；年化因子显式提供；首批 Factor volatility_20d 不年化。
- RSI：Wilder 平滑；初始平均涨跌幅使用 SMA seed，需要 window+1 个 close。
- MACD：fast/slow/signal EMA 均按 SMA seed；fast_window < slow_window；histogram=2*(DIF-DEA)。
- ATR：TR=max(high-low, abs(high-prev_close), abs(low-prev_close))；Wilder 平滑、初始 SMA；N 个 TR 对应的 OHLC bar 数及首个 previous_close 来源仍待 Golden。
- Bollinger：middle=SMA；总体标准差 ddof=0；multiplier>0。
- Factor：momentum_20d/60d 为 close_t/close_(t-N)-1；volatility_20d 为 20 个 simple daily return 的样本标准差。
- 首批 Factor 只做单证券时间序列；横截面排序、行业中性化、winsorize/zscore/rank 和其他因子均 deferred。
- 价格窗口必须同一 adjustment_basis/reference_date；缺失不填充；无效价格不得生成有效值。

### 7.2 Indicator Golden 场景

每个指标至少覆盖 normal、minimum_window、insufficient_window、missing_session、invalid_price、adjustment_mismatch、degraded_input、deterministic_repeat。所有样本标记为 synthetic_fixture。

- EMA/RSI/MACD：固定 seed、warm-up 和首个有效输出位置。
- Return：simple/log、正价格约束、窗口起止索引。
- Volatility：ddof=1，年化因子显式传入；首批 Factor 波动率不年化。
- ATR：明确 N 个 TR 所需 bar 数及 previous_close 来源。
- Bollinger：ddof=0、multiplier 边界和 upper/middle/lower 顺序。

### 7.3 Factor Golden 场景

| 因子 | 最小输入 | 公式 | 单位 |
|---|---:|---|---|
| momentum_20d | 21 个连续有效复权收盘价 | close_t / close_(t-20) - 1 | ratio |
| momentum_60d | 61 个连续有效复权收盘价 | close_t / close_(t-60) - 1 | ratio |
| volatility_20d | 21 个连续有效复权收盘价生成 20 个 simple returns | sample_std(returns, ddof=1) | ratio |

每个因子覆盖完整窗口、少一根 bar、缺失交易日、停牌/无效价格、复权基准混合、quality unknown/degraded 和重复执行。交易日连续性由 Data 交易日历版本判断，不按自然日间隔判断。

### 7.4 样本和真实验收边界

- 首批 Golden 使用手工可复算 synthetic fixture，记录生成规则、输入、公式版本、期望值和 tolerance。
- 价格输入按目标 Data v2 Decimal string 契约设计；当前 Data OpenAPI v1 仍是 number，不能用 v1 真实响应证明 Decimal 无损。
- 浮点统计量声明绝对/相对 tolerance；精确价格指标声明 scale 和 rounding_mode。

### 9.1 Indicator

### 9.3.1 Registry 数值边界补充

Registry 对 JSON number 不再经 float64 往返后检查精度，而是保留十进制数字并精确展开指数记法，再校验整数位数、小数位数和范围。指数绝对值超过 10000 时拒绝，避免异常指数触发不受控的大整数展开。

新增测试覆盖：
- 19 位小数超过声明的 18 位精度时拒绝，避免 float64 舍入后误通过。
- 指数展开后的整数位数按实际十进制值计算。
- `0.001e3` 归一化为整数 1，不因展开产生的前导零误拒绝。
- JSON 数字字符串、尾随 JSON、整数小数 scale 等边界。

## 10. QNT-CTR-005 Manifest 领域实现

新增位置：`internal/quant/manifest/`。

- `FingerprintPayload` 使用 RFC 8785 JCS + SHA-256 计算强类型 payload 指纹；调用方只传 payload，不把 AuthorizationRef/Manifest Envelope 混入摘要。
- `Build` 生成 Manifest：限制 result_type/schema_version，要求 UTC system_as_of、非空且唯一的输入快照引用、64 位小写 SHA-256；快照引用排序后参与 fingerprint。
- `Verify` 重算 manifest_fingerprint，校验 result_id=`quant_result:sha256:<manifest_fingerprint>`、UTC 时间、快照排序/唯一性和摘要字段。
- 测试源码使用项目 QNT-CTR-005 Golden 验证生成结果完全一致，并覆盖 JSON 顺序规范化、缺失/重复快照、非法类型/版本/指纹及篡改检测。
- 本实现只负责不可变 Manifest 与 payload 指纹，不签发 AuthorizationRef、不推断可信 Principal、不替代读取时当前授权复核；这些边界仍按 QNT-CTR-005 由 Quant Application/Policy Adapter 后续接入。
- 当前全仓 CI 仍被 Research 模块 gofmt 解析错误阻断，以上测试尚未执行。


### 10.1 Manifest 与结果载荷绑定

- `manifest.BuildWithPayload` 根据强类型 payload 的 RFC 8785 JCS + SHA-256 计算 `result_fingerprint`，再生成内容寻址 Manifest；调用方若同时提供指纹，必须与 payload 实际指纹一致。
- `Manifest.VerifyPayload` 先验证 Manifest 自身的 `manifest_fingerprint/result_id`，再复算 payload 指纹，防止合法 Manifest 被错误 payload 复用。
- 该能力只证明载荷与 Manifest 的内容绑定，不证明 payload 符合对应 `result_type/schema_version` 的业务 Schema，也不签发/复核 AuthorizationRef；Schema 校验和读取时当前授权仍是独立门禁。
- 新增测试覆盖等价 JSON 的规范化一致性、payload 内容变化、调用方伪造指纹和 Manifest 身份篡改。当前仅有测试源码，须以当前 SHA CI 实际执行结果作为验收证据。


### 10.2 Manifest 时间戳规范化校验

- `Manifest.Verify` 除检查时间可解析且以 UTC 表示外，还要求其文本等于 UTC RFC3339Nano 的规范格式，拒绝语义相同但带冗余小数位的非规范表示。
- 新增负例测试：即使调用方重新计算 Manifest 指纹与 result_id，非规范时间文本仍不能通过验证。
- 该修复只收紧 Quant Manifest 自身的规范化边界，不修改其他模块文件。

### 10.7 CalculationContext 快照引用边界

- `CalculationContext.Validate` 对每个 `input_snapshot_ref` 执行不透明引用边界校验：非空、首尾无空白、必须是合法 UTF-8、长度为 1～128 字节、首尾无空白，并继续拒绝重复引用。
- 128 字节上限遵循 GOV-CTR-003 的不透明 ID 长度规则；不解析引用内部结构，不推导或重写引用值。
- 测试覆盖非法 UTF-8、前导/尾随空白、129 字节拒绝及 128 字节接受。
- 此校验不证明快照存在、可访问、内容完整或授权有效；这些属于 Data 快照解析与授权门禁。
