# Quant 首批输入输出契约与验收补充

- 适用任务：QNT-001～003
- 契约范围：QNT-CTR-001～005；公共语义遵循 GOV-CTR-001～006
- 状态：实现输入基线；不代表 Schema、Golden、Contract Test 或 L2 已通过
- 权威关系：项目级契约目录登记编号、状态和公共语义；本文件细化 Quant 生产方/消费者边界，不改变已接受的项目级契约

## 1. 依赖方向

Quant 是确定性计算模块。领域层不依赖其他业务模块；Application 通过端口读取 Data 快照并调用 Platform 公共原语。

- Data 拥有行情、证券主数据、交易日历、行业历史成分、财务和估值事实。
- Quant 只通过自己的 Data Adapter 消费公开 DTO/API，不 import Data Domain、Repository、SQL Model、Provider Adapter 或 HTTP DTO。
- Researchflow 是 Quant Application 的主要编排消费者；Quant 不依赖 Research/Researchflow 内部类型，不调用 LLM、不下单、不执行策略动作。
- Quant 风险事件在本地事务写入 Outbox，按 INT-CTR-001 投递 Notification；不直接依赖 Notification 领域包、Repository 或发送接口，发布失败不得回滚已提交风险事实。

## 2. 计算上下文规范

跨模块 DTO 使用 snake_case，时间字段遵循 GOV-CTR-002。首批请求至少包含 schema_version、request_id、correlation_id、scope、security_id（按场景必需）、system_as_of、trade_date、period、input_snapshot_refs、adjustment_basis（按场景必需）、typed parameters、quality_policy、idempotency_key。

system_as_of 是系统知识截止，不是交易日。Data 旧 API 的 as_of 仅允许在 Data Adapter 内显式映射；Quant 对外 DTO、结果和跨模块调用统一使用 system_as_of。Quant 对外 DTO 统一使用 system_as_of。当前分支 services/market-data/openapi.yaml 仍登记 v1 DailyBar（数值字段为 JSON number，PIT 查询参数为 as_of，行级时间字段为 system_observed_at）；未发现已发布的 Data v2 Decimal/system_as_of OpenAPI 路由或 Schema。DATA-CTR-005 仍为 pending_evidence，真实 Data Adapter 不得宣称已接入 v2。

历史输入必须满足：
1. snapshot_ref 不可变，保存来源和 source_version。
2. 严格 PIT 的 available_at 必须有来源证据且不晚于 system_as_of；不得用 published_at、fetched_at 或当前时间推导。
3. 交易日、复权基准/参考日期、证券主数据版本、行业成分版本必须一致。
4. 不同 system_as_of、adjustment_basis、单位或不可比较质量的数据不得混算。
5. null/unknown/unavailable 不得转成 0、false 或空字符串。

## 3. 数值与 Metric Registry

每个 metric_code 必须注册 JSON 数值类型、unit、范围、精度/scale、舍入模式、容差、窗口/样本口径、缺失语义、quality_policy 和算法版本。

- 精确价格/金额使用 decimal string；禁止 float64 转字符串伪装无损。
- 统计量仅在明确允许浮点误差时使用 JSON number，并声明 tolerance 和舍入策略。
- 百分比区分 percentage_point 与 ratio；转换必须位于明确 Adapter/计算边界并有 Golden。
- 计数使用 integer，遵循 GOV-CTR-001 安全整数上限。
- value=null 时 metric_status 必须说明原因；metric_status=available 时 value 必须非 null。
- quality_status=invalid/unknown 时不得 available；上下界必须同时存在或同时为 null，类型与 value 一致。

SMA/EMA/Return/Volatility/RSI/MACD/ATR/Bollinger 参数 Schema 固定窗口、最小样本、seed、缺失处理、复权要求和精度。首批 Factor 仅为单证券时间序列 momentum_20d、momentum_60d、volatility_20d；不做横截面排序、行业中性化、winsorize/zscore/rank 或其他因子扩展，这些均延期。Factor 不隐式依赖 Indicator Engine。

## 4. 结果与风险契约

QuantResult 使用 result_type + schema_version 判别的强类型 payload，禁止任意 map。Envelope 至少包含 schema_version、result_id、result_type、scope、security_id（按场景必需）、system_as_of、trade_date、period、algorithm_version、parameter_fingerprint、input_snapshot_refs、quality_status、result_status、authorization_ref、payload。

result_status 与 quality_status 独立；completed 不代表 valid。insufficient_data、insufficient_sample、rejected、failed 不得伪装为 completed。未知 result_type/schema_version 必须拒绝，不回退旧版本。

Quant Result Manifest 不可变，直接绑定 result_type、schema_version、system_as_of、input_snapshot_refs 和 result_fingerprint；result_fingerprint 对强类型 payload 计算，payload 内的 algorithm_version/parameter_fingerprint 由该摘要间接绑定。调用主体不属于 Manifest 字段，由 Quant 签发的 GOV-CTR-006 AuthorizationRef 单独绑定 subject_ref 和 resource_ref=result_id：policy_owner=quant、subject_ref 来自可信认证 Context、resource_ref=result_id、purpose_code=quant_analysis、content_level=full。读取时仍须检查当前授权；历史 allowed 不能覆盖当前 denied/expired/unknown。

RiskDecision 只表达 pass/reject/unknown、规则版本、评估时间、system_as_of、输入引用和原因。数据缺失、规则无法评估或质量不足时不得 pass；硬风险结论不能被评分或 LLM 覆盖。风险事件仅在首次形成或 status/硬阻断原因集合实质变化并持久化后发布，遵循 INT-CTR-001。

### 6.2 待总规划澄清项

以下问题只登记在 Quant 专项文档，不擅自修改项目级契约或现有 QNT Schema：

1. **use_case 幂等作用域。** QuantAnalysisRequest 字段表没有 use_case，但幂等作用域和请求指纹使用 use_case。需要明确由 AnalyzeStock/AnalyzeMarket 等 Facade 路径稳定映射，还是增加显式字段；映射必须有测试。
2. **QuantResultRef 与 QuantResult Envelope 重叠。** 两者字段高度重叠，需要明确 Reference 是 Envelope 的引用投影/索引视图还是独立 DTO，避免两份 Schema 分叉。
3. **纯函数空快照引用冲突。** Envelope 描述允许白名单纯函数的 input_snapshot_refs 为空，但 QNT-CTR-005 Manifest Schema 当前 minItems=1。需明确纯函数是否能生成可持久化/可引用结果；未决前不放宽 Manifest Schema。
4. **请求/结果 scope 不同。** Request 为 stock/market/industry，ResultRef 还包含 portfolio。portfolio 属 QNT-012 后续能力，首批 Facade 不开放。
5. **连续有效交易日。** 21/61/21 个交易日必须按 Data 交易日历版本判定，不是自然日连续或数组连续；应有交易日缺失则窗口不完整。
6. **ATR 首个 TR 边界。** 固定窗口 N 是 N 个 TR 还是 N+1 根 OHLC bar，previous_close 的首个来源必须在 Golden 明确。
7. **NOT_COMPARABLE 状态落点。** 诊断要求显式不可比较，但 QuantMetric.metric_status 和 QuantResult.result_status 当前枚举没有 not_comparable；需明确映射为 rejected + reason_code 或扩展状态，不能静默映射成 unknown/insufficient_data。
8. **Data v2 证据尚不存在于当前 OpenAPI。** 当前 `services/market-data/openapi.yaml` 为 v1.0.2，DailyBar 数值字段是 JSON number，PIT 参数为 `as_of`，行级时间为 `system_observed_at`；当前 OpenAPI 未登记 DailyBars v2 Decimal/system_as_of Schema/Route。DATA-CTR-005 仍 pending_evidence，Quant 真实 Adapter 不得宣称已接入 v2。

### 6.4 首批算法口径

- EMA：首 window 个 close 的 SMA seed，之后 alpha=2/(window+1)。
- RSI：首 window 个变化的平均涨跌幅 SMA seed，之后 Wilder 平滑；需要 window+1 个 close。
- MACD：fast/slow/signal EMA 均按 SMA seed；fast_window < slow_window；histogram=2*(DIF-DEA)。
- Volatility：window 个收益样本，ddof=1；年化因子显式提供；首批 Factor volatility_20d 不年化。
- Bollinger：middle=SMA；总体标准差 ddof=0；multiplier>0。
- ATR：TR=max(high-low, abs(high-prev_close), abs(low-prev_close))；Wilder 平滑、初始 SMA；样本边界待决。
- Factor：momentum_20d/60d 为 close_t/close_(t-N)-1；volatility_20d 为 20 个 simple daily return 的样本标准差。
- 首批 Factor 只做单证券时间序列；横截面排序、行业中性化、winsorize/zscore/rank 和其他因子均 deferred。
- 价格窗口必须同一 adjustment_basis/reference_date；缺失不填充；无效价格不得生成有效值。

### 7.2 Indicator Golden 场景

每个指标至少覆盖 normal、minimum_window、insufficient_window、missing_session、invalid_price、adjustment_mismatch、degraded_input、deterministic_repeat。所有样本标记为 synthetic_fixture。

- ATR：明确 N 个 TR 所需 bar 数及 previous_close 来源。
- Bollinger：ddof=0、multiplier 边界和 upper/middle/lower 顺序。

### 7.3 Factor Golden 场景

| 因子 | 最小输入 | 公式 | 单位 |
|---|---:|---|---|
| momentum_20d | 21 个连续有效复权收盘价 | close_t / close_(t-20) - 1 | ratio |

### 7.4 样本和真实验收边界

- 首批 Golden 使用手工可复算 synthetic fixture，记录生成规则、输入、公式版本、期望值和 tolerance。

- 浮点统计量声明绝对/相对 tolerance；精确价格指标声明 scale 和 rounding_mode。
- 只有真实 Data Adapter 提供 Provider、证券、交易日期、snapshot_ref、source_version、adjustment_basis/reference_date、质量和覆盖率证据后，才能登记真实数据验收。Fixture 通过不等于真实数据通过。

## 6. QNT-CTR-001～005 待决项与阻断边界

本节不修改项目级契约，只将 Q0-002 核对发现的差异明确带入实现约束。详细证据和阶段状态见本文件及 02-任务拆分与验收.md 的 Q0-002/QNT-001 进度记录。

1. use_case 幂等作用域：请求 DTO 没有独立 use_case 字段，但幂等作用域使用 use_case。首批只能由 AnalyzeStock/AnalyzeMarket 等 Facade 形成稳定映射；不得接受客户端任意字符串，也不得由不同 Facade 意外共用幂等空间。
2. QuantResultRef 与 QuantResult Envelope：字段高度重叠。未明确前，模块内部可共享领域表示，但对外不得发布两套独立 Schema 或让两份 DTO 各自演进。
3. 纯函数空输入：Workflow Template 可声明 allow_empty_inputs，但当前 QNT-CTR-005 Manifest Schema 对 input_snapshot_refs 要求 minItems=1。未获总规划决议前，禁止为无输入结果签发可持久化 QuantResult/Manifest；不得自行放宽 Manifest Schema。
4. Scope：请求首批仅 stock/market/industry；结果 DTO 出现 portfolio 不代表首批 Facade 支持 portfolio，必须标记 deferred。
5. 连续有效交易日：Factor 窗口必须使用 Data 交易日历版本识别应有交易日；缺失交易日视为窗口不完整，不按数组连续或自然日相邻推断。
6. ATR 初始窗口：Golden 必须明确 N 个 True Range 对应 N 根还是 N+1 根 OHLC bar，避免首个输出偏移。
7. NOT_COMPARABLE：当前 Metric/Result 状态枚举缺少明确落点。未决前必须保留稳定 reason_code 和诊断状态，不得擅自映射为 unknown/insufficient_data 或新增公共枚举。
8. Data v2 证据：当前 `services/market-data/openapi.yaml` 仍是 v1.0.2，DailyBar 数值字段为 JSON number，PIT 参数为 `as_of`，行级时间为 `system_observed_at`；当前 OpenAPI 未登记 DailyBars v2 Decimal/system_as_of Schema/Route。DATA-CTR-005 仍 pending_evidence。
9. Registry 算法版本选择：QNT-CTR-001 要求 code、schema_version、algorithm_version 分开管理，但尚未定义同一 code/schema_version 存在多个 algorithm_version 时，服务端如何选择执行版本、历史版本如何保留/复算。不得让客户端任意指定算法版本，也不得用 Registry 注册顺序隐式选择。
10. 通用 Registry 复用边界：`internal/analysis/registry` 已有无业务依赖的泛型注册容器（重复 ID 拒绝、Freeze、稳定排序、并发读写），但包路径属于旧 analysis。Quant 不应复制第二套通用容器，也不应在未评审依赖边界前直接耦合旧 Analysis Application；需决定复用该纯工具包或由公共基础层提供共享位置。

## 8. QNT-001 计算上下文实现边界

当前实现位置：`internal/quant/domain/context.go`；测试：`internal/quant/domain/context_test.go`。
