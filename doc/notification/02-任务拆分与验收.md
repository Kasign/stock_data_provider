## 依赖分层

- NTF-001/002 可在模块分支内独立完成领域模型、Schema/Fixture、模板渲染和内存测试，不等待 Platform Storage、Worker 或真实渠道。
- NTF-003 的 Channel Port、Fake Adapter 和错误分类可先做；真实发送无凭据时标记 blocked/skipped，不标记通过。
- NTF-004/005 先实现模块内有界 Dispatcher 和状态机；Platform Task Queue 不作为领域依赖。
- NTF-006 Repository Port/Schema 可并行设计；真实 DB 和根 Migration 属 L3。
- 根 DI、HTTP、Worker、Migration 注册由 Integration Owner 集中修改。

## 幂等、状态与恢复验收

- Event Inbox 幂等与 Delivery 幂等是两道防线：事件接收去重与订阅/渠道投递去重分别测试。
- 相同幂等键相同 fingerprint 返回原结果；同 key 不同 fingerprint 返回冲突，不能覆盖旧记录。
- DeliveryAttempt 追加保存；每次实际外部调用对应一个 Attempt，已完成 Attempt 不覆盖。
- 网络超时但无法确认渠道是否接收时进入 unknown；无渠道幂等/查询证据不得自动重发。
- Outbox 只保证本地事务与待投递事件原子性，不保证外部渠道 exactly-once。
- recipient_scope 与 recipient_ref 分离；真实目标只能由已授权 Subscription/Channel 配置解析。
- 退订会抑制尚未发送的 queued/retry_wait Delivery；sending 中的外部副作用不能承诺撤回。
- 状态更新采用 CAS/版本号和租约 fencing，过期 Worker 不能覆盖当前状态。

## 验收门禁

- 真实渠道受控测试发送；无凭据标记 blocked/skipped，不标记通过。
- 幂等、重试、unknown 和恢复测试证明不会因不确定结果盲目重复发送。
- 发送失败不影响上游业务事务。
- Secret/目标/通知内容按安全策略脱敏。
- 测试发送不得触达未明确指定的真实订阅者。
- 模块级 Fake/内存测试与 L3 真实渠道、Storage、Worker 集成验收分开记录。
