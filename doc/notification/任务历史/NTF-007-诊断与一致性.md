## 已实现/复核范围

Delivery/Attempt/StateEvent 一致性诊断、DeliveryConsistencyService、MySQL REPEATABLE READ 一致性快照读取、LeaseRecoveryReport 到 Platform Diagnostics Observation 映射、安全 DTO。

## Review 结论

- DeliveryConsistency 分别判断 Attempt 历史与 StateEvent 历史，缺失或不可比较的历史标记 not_comparable；已知矛盾标记 fail；合法中间态可 degrade；全部可比较且一致才 pass。
- 聚合优先级为 fail > not_comparable > degrade > pass，已知冲突不会被其他数据源不可用掩盖。
- MySQLDeliveryConsistencySnapshotReader 在一个 REPEATABLE READ、ReadOnly 事务内读取 Delivery、完整 Attempts、完整 StateEvents；不把多个独立查询伪装成同一快照。
- DeliveryConsistencyResult 是 allowlist DTO，只输出状态、版本、计数和固定 reason_code；不输出 Delivery/Recipient/Channel ID、Payload、EvidenceRef、Provider Message、Actor/Request ID 或原始错误。
- LeaseRecoveryReport 对批次计数闭合、Unknown ID 非空和唯一性进行校验；Unknown Delivery IDs 仅供内部 Worker 对账，使用 `json:"-"`，不会被 JSON 序列化。
- ToDiagnosticsObservation 按 failed > outcome_unknown > conflicted > unprocessed 分类；属性仅输出计数，不包含内部 Delivery ID；生成的 Observation 通过 Platform Observation.Validate。
- 根 HTTP、鉴权、权限、审计、诊断入口和 Worker 生命周期属于 Server；Notification 只提供模块内诊断服务和 DTO，不重复建设公共入口。
