## 已实现与复核范围

- Domain：ChannelConfigSnapshot、能力声明、RecipientTarget、发送请求/结果、Lookup 请求/结果。
- Application SPI：ChannelAdapter、ChannelResolver、RecipientResolver、ChannelDeliveryLookup。
- Registry：按 `channel_ref + config_version` 精确注册和解析；Adapter 快照与持久化快照必须一致。
- 结果语义：accepted/rejected/ambiguous/not_sent 分离；幂等、Retry-After、Lookup 按显式能力声明启用；retryable 错误码按渠道配置白名单判定；not_sent 的 Attempt 完成必须带 evidence_ref。
- Storage：MySQL ChannelConfig Repository 保存不可变配置快照和 Digest，只保存 SecretRef。
- Platform 复用：`config.Secret` 用于敏感凭据注入并对日志/序列化脱敏；`httpclient.Client.Bind` 提供绑定目的地址策略的 BoundDoer。无需在 Notification 重建通用 HTTP Client 或 Secret Store。

## 首个真实渠道：企业微信群机器人 Webhook

- Adapter：`internal/notification/channel/wecom`，支持文本/Markdown。
- 目的地址限制：仅允许 `qyapi.weixin.qq.com:443` 和指定 Webhook 路径；禁用重定向。
- 凭据：GitHub Actions Secret 名称为 `WECHAT_WORK_WEBHOOK_URL`，值不进入代码、文档或日志。
- Live Workflow：`.github/workflows/notification-wecom-live.yml`，手动触发。
- Provider 结果语义：成功业务响应判定 accepted；业务拒绝判定 rejected；HTTP 非 2xx、畸形响应及传输错误按 ambiguous 处理，不盲目重发。
- 群机器人不提供服务端幂等、Delivery Lookup、Retry-After 或可靠送达回执；本 Adapter 不虚报这些能力。
