## NTF-005 Review 与修复结论

- 渠道调用前先持久化 Attempt；发送时间预算受单次超时、Delivery 总截止和租约到期共同约束。
- Attempt 结果先写入不可变历史，Delivery 状态再 CAS 更新；持久化确认丢失时不重发，依靠恢复路径读取既有 Attempt 收敛。
- 普通 retry 只接受显式 retryable rejection；unknown 的 retry 必须由精确版本 Provider Lookup 返回权威 not_accepted 证据，且 observed_at 不早于 Attempt。
- 原缺口：过期租约期间的运行中 Attempt 没有完成结果，LeaseRecovery 会将 Delivery 标记 unknown；但 Lookup 请求构造和 verified evidence 只接受完成态 ambiguous Attempt，无法对账。
- 已修复：Lookup 允许最后一条 Attempt 为未完成态；verified evidence 精确绑定该 Attempt；RetryPolicy 只在 evidenceConfirmed unknown 路径接受未完成 Attempt，并仍要求 Provider 权威未接受证据。普通 ScheduleRetry 不放宽。
- Run [44287531891](https://github.com/Kasign/stock_data_provider/actions/runs/44287531891) 的根模块测试、Notification MariaDB lifecycle integration 和全部必需 Job success。

## NTF-007 Review 结论

- DeliveryConsistency 对 Attempt 历史和 StateEvent 历史独立判定；聚合优先级为 fail > not_comparable > degrade > pass，缺失/不可比较历史不会被误判为 pass。
- 安全 DTO 仅暴露状态、版本、计数、固定 reason_code；不输出 Delivery/Recipient/Channel ID、EvidenceRef、Provider Message、Actor/Request ID、Payload 或原始错误。
- LeaseRecoveryReport 校验计数闭合、未知 Delivery ID 唯一且非空；未知 ID 使用 `json:"-"`，不会进入公开诊断输出。
- Recovery Diagnostics 映射 Platform Observation 时按 failed > outcome_unknown > conflicted > unprocessed 分类，属性只含计数；映射结果通过 Platform Observation.Validate。
- 根 HTTP、权限、审计、生产 Worker 生命周期归 Server；Notification 不复制这些入口或权限体系。

## 判定规则

- PASS：实现、调用场景、自动化测试和必要集成证据相互一致。
- DEGRADE：非关键依赖不可用，核心安全/一致性边界仍成立，并记录 reason_code/evidence_ref。
- FAIL：存在可复现的数据一致性、安全、状态迁移或调用边界缺陷。
- NOT_COMPARABLE：缺少真实渠道、身份目录或生产环境证据，无法验证外部行为。
