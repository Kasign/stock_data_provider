# INT-CTR-001：首批业务事件到 NotificationEvent 映射决议

- 决议日期：2026-11-06
- 决议状态：语义决议 accepted；Schema/Golden/Contract Test 证据 pending_evidence
- 适用契约：INT-CTR-001、NTF-CTR-001～003、RSC-CTR-002、FLOW-CTR-001/003、QNT-CTR-005
- 权威边界：本文定义首批跨模块事件映射；Notification Envelope、Inbox/Delivery 和 Schema Registry 机制仍以 `doc/notification/03-ApplicationPort与投递状态契约.md` 为准；当前契约状态以项目级契约目录为准。

## 1. 决议目标与边界

首批自动通知只覆盖三类有明确业务价值、且能从已持久化领域状态稳定产生的事件：

1. Researchflow 分析 Run 到达终态；
2. Quant 风险决策首次形成或发生实质变化；
3. Research 研究事件生命周期发生状态迁移。

Notification 只接收并投递版本化事件，不计算风险、不判断研究事实、不读取 Research/Quant/Researchflow Repository。事件生产方负责事实提交、事件生成和 Outbox；Notification 负责 Schema 校验、Inbox 幂等、Subscription 匹配和 Delivery。

首批不发布 Run 创建/运行中/Stage 进度事件，不为每条 Evidence、Claim、Hypothesis、Scenario 或普通指标变化单独发通知。后续新增事件类型必须新增映射决议和 Schema，不得扩大现有事件含义。

## 2. 首批事件映射表

所有事件的 `schema_version` 首发固定为 `1.0.0`。`event_type + schema_version` 是 NTF-CTR-001 的不可变注册键。

| event_type | source_module | 生产方 | 触发时点 | subject_ref | 发布幂等键 |
|---|---|---|---|---|---|
| `researchflow.run.terminal` | `researchflow` | Researchflow | Run 的终态（succeeded/partial/failed/cancelled）通过事务/CAS 固化后，仅发布一次 | `run_ref` | `run-terminal:{run_ref}` |
| `quant.risk_decision.changed` | `quant` | Quant | 同一业务主体首次形成 RiskDecision，或 status / 硬阻断 reason code 集合相对上一决策发生变化并已持久化 | 单一风险评估主体的稳定引用；不得用 decision_id 代替 | `risk-decision:{subject_ref}:{decision_id}` |
| `research.event.lifecycle_changed` | `research` | Research | ResearchEvent 生命周期状态发生一次已提交迁移 | `research_event_ref` | `research-event-state:{research_event_ref}:{event_version}` |

### 2.1 researchflow.run.terminal

Payload 必须包含：

| 字段 | 类型 | 约束 |
|---|---|---|
| `source_event_ref` | string | 指向 Run 的不透明引用；不复用 NotificationEvent.event_id |
| `run_ref` | string | 必须与 envelope.subject_ref 一致 |
| `status` | enum | 仅 succeeded/partial/failed/cancelled |
| `termination_reason` | string/null | 必填字段；无原因时显式 null |
| `system_as_of` | RFC3339Nano UTC | 本次 Run 固定的知识截止时间 |
| `finished_at` | RFC3339Nano UTC | Run 终态固化时间 |
| `result_summary_ref` | string/null | 不透明结果摘要引用；无结果时显式 null |
| `template_ref` / `template_version` | string | 本次执行固定的模板引用和版本 |

仅终态固化后发布。Run 的 created、queued、running、cancelling 和 Stage/Attempt 变化不发布首批通知。用户取消导致 Run 最终 cancelled 时，照常发布终态事件；不得在进入 cancelling 时提前发布终态通知。

### 2.2 quant.risk_decision.changed

Payload 必须包含：

| 字段 | 类型 | 约束 |
|---|---|---|
| `source_event_ref` | string | 指向本次不可变 RiskDecision 的 decision_id |
| `decision_id` | string | 稳定决策 ID |
| `previous_status` | enum/null | pass/reject/unknown；首次评估显式 null |
| `current_status` | enum | pass/reject/unknown |
| `rule_set_version` | string | 本次实际使用的规则集版本 |
| `changed_block_reason_codes` | array<string> | 去重并按字典序排序；无阻断原因时为空数组 |
| `system_as_of` | RFC3339Nano UTC | 决策输入知识截止时间 |
| `evaluated_at` | RFC3339Nano UTC | 决策完成时间 |

触发规则：

- 首次决策发布一次，`previous_status=null`。
- 后续仅当 `status` 变化，或硬阻断 reason code 集合变化时发布；仅 warning/info 原因变化不触发首批通知。
- 同一 RiskDecision 涉及多个业务主体时，按主体拆分事件，每个事件只有一个 subject_ref，并使用各自独立的幂等键。
- RiskDecision=unknown/reject 是有效业务结论，不得被通知层改写为失败或忽略；通知只展示来源决策状态和安全摘要。

### 2.3 research.event.lifecycle_changed

Payload 必须包含：

| 字段 | 类型 | 约束 |
|---|---|---|
| `source_event_ref` | string | 指向 ResearchEvent 不可变版本的引用 |
| `research_event_ref` | string | 必须与 envelope.subject_ref 一致 |
| `event_version` | integer | 正整数，单调递增 |
| `previous_state` | enum/null | detected/consolidating/active/materializing/fading/invalidated/closed；首次创建显式 null |
| `current_state` | enum | 同上，不得与 previous_state 相同 |
| `reason_code` | string/null | 稳定机器码；无原因时显式 null |
| `system_as_of` | RFC3339Nano UTC | 本次状态判断使用的知识截止时间 |
| `changed_at` | RFC3339Nano UTC | 状态迁移提交时间 |

只在 ResearchEvent 生命周期状态真正迁移并持久化后发布；普通 Evidence 追加、来源补录、描述修订但状态不变，不触发首批通知。

## 3. Envelope 与身份规则

三类事件统一遵循 NTF-CTR-001/002：

- `source_module` 首批枚举为 `quant`、`research`、`researchflow`；不得由 Notification 根据 event_type 猜测来源。
- `event_id` 是 NotificationEvent 自身的稳定不透明 ID，由生产方生成并写入 Outbox；不得直接复用 ResearchEvent.event_id、RiskDecision.decision_id 或 Run 引用。
- `idempotency_key` 按第 2 节定义，在同一 source_module 范围内全局唯一；同一发布意图重试时保持不变，不得按 event_type 分桶后复用。
- `occurred_at` 使用来源事实的业务时间：Run 使用 finished_at，RiskDecision 使用 evaluated_at，ResearchEvent 使用 changed_at；不得使用 Notification 接收时间。
- `correlation_id` 从可信父 Request/Run Context 继承；没有父链路时由生产方生成高熵 ID，不信任客户端自报值。
- Payload 中的 `source_event_ref` 指向来源领域对象/不可变版本；它与 NotificationEvent.event_id 是不同身份空间。
- Payload 只携带必要状态、版本和不透明引用；不得携带原始 Prompt、完整新闻正文、Secret、任意收件人地址或未经脱敏的敏感字段。

## 4. Outbox、重放和幂等

1. 生产方在本模块本地事务中同时提交领域状态变更和 Outbox 记录；事务回滚时不得发布事件。
2. Outbox 投递失败可重试；重试必须复用原 event_id、idempotency_key、occurred_at、correlation_id 和完全相同的 payload。
3. Notification Inbox 以 (source_module, event_id) 去重；Publish 以 (source_module, idempotency_key) 幂等。相同键、相同 fingerprint 返回原结果；相同键、不同 fingerprint 返回 idempotency_conflict。
4. 生产方不得通过重新生成 event_id 或更换 idempotency_key 绕过冲突；修正事实必须形成新的领域版本和新的发布意图。
5. 不依赖跨模块数据库事务；调用方 Outbox 与 Notification Inbox 提供可靠交付边界。

## 5. 取消、撤回与更正语义

- 领域状态尚未提交、Outbox 事务回滚：事件不存在，不得进入 Notification。
- Run 被用户取消：只有 Run 最终状态通过 CAS 固化为 cancelled 后，发布 `researchflow.run.terminal`；cancelling 不是终态。
- ResearchEvent 被 invalidated/closed：发布新的 `research.event.lifecycle_changed` 状态迁移事件，不删除或改写此前已发布的事件。
- RiskDecision 发生新的状态/硬阻断原因变化：发布新的 `quant.risk_decision.changed`，保留 previous/current 状态链。
- 已写入 Outbox 并被 Notification 接收的事件不可原地撤回、删除或复用 ID。事实更正通过新版本/新事件表达；已发送通知不能承诺召回。
- Notification 的 queued/retry_wait/sending/sent 状态仍按 NTF-CTR-002/003 管理。来源模块不直接修改 Delivery；用户退订、当前授权和渠道状态由 Notification 在发送前按自身契约检查。
- 不承诺 exactly-once 外部投递；超时且无法确认渠道是否接受时按 NTF-CTR-003 进入 unknown，不盲目重发。

## 6. 明确不在首批范围

- Run created/queued/running/cancelling、Stage/Attempt 进度通知。
- 每条 Evidence、Claim、Hypothesis、Scenario、新闻抓取或普通指标变更通知。
- Quant 非风险类指标/因子变化、组合调仓建议和交易指令通知。
- Notification 自动推导订阅、接收人或告警条件。
- 发送后召回、跨模块事务、外部渠道 exactly-once。

新增上述事件类型或扩大触发范围，必须另行登记 event_type/schema_version、触发决议和对应 Golden；不得修改本决议中的既有 1.0.0 语义。

## 7. 验收证据清单

INT-CTR-001 当前语义决议为 accepted，但在以下证据齐备前保持 pending_evidence：

- 已建立 4 份 Draft 2020-12 Schema：`schema/notification-event-envelope-1.0.0.schema.json`、`schema/researchflow-run-terminal-1.0.0.schema.json`、`schema/quant-risk-decision-changed-1.0.0.schema.json`、`schema/research-event-lifecycle-changed-1.0.0.schema.json`；仍需用实际 Validator 执行格式/边界校验。
- 已建立 6 个代表性 Golden，覆盖 Run succeeded/cancelled、RiskDecision 首次/拒绝变化、ResearchEvent 首次/invalidated；重放、重复状态、冲突指纹和 Outbox 回滚仍需转为自动化 Fixture/Contract Test。
- Outbox 事务提交/回滚、重复发布、相同幂等键不同 payload、并发 Inbox 唯一约束测试。
- RiskDecision 多主体拆分、硬阻断原因排序/集合变化、warning-only 变化不触发测试。
- Run cancelled 与其他终态、ResearchEvent invalidated/closed、更正事件不可覆盖历史的测试。
- Notification 对未知 event_type/schema_version 的拒绝测试；不回退旧 Schema。
- 三个生产方到 Notification 的字段映射 Contract Test，记录测试命令和提交 SHA。

上述证据未完成前，只阻断这三类自动事件的生产发布和对应真实通知调用点；不阻断 Research/Quant/Researchflow 领域事实创建，也不阻断 Notification 独立 Domain、Inbox/Delivery 状态机和 Fake Channel 开发。
