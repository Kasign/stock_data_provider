# 依赖 03：真实渠道与凭据

状态：BLOCKED（等待项目决策及 Provider 输入）

## 必须明确

1. 首个真实渠道及业务用途。
2. Provider 协议、请求/响应格式、超时和限流规则。
3. 凭据申请、存放、轮换和撤销流程；Notification 只接收 SecretRef/受控 Secret 能力。
4. Provider 幂等键支持范围及有效期。
5. accepted/rejected/ambiguous/not_sent 的可判定条件。
6. Retry-After 可信度及 retryable 错误码白名单。
7. Delivery Lookup、回执 Webhook 或人工对账能力。
8. 发送目标如何从 Recipient Directory 授权解析。

## 验收门禁

- 无真实凭据和受控测试目标：not_comparable。
- 明确拒绝且 Provider 证明未接受：按白名单和 RetryPolicy 决定是否重试。
- 请求可能到达 Provider 但缺少可靠结果：unknown，禁止盲目重发。
- 只有真实 Provider 协议测试、回执和对账证据通过，才能标记渠道 L3 PASS。

## 公共能力复用

使用 Platform Secret 与受控 HTTP Client；不得在 Notification 重建 Secret Store、通用 HTTP Client 或凭据管理。
