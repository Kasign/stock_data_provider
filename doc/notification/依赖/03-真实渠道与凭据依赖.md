# 依赖 03：真实渠道与凭据

状态：IN_PROGRESS（已确定企业微信群机器人 Webhook；Adapter/Live workflow 已提交，待真实验收）

## 已确定

- 首个真实渠道：企业微信群机器人 Webhook。
- GitHub Actions Secret 名称：`WECHAT_WORK_WEBHOOK_URL`（用户已配置；值不进入代码、文档或日志）。
- Adapter：`internal/notification/channel/wecom`。
- 手动验收 Workflow：`.github/workflows/notification-wecom-live.yml`。
- 真实验收仍待 workflow 运行并确认群内收到测试消息。

## 待确认的关键输入

1. CI 单测和 live workflow 首次执行结果。
2. 生产环境 Secret 注入、轮换与撤销流程（当前 Secret 仅用于验收）。
3. 企业微信业务错误码是否需要维护 retryable 白名单；当前默认空白名单，即拒绝后不自动重试。
4. Server Recipient Directory 如何授权绑定群机器人目标；Webhook 本身固定绑定群，不支持任意用户地址。
5. 群机器人无可靠服务端送达回执、Delivery Lookup 和幂等保证；ambiguous 需人工/外部证据对账，不得自动重发。

## 凭据安全

- 群机器人 Webhook URL 如果包含 key，整个 URL 都是敏感凭据，不应提交到仓库、写入文档或放入普通聊天记录。
- 建议将 Secret 放入部署环境的受控配置/密钥注入通道；Server 通过 Platform `config.Secret` 将值注入具体 Adapter。
- 具体 Adapter 使用 Platform `httpclient.Client.Bind`，按企业微信官方主机名和必要端口创建固定目的地址策略；不允许任意 URL 由业务数据控制。
- ChannelConfig Repository 只保存 SecretRef，不保存 Secret 明文。

## 验收门禁

- 无真实凭据和受控测试目标：NOT_COMPARABLE。
- 明确拒绝且 Provider 证明未接受：按白名单和 RetryPolicy 决定是否重试。
- 请求可能到达 Provider 但缺少可靠结果：unknown，禁止盲目重发。
- 只有真实 Provider 协议测试、回执和对账证据通过，才能标记渠道 L3 PASS。

## 公共能力复用

使用 Platform Secret 与受控 HTTP Client；不得在 Notification 重建 Secret Store、通用 HTTP Client 或凭据管理。
