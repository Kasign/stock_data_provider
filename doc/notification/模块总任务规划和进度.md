## 1. 模块目标与边界

Notification 负责内部业务事件接收、订阅与受众快照、Fanout、DeliveryPlan、模板渲染、渠道适配、Delivery/Attempt 生命周期、重试、租约恢复、Unknown 对账和一致性诊断。业务事实由生产模块拥有；Server 负责 Relay、根装配和 Worker 生命周期；Platform 提供 Secret、受控 HTTP Client、Storage、Diagnostics 等技术原语。

## 4. 关键规则

1. recipient_ref 只能是不透明稳定引用；敏感地址由受控 Recipient/Channel Adapter 解析。
2. Channel、Template 按 DeliveryPlan 固定版本精确解析，不回退 latest。
3. 非空 Filter 无版本化 Matcher 时 fail closed；语义由事件 Owner 冻结。
4. 仅在 Provider 能力已验证支持时发送幂等键、采信 Retry-After 或执行 Lookup。
5. ambiguous 不自动重试；not_sent 必须有证据。
6. Attempt 追加历史不可覆盖；租约恢复校验 Worker、版本和 fencing token。
7. 无真实渠道时保持 BLOCKED/not_comparable，不用 Fake 宣称生产通过。

## 6. 生产闭环顺序

1. 完成 NTF-009 当前代码与证据 Review。
2. 决定首个真实渠道及目标身份目录。
3. 冻结 Provider 请求/响应、凭据、回执、幂等、Retry-After、Lookup 语义。
4. Server 装配 Recipient Directory、ChannelAdapter、Fanout/Delivery Worker。
5. 业务 Owner 提供真实模板和 Filter 规则。
6. 在受控环境验收发送、失败、重试、Unknown 对账、进程恢复和优雅关闭。
7. 分别验收 Outbox→Inbox、Inbox→Fanout、Delivery→Channel。
