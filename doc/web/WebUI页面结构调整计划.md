# WebUI 页面结构调整计划

更新时间：2026-11-12  
核对基线：feat/webui-market-data-console @ 2de5cd6c2241bb6a691155d5e28d2668a4b8b0bc  
阶段：W1 - 现有工作台收口  
范围：仅规划 `web/**` 的页面结构和交互调整；本文件本轮不代表代码已经修改。

> 本文是 W1 的实施计划，不替代《WebUI 整体规划》的全局路线。页面调整应分批进行，每批有明确的页面范围、真实能力和验收标准。当前先确定信息架构和迁移顺序，不一次性重写整个 Web。

## 1. 本轮核对结论

当前主导航有 11 个入口：
市场总览、个股行情、自选与观察、个股深度研究、分析任务、选股与筛选、告警、问股、通知中心、数据中心、设置中心。

对应页面均以 `data-view` / `VIEW_META` 和 `*-view` 容器切换。当前主页面切换由 `app.js#setView` 负责；个股研究页内另有研究分区导航，设置中心有 10 个分组导航。不要再增加第二套路由或导航状态管理。

当前 11 个入口中：
- 核心可用页面：市场总览、个股行情、自选股、个股研究、分析任务、数据中心、设置中心。
- 后端能力待接入页面：选股与筛选、告警、问股、通知中心。部分页面只有本地草稿或不可用状态，不应因页面存在而视为服务端功能已经可用。
- 个股研究页同时包含行情摘要、日 K、技术指标、公司资料、财务/估值、资金流/筹码、公告、本地研究笔记和本地 Run 报告归档。
- 分析任务页包含最近任务引用、创建任务和 Run Flow 对话框；最近任务是本地有限引用，不是服务端历史。
- 设置中心包含显示偏好、连接与服务、浏览器本地数据、基础设置、数据源、AI、通知、调度、选股和安全备份等 10 个分组。

## 2. 目标导航收敛方案

目标仍为七个一级入口。迁移采取“入口收敛、内容分区”的方式，不把所有现有页面合并成一个超长页面。

| 目标一级导航 | 现有入口/内容 | W1 处理建议 | 真实能力限制 |
|---|---|---|---|
| 市场观察 | 市场总览、个股行情 | 两者归入同一市场工作区；市场总览为默认视图，个股搜索/行情/全市场分页作为二级视图或页内工作区 | 继续复用现有查询、行情和分页能力 |
| 研究中心 | 个股深度研究、问股 | 个股研究作为主体；问股作为明确标注“服务端待接入”的研究辅助入口，不作为可用聊天能力 | Research/Evidence 和 Chat API 尚须按真实 Server 接入 |
| 量化研究 | 选股与筛选、个股技术指标 | 技术指标继续作为行情/个股研究的派生展示；选股页面保留为待接入能力入口，待 Quant API 可用后再开放实际操作 | 当前页本地筛选不是全市场策略扫描；不在 Web 计算策略/回测 |
| 研究任务 | 分析任务、Run Flow | 作为独立主入口；保留创建、状态/阶段事件和 Run 结果；Run Flow 仍是任务详情，不创建第二个任务页状态机 | 服务端历史、模板、取消和综合结果按 Researchflow API 接入 |
| 跟踪中心 | 自选与观察、告警、通知中心 | 自选作为当前可用主体；告警草稿、本地通知偏好与服务端告警/通知能力明确分区；通知收件箱 API 未接入时展示不可用原因 | 本地草稿不能显示为服务端规则/投递/收件箱 |
| 数据中心 | 数据中心 | 保持独立，不与设置混合 | 仅展示真实服务健康、能力和诊断 |
| 系统设置 | 设置中心 | 保持独立，10 个设置分组按“本地偏好/服务端只读/服务端管理待接入”组织 | Session/CSRF 由 Server 实际接入后切换，不提前删除兼容配置 |

### 2.1 现有入口迁移矩阵

| 当前入口 | 目标归属 | W1 迁移策略 |
|---|---|---|
| `market` 市场总览 | 市场观察 | 保留为默认页 |
| `stocks` 个股行情 | 市场观察 | 作为市场观察的行情子视图；股票查询入口可由全局搜索/研究入口复用 |
| `watchlist` 自选与观察 | 跟踪中心 | 保留本地自选标识和本地数据边界 |
| `research` 个股深度研究 | 研究中心 | 保留完整个股研究工作区；逐步将结构化证据与本地笔记区分 |
| `tasks` 分析任务 | 研究任务 | 保留为独立主视图 |
| `screening` 选股与筛选 | 量化研究 | 保留待接入状态；不得伪装成可执行扫描 |
| `alerts` 告警 | 跟踪中心 | 本地草稿与未来服务端告警拆分标识 |

| `notifications` 通知中心 | 跟踪中心 | 保留不可用说明；不展示虚构通知数量 |
| `data` 数据中心 | 数据中心 | 原样保留核心职责 |
| `settings` 设置中心 | 系统设置 | 原样保留核心职责 |

## 3. 页面内部职责重整

### 3.1 市场观察
- 默认视图：核心指数、市场广度、市场活动、行业/概念、市场级资金流和市场快照。
- 行情子视图：证券搜索、单股报价、日 K、全市场分页行情。
- 市场页面不承载个股完整研究笔记、Run 历史或服务端策略扫描。
- 市场与行情子视图之间切换时，保留当前查询上下文；切换页面不隐式遍历全市场。

### 3.2 研究中心
- 研究对象上下文：当前证券/行业/事件对象身份、名称、来源和选择状态。
- 当前已实现的个股研究数据仍按需加载，不把未加载解释为零。
- 将研究内容概念上分为“行情与基础资料”“研究证据/观点”“本地研究记录”“关联任务结果”。
- 本地研究笔记和本地 Run 报告归档继续明确标注本地保存；未来 Research 对象需以服务端 ID 和授权边界为准。
- 问股功能仅保留能力状态说明，等待 LLM/Server 的会话、消息、流式和取消契约。

### 3.3 量化研究
- W1 不新增计算逻辑，不将 MA/RSI/MACD 改造成服务端 Quant 因子。
- 现有条件选股页面只作为能力待接入入口；本地保存条件方案不等于服务端策略。
- Quant API、PIT、数据质量、风险门禁和回测版本具备前，不开放执行按钮或伪造候选结果。
- Quant RiskDecision=block 必须以服务端事实呈现，不能由 LLM/前端评分覆盖。

### 3.4 研究任务
- 页面主工作区聚焦创建任务、最近任务引用和服务端状态。
- Run Flow 作为选中任务的详情层，继续展示阶段事件、节点诊断、结果与质量门禁。
- 最近任务区域明确“本地引用”标签；未来服务端历史列表必须另有真实分页 API。
- 不把任务执行对话框复制成另一个任务管理页，不由前端推断 Run 终态。

### 3.5 跟踪中心
- 自选列表是当前可用的本地跟踪工具。
- 告警区分本地草稿、服务端规则、触发历史和投递尝试。
- 通知区分本地偏好与服务端收件箱；偏好设置仍在系统设置中管理。
- 领域归属未批准前，不创建 Portfolio/Alert/Report 独立领域对象。

### 3.6 数据中心与系统设置
- 数据中心只回答“服务、Provider 和诊断目前报告了什么”。
- 设置中心只回答“用户可配置什么、配置保存在哪里、当前是否可修改”。
- 设置分组按实际可用性分层，服务端管理不可用时显示原因，不留看似可提交的空表单。

## 4. 导航与路由实现约束

1. 继续使用现有 `setView`、`VIEW_META`、`data-view` 和 URL hash 机制；不新增 Router。
2. 七个一级入口的内部子视图可以继续使用当前页面状态/局部导航，不新增全局状态框架。
3. 如果一个一级入口包含多个现有视图，子视图切换必须有可访问的按钮、明确当前态、浏览器前进/后退语义和刷新恢复规则。
4. 旧 hash（market/stocks/watchlist/research/tasks/screening/alerts/chat/notifications/data/settings）需制定迁移映射，不能在未验证外链和书签影响前直接删除。
5. `setView` 对视图标题、刷新按钮上下文、导航 aria-current、焦点移动、滚动位置和页面数据刷新均有影响；修改时须一并回归。
6. 禁止仅通过 CSS 隐藏导航但保留无效交互；禁用/待接入入口应提供明确状态和可访问说明。
7. 移动端导航和桌面侧栏共用同一视图状态，不维护两套导航状态。

## 6. 本阶段明确不做

- 不修改 Go、Server、Platform、Data、News、Research、Quant、Researchflow、LLM、Notification 代码。
- 不新增或猜测任何业务 API。
- 不实现 Portfolio、Alert、Report 独立领域模块。
- 不实现真实 Chat、策略扫描、服务端通知收件箱或服务端告警评估。
- 不在 W1 切换认证方案或删除现有连接兼容逻辑。
- 不重写 app.js，不批量重命名/拆分模块，不引入 React 或全局 Store。
- 不把本地数据迁移成服务端数据，不做数据库迁移。
