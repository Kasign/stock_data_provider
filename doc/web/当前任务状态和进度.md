### 源码级部署预检（2026-11-18）

核对代码基线：`4223d9039aa2e97bf3ae941f8ab2a28c18f68084`。以下是仓库静态配置结论，不代表目标环境已部署或已通过浏览器验收。

- **代理路径匹配：已核对。** Web 请求使用 `/analysis-api/api/v1/owner/...`；Nginx 将 `/analysis-api/` 转发到 Root Server 的 `/`，并将 Cookie Path 从 `/api` 改写为 `/analysis-api/api`；Root Server 注册的 Owner Session 路由为 `/api/v1/owner/...`。
- **Cookie 规则：代码约束已核对。** Platform Cookie 实现固定 HttpOnly、SameSite=Lax、不设置 Domain；Server 默认 Cookie Path 为 `/api`、Secure=true。HTTPS Origin 下配置校验会拒绝关闭 Secure。实际 Set-Cookie/Clear-Cookie 响应头仍需在目标环境检查。
- **Owner Session 启用条件：待目标环境配置。** `.env.example` 中 `OWNER_SESSION_ENABLED=false`；启用时必须设置准确的 `OWNER_SESSION_PUBLIC_ORIGIN`，并按目标硬件基准测试填写 Argon2id 参数。仓库没有目标环境真实 `.env`，不能推断当前线上配置。
- **Host/Origin：代码约束已核对。** Server 校验 Host 与配置 Origin 的 Host 一致，并对登录和非安全请求校验 Origin 的 Scheme/Host；Nginx 传递 Host 与 X-Forwarded-Proto。目标环境仍需验证外部域名、TLS 终止位置和 Public Origin 一致。
- **可信代理/IP：存在已知边界。** 登录限流取 TCP 直接对端地址（`RemoteAddr`），不读取 `X-Forwarded-For`。这不会盲目信任客户端伪造的转发头，但经过 Nginx 时，IP 维度限流会识别为代理地址，不能区分真实访客。当前未发现 Server 侧可信代理 CIDR/跳数配置；目标环境验收前需明确接受代理地址限流，或另行设计明确 allowlist 的可信代理方案。不得直接改为无条件信任 `X-Forwarded-For`。
