# Researchflow 研究流程与状态机设计

## 1. 职责

接收 ResearchRequest，选择版本化 Workflow Template，创建 Run/Stage/Attempt，按 DAG 调用 Quant/Research/LLM/Notification Ports，管理 deadline/并发/取消/重试/恢复，校验引用和结构化输出，综合并归档结果。

不实现指标算法、Event 规则、模型协议或通知渠道。Platform Task Runner 提供执行基础设施；Researchflow 管理研究 Run/Stage 领域状态。

## 2. 标准研究阶段

0 受理和范围解析；1 输入快照与质量门禁；2 市场环境；3 行业/主题；4 个股量化；5 事件研究；6 Context/假设；7 策略/情景验证；8 硬风险门禁；9 结果综合和校验；10 持久化与跟踪。

模板：market_review、industry_review、stock_research、event_research、strategy_evaluation、portfolio_simulation。模板声明 required/optional stages；裁剪阶段必须记录 skipped 和 reason_code。

## 3. 状态模型

Run：created → queued → running → succeeded/degraded/failed/cancelled/timed_out。

Stage：pending → ready → running → succeeded/degraded/skipped/failed/cancelled/timed_out。

Attempt 保存每次执行历史，重试不得覆盖。必需阶段失败默认 Run failed；可选阶段失败可 degraded；数据质量阻断不盲目重试；取消和超时传播 context cancellation；状态迁移校验前置状态并保持幂等。

## 4. DAG 与资源

DAG 必须无环。独立市场/行业/个股子分析可并行。每个 Run 设置总 deadline、阶段并发、模型调用和数据请求预算。重试有限且带退避，不允许 Adapter/业务层/Runner 多层叠加。缓存键包括 as_of、snapshot、复权、算法和质量版本。首期不建设可视化 DAG 编辑器或分布式工作流平台。

## 5. Context 和 Tool Policy

Research 定义 Context/Evidence 模型；Flow 负责按模板组装、排序、Token Budget 和裁剪。工具 Registry/Allowlist/Scope、参数 Schema、权限、预算、超时和幂等由 Flow 管理。模型返回的工具参数必须再次校验，LLM Adapter 不直接执行工具。

## 6. 结果综合

结果必须分层展示事实、Quant 数值、Research 证据/假设、LLM 辅助解释、unknown/degraded/limitations 和硬风险门禁。模型不得修改数值事实、引用或风险状态。

## 7. Persistence / Diagnostics / Integration

Researchflow 拥有 Run/Stage/Attempt/WorkflowResult Repository 和 Migration。Platform 提供连接池、事务和 Migration Runner。Flow 提供领域 Check，注册到 Platform Diagnostics。模块分支只提供 Application Facade；根 HTTP 路由、DI、Worker 启动和 OpenAPI 在集成批次处理。
