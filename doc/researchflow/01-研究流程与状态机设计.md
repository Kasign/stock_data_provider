# Researchflow 研究流程与状态机设计

## 1. 职责

接收 ResearchRequest，选择版本化 Workflow Template，创建 Run/Stage/Attempt，按 DAG 调用 Quant/Research/LLM/Notification Ports，管理 deadline/并发/取消/重试/恢复，校验引用和结构化输出，综合并归档结果。

不实现指标算法、Event 规则、模型协议或通知渠道。Platform Task Runner 提供执行基础设施；Researchflow 管理研究 Run/Stage 领域状态。

## 2. 标准研究阶段

0 受理和范围解析；1 输入快照与质量门禁；2 市场环境；3 行业/主题；4 个股量化；5 事件研究；6 Context/假设；7 策略/情景验证；8 硬风险门禁；9 结果综合和校验；10 持久化与跟踪。

模板：market_review、industry_review、stock_research、event_research、strategy_evaluation、portfolio_simulation。模板声明 required/optional stages；裁剪阶段必须记录 skipped 和 reason_code。

## 3. 状态模型与结果归并

本节最终规则以 [CONTRACT-006/007 最终决议](03-CONTRACT-006与007最终决议.md) 为准；旧版草案中与该决议不一致的迁移/重试规则不再适用。

- Run：created/queued/running/cancelling/succeeded/partial/failed/cancelled；不设置 Run.degraded/timed_out。partial 表示覆盖不完整，质量由 quality_status 单独表达。
- Stage：pending/ready/running/retry_wait/succeeded/degraded/skipped/failed/timed_out/cancelled/blocked。Attempt：running/succeeded/degraded/failed/timed_out/cancelled。retry_wait 是非终态；blocked 不创建 Attempt；skipped 只用于创建 Run 时的适用性裁剪。
- Template 版本固定 on_degraded、on_skipped、on_failed、on_timed_out、on_blocked 传播策略，以及 max_attempts、retryable_reason_codes、backoff_policy、attempt_timeout。仅白名单错误自动重试；Attempt 失败先进入 retry_wait，重试预算耗尽后才参与 Run 聚合。
- required Stage 的适用性在 CreateRun 前解析；不适用写入 excluded_stages，不创建 Stage。DAG 不得为空。
- 硬风险门禁由 Registry stage_code + gate_type=hard_risk 双重标识。Template 必须声明 requires_hard_risk_gate：可执行结论模板必须包含适用门禁；纯观察/研究模板 actionability_status=not_evaluated。门禁执行层失败/降级/跳过/阻断/超时导致 Run.failed；RiskDecision=reject/unknown 是有效业务结果但 actionability_status=blocked。只有 Run=succeeded 且所有适用硬门禁明确 pass 才可能 actionable。
- created/queued 无在途 Attempt 时可直接取消；running 取消进入 cancelling。deadline 使用数据库 UTC 时钟，db_now >= deadline_at 时 deadline 优先；未启动 Stage 标记 timed_out，在途 Attempt 停止或 fencing 后 timed_out。
- Run 终态必须保证所有 Stage 终结、无 running Attempt；最终归并通过事务和 Run.version CAS 固化。
- fencing 只保护本地状态写入；外部副作用必须具备下游幂等键，结果不确定且下游不支持幂等时禁止自动重发。

## 4. DAG 与资源预算

DAG 必须无环。市场、行业和个股等互不依赖的阶段可并行；依赖阶段只能在上游 Stage 终态且输出校验通过后进入 ready。Template 固定节点依赖、required/optional、适用性规则、优先级、传播策略和 retry_policy，并参与版本 fingerprint。

Executor 限制全局 Worker 数、全局排队容量、单 Run 并行 Stage 数和单 Attempt 执行时长。队列容量满时拒绝创建 Run，不建立无界内存队列或无限 goroutine。queued Run/Stage 必须持久化并支持重启恢复；就绪任务采用稳定排序。租约与 fencing 规则见 CONTRACT-007 最终决议。

## 5. Context 和 Tool Policy

Research 定义 Context/Evidence 模型；Flow 负责按模板组装、排序、Token Budget 和裁剪。工具 Registry/Allowlist/Scope、参数 Schema、权限、预算、超时和幂等由 Flow 管理。模型返回的工具参数必须再次校验，LLM Adapter 不直接执行工具。

## 6. 结果综合

结果必须分层展示事实、Quant 数值、Research 证据/假设、LLM 辅助解释、unknown/degraded/limitations 和硬风险门禁。模型不得修改数值事实、引用或风险状态。

## 7. Persistence / Diagnostics / Integration

Researchflow 拥有 Run/Stage/Attempt/WorkflowResult Repository 和 Migration。Platform 提供连接池、事务和 Migration Runner。Flow 提供领域 Check，注册到 Platform Diagnostics。模块分支只提供 Application Facade；根 HTTP 路由、DI、Worker 启动和 OpenAPI 在集成批次处理。
