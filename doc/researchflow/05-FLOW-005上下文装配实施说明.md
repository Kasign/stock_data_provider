# FLOW-005 上下文装配实施说明

## 1. 职责边界

Research 定义并持有 Context、Evidence 领域模型。Researchflow 不复制这些领域模型，也不访问 Research Repository；本模块只负责一次 Run 的分区选择、稳定排序、Token Budget、裁剪决策和模型上下文装配计划。

本阶段新增的 `contextassembly` 包只接受最小规划输入并返回分区 ID 计划，不承担 Research DTO 的序列化、证据查询、内容授权或模型 Tokenizer 实现。

## 2. 已冻结的规划规则

依据项目级《Quant-Research公开DTO字段级契约》：

1. Section 的优先级来自 Workflow Template，数值越小优先级越高；同优先级按 section_id 字典序排序，保证结果确定。
2. required Section 必须纳入；required Section 因预算无法纳入时，整个规划失败，不得静默裁剪。
3. 含有受保护 Evidence 的 Section 必须整体纳入。受保护 Evidence 由上游 Research/Template 规则显式标记，至少覆盖关键反证和风险限制；若预算不足，规划失败。
4. 其他可选 Section 按稳定优先级贪心纳入；放不下时输出 `budget_exceeded`，保留 section_id、source_owner、source_refs 和安全说明。
5. 所有候选 Section 都必须进入纳入或省略结果；不能静默消失。纳入、省略顺序均稳定。
6. Token 数由目标模型对应的 Tokenizer/Adapter 提供估算值；本包不自行按字符数猜测 Token。估算值必须非负，预算必须为正数。
7. 本包不修改 Research Context；上层负责把计划映射为 Context DTO，并通过 Research Application 创建不可变 Context 版本。

## 3. 当前实现范围

- 已实现纯函数 `BuildPlan`：校验 Section ID、来源、引用唯一性、受保护 Evidence 引用完整性和 Token 估算边界。
- required 与受保护 Evidence Section 作为强制纳入项；强制项超出预算时 fail closed。
- 可选 Section 按 priority/section_id 稳定排序并按 Token 估算贪心纳入。
- 省略项输出固定 reason_code=`budget_exceeded`、安全消息和来源引用。
- 当前尚未实现 Tool Policy、模型 Tokenizer、Research Facade Adapter、Context 持久化与真实模型调用。

## 4. 验收边界

- 定向测试：`go test ./internal/researchflow/contextassembly`
- 全模块测试仍需通过 P0 门禁：`go test ./internal/researchflow/...`、Race、Vet。
- 真实 Tokenizer 的估算准确性必须按目标模型单独验证；估算值未知时不得伪造精确 token 计数。
- 未经来源 Owner 当前授权的正文不得进入上下文；本包只处理引用和规划元数据，不持有正文。
- LLM 只返回结构化 Tool Call 意图，不执行工具；Tool Policy 作为 FLOW-005 后续切片实现。


## 5. Tool Policy 第一切片

新增 `internal/researchflow/toolpolicy`：

- Registry 只接受服务端注册的工具定义；名称唯一，参数 Schema、超时、单工具调用上限为必填。
- 每个工具声明所需 Scope；调用方本次授权 Scope 不完整时拒绝。
- 模型输出只作为 `Intent`；必须重新验证工具名、参数 JSON Schema、幂等键、总调用数、单工具调用数和累计超时预算。
- 授权结果带有调用 ID、幂等键、参数快照和受 Run Deadline/剩余预算裁剪后的调用时限。
- 本包不执行工具、不访问 Research Repository、不发起网络请求；真正执行仍需由 Researchflow Executor 在绑定 Run/Stage/Attempt 后完成二次校验与幂等控制。
- Schema 校验由调用方注入本地 Validator，避免复制 LLM 的 JSON Schema 实现，也禁止远程 Schema 资源加载。

定向测试：`go test ./internal/researchflow/toolpolicy`。本次 GitHub Actions 根模块仍被 Research 模块 gofmt 阻断，因此这些测试尚未取得 CI 执行证据。


## 6. LLM Tool Call 意图适配

新增 `toolpolicy/llm_adapter.go`：

- 只接收 LLM 已完成响应中的 Tool Call；响应不完整或调用状态非 completed 时拒绝。
- 校验 Call ID 唯一、工具名边界和参数 JSON 语法，将 LLM DTO 转换为本模块 Intent。
- 适配结果仍必须经过 `Registry.Authorize`；适配成功不代表获得权限，也不代表工具已执行。
- 不读取 LLM 的输出文本推断工具调用，不在 LLM Adapter 中执行工具。
- 定向测试：`go test ./internal/researchflow/toolpolicy`。


### Schema 校验实现复用

- `NewLLMRegistry` 默认复用 `internal/llm.ValidateJSONAgainstSchema`，采用已有 Draft 2020-12 实现、深度/载荷限制及禁用外部 Schema Loader 的安全策略。
- 不要求 Server 或调用方重复实现 JSON Schema Validator；测试替身仍可通过 `NewRegistry` 注入。


### 工具定义下发与 Schema 准入

- Registry 构造时先调用 Validator 校验工具参数 Schema；LLM 默认实现复用 Draft 2020-12 编译器和禁用外部资源加载策略。
- `ToolDefinitionsFor` 只向模型暴露当前 Scope 已授权且单工具/全局预算尚未耗尽的注册工具，名称稳定排序。
- 模型可见工具集只是提示边界，不是授权凭证；响应仍逐项调用 `Authorize`，再次验证 Scope、Schema、幂等键和预算。


### 模型上下文窗口预算计算

新增 `contextassembly.AvailableBudget`，先从模型上下文窗口扣除系统提示、工具 Schema、输出预留和安全余量，再将剩余输入预算交给 `BuildPlan`。

- 所有 token 数均由目标模型对应的 Tokenizer/Adapter 或模型配置提供；本函数不估算 token。
- 任一预留为负、模型窗口无效、预留超过窗口或扣除后没有剩余空间时均拒绝规划。
- 该函数只负责预算算术，不持有上下文正文，也不依赖 LLM Provider。
- 定向测试：`go test ./internal/researchflow/contextassembly`。


### 规划输入标识规范化约束

Section ID、Source Owner 和所有 Source/Evidence 引用必须是已规范化的不透明标识，不接受前后空白。避免同一资源因空白差异形成不同规划身份，或在映射 Research DTO 时被拒绝。


### Research Application Context DTO 适配切片

新增 `ToResearchCreateContextCommand`，把 Researchflow 的分区选择结果映射为 Research Application 的稳定 `CreateContextCommand`：

- Researchflow 提供候选分区及预算选择结果；Research 提供分区版本、质量状态、装配时间和 Context 级质量评估。
- 映射保留全部已评估 SectionRef，包括未纳入模型上下文的分区；included/omitted 仅表达本次模型装配选择。
- 映射前验证候选集合与 Plan 完整且互斥地分区、引用/Owner/Required 一致、预算账目合法。
- QualitySummary 的冲突数、陈旧数、状态和原因码原样保留；只校验缺失 required/optional 数与 Plan 一致，不从 token 裁剪推导数据质量。
- SystemAsOf 和 AssembledAt 必须为 UTC；分区版本和质量状态必须由 Research/上游适配器提供。
- 适配器不调用 Research、不创建 Context、不读取 Evidence 正文、不做授权；Server/Worker 后续负责将其输出交给 Research Application Port。
- 定向测试：`go test ./internal/researchflow/contextassembly`。


### 上下文装配流程组合

新增 `AssembleResearchContext`，按固定顺序组合：
1. 使用模型窗口和系统提示/工具 Schema/输出预留/安全余量计算可用输入预算；
2. 在可用预算内执行必选分区、受保护证据和可选分区选择；
3. 将完整 SectionRef、Included/Omitted 和 Research 质量评估映射为 Research Application CreateContextCommand。

调用方必须在进入本函数前通过所选模型 Tokenizer 生成每个 SectionCandidate.EstimatedTokens；本函数不接受字符数估算，也不将模型 usage 当作预估值。必选项超预算时 fail closed，不生成部分 Research Context 命令。


### Research 质量统计与预算裁剪解耦修正

Research 的 `MissingRequiredCount` / `MissingOptionalCount` 表示来源/上下文质量事实，不表示模型预算裁剪数量。Researchflow 的 `OmittedSections` 只记录本次上下文预算选择结果。DTO 适配器现仅校验并原样传递 Research 的质量状态、缺失/冲突/陈旧计数及原因码，不再根据 Plan 推导或覆盖缺失计数；预算裁剪独立保存在 `OmittedSections`。


### 模型 Tokenizer 接入端口

新增 `contextassembly.Tokenizer` 与 `EstimateSectionTokens`，要求按目标模型 ID 和 Tokenizer 版本调用真实 Tokenizer，并返回带 Tokenizer Provenance 的候选分区副本。

- 每个 Section 必须有已授权的正文输入；本函数只计数，不负责获取正文、授权或持久化。
- 输入候选与正文必须一一对应；缺失、重复、额外内容和非正数计数均拒绝。
- 原候选切片和引用数组不被修改；返回值不包含正文。
- 当前 `internal/llm` 只定义模型请求/响应与 Schema 校验，未提供模型 Tokenizer 实现。因此本提交只建立强制模型身份/版本校验的端口，不伪造字符计数实现；生产接入必须由具体模型 Provider/Tokenizer 实现该接口。
- 定向测试使用测试替身验证边界，不作为真实模型 Tokenizer 的准确性证据。


### 最终模型输入组合与精确预算复核

新增 `ComposeModelInput`，在完成来源授权和分区选择后，将研究问题、Scope、SubjectRefs、固定 SystemAsOf、分区版本、Owner、来源/Evidence 引用及已授权正文序列化为稳定 JSON 输入。

- 只允许 Plan.IncludedSections 对应的正文进入输入；缺失、重复或多余正文均拒绝，OmittedSections 的正文不会被序列化。
- 使用目标模型 Tokenizer 对最终完整 JSON 序列化结果重新计数，而不是把分区 Token 估算简单相加；最终序列化超过可用输入预算时 fail closed。
- 输入同时携带 Research 质量摘要、预算裁剪清单、分区版本/质量/装配时间和受保护 Evidence 引用；模型可见范围不包含被裁剪分区正文。返回结果仅在内存中携带输入正文，不持久化、不记录日志、不调用 LLM。
- 本方法与 Research Context DTO 投影共享同一 Plan 校验；Server 后续负责将 Text 映射到 `internal/llm.ModelRequest.InputText` 并发起模型请求。
- 定向测试：`go test ./internal/researchflow/contextassembly`。
