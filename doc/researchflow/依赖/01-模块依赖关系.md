# Researchflow 模块依赖关系

更新时间：2026-11-18  
维护分支：`feat/researchflow`

## 1. 依赖方向

Researchflow 是编排调用方，不是领域数据所有者。它通过公开 Application Port 消费领域能力，不访问其他模块 Repository，不通过 localhost HTTP 调用同进程模块。

| 模块 | 消费场景 | 必需输入/输出 | 责任边界与前置条件 |
|---|---|---|---|
| News | 搜索新闻候选、读取可授权证据 | 查询参数、候选/证据 DTO、来源授权语义 | News 拥有新闻事实、Provider 采集与来源可用时间 |
| Data | 获取行情、财务和主数据快照 | PIT 快照引用、版本、质量与来源 | Data 拥有字段口径、快照和数据质量；Researchflow 不重算或修正数据 |
| Research | 创建/读取 Context、Evidence、Claim | Research Application DTO、Owner 授权结果 | Research 拥有语义实体和资源授权；Researchflow 只装配单次 Run 上下文 |
| Quant | 获取版本化指标/策略/风险结果 | Quant Result Manifest、Envelope、Payload Schema | Quant 拥有计算、指标和 RiskDecision 语义；Researchflow 只校验并编排 |
| LLM | 结构化生成、解释、工具调用意图 | ModelRequest/Response、Usage、模型能力和 Tokenizer Provenance | LLM 拥有模型协议和 Provider；工具授权/执行仍由 Researchflow 控制 |
| Notification | 接收 Run 终态通知 | Outbox/Terminal Event、幂等事件引用 | 不作为同步 DAG Stage；渠道投递与重试由 Notification 管理 |
| Platform | 横向技术原语 | Fault、Diagnostics、HTTP Client、Storage、配置等 | 已有能力优先复用；不在 Researchflow 重建通用连接池/HTTP/诊断基础设施 |
| Server | 生产组合装配 | Facade/Adapter、Registry、Runtime 构造参数 | Server 负责 Bootstrap、根 Migration、生命周期和 HTTP 路由，不接管领域规则 |

## 2. 当前生产接入状态

- 已有正式生产 Stage：`news.search_candidates@1.0.0`，其真实 Provider/Runtime 证据以 Integration 验收记录为准。
- Data/Research/Quant/LLM 的领域 Stage 不得仅因接口想象或 WebUI 需求而注册。
- Context Assembly 当前有 Research DTO 投影，但生产 Owner 授权 Adapter 和真实 Research Facade 仍需证据。
- Result Composer 当前有 Quant Envelope/Research DTO/LLM Response 的组合校验逻辑；生产读取与授权必须由各 Owner Facade 执行。
- Notification 通过 Outbox 终态事件接入，不得将其变成 DAG 同步步骤。

## 3. 依赖准入原则

新增依赖必须先确认：
1. 被调用模块已有稳定公开 Application Port，且不依赖 Researchflow。
2. 调用场景属于真实研究任务，而非预想中的展示需求。
3. DTO 字段有明确 Owner、数据来源、语义、版本和时间口径。
4. 授权由资源 Owner 复核；AuthorizationRef 不当作 bearer token。
5. 错误和诊断可映射为 pass/degraded/fail/not_comparable，且 skipped 不冒充 available。
6. 同进程调用通过注入的强类型 Port；不新增重复 HTTP API/Repository。
