## 1. 模块目标与边界

Researchflow 是研究流程编排层，负责 Run/Stage/Attempt 生命周期、Workflow Template、DAG、调度、执行租约、重试、取消、Deadline、上下文装配、工具治理、结果综合与 Outbox。它通过 Data、News、Quant、Research、LLM 的公开 Application Port 编排研究，不接管各领域模块内部规则。

- Notification 不作为同步 DAG Stage；Run 终态通过 Outbox 事件连接 Notification。
- Platform 提供公共技术原语，不替代 Researchflow 状态机和业务编排。
- Server 是组合根，负责配置、Migration 总注册、Scheduler/Worker 生命周期和 HTTP 路由。
- 不为没有生产 Provider、真实调用方或冻结 Schema 的 Stage 创建占位 Registry Entry。
- 不为 WebUI 展示提前增加 API；当前不开放独立 Researchflow HTTP API。

## 4. 生产 Stage 范围

- 当前已确认在 Server Researchflow Runtime 装配的正式 Stage：`news.search_candidates@1.0.0`。
- News Search 的真实 Provider/Worker/MariaDB 证据以 Integration 对应验收记录为准。
- Data、Research、Quant、LLM 的生产 Stage Adapter 未全部闭环；没有真实 Application Port、冻结 Schema、Provider 和调用方时不得占位注册。
- Provider Outcome、Payload、QualitySummary 是 Stage Output Evidence；没有独立 Diagnostic Record 时 DiagnosticRefs 可以为空。
- 不从 Provider 的 published_at/published_date/observed_at 推导 News Evidence 的 available_at。

## 6. 安全与可靠性门禁

1. Run 的 system_as_of、输入快照、Template 版本在重试中不可改变。
2. CreateRun 幂等主体来自可信 RequestIdentity，不接受请求体自报 caller_ref。
3. Claim、Lease、Fencing、CAS 与 Finalization 以 MariaDB 事务为最终权威。
4. Worker 并发有界；全局容量不能只依赖进程内 WorkerPool。
5. required Stage 的失败、blocked、timeout 不得用 skipped/no_impact 掩盖；硬风险门禁不可被评分覆盖。
6. 失败 Attempt 保留历史；重试创建新 Attempt；过期 Worker 不得提交覆盖新结果。
7. Provider Outcome、Stage ReasonCode、Platform Diagnostic Record 分开建模。
8. Run 终态、ResultSummary 与 Outbox 保持原子提交。
9. 新字段必须记录 Owner、来源、语义和版本；新接口必须对应真实调用方。
10. 诊断判定必须明确 pass/degraded/fail/not_comparable；缺少比较基准时不得判为通过。
