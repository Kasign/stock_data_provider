# FLOW-006 结果综合与校验实施说明

## 1. 职责与边界

Researchflow 是跨模块结果综合的唯一编排者。Quant 拥有数值计算和 RiskDecision 语义；Research 拥有 Evidence/Claim/Context 语义；LLM 只提供辅助解释。Researchflow 不重算 Quant 指标、不改写 Research 证据、不让 LLM 覆盖事实或硬风险结论。

本阶段只实现 Quant 共同 Envelope 的通用校验与强类型 Payload Schema Registry 接口。由于项目契约尚未提供各 `result_type/schema_version` 的具体 Payload Schema，本模块不注册伪 Schema、不解析未知 Payload，也不将 `json.RawMessage` 转成任意 map。

## 2. Quant Result Envelope 校验

新增 `internal/researchflow/resultvalidation`：

- Registry 以 `result_type + schema_version` 精确注册 Payload Validator；同一键不允许覆盖。
- 未知 result_type 返回 `unsupported_result_type`；已知类型但未注册 schema 返回 `unsupported_schema`，不回退旧版本。
- 校验 Envelope 必填字段、范围、状态枚举、UTC 时间、Run.system_as_of 一致、参数指纹、输入快照引用和 AuthorizationRef。
- Payload 必须是 JSON object，并交由精确注册的强类型 Schema Validator 校验；未注册或 Schema 失败均拒绝。
- `completed` 仅表示计算完成；quality_status=invalid/unknown 或 result_status 非 completed 一律不可用。degraded 仅在 Template 明确 `AllowDegraded` 时可用。
- 纯函数空输入仅在 Template 显式 `AllowEmptyInputs` 时允许；不将普通缺少输入降级成可用结果。

当前只提供 Validator Port/Registry，不提供任何具体 Quant Payload Schema。具体注册必须由 Quant 契约/Schema Golden 提供依据。

## 3. RiskDecision 硬门禁

- RiskDecision.status 仅允许 pass/reject/unknown。
- 任一 severity=block 的 reason 为 triggered 或 unknown 时，status=pass 必须拒绝。
- reject/unknown 是有效业务结论，必须保留，不得由 LLM 评分、解释或建议覆盖。
- RiskDecision.system_as_of 必须与 Run.system_as_of 完全一致；时间和原因引用必须完整。
- 当前校验规则不提供任何 override 字段，也不根据模型解释推断风险状态。

## 4. 未实现范围

- Quant 每种 result_type/schema_version 的具体 Payload Schema 与 Golden。
- Quant Application Facade/Result Manifest 的真实读取及当前授权复核。
- Research Evidence/Claim Facade Adapter 和证据引用闭环。
- LLM 解释与事实/风险的最终 Result Composer。
- ResultSummary 持久化及 Run 终态事务（FLOW-007）。

## 5. 验收

- `go test ./internal/researchflow/resultvalidation`
- `go test ./internal/researchflow/...`
- 未注册 discriminator、未知版本、错误 Payload、时间错配、缺少输入、质量 degraded/unknown、Risk block triggered/unknown 等边界必须覆盖。
- 本阶段 Fixture 仅验证 Researchflow 自身的校验边界，不代表 Quant 真实 Schema/授权接入通过。
