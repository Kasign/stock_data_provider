# 数据质量与状态契约

更新日期：2026-10-30

## 1. 责任边界

- Go 行情数据层负责 Provider 调用、数据标准化、单位归一、来源/时间/质量元数据、缓存与降级。
- WebUI 负责请求状态、用户交互、数据展示和错误提示，不重复推测服务端数据质量。
- 分析服务负责分析任务、阶段事件和完整运行结果；浏览器只保存最近任务引用。

## 2. 数据质量状态

| 状态 | 含义 | 前端处理 |
|---|---|---|
| valid | 数据通过当前质量校验 | 正常展示 |
| degraded | 数据可用但存在缺失、覆盖或来源限制 | 展示并提示降级原因 |
| stale | 使用过期缓存/旧版本 | 显示数据时间和过期状态 |
| invalid | 数据不满足契约或校验失败 | 不作为有效事实使用 |
| unknown | 无法确认数据质量或空结果语义 | 显示未知，不转换为 0 |

请求状态（loading/empty/error）与数据质量状态必须分开。HTTP 200 不等于质量 valid。

## 3. 时间语义

统一区分以下时间，不得互相替代：

| 字段 | 语义 | 典型用途 |
|---|---|---|
| report_date | 财务报告期末、指数权重报告日等业务归属日期 | 标识数据描述哪个报告期/源端快照日，不代表当日已经公开 |
| provider_time | Provider 明确返回的源端生成/更新时间 | 判断源端快照新鲜度；不自动等于数据首次可用时间 |
| available_at | 该条数据首次可供市场参与者使用的时间，必须是带时区的精确时间戳 | 严格 PIT 的信息可用性边界 |
| fetched_at | 本服务收到 Provider 响应的时间 | 请求链路和数据采集审计 |
| normalized_at | 本服务完成字段映射、单位归一和质量处理的时间 | 标准化链路审计 |
| system_observed_at | 本服务将某个内容版本持久化记录的时间 | 重建系统在某一时刻实际掌握的版本 |

- 财务报告期末（report_date）不是公告时间（available_at）。不得因报告期已经结束，就在公告前使用该报告数据。
- 只有 publication_date 而没有具体时刻时，同一自然日内不能证明数据早于某个 as_of 时刻；严格 PIT 必须排除该分区。只有明确 available_at 且 available_at 不晚于 as_of 时，才允许在同一天内使用。
- provider_time 只描述源端快照/生成时间；除非供应商契约明确证明它就是首次公开时间，否则不能代替 available_at。
- fetched_at 和 normalized_at 是服务端时间，不能回填或冒充源端发布时间。
- system_observed_at 只证明本系统何时记录该版本；它不能单独证明数据当时已对市场公开。严格 PIT 同时检查数据可用时间和系统观察时间。
- 缺少精确源端时间时应保留 degraded/unknown，不得推断为 valid。

## 4. 数值与单位

- 股票价格：CNY/股。
- 成交量：股。
- 成交额：CNY。
- 百分比字段：百分点；1.25 表示 1.25%，不是 0.0125。
- 资金流字段必须使用明确的资金流定义，不得用成交额代替净流入。
- 指数成交额若 Provider 未提供可验证单位，应保留 provider_defined，不得擅自归一为 CNY。

## 5. 空数据语义

- 空列表可能表示源端未提供、Provider 暂不可用、日期未发布或覆盖未确认。
- 只有 Provider 明确证明覆盖完整时，才能将空结果解释为“无事件/数量为零”。
- unknown、null、缺失字段不得默认为 0、正常、未停牌或没有风险。

## 6. 历史与复权

- 请求复权参数：none、forward_adjusted、backward_adjusted。
- unknown 仅为响应状态，不是请求参数。
- 日 K 的 as_of 是系统观察时间点，只能读取本地记录的历史版本；不能实时回源后冒充历史。
- 复权数据必须保留 adjustment_basis、adjustment_method、adjustment_reference_date 和源端版本；不得混合不同复权基准。
- 复权因子后续修订不得覆盖历史观察版本；回看历史时必须能识别当时使用的因子版本。当前因子历史持久化与公司行动事件链仍需继续补齐，不能仅凭复权后的价格序列宣称公司行动 PIT 完整。
- 指数成分历史查询返回的 provider_report_date 是源端权重报告日期，不是成员关系的 effective_from/effective_to。若 Provider 未提供有效区间，不得将月度报告日推断成完整的成分生效区间；响应应保留 degraded 和明确原因。
- 财务 PIT 按分区的 available_at 过滤；只有 publication_date 时，严格排除与 as_of 同日的分区。历史修订按 system_observed_at 选择当时已记录的版本。
- 研究结论应保留参考时点、行情快照标识、数据质量和适用周期。

## 7. 错误与并发

- 统一错误信封：error.code、error.message，可包含 request_id。
- 前端保留 HTTP 状态、错误码和请求 ID，错误摘要限长。
- 搜索、行情和任务等异步请求应取消旧请求或使用 generation guard，避免迟到响应覆盖新上下文。
- 部分失败必须保留逐项状态，不能将部分成功伪装为整体成功。

## 8. 权威文件

- 行情 API：services/market-data/openapi.yaml。
- 行情路由：services/market-data/internal/httpapi/server.go。
- WebUI API 客户端：web/src/api.js。
- 数据层能力清单：GET /api/v1/data-sources。
- Provider 运行诊断：GET /api/v1/data-sources/diagnostics，当前只覆盖 quote/daily_bars 的进程内熔断器观测。
