# 开发、部署与本地运行说明

更新日期：2026-11-19

## 1. 仓库运行边界

- `web/`：原生 HTML/CSS/JavaScript ES Modules WebUI。
- `internal/server/`：唯一外部 HTTP 入口与组合根。
- `internal/marketdata/`：Root Server 同进程 Data 模块，复用 Root 的 MariaDB、Redis 和受控出站能力。
- News、Research、Researchflow、Quant、LLM、Notification 等模块由 Root Server 按各自契约装配。
- 生产 Compose 仅运行 `stock-analysis-server` 和 `stock-analysis-web`；不部署独立 Data HTTP 服务。

## 2. WebUI 本地开发

进入 `web/` 后查看 `package.json` 的 scripts。WebUI 只访问同源 Root API：

- Data、Owner Session、Root readiness：`/api/**`。
- Root liveness：`/healthz`。
- 不配置独立行情/分析 Base URL；浏览器设置中的旧路径会被规范化为 Root 同源入口。
- 浏览器不保存或发送 Data API Key / `X-API-Key`，也不持有 Owner Bearer 或第三方 Provider 凭据。

本地开发若未启用 Owner Session，受保护业务接口将按 Server 认证策略拒绝请求；不得通过关闭认证或注入静态 Owner Bearer 绕过。

## 3. 生产部署

以仓库根目录 `docker-compose.yml`、`.env.example` 和当前契约为准。

1. 复制 `.env.example` 为 `.env`，填入真实数据库、Redis、Platform Owner Bearer 运维凭据和 Provider 配置。不要覆盖目标环境已有 `.env`，应先备份并逐项核对后再合并。
2. 设置 `OWNER_SESSION_PUBLIC_ORIGIN` 为 WebUI 对外的精确 HTTPS Origin（不带路径、无尾斜杠）。
3. 在目标部署主机完成 Argon2id 基准测试，再填写 `OWNER_SESSION_ARGON2_MEMORY_KIB`、`OWNER_SESSION_ARGON2_ITERATIONS`、`OWNER_SESSION_ARGON2_PARALLELISM`。Compose 会拒绝缺少这些值的启动配置。
4. 校验配置：`docker compose --env-file .env config`。
5. 部署：`docker compose --env-file .env up -d --build`。

Compose 强制启用 Owner Session；Cookie 固定 HttpOnly、Secure、SameSite=Lax、无 Domain、Path=/api。不要在未填写 Origin 和 Argon2id 基准参数时启动生产部署。

## 4. API 路由与认证

- Nginx 的唯一业务 upstream 是 `stock-analysis-server:8092`，`/api/` 原样转发，不做路径改写。
- WebUI 使用 HttpOnly Owner Session Cookie；CSRF Token 只保存在页面运行时内存，所有非安全 Session 请求发送 `X-CSRF-Token`。
- Server Data 路由显式允许 `owner_session` 和 `owner_bearer`；Owner Bearer 仅供受控运维调用，不下发浏览器。
- `POST /api/v1/data-sources/probe` 必须通过 Session Origin/Host 与 CSRF 原子校验。
- `GET /api/readyz` 是浏览器只读就绪视图；Root 原始 `/readyz` 与 `/diagnostics` 仍为 Owner Bearer 运维路由。
- Data 领域资源授权仍由 Data 自身按 DATA-CTR-008 执行；Owner Session 不等于领域授权通过。

## 5. 部署边界

- 不存在独立 Data 服务、Data API Key、`/market-api/` upstream 或 `/analysis-api/` upstream。
- 不保留旧服务、旧 Key 兼容层或双轨回滚部署资产。
- 旧 Data HTTP 认证契约 DATA-CTR-006 已退役；唯一认证权威是 SRV-CTR-002 1.1.0。
- Provider 凭据属于服务端配置，不得与已退役的浏览器 Data API Key 混淆。

## 6. 运行与验收

完整浏览器验收以 `doc/WebUI提测验收清单.md` 为准。自动化测试、HTTP 健康检查、Provider 能力声明和真实 Provider 数据验收是不同证据；不得用其中一项替代其他项。
