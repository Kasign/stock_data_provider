## 2. 规划结论

Research 的目标仍是可追溯、遵守 PIT 的研究领域语义能力。当前主要缺口不是继续扩展基础领域模型，而是完成消费者契约、真实证据验证和系统组合边界验收。

整体分为四阶段：

1. **消费边界收敛**：RSC-001 Context 消费契约优先；RSC-008 只有在 Researchflow 提供真实 Facade/调用点后才进入。
2. **领域证据闭环**：RSC-003 Event 来源时间/派生链验证；RSC-005 Claim/Hypothesis Scope 和真实样本。冻结契约与 Fixture 可支撑规则级测试，但不能替代真实来源验收。
3. **外部依赖解锁**：RSC-002 保持 SHELVED，等待 News available_at 和授权/精确版本读取证据；RSC-004 保持 BLOCKED，等待 Data 的稳定实体引用和公开 Port；RSC-006 等待 Quant Registry/ResultRef 与 Researchflow 真实消费者。
4. **系统组合验收**：Root DI、根 Migration、Outbox Relay、Worker 生命周期和生产调用链由 Server/Integration 及对应模块 Owner 负责；Research 只验收本模块 Port/Adapter/领域行为，不重复建设其他模块能力。

## 5. 规划门禁

- 一个时间点只允许一个 Research 当前执行任务。
- 任务进入执行前必须确认真实调用方、冻结契约、代码现状和失败语义；已有能力只补缺口。
- 不因等待外部 Owner 而在 Research 内复制 Data、News、Quant、Researchflow、Platform 或 Server 能力。
- Fixture/Mock 只支持规则级和模块级测试；生产真实数据验收需记录来源、版本、时间、样本及精确 SHA/CI。
- 每项诊断必须明确 pass、degraded、fail、not_comparable；不可比较不得折算为通过。
- 新接口/字段必须有真实调用场景、权威来源、语义、PIT/版本规则和 Schema/Golden 影响；否则不增加。
- RSC-007 的模块级 DONE 与 Server Migration/Relay/Worker 的系统级验收分开记录。
