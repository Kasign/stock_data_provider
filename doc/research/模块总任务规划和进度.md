## 1. 模块目标与边界

Research 负责 A 股研究领域中的 Context、Evidence、Event、Claim、Hypothesis、Scenario 等语义模型，确保事实、推断、假设分离，所有引用可追溯，并遵守 Point-in-Time（PIT）约束。

- Data 是证券主数据、行情、财务、估值、交易日历和数据质量的权威来源。
- News 是新闻采集、原文、身份、版本、授权与只读证据查询的权威来源。
- Quant 负责确定性数值计算及版本化结果。
- Researchflow 负责 Run/Stage/Attempt、上下文装配、预算、阶段编排和最终结果。
- Platform 提供通用 Fault、Storage、Diagnostics 等技术原语。
- Server 是组合根，负责共享资源、依赖注入、Migration 总注册、路由和 Worker 生命周期。

Research 不采集新闻、不拥有行情事实、不重算 Quant 指标；不直接依赖 Quant 或 Researchflow 私有包，不访问其他模块的私有 Repository/SQL/Domain。跨模块输入必须经冻结契约和公开 Application Port/Adapter。

## 4. 关键规则

1. Evidence 必须有来源、版本、授权引用、内容指纹和可比较的 PIT 时间；缺少 available_at 时不得作为有效 PIT 事实。
2. 不得使用 published_at、observed_at 或抓取时间推导 available_at。
3. 授权引用不是 Bearer Token；读取时必须由 Owner 复核当前授权。
4. 严格 PIT 校验失败或不可比较时，不得把证据纳入有效事实集合。
5. Claim/Hypothesis 的支持与反证必须分组校验，不得把引用存在等同于论证成立。
6. Scenario 只表达情景条件和预期，不代替 Quant 计算或 Researchflow 编排。
7. Outbox 与业务写入保持事务边界；通知投递状态由 Notification 拥有。
8. 模块状态必须区分代码实现、模块测试、精确 SHA CI、消费者契约验收和真实生产数据验收。

### 7.3 不进入 Research 分支的工作

- Server 负责 Root Bootstrap、共享资源、依赖注入、根 Migration Registry、Relay/Worker 生命周期和 HTTP 路由；Research 只提供公开 Application Port、Adapter/Repository 构造入口及领域规则。
- Platform 负责 Fault、Storage、Diagnostics Runner、通用授权/运行原语；Research 只提供领域 Check，不复制 Runner、存储连接池或通用授权框架。
- News 负责 available_at 来源证据、新闻版本、当前授权与精确内容读取一致性；Research 不推断 available_at，不改写 News 事实。
- Data 负责 Security/Industry 主数据及 DATA-CTR-007；Research 不自建证券/行业主数据。
- Quant 负责 Metric Registry、数值计算和 Evaluation 结果；Research 不重算指标、不定义 Quant 私有结果结构。
- Researchflow 负责 Run/Stage/Attempt、Context Assembly、预算、流程重试和跨模块调用；Research 不新增流程状态或 Token Budget 字段。

### 7.4 新增接口与字段准入

任何后续新增接口必须先提供真实调用方、调用链和失败处理；新增字段必须登记权威来源、业务语义、PIT/版本语义及 Schema/Golden 影响。每项诊断必须定义通过、降级、失败、不可比较四种结果。真实数据验收必须记录来源、版本、时间、样本和精确 SHA/CI；Mock、Fixture、代码存在或单纯 Go CI 通过不得升级为真实数据 PASS。
