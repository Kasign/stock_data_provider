# Research 研究领域模型与证据体系

## 1. 目标与边界

Research 将 Data/News 提供的可追溯输入组织为事实、证据、事件、假设和情景。它不采集新闻、不拥有行情事实、不重算 Quant 指标、不依赖 Researchflow。

唯一职责边界：

- Research 拥有 Context 的研究语义、证据集合、分区完整性和质量摘要。
- Researchflow 拥有一次 Run 的 Context Assembly、分区选择、排序、Token Budget、裁剪和执行状态。
- Data/News 是各自事实、版本、来源和授权的权威所有者。
- Quant 拥有数值计算、概率分布和评估结果；Research 不直接依赖或调用 Quant。按 RSC-DEC-001，Quant 结果由 Researchflow 通过公开 Port 获取并完成当前授权复核，再将已授权 DTO 或不透明引用传入 Research。Research 不自行解引用。
- Platform 提供通用诊断执行原语，不接管 Research 领域质量规则。

## 2. Context

ResearchContext 是特定研究问题、研究范围和系统知识截止时间下的版本化语义快照。跨模块字段基线以 `doc/整体任务规划/Quant-Research公开DTO字段级契约.md` 第 3.1 节为准。

### 2.1 字段及数据来源

| JSON 字段 | 数据来源 | 语义与约束 |
|---|---|---|
| schema_version | Research DTO 版本 | SemVer；消费者只解析明确支持的版本 |
| context_id | Research ID 生成器 | 不透明 Context 标识 |
| context_version | Research 版本管理 | 从 1 开始单调递增；已发布版本不可原地修改 |
| research_question | 可信调用方的研究请求 | 具体研究问题，不得用自由模型输出覆盖原始问题 |
| scope | 可信调用方的研究请求 | market/industry/stock/event，明确研究对象范围 |
| subject_refs | 调用方及已验证实体引用 | 证券/行业/Event 不透明引用；允许空数组但不允许 nil/空字符串元素 |
| system_as_of | Researchflow CreateRun 产生并传递 | 本次 Run 唯一知识截止时间；Research 原样保留并校验，不自行刷新 |
| section_refs | Research 领域评估结果 | 本次评估的全部分区及其版本、来源、Evidence、质量和时间引用 |
| quality_summary | Research 对自身 Context/Evidence 完整性的归纳 | 不覆盖 Data Probe、News 业务质量或 Platform Diagnostics |
| included_sections | section_refs 中 included=true 的 section_id | 必须与 section_refs 精确一致 |
| omitted_sections | section_refs 中 included=false 的分区及原因 | 必须与 section_refs 精确一致；每个省略项提供唯一 reason_code |
| builder_version | Research 构建规则版本 | 用于解释语义构建版本，不等同于 Run/Stage 版本 |
| created_at | Research 创建记录时的系统时间 | Context 记录创建时间，不替代 system_as_of |

### 2.2 ContextSectionRef

字段依据项目级 DTO 文档第 9.1 节。

| JSON 字段 | 数据来源 | 语义 |
|---|---|---|
| section_id | Research Section Registry | 稳定分区编码；同一 Context 唯一 |
| section_version | 分区生产方 | 分区内容版本/指纹；同一 section_id 当前版本只能出现一次，除非明确为对比研究 |
| source_owner | 分区权威生产方 | data/quant/research/news；Quant 引用遵循 RSC-DEC-001 |
| source_refs | 分区权威生产方 | 来源对象引用；仅纯 Research 派生分区可为空 |
| evidence_refs | Research Evidence Registry | 分区内 Evidence 引用；无 Evidence 时为空数组 |
| quality_status | 分区生产方质量结果 | valid/degraded/invalid/unknown |
| required | Researchflow Template/调用场景 | 本次研究是否要求该分区；Research 不负责 Stage 阻断策略 |
| included | Research 评估结果 | 是否实际纳入 Context |
| assembled_at | 分区装配时的系统时钟 | 本次分区装配时间 |
| system_as_of | Researchflow Run | 必须与 Context.system_as_of 完全一致 |

### 2.3 OmittedSection

字段依据项目级 DTO 文档第 9.2 节。

| JSON 字段 | 数据来源 | 语义 |
|---|---|---|
| section_id | 对应 ContextSectionRef | 被省略分区编码 |
| source_owner | 对应 ContextSectionRef | 来源模块 |
| reason_code | Research/分区评估结果 | not_requested/budget_exceeded/unavailable/unauthorized/quality_rejected/failed/duplicate |
| required | 对应 ContextSectionRef | 是否为本次研究必需分区 |
| source_refs | 对应 ContextSectionRef | 已知来源引用；允许空数组 |
| safe_message | Research 安全错误映射 | 可对调用方展示的安全摘要，不包含敏感原文或凭据 |
| retryable | 来源/装配操作结果 | 仅说明技术上是否可重试；不替代 Researchflow 的重试预算、deadline 和幂等策略 |

### 2.4 QualitySummary

字段固定为：

- status：valid/degraded/invalid/unknown。
- missing_required_count：被省略的必需分区数。
- missing_optional_count：被省略的可选分区数。
- conflict_count：Research 自身发现的证据/分区冲突数。
- stale_count：Research 自身发现的过期分区/证据数。
- reason_codes：去重并按字典序排序的稳定原因码。

计数必须为非负整数。QualitySummary 只描述 Research 自身 Context/Evidence 完整性，不替代 Data、News 或 Platform 的质量状态。

### 2.5 Context 不变量和职责边界

1. context_version 从 1 开始单调递增；重新装配、增删分区或改变证据集合必须生成新版本。
2. section_refs 包含本次评估的全部分区；section_id 唯一，source_refs/evidence_refs 使用非 null 数组。
3. included_sections 必须恰好等于 included=true 的 section_id 集合；omitted_sections 必须恰好对应 included=false 的分区。
4. omitted_sections 不得重复或遗漏；每个省略项必须与 section_refs 中的 source_owner、required、source_refs 一致，并提供 reason_code。
5. included_sections 和 omitted_sections 按 Template 稳定优先级排序；同优先级按 section_id 升序。Research Domain 不自行决定 Token Budget。
6. 任一 required section 被 omitted，Context 不得标记为 valid；是否阻断 Run 由 Researchflow Template 的 Stage 传播策略决定。
7. Research 只保存稳定引用和质量语义，不复制 News 原文，不自行签发 Data/News/Quant 的授权。
8. Research 不增加 Token 数量、Run/Stage/Attempt、裁剪策略字段；这些属于 Researchflow。
9. Research 不因本地 Fixture 验收而宣称真实 Data/News 接入通过。

### 2.6 Context 诊断判定

| 结果 | 判定标准 |
|---|---|
| 通过 | 结构合法；quality_summary.status=valid；必需分区齐全；分区与 Context 的 system_as_of 一致；引用版本可验证 |
| 降级 | status=degraded；可选分区缺失或质量受限且原因明确；不得把必需分区缺失标 valid |
| 失败 | 结构非法、分区引用不一致、必需分区缺失却标 valid、status=invalid，或已确认的 system_as_of 冲突 |
| 不可比较 | status=unknown、权威 system_as_of 缺失、引用版本/时间精度无法比较，或上游缺少必要验证证据 |

当前代码实现结构校验和 system_as_of 一致性校验；尚未验证远端引用、授权状态、真实来源版本及完整质量聚合。

## 3. Evidence

Evidence 遵循项目级 `RSC-CTR-001` Schema/Golden：

- `doc/整体任务规划/schema/RSC-CTR-001-evidence-1.0.0.schema.json`
- `doc/整体任务规划/golden/RSC-CTR-001-evidence.golden.json`

RSC-CTR-001 是 Evidence 契约，不是 Context 契约。Go DTO、序列化、指纹和校验必须以 Schema/Golden 为准。

关键字段语义：

| 字段 | 来源 | 语义 |
|---|---|---|
| evidence_id | Research | Evidence 不透明标识 |
| evidence_type | Research 领域分类 | fact/reported_fact/inference/hypothesis/unknown |
| source_owner | 上游模块归属 | data/news/quant/research |
| source_ref / source_version / source_locator | 来源 Owner | 稳定来源、版本和定位引用；不代表授权正文可读 |
| derived_from_refs | 上游 Evidence / Research 派生过程 | 派生链；inference/hypothesis 至少有一个来源引用 |
| claim_ref / subject_refs | Research 或上游稳定身份引用 | 关联主张和研究对象 |
| published_at | 来源声明 | 来源发布时间；不代表系统何时知道 |
| available_at | 可验证的来源可获得性证据 | 无证据时为 null；禁止从 published_at 或 system_observed_at 推算 |
| system_observed_at | 系统采集/观察记录 | 系统实际观察时间 |
| valid_time_start/end | 来源事实的业务有效时间证据 | 成对出现；不能用系统观察时间替代 |
| system_as_of | 研究调用的权威知识截止时间 | PIT 系统时间轴 |
| stance | Research 对 Claim 的关系 | supports/contradicts/neutral |
| confidence + method/version | 有版本的评估方法 | 有数值置信度时必须同时提供方法及版本；不得由 LLM 无依据赋值 |
| quality_status | 上游质量证据和 Research 规则 | valid/degraded/invalid/unknown |
| content_level | 上游授权结果 | metadata/summary/snippet/full；Research 不自行提升内容级别 |
| authorization_ref | 来源 Owner 授权决策快照 | 不可变授权引用；读取内容时仍须复核当前授权 |
| limitations | 来源限制及研究限制 | 保留内容、时间、用途和解释限制 |
| content_fingerprint | 规范化契约输入 | 按 RSC-CTR-001 的 JCS/SHA-256 规则计算 |

Evidence 规则：

1. 原文和授权归 News 或原始事实 Owner；Research 保存稳定引用、指纹和获准的最小内容。
2. News → Research 只读 Facade、历史知识时间过滤、稳定分页快照和不可变授权决策未完成时，只能用 Fixture 做领域测试，不得宣称真实新闻证据接入通过。
3. 授权未知、撤销或无法复核时，不得把历史授权引用当作当前内容读取许可。
4. 严格 PIT 模式下，available_at 为 null/unknown 或晚于 system_as_of 的证据不得作为该时点已公开可得的事实参与研究。
5. 指纹只证明规范化输入一致，不证明来源事实真实。

## 4. Event

Event 是跨多条新闻/公告的同一现实事件，不是 Article 别名。记录事件类型、版本、发生/公开/可用/观察时间、实体关联、来源 Evidence、重复簇、生命周期、影响假设、预期时效、不确定性、反向证据和价格验证引用。

生命周期：detected → consolidating → active → materializing → fading → invalidated/closed。事件创建、归并、拆分和状态变化必须追加版本；历史版本不得覆盖。

研究顺序：事实确认 → 多来源归并 → 实体关联 → 影响路径假设 → 时效/失效条件 → 价格/行业表现验证 → 历史样本比较。价格上涨不能反向证明新闻事实正确。

## 5. Claim / Hypothesis

Claim 是可被证据支持或反驳的陈述；Hypothesis 是带验证方法的研究假设。必须记录范围、system_as_of、支持/反证、required_data_refs、validation method、expected observation、invalidation condition、状态、版本和限制。无验证与失效条件的“看好/利好”不构成合格假设。

## 6. Scenario

Scenario 是条件化未来路径，不是单一目标价。记录基准时点、周期、触发条件、正反证据、预期路径、风险、失效条件、历史样本和 Quant 概率分布引用。数值概率由 Quant 计算；Research 不直接调用 Quant，引用路径遵循 RSC-DEC-001。样本不足时返回 qualitative/unknown。

## 7. 事实类型

- fact：有可验证来源和时间的事实。
- reported_fact：来源声称但未独立核验。
- inference：基于事实推导的解释。
- hypothesis：等待验证的研究假设。
- unknown：证据不足，不能判断。

禁止将 inference 静默升级为 fact；历史 Run 必须引用当时的 Event/Evidence 版本。
