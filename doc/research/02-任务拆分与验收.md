## 2. RSC-001 Context 第一批实现

### 2.1 字段来源和语义

字段依据项目级 `03-模块接口契约/Quant-Research公开DTO字段级契约.md` 第 3.1、9.1、9.2、9.8 节。

| 字段 | 数据来源 | 语义 |
|---|---|---|
| schema_version | Research DTO 版本 | SemVer |
| context_id | Research ID 生成器 | 不透明 Context 标识 |
| context_version | Research 版本管理 | 从 1 开始单调递增；不可原地覆盖 |
| research_question | 可信调用方 | 研究问题 |
| scope | 可信调用方 | market/industry/stock/event |
| subject_refs | 调用方及已验证实体引用 | 证券/行业/Event 引用 |
| system_as_of | Researchflow CreateRun | Run 唯一系统知识截止时间 |
| section_refs | Research 分区评估结果 | 全部分区及版本、来源、Evidence、质量和时间 |
| quality_summary | Research 领域质量归纳 | 仅描述 Context/Evidence 完整性 |
| included_sections | section_refs | 必须等于 included=true 的 section_id 集合 |
| omitted_sections | section_refs + 省略原因 | 必须等于 included=false 的分区及原因 |
| builder_version | Research | 语义构建规则版本 |
| created_at | Research 创建记录时钟 | 创建时间，不替代 system_as_of |

### 2.2 必须满足的不变量

- context_version 从 1 开始单调递增；重新装配或改变证据集合必须产生新版本。
- section_refs 内 section_id 唯一；source_refs/evidence_refs 使用非 null 数组，引用不得重复。
- 非 Research 自身派生分区必须有 source_refs；纯 Research 派生分区可为空。
- section_refs 中每个 system_as_of 必须与 Context.system_as_of 完全一致。
- included_sections 必须精确等于 included=true 的 section_id；omitted_sections 必须精确对应 included=false 的分区。
- 每个 omitted section 必须具有稳定 reason_code、required、source_refs、safe_message、retryable。
- QualitySummary 计数为非负整数，reason_codes 去重并按字典序排序；missing_required/optional_count 必须与 omitted_sections 对应。
- required=true 的分区被省略时 Context 不得标 valid；是否阻断 Run 由 Researchflow Template 决定。

### 2.11 RSC-007 Research Storage 第一阶段

调用场景和边界：

- Context Repository：Context Assembly 完成后追加不可变版本；Researchflow 历史 Run 回放时按 context_id/context_version 读取精确快照。
- Evidence Repository：来源 Adapter 完成结构/指纹/授权上下文校验后写入；按 evidence_id 读取。RSC-CTR-001 没有 Research-owned evidence_version 字段，因此当前按 evidence_id 不可变存储；相同 ID/相同 content_fingerprint 可幂等，冲突内容拒绝。不得自动生成替代 ID；语义变化如何形成新版本仍待项目契约明确。
- Event Repository：多来源归并/状态变化后追加 event_id/event_version；按精确版本回放。
- Claim Repository：研究主张/假设修订后追加 claim_id/claim_version；按精确版本回放。
- 不新增 List/Search API；当前没有已冻结的调用场景和过滤契约。
- Migration namespace 固定为 research，首版 Version=1；SQL 由 Research 拥有，执行必须由组合根显式调用 Platform ApplyMigrations，不在包初始化或 Repository 构造时自动执行。
- payload_sha256 是存储层对完整 JSON payload 的传输/幂等校验摘要，不是 Research 领域字段，也不替代 Evidence.content_fingerprint。
- system_as_of、system_observed_at、available_at 使用固定 30 字符 UTC RFC3339Nano（9 位小数）字符串并以 ascii_bin 排序，避免 MariaDB DATETIME(6) 截断 PIT 纳秒精度；Migration v2 将 v1 的 DATETIME(6) 历史值迁移为 6 位微秒 + 3 位零纳秒。created_at/updated_at 仍用 DATETIME(6)，由应用时钟提供，不参与 PIT 判定。
- 当前 Migration 不包含 Outbox 表：changed_at 的 INT-CTR-001 DTO 映射仍是 RSC-OPEN-002，待契约统一后再定义 Outbox payload/唯一键和重试字段。

当前只完成 Port 与 Schema 清单；Context/Event/Claim SQL Adapter、事务内版本追加、完整 payload 幂等、并发冲突和真实 MariaDB 故障恢复尚未实现/验收。Evidence SQL Adapter 暂缓，见 RSC-OPEN-007。

## 4. 跨模块边界决议与待决项

### RSC-DEC-001：Quant 来源引用不等于 Research 直接依赖 Quant

Quant-Research DTO 允许 Evidence.source_owner=quant 和 Scenario.quant_evaluation_ref，但项目级依赖 DAG 明确 Research 不直接依赖 Quant。Quant 结果如需进入 Research，由 Researchflow 通过公开 Quant Port 获取并完成调用主体、资源归属和当前 AuthorizationRef 复核，再把已授权的强类型 DTO 或不透明引用传入 Research。Research 仅保留引用及来源授权元数据，不直接读取 Quant Repository/Domain，不把历史 allowed 当作持续读取许可。

### RSC-DEC-002：Lifecycle changed_at 的事务时间语义

项目级《五模块跨模块实现前置契约复核与合并清单》已确定 changed_at 为 Event 生命周期状态迁移提交时间，必须与 Event 新版本及 Outbox 在同一领域事务内固化，Outbox 重试不得刷新。changed_at 不是 occurred_at 或 system_observed_at。

当前 Research Domain 只提供 LifecycleTransition 负载构造和校验，尚未实现事务和 Outbox。

### RSC-OPEN-002：ResearchEvent.changed_at 与 INT-CTR-001 DTO 映射缺口

Quant-Research DTO 第 3.3 节没有 changed_at 字段，而 INT-CTR-001 的 lifecycle_changed 事件要求 changed_at。项目级 Review 已明确其语义，但 DTO/Outbox 的具体映射字段仍须在项目契约中统一；Research 不得把 occurred_at 或 system_observed_at 冒充 changed_at。此项只阻断 lifecycle_changed 通知生产映射，不阻断 Event Domain 单测。

## 5. 验收门禁

- Evidence 必须遵循 RSC-CTR-001 Schema/Golden；不得把该契约误称为 Context 契约。
- Context DTO 字段依据项目级 Quant/Research 字段契约；当前没有 Context 专属冻结 Schema/Golden，内部模型不得提前作为 frozen 公共契约。
- News 只读查询、system_as_of 历史知识过滤、授权决策快照和稳定分页未完成时，Research 只能使用 Fixture 做领域测试。
- Research 不复制 News 原文、不自行判断来源授权、不把来源当前授权等同于历史授权。
- Event 合并/拆分和生命周期变化必须可回溯。
- 实体关联不能仅凭 LLM 自由生成。
- Hypothesis 必须可验证、可证伪。
- Scenario 概率引用 Quant；无样本时为 unknown/qualitative。
- Research 不建设 Run/Stage/Attempt 状态机，不重复 Platform Diagnostics Runner。
- 不修改 News 原文表和根 Migration 注册入口。


### 2.8 RSC-001 Context 版本追加校验补充

本轮在 `internal/research/context/validate.go` 增加 `Context.ValidateNextVersion(previous)`，用于 Repository 追加写入前检查：
- previous 与 next 均须先通过完整 Context 结构校验；
- context_id 必须保持一致；
- context_version 必须恰好递增 1，拒绝跳号和覆盖；
- system_as_of 与 created_at 均不得倒退。

该方法不执行并发 CAS、不生成 ID、不保存 Context，也不查询 section/source/evidence 的远端版本与授权。持久化追加、幂等键和并发冲突处理仍需等 Repository/Storage 集成契约落地。本轮新增测试尚未执行，不据此标记 RSC-001 通过。


### 2.9 RSC-002 固定过期时间本地门禁

依据 GOV-CTR-006 第 4 节，新增 `ValidateEvidenceAuthorizationBindingAt`，先执行已有快照指纹及可信主体/资源/用途/Owner/内容级别绑定，再以调用方提供的可信 UTC 时点检查 `expires_at`。边界严格为 `now >= expires_at` 时拒绝；`expires_at=null` 仅表示无固定过期时间。

该方法只覆盖固定过期时间，不代表 Owner 当前策略仍允许，也不执行撤销查询、Scope 变化复核或 TOCTOU 一致性保护。调用场景是 Research 来源 Adapter 在返回内容前执行本地快照校验；生产读取仍必须由签发 Owner 完成实时策略复核和读取一致性保护。新增测试尚未执行。

### 2.10 RSC-005 Hypothesis 文本字段规范化

`validation_method` 和 `expected_observation` 改用统一必填字符串校验，拒绝空值、全空白和首尾空格。没有新增状态迁移语义，也没有填补 `supersedes_version` 字段缺口。新增测试尚未执行。



### RSC-OPEN-007：Evidence 不可变存储与授权快照续期语义

RSC-CTR-001 的 content_fingerprint 明确排除 authorization_ref；当前 Research Migration 的 payload_sha256 则针对完整 JSON payload，包含 authorization_ref。因此，同一 evidence_id 在内容完全不变但 Owner 重新签发 AuthorizationRef 时，会出现 content_fingerprint 相同、payload_sha256 不同的情况。

在项目契约明确前，Repository 采用完整 payload 不可变策略：相同 evidence_id + 相同完整 payload 幂等；相同 evidence_id + 不同完整 payload 冲突，不覆盖旧授权快照，也不自动生成替代 ID。该策略意味着不能用更新 Evidence 行的方式续期授权；读取时当前授权复核必须由来源 Owner 完成。若未来需要保存多次授权签发记录，应由契约明确独立授权记录/关联模型，而不是修改 Evidence 内容指纹规则。


RSC-007 Port 追加约束：Context/Event/Claim 的 Append 必须在同一数据库事务中锁定 aggregate head、校验当前最新版本、执行领域 ValidateNextVersion、插入版本快照并更新 head；相同 ID+版本+完整 payload 重放为幂等成功，不同 payload 冲突，版本跳号拒绝。Evidence 按 evidence_id 不可变写入，相同完整 payload 重放幂等、不同完整 payload 冲突；RSC-OPEN-007 的授权续期语义未决前不得按 content_fingerprint 单独放宽幂等。


### 2.12 RSC-007 Context/Event/Claim SQL Adapter 第一批实现

本轮新增 `internal/research/storage/repository.go` 及三个 typed Adapter 文件：

- `ContextRepository` 实现 `context.Repository`；`EventRepository` 实现 `event.Repository`；`ClaimRepository` 实现 `claim.Repository`。
- 构造函数接收 `*sql.DB` 和可选 `Clock`，只组装 Repository，不连接数据库、不自动执行 DDL；Migration 仍由组合根显式注册到 Platform Storage Runner。
- Append 在一个 InnoDB 事务内执行：INSERT IGNORE 初始化 aggregate head → SELECT ... FOR UPDATE 锁定 head → 检查版本连续性/幂等重放 → 读取上一版本并执行领域 ValidateNextVersion → 插入不可变快照 → CAS 更新 head → Commit。
- 相同 ID+版本+完整 JSON payload SHA-256 一致时幂等成功；同版本不同 payload、版本跳号或版本回退返回冲突。事务中途错误依赖 Rollback，不会先推进 head。
- GetVersion 只按 ID+精确版本读取；解码后重新执行领域 Validate，并检查 payload 内 ID/version 与查询键一致。缺失记录返回 `storage.ErrNotFound`。
- PIT 索引列使用 Migration v2 的 RFC3339Nano 文本格式；created_at/updated_at 使用应用 Clock，不参与 PIT 比较。
- SQL 标识符只来自 Adapter 内常量，所有业务值均使用参数绑定。

当前实现状态：代码已写入；环境变量门禁的 MariaDB 集成测试覆盖首次写入、连续追加、相同 payload 重放、冲突 payload、跳号、精确读取、并发相同/冲突追加、插入失败后的 aggregate head 回滚和 Context Cancel。尚未执行仓库级 gofmt/go test，也没有真实 MariaDB 验证；未完成前不将 RSC-007 标记为验收通过。Evidence Adapter 仍按 RSC-OPEN-007 暂缓。
