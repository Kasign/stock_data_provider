所有任务初始为完成：否。状态只有在对应设计/实现、自动化测试和任务要求的集成/真实验收证据齐全后才能标记完成。文档完成不等于代码完成；Mock/Fixture/CI 通过不等于真实数据验收。

## 3. 执行批次与并行边界

### Batch 0：架构与契约
- ANA-001 → ANA-002。
- 交付：架构评审、阶段契约、领域模型、输入输出 Schema。
- 禁止：大规模业务代码、共享入口改造、旧代码删除。

### Batch 1：基础领域能力（可并行）
- ANA-003 Quant 基础；
- ANA-004 Context；
- ANA-005 Evidence；
- ANA-007 Persistence 设计。
- ANA-006 Notification 可单独设计，但不阻塞主分析链路。

并行条件：ANA-002 的公共字段和时间/质量语义冻结；各模块只写自己的目标目录和测试。

### Batch 2：分析子引擎（契约冻结后并行）
- ANA-008 个股；
- ANA-009 市场；
- ANA-010 行业；
- ANA-011 Event Research。
- Event Research 必须等待 News 事实/来源契约；不能自行建设新闻采集和原文存储。
- 市场/行业必须等待 Data 对应成分、交易日历、行情覆盖契约。

### Batch 3：研究上下文与编排
- ANA-012 Context Builder；
- ANA-013 Orchestrator。
- 先完成模块 Ports 和阶段输入输出，再实现 DAG 和恢复逻辑。

### Batch 4：存储与模型接入
- ANA-014 Persistence 实现；
- ANA-015 LLM Adapter。
- 两者可在接口冻结后并行；不得提前修改根 Migration 注册和共享服务装配。

### Batch 5：策略、预测与风险
- ANA-016 策略/回测/评估；
- ANA-017 概率预测/风险/组合。
- 预测依赖回测和历史样本；组合研究不能先于风险契约和策略评估。

### Batch 6：迁移与集成
- ANA-018 集中切换旧 StockFlow、MarketReviewFlow、Python Bridge 调用方和服务入口。
- 按 MIG-013 固定样本差异分类验收；按 MIG-014/015 删除 Bridge、Python 运行时和部署依赖。
- 若任何调用方、任务、数据表或回滚路径未查清，不得清理旧实现。

## 4. 旧实现迁移评估

### 4.1 评估范围

至少盘点：
- `internal/analysis/**`；
- `go-core/internal/application/**`；
- `go-core/internal/contextpack/**`；
- `go-core/internal/domain/**`；
- `go-core/internal/indicators/**`；
- `go-core/internal/market/**`；
- `go-core/internal/ports/**`；
- Python 的 analyzer、pipeline、Agent、Skills、Tools、策略、筛选、回测、告警和报告模块。

### 4.2 处置分类

| 分类 | 条件 | 动作 |
|---|---|---|
| reuse | 算法正确、边界充分、测试可靠、依赖可隔离 | 迁入新模块并适配新契约 |
| rewrite | 职责混杂、流程过简、模型错误或难以测试 | 按目标设计重写 |
| retire | 无调用方、重复、已被新模块替代 | 在切换确认后删除 |
| defer | 非首期范围或依赖未满足 | 保留记录，不进入当前实现 |

任何代码迁移都要记录来源路径、调用方、算法/业务语义、测试证据、处置理由和目标路径。禁止仅凭文件名或目录名判断可复用。

### 4.3 明确不可直接继承的假设

- 简单 MA20/5 日收益/20 日收益不等于完整趋势模型；
- 自选股统计不等于全市场宽度；
- 成交额不等于资金净流入；
- 当前行业成分不等于历史行业成分；
- Provider 当前复权数据不等于严格 PIT 历史复权；
- LLM 输出不等于事实或量化结果；
- 策略候选信号不等于可执行计划；
- 回测代码存在不等于交易制度模拟正确。

## 5. 共享文件隔离清单

ANA-001～017 前期原则上不修改：
- `cmd/**`；
- `internal/service/wiring.go`；
- `internal/platform/**`；
- `internal/analysis/**` 的公共契约和共享入口；
- `internal/platform/httpapi/**` 或根 HTTP 路由；
- 根 Migration 注册、启动 Worker 和部署文件；
- Data/News/Platform/WebUI 专项文档。

若必须依赖某项公共契约，先在分析分支定义本领域 Port/Adapter 边界，并向契约所有者提出评审；不要复制公共实现或跨分支直接改代码。

ANA-018 才集中协调 API DTO/OpenAPI、DI、Worker、Migration 注册和部署入口。最终集成前核对共同祖先、分支 HEAD、文件差异、接口兼容和数据库迁移顺序。

## 6. 验收门禁

- 设计门禁：阶段、依赖、数据契约、失败语义和版本策略明确。
- 单元门禁：算法固定样本、边界、缺失值、单位和时区测试。
- 契约门禁：Data/News/Platform Adapter 的真实契约测试。
- PIT 门禁：历史 as_of 不使用未来数据，历史版本可复现。
- 质量门禁：unknown/degraded/invalid 不得静默转为 valid。
- 量化门禁：交易制度、成本、样本外和防过拟合测试。
- LLM 门禁：Schema、引用、事实边界、权限和脱敏。
- 运行门禁：超时、取消、重试、部分失败和恢复。
- 持久化门禁：幂等、事务、版本和恢复。
- 集成门禁：真实配置、服务调用、Migration、部署和旧调用清零。
