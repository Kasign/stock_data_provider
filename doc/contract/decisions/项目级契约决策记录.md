## DEC-PLAT-002-006：Owner Session 与 Bearer 身份边界

- 日期：2026-11-10
- 状态：`confirmed_candidate`
- 已有依据：Platform 17 号文档和 18 号 Session 原语设计明确区分 owner_bearer、service bearer、owner_session；Session Token 仅由 HttpOnly Cookie 携带，Server 负责 Session 路由矩阵与登录业务装配，Platform 不负责登录 Handler。
- 候选基线：不得将 Cookie Session 伪装为 Authorization Bearer；每条路由显式声明接受的认证方式；Cookie 状态变更请求执行 CSRF 与 Origin/Host 校验；Session/Redis 故障 fail closed；资源级授权由领域模块复核。
- 尚缺证据：当前 Server Bootstrap 是否接入 Session Middleware、Cookie、CSRF、Credential Version 检查和审计；WebUI 请求是否与实际路由一致；目标部署 HTTPS/可信代理证据。
- 结论：技术边界可作为候选核验基线，但在 Server/WebUI 消费者和部署证据齐备前不冻结完整 Web 登录契约。
