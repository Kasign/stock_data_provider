# 项目级契约治理

本目录是项目级跨模块契约的冻结决策入口，服务于 `integration` 集成基线。契约冻结状态、冻结版本、审查结论和待决事项统一在本目录登记。

## 权威边界

| 内容 | 权威来源 |
|---|---|
| 项目级冻结结论、冻结版本、冻结范围、未决事项 | [PLAT-002 项目级契约冻结登记簿](./PLAT-002-项目级契约冻结登记簿.md) |
| 契约编号、领域契约明细、历史状态及既有证据索引 | [跨模块契约目录与冻结状态](../整体任务规划/02-契约治理/跨模块契约目录与冻结状态.md)（从 `feat/design_doc` 汇入的既有目录；本次以 integration 实际内容重新校准） |
| 公共平台技术原语 | [Platform 公共平台契约规范](../platform/08-公共平台契约规范.md) |
| 各领域 DTO、Port、Schema、Golden | 对应模块专项文档与机器契约文件 |
| Server 组合根和生命周期 | [Server 实施规划](../server/README.md) 及实际实现 |
| WebUI 与数据服务的 HTTP 契约 | 对应 OpenAPI、服务端实现和 WebUI 请求代码 |

本目录不复制各模块完整字段表、Schema 或 Golden。模块专项文档仍负责字段级定义；本目录负责项目级决策、冻结状态和跨模块一致性。

## 冻结原则

1. `integration` 是本次审查的代码聚合基线；每次冻结必须记录精确 HEAD SHA。
2. 文档描述、代码实现、自动化测试、消费者接入和生产验收是不同证据，不得互相替代。
3. `accepted` 不等于 `frozen`；`implemented`、`closed`、单模块 CI 通过也不自动等于冻结。
4. 每项契约只有在适用的 Schema、Golden、生产方/消费者 Contract Test、版本兼容和安全边界证据齐备后，才能标记 `frozen`。
5. 未决的关键语义标记 `pending_decision`；语义已明确但证据不足标记 `pending_evidence`；明确延期且不阻断范围的标记 `deferred`。
6. 代码或契约变更必须更新本目录的版本与决策记录；不得静默修改已冻结契约。
7. 模块核验由对应模块执行窗口完成并提供分支 SHA、文件/测试证据；GPT 自己实现再自审不构成独立消费者确认。跨模块争议由项目负责人裁决。

## 目录外既有资料

`doc/整体任务规划/02-契约治理/跨模块契约目录与冻结状态.md` 是此前从 `feat/design_doc` 汇入 integration 的大型契约目录，仍保留既有契约编号、详细定义索引和证据缺口。它的头部仍声明原维护分支为 `feat/design_doc`，该声明与本次 integration 作为聚合审查基线的安排不一致。后续需由项目负责人确认是否将其维护权正式迁移到 integration；在此之前，本目录只记录本次审查的冻结决策，不擅自改写原目录的历史内容。
