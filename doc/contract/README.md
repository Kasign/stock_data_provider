- 各模块专项文档仍是其领域字段级定义的唯一来源；项目级登记簿不替代生产方的领域定义。

## 3. 冻结规则

1. 每次审查和冻结都绑定精确分支与 HEAD SHA；后续 HEAD 前进不自动改变既有冻结版本。
2. 代码、文档、Schema、Golden、生产方测试、消费者测试和生产验收是不同证据，不能互相替代。
3. `implemented`、`accepted`、单模块 CI success、Fake 测试通过或文档存在，均不等于 `frozen`。
4. 只有语义、Owner、直接消费者、版本、机器契约、适用 Golden、生产方/消费者测试、兼容性和安全门禁齐备，才允许冻结。
5. 未决语义标记 `pending_decision`；语义基本明确但证据不足标记 `pending_evidence`；延期必须说明原因、触发条件和影响范围。
6. 不把同一执行者编写和自审的材料描述为模块间独立确认。没有独立消费者确认时必须明确标注证据属性。
7. 冻结契约的语义变更必须先记录决策、影响消费者、版本升级、迁移和回滚策略，不得静默修改。
