## 1. 目标与原则

统一诊断需要回答：服务是否存活、必需依赖是否可用、领域能力能否执行、数据/结果是否可信、某次运行在哪个阶段失败，以及如何定位到详细证据。

统一的是公共契约、执行边界、关联标识和摘要聚合；不统一重写领域规则、数据模型、历史存储和证据内容。

- 复用优先：Data 已有诊断体系，不从零重建。
- 领域所有权：领域负责检查规则、质量判断、证据解释和持久化。
- 平台提供原语：Platform 提供 Fault、Observation、Check 执行器、超时/并发、访问保护和基础聚合。
- 分层诊断：进程健康、依赖能力、数据质量、任务运行不可混成一个布尔值。
- 轻量优先：首期单实例，不建设 Metrics/Trace 后端、通用诊断工作流或诊断数据仓库。
- 诊断不阻塞业务：诊断存储失败不能阻断无关业务；可选 Redis 缓存不可被提升为全服务必需依赖。

## 3. 各模块诊断现状

### 3.1 Platform：公共基础能力待实现

平台分支已通过文档定义 Observation/Fault 字段及 SSRF 安全要求，但不能据此认为已有可运行实现。

待交付：Fault 类型及安全序列化、Observation/Check Result 类型与校验、轻量 Check 执行器、单项 Timeout/总 Deadline/有限并发、required/optional 语义、基础聚合、访问保护，以及可调用的 SSRF 安全 HTTP Client 和完整安全测试。

平台不承担任何领域 Probe 或质量规则。

### 3.2 Data：已有较完整的领域诊断体系

本轮核对 Data 分支 e7d7d0726decd73f920b7fa967baaf45a3fabb66 的代码和文档；其最新提交只调整复权因子匹配优先级，诊断代码路径未变，确认数据诊断不是单一 Health API，而由多类组件组成。

| 能力 | 代码/文档位置 | 现状与边界 |
|---|---|---|
| 主动 Provider Probe | services/market-data/internal/service/provider_probe.go | 按 Provider/Capability 和检查维度执行 |
| Probe HTTP 接口 | services/market-data/internal/httpapi/provider_probe.go、server.go | 发起主动 Probe 并返回结构化结果 |
| Probe 领域模型 | services/market-data/internal/model/provider_probe.go | 表达 Probe Run、结果和状态 |
| Probe 历史 | services/market-data/internal/repository/provider_probe.go | MariaDB 保存及查询历史 |
| 被动运行诊断 | services/market-data/internal/service/resilience.go | 从真实业务请求熔断状态观察运行健康，不主动请求上游 |
| 字段质量诊断 | services/market-data/internal/validation/ | Validation、Issue、Report 等结构化质量问题 |
| Provider 原始字段诊断 | services/market-data/internal/provider/quote_field_diagnostic.go 等 | 保留原始字段解析和字段级问题 |

| Coverage / Cross Provider | Probe/质量实现及数据侧专项规划 | 覆盖率、跨源可比性和对账证据 |
| 交易上下文 | 数据侧诊断与质量规划 | 交易日历、证券交易状态等上下文约束 |

主动 Probe 的检查维度包括 connectivity、contract、quality、freshness、cross_provider、storage。这些是 Data 领域诊断维度，不应全部搬进 Platform。

接口职责：
- GET /api/v1/data-sources/diagnostics：读取被动运行诊断；当前来自 in-process circuit breaker，代码标注 scope 为 quote、daily_bars。它不是主动 Probe，也不是完整历史查询。
- POST /api/v1/data-sources/probe：执行主动 Provider Probe。
- GET /api/v1/data-sources/probe/history：查询持久化 Probe 历史。

Data 能力较成熟不代表所有数据域都已接入或所有真实 Provider 均已验收。下一步继续完成既有 DATA-003 及其子项：Reporter 覆盖、Freshness SLA、交易边界、跨源可比性、真实 Provider/存储验收等。不得仅因存在 Probe API 就标记整个数据诊断完成。

### 3.3 News：领域诊断已规划，运行实现待推进

News 已提出公共平台需求并形成领域诊断设计方向，但当前尚不能认定具备与 Data 同等的运行诊断体系。

领域范围：Source 配置/授权、DNS/TLS/HTTP、限流配额、搜索契约、候选数量、Fetch 响应类型/大小、安全拦截、Parse 编码/正文/时间、Normalize、Deduplicate、证券关联、Persist、来源可信度和新鲜度。

采集阶段必须区分成功、失败、跳过和降级。HTTP 成功不等于新闻质量成功；解析失败不等于平台 Check 执行器故障。详细结果归 News Ingestion Run 和领域证据所有。

安全门禁：News 负责来源授权与 allowlist；Platform 负责 DNS/IP 校验、受控 Dial、逐跳重定向和代理策略。安全 HTTP Client 的实现和测试通过前，不开放任意来源真实抓取。

### 3.4 Research：基础服务检查已有，领域运行诊断待补齐

Research 当前位于独立 go-core Go Module。本轮可见代码已有 /healthz、/ready 和可注入 ReadyCheck、Request ID、Recovery、基础应用错误类型与工作流错误映射。

尚未看到与 Data Probe 同等的完整领域诊断模型、Analysis Run/Stage 诊断历史或统一 Observation/Fault 接入。

领域范围：输入快照与质量门禁、as_of/PIT、Context Pack、Quant 阶段、LLM Gateway、Evidence 引用、Workflow Stage、结果完整性和可复现性。

建议建立 AnalysisRun → Stage → Dependency/Fault → Evidence 关系。诊断历史与分析任务关联，由 Research 保存。独立 go-core Module 不得直接 import 根模块 internal 包；首期按 HTTP 契约或独立 Adapter 接入。

### 3.5 Notification：随通知模块建设领域投递诊断

当前尚未形成可验收的完整投递诊断。进入实际开发时覆盖渠道配置/可用性、测试发送目标、副作用确认、Delivery Run、重试、幂等、限流、失败 Fault、积压和最终状态。测试发送不得默认触达真实订阅者。

### 3.6 WebUI：已有 Data 诊断消费能力

WebUI 已有数据中心诊断页面，消费 Data 被动诊断、主动 Probe、Probe 历史、字段问题、Coverage 和 Cross-Provider 结果。

WebUI 负责展示状态、原因、耗时、Probe 操作、历史和证据导航；不负责探测 Provider、推导质量/Freshness、重算 Coverage/Cross-Provider。当前重点是核对真实 API、真实数据和历史持久化联调，不重新建设 Data 诊断页面。

### 4.1 四个诊断层次

| 层次 | 诊断对象 | 责任方 | 示例 |
|---|---|---|---|
| L1 进程与基础设施 | 进程、必需依赖和资源 | Platform + 服务 Bootstrap | Liveness、MariaDB、Redis、HTTP Client |
| L2 领域能力 | 外部能力和业务能力是否可执行 | 各领域 | Data Provider、News Source、LLM、Notification Channel |
| L3 领域质量 | 输入/输出是否可信 | 各领域 | Validation、Freshness、Coverage、News 内容质量、Evidence 完整性 |
| L4 运行与任务 | 一次执行如何完成 | 各领域 | Probe Run、Ingestion Run、Analysis Run、Delivery Run |

四层是不同诊断对象，不是同一状态枚举。平台可对 L1 和显式注册的 L2 Check 做基础聚合；L3/L4 的判断与历史保留在领域。

### 4.2 诊断执行类型

- 被动观察：读取真实业务调用积累的状态，例如 Data 熔断器诊断；查询不得触发上游请求。
- 主动轻量检查：连通性、配置和低成本契约检查；有单项超时和并发上限。
- 主动深度检查：字段质量、跨源比较、完整采集等有成本/配额的动作；由领域 API 明确触发并展示范围。
- 运行结果诊断：读取某次 Run/Task 的阶段状态和证据，不重新执行任务。

## 5. 统一公共契约与状态映射

### 5.1 Observation

公共 Observation 最低字段：
- status：healthy、degraded、unavailable、skipped、failed；
- reason_code：非 healthy 必填，稳定机器标识，由领域命名空间维护；
- safe_message：必填脱敏摘要；
- checked_at：UTC 时间；
- duration：本次检查耗时；
- evidence_ref：可选、不透明、受权限保护的领域证据引用；
- attributes：可选、有界、低敏感、白名单结构化标量。

平台不解析 evidence_ref，不负责证据生命周期和授权。没有持久化证据时可以省略。

### 5.2 Fault

统一 Fault 字段：Class、Code、SafeMessage、可选 Dependency、Retryable（默认 false）、内部 Cause。实际重试还必须满足幂等、策略允许、预算和 Deadline。领域可以进一步禁止重试。

### 5.3 状态不可混用

| 语义 | 示例 | 不应混淆 |
|---|---|---|
| Check 执行状态 | healthy/degraded/unavailable/skipped/failed | 不代表数据质量等级 |
| Provider 业务结果 | returned/returned_degraded/failed/unknown | 不代表 Check Runner 是否成功 |
| 字段质量 | valid/degraded/invalid/unknown | 不代表网络连通性 |
| Freshness | fresh/stale/unknown/not_applicable | 不代表 Provider 是否可连接 |
| Run 状态 | queued/running/succeeded/partial/failed/cancelled | 不直接等同依赖健康状态 |

领域 Adapter 必须保留原状态；公共 Observation 只表达公共 Check 结果。

## 6. 证据、历史和存储所有权

| 领域 | 历史事实所有者 | 平台职责 |
|---|---|---|
| Data | Data Probe Repository / MariaDB | 契约适配、摘要聚合和导航 |
| News | News Ingestion Run / 新闻证据存储 | 统一 Fault/Observation 和基础执行 |
| Research | Analysis Run / Stage / Evidence Repository | 统一 Fault/Observation 和基础执行 |
| Notification | Delivery Run / 投递记录 | 统一 Fault/Observation 和基础执行 |
| Platform | 仅保存必要即时结果，首期不建通用历史库 | 基础 Check 和最小摘要 |

不把各领域详细记录复制到平台数据库。统一摘要可保存引用和计数，但不能成为领域事实来源。诊断存储不可用时不得阻断无关业务。

## 7. 统一查询与 WebUI 接入

首期不建立独立 Diagnostics Service。由最终集成分支在现有 Server 提供轻量聚合入口，数据来自领域已存在的摘要接口或注册的轻量 Check。

建议接口语义（路径待 OpenAPI 评审，不在本文冻结）：服务级摘要、领域诊断详情、Run 详情、Evidence 导航。

- 聚合超时不能拖垮业务 API。
- 领域接口不可用时明确标记 unavailable/unknown，不静默当 healthy。
- 聚合接口不复制领域大字段或原始响应。
- WebUI 展示摘要和领域详情链接，不合并业务规则。

## 9. 故障场景验收矩阵

| 场景 | 预期 | 归属 |
|---|---|---|
| MariaDB 不可用 | readiness/unavailable，标记必需依赖 | Platform + Service |
| Redis 缓存不可用 | 可选缓存 degraded/skipped，业务旁路 | Platform + 使用方 |
| Provider 超时 | Dependency Fault，Probe/Run 记录依赖和耗时 | Data |
| Provider 字段异常 | Check 可执行成功，但 Quality/Validation degraded/invalid | Data |
| Freshness 过期 | Freshness stale，保留评估时间和数据时间 | Data |
| SSRF 私网目标 | 拨号前拒绝，稳定 reason_code/Fault，不建立连接 | Platform + News |
| 重定向到私网/未授权 Host | 每一跳重新执行来源和 IP 策略并拒绝 | Platform + News |
| News 正文解析失败 | Ingestion Stage parse failed，关联证据引用 | News |
| News 去重冲突 | 记录身份/hash 冲突，不误报网络故障 | News |
| LLM 超时 | Analysis Stage 记录依赖超时和 Run/Stage | Research |
| Evidence 缺失 | 质量门禁失败/降级，不把模型输出当已核实事实 | Research |
| Notification 限流 | Delivery Run 记录 retryable/dependency 和最终状态 | Notification |
| 诊断存储失败 | 不阻断无关业务，明确历史不可用 | 各领域 |
