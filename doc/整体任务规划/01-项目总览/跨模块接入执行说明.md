- 文档性质：模块实施任务单与交接入口
- 权威分支：`feat/design_doc`
- 当前准入基线：A1（可按文档开始实现）
- 对应准入清单：[跨模块接入准入清单](./跨模块接入准入清单.md)

> **给负责人：可以开始实现，不需要等待其他模块全部完成。** 但当前只是 A1：允许模块内部实现和模块级测试并行推进；尚不代表跨模块联调通过、契约 frozen 或生产可用。Data 是例外：当前优先执行 MDM-001～007 结构迁移，DATA-CTR-005～008/GOV-CTR-006 的实现统一放在 MDM-008，不得按本说明通用 DTO/授权步骤提前改造。

## 1. 你现在应该怎么做

每个模块负责人按以下顺序执行：

1. 确认自己负责的模块和目标分支，只在该模块分支内提交代码；不要在 `feat/design_doc` 上实现业务代码。
2. 先读本说明中本模块的“必读文档”，再读契约登记簿中对应契约的完整条目。
3. 按本说明列出的 P0 任务顺序实施。遇到文档冲突、字段缺失或语义歧义，先提问题并记录，不要自行创造第二套语义。
4. 对当前准入阶段允许实现的公开 DTO/接口补 Schema/Golden/Validator/Contract Test；Data 的 DATA-CTR-005～008 属 MDM-008，不适用本阶段提前实现。运行时授权、并发和网络安全不能只靠 JSON Schema 证明。
5. 完成后提交“模块接入证据”，按第 6 节格式记录测试命令、结果、提交 SHA、CI Run 和未完成项。
6. 只有证据满足 A2 条件，才申请跨模块联调；不得自行把契约状态改为 `frozen`。

**不需要等待：** 其他模块完成全部功能、真实 Provider 凭据、生产部署、全项目集成测试。只要不依赖未完成的调用点，就可以先做模块内部结构和本地 Fixture；Data 当前按 MDM 阶段顺序执行，不提前进入契约 DTO/授权改造。

### 必读文档

1. [公共平台最小契约规范](../platform/08-公共平台契约规范.md)
2. [跨模块契约目录与冻结状态](./跨模块契约目录与冻结状态.md)：重点 PLAT-CTR-001～007、GOV-CTR-003、GOV-CTR-006。
3. [跨模块契约样例与 Golden 验收矩阵](./跨模块契约样例与Golden验收矩阵.md)
4. [跨模块接入准入清单](./跨模块接入准入清单.md)

### 实施顺序

- P0-1：稳定 Fault 公共类型、错误码到 HTTP 状态/公开错误 DTO 的映射；区分认证失败、授权拒绝、依赖不可用，不允许吞掉业务模块 reason。
- P0-2：稳定 Request Context、Request ID 生成/校验/传播；字段身份和作用域遵循 GOV-CTR-003，不在 Platform 重定义业务 ID 语义。
- P0-3：完成 Secret/认证中间件边界、日志脱敏和配置注入；禁止把 Secret 放入日志、错误详情或浏览器可见配置。
- P0-4：提供受控 HTTP Client/Transport，明确超时、重定向、DNS/IP 校验、SSRF 与 DNS rebinding 防护；调用方不得绕过统一安全策略创建裸 Transport。
- P0-5：明确 Config/Diagnostics 的稳定接口、默认值、生命周期和错误行为。
- P0-6：提供最小组合测试，证明 Middleware → Context → Handler → Fault 映射链路一致。

### 代码边界

- Platform 只提供技术原语，不拥有 Data/News 的业务授权策略、Provider 状态或领域错误语义。
- News 与 Platform 同属根 Go Module 时，News 可依赖 Platform 的公开 package。
- Data 与 Server 归并到同一根 Go Module 后，Data 可依赖 `internal/platform` 的公开技术 package；仍不得依赖 Platform 私有实现或其他业务模块的 `internal`。Data 对其他业务模块只暴露 Application Port/DTO，不暴露 Provider、Repository、SQL Model。
- 本轮不要求 Trace SDK、动态 ServiceKey CRUD 或完整服务发现；这些延期项不阻断 A1/A2 的首批范围。

### 必须交付

- PLAT-CTR-001～007 对应的 Go API/DTO/配置映射说明。
- 直接调用方可运行的最小示例或测试 Fixture。
- Fault、Request Context、Security/Secret、HTTP Client 的 Contract Test。
- HTTP Client 安全测试：至少覆盖私网/环回/链路本地地址、重定向越界、DNS 解析变化或等价防护验证。
- Secret 脱敏测试、生命周期/关闭测试，以及可复现 CI 记录。

## 4. Data 执行任务

### 必读文档

1. [Data 服务间认证映射与 Secret 注入设计](./Data服务间认证映射与Secret注入设计.md)
2. [跨模块契约目录与冻结状态](./跨模块契约目录与冻结状态.md)：重点 DATA-CTR-005～008、GOV-CTR-003、GOV-CTR-006。
3. [跨模块契约样例与 Golden 验收矩阵](./跨模块契约样例与Golden验收矩阵.md)
4. [跨模块接入准入清单](./跨模块接入准入清单.md)
5. Data 分支迁移跟踪文档 `doc/api/migration/MarketData模块化单体迁移计划与进度.md`：以其 M0～M6 任务与最新审计发现作为实施清单；架构决策和公共契约仍以本分支对应文档为准。

### 实施顺序

**当前执行 MDM-001～007 结构迁移；DATA-CTR-005～008 的实现暂缓至 MDM-008。**

1. MDM-001：完成 Provider 出站 HTTP/TCP、全部 Handler/调用方、Config/配置文件、DB/Redis、Migration、Worker、Compose/CI 的只读清单。
2. MDM-002：将 `services/market-data` 迁入根 Go Module 的 `internal/marketdata`，统一 Go 版本、依赖和 CI；保持 Provider 行为及 Data v1 DTO/OpenAPI 语义不变。
3. MDM-003：提取 Data Bootstrap/Application Port，按领域拆分强类型用例接口和 DTO；HTTP Adapter 复用同一 Application，不把全部 Provider/Repository 暴露给消费者。
4. MDM-004：Root Server 注册 Data Module；Analysis 改为 InProcess Adapter；Data HTTP Adapter 挂入 Root Router。Application Port 必须保留 nullable/精度/单位/质量/复权/PIT 元数据，并明确 Analysis.AsOf 到 Data revision cutoff 的映射。
5. MDM-005：统一共享 DB/Redis、显式 Migration Registry、Worker Start/Stop/Drain；Provider HTTP Client 按 Platform 安全策略逐项接入，BaoStock/PyTDX TCP 单独治理。
6. MDM-006：默认 Compose 移除 Data 独立容器；Nginx 两个 API 前缀统一转发 Root Server；WebUI 删除 Data Key 输入、localStorage 读写和请求头；处理旧 go-migration Profile 保留/退役决策。
7. MDM-007：完成迁移前后 v1/Provider/质量/PIT/持久化/错误/缓存/生命周期回归，作为结构迁移验收。
8. MDM-008：结构迁移验收完成后，再按 DATA-CTR-005～008、GOV-CTR-006 实施公共 DTO、可信 Principal/Scope、Snapshot Manifest、AuthorizationRef、读取时复核和 Request ID 契约。

结构迁移期间不得批量修改 DATA DTO/Schema 或自行发明认证字段。

### 强制边界

- 进程内 Data Application Port 不使用 Data API Key；Data API Key 仅适用于保留的远程 HTTP Adapter，与 Platform Service Secret、Owner Token、Provider Token 仍严格分离。
- 浏览器、WebUI、前端配置和响应体不得接触任何服务端 Secret；如启用远程 Data Adapter，只能由服务端注入 `X-API-Key`。
- `subject_ref` 必须来自认证后可信 principal；`resource_ref` 必须绑定被访问的具体 Snapshot Manifest。
- AuthorizationRef 是审计快照，不是 bearer token；不能仅凭历史 allowed 就允许后续读取。
- 当前结构迁移不要求等待 Quant/Research 完成或真实全量 Provider 可用；但 DATA-CTR-005～008 的 DTO、Validator、授权实现必须等到 MDM-008 阶段，不得提前执行。

### MDM-008 阶段必须交付

以下均为结构迁移验收完成后的契约阶段交付，不是 MDM-001～007 结构迁移阶段的验收项。

- 进程内可信 Principal/Scope → Data Application Context 的映射测试；远程 Adapter 模式下补 Data API Key → trusted principal/Scope 映射测试。
- DATA-CTR-008 Schema/Golden/Validator，以及 Manifest 内容寻址和引用一致性测试。
- Data v2 DTO/Handler Contract Test，包含精度、单位、时间和缺失值边界。
- Scope 越权、Key 轮换/撤销、读取复核、撤销/过期竞态和依赖不可用测试。
- CI 执行记录与尚未覆盖的 Provider/部署限制。

## 5. News 执行任务

### 必读文档

1. [新闻来源授权矩阵](../news/新闻来源授权矩阵.md)
2. [跨模块契约目录与冻结状态](./跨模块契约目录与冻结状态.md)：重点 NEWS-CTR-001～003、GOV-CTR-006。
3. [GOV-CTR-006 机器契约与 Golden](./GOV-CTR-006-AuthorizationRef机器契约与Golden.md)
4. [跨模块契约样例与 Golden 验收矩阵](./跨模块契约样例与Golden验收矩阵.md)
5. [跨模块接入准入清单](./跨模块接入准入清单.md)

### 实施顺序

- P0-1：将 Provider Output、Source、Endpoint 三类策略合并为一次完整授权决策快照；不得只检查其中一层。
- P0-2：按 NEWS-CTR-002 生成 AuthorizationRef；subject_ref 使用可信 caller，resource_ref 指向精确不可变 Evidence 版本。
- P0-3：落实 requested_content_level 与授权 content_level 比较；请求 full 但授权仅 snippet 时必须拒绝，不得静默降级。
- P0-4：conditional 授权必须绑定明确条件；条件变化或快照失效时重新签发/复核。
- P0-5：每次读取时复核 Owner 当前策略；对过期、撤销、unknown、策略服务不可用和 TOCTOU 竞态 fail closed。
- P0-6：补充 Schema/Golden/Validator、Provider/Source/Endpoint 组合策略测试、精确 Evidence 版本引用和内容级别拒绝测试。

### 强制边界

- 不可变 Evidence 版本是授权资源；不得用可变 news_id 代替精确版本资源。
- Provider 的检索/输出许可不能替代原始发布者对持久化、全文或衍生内容的授权。
- 来源授权矩阵中的限制必须落到具体 Provider/Source/Endpoint 配置和写入/读取门禁；不能只作为文档提示。
- 请求 full 而只允许 snippet 时直接拒绝，不能以自动降级掩盖授权不足。
- News 与 Platform 同属根 Go Module 时依赖其公开 package；不得依赖 Platform 私有实现。
- 不要求等待 Research 的 Evidence 消费端完成后才实现 News 自身的授权签发、Evidence 版本和测试。

### 必须交付

- NEWS-CTR-002 Schema/Golden/Validator 与字段绑定测试。
- Provider Output + Source + Endpoint 三层策略组合测试。
- full/snippet/metadata 内容级别允许与拒绝测试。
- conditional 授权、过期、撤销、unknown、授权服务不可用和 TOCTOU 并发测试。
- 精确 Evidence 版本 resource_ref 一致性测试。
- 来源授权矩阵对应的配置证据；对权利未确认的来源保持禁用或限制，不得默认放开。
- 模块 CI 记录和未解决来源权利清单。

## 6. 所有模块统一的交付证据格式

每个模块完成一批任务后，在本模块文档或验收记录中追加以下信息：

| 项目 | 必填内容 |
|---|---|
| 模块/契约 | 模块名、契约编号和版本 |
| 实现位置 | DTO、Handler/Port、Adapter、Validator、测试文件路径 |
| Schema/Golden | 文件路径、版本、覆盖场景 |
| 测试命令 | 可复制执行的完整命令 |
| 本地结果 | 通过/失败/跳过；跳过必须写原因 |
| CI 证据 | Workflow、Run URL、结论、执行提交 SHA |
| 安全/竞态 | 授权复核、撤销/过期、并发、Secret/网络边界的覆盖情况 |
| 未完成项 | 明确阻断调用点、风险、Owner 和下一步 |
| 基线 | 实现分支、实现提交 SHA、对应设计基线 SHA |

**测试结果必须如实分类：**
- PASS：命令真实执行且通过。
- FAIL：真实执行且失败，附失败摘要。
- SKIPPED：未执行，说明缺少凭据、环境或暂不适用的原因。
- NOT IMPLEMENTED：功能或测试尚未实现。

不得把 SKIPPED 写成 PASS，不得用本地文档校验替代模块 CI，不得用模块单测替代跨模块联调。

## 7. A1 → A2 → A3 升级条件

### A1（当前）

允许开始模块内部实现、DTO/Adapter/Handler、Schema/Golden/Validator 和模块级测试。无需等待跨模块联调。

### A2（申请联调前）

对应模块必须同时提供：

- Schema/Golden Validator 已进入模块 CI，并对仓库真实文件执行。
- 生产方序列化/反序列化 Contract Test 通过。
- 直接消费者映射测试通过；消费者不得自行重定义生产方字段语义。
- Principal/Resource/Scope/PolicySnapshot 绑定测试通过（适用授权的模块）。
- 当前授权复核、撤销/过期、unknown、依赖不可用和 TOCTOU 竞态测试通过（适用授权的模块）。
- Fault、身份、时间、内容级别和精度等跨模块映射有可复现测试。
- 测试命令、CI Run URL、执行提交 SHA 和证据路径齐全。

A2 按契约和调用点逐项评定，不因一个模块通过就自动提升其他模块。

### A3（生产接入）

在 A2 基础上，还必须完成真实部署配置、Secret 注入与轮换/撤销、网络出口和安全演练、生产级并发/故障恢复、监控告警与回滚验证。当前不在本轮 A1 交付范围内。

## 8. 需要向项目总规划反馈的问题

遇到以下情况不要自行修改契约：

- Schema 与专项字段表不一致。
- Golden 与文档语义不一致。
- 生产方/消费者对字段含义、时间、单位、精度或错误码有不同理解。
- 需要新增授权用途、内容级别、资源类型或策略类型。
- 需要改变模块依赖方向、跨进程边界或凭据归属。

反馈时提供：契约编号、文档路径/章节、当前约定、冲突证据、建议方案和受影响模块。没有明确决议前，不得通过代码“先兼容两种解释”制造双重语义。
