## 1. 本轮盘点结论

1. 当前材料已经覆盖主要模块职责和目标依赖方向，但尚未形成可逐条追踪的完整契约登记簿。

3. 旧编号与模块任务编号容易混淆。自本目录起，契约统一使用 `<DOMAIN>-CTR-NNN`，任务继续使用原任务编号。示例：`FLOW-CTR-001` 是契约，`FLOW-001` 是任务，两者不是同一对象。
4. 历史 Researchflow CONTRACT-006/007（现映射 FLOW-CTR-001/002）的设计决议已经关闭，但缺少正式 Schema、Golden 和 Contract Test，当前登记为 `pending_evidence`，不是 `frozen`。
5. Quant、Research、LLM、Notification 的首批 DTO/Port 语义已形成可实现基线；剩余主要是机器可读 Schema、Golden、消费者映射和 Contract Test 证据，跨模块通知事件映射仍保留明确的 pending_decision。不能将设计完成等同于 frozen。
6. Platform 公共技术原语已形成可用设计基线；其真实包接口、序列化、错误映射、安全测试及服务装配证据仍需按具体调用点验收。
7. 本次登记不依赖其他分支编译或 CI，也不宣称已对所有模块分支的最新源码完成复核。生产实现的 L3 状态必须由各模块实际环境验收记录证明。

## 2. 契约状态口径

| 状态 | 本目录使用标准 | 开发影响 |
|---|---|---|
| `pending_decision` | 关键语义、生产责任或边界尚未决定 | 只阻断需要猜测该语义的调用点 |
| `accepted` | 项目统一决策已确定语义和责任边界 | 可按该语义设计/实现；不能声称已冻结 |
| `pending_evidence` | 语义已确定，缺 Schema、Golden、消费者映射或必要 Contract Test | 可开展实现和测试；依赖该契约的调用点不得宣称 L2 |
| `frozen` | 版本、Schema、Golden、消费者映射、边界测试和必要兼容性测试均通过 | 可作为稳定实现基线 |
| `deferred` | 明确延期、目标批次和不阻断范围 | 仅阻断延期项明确列出的调用点 |
| `rejected` | 已否决并记录替代方案 | 禁止继续作为有效契约引用 |

**禁止将状态混用：**
- `closed` 是某次设计决策已结束的工作流描述，不替代契约状态。
- `implemented` 不是契约冻结状态。
- CI 通过不自动使契约 frozen；CI 失败也不自动使无关契约失效。
- `frozen` 必须有可定位的 Schema、Golden、测试文件和通过记录，不能只凭文档自述。

## 3. 契约编号规则与历史迁移

### 3.1 新编号

契约编号统一为 `<DOMAIN>-CTR-NNN`：

- `GOV-CTR`：项目公共语义、契约治理、门禁。
- `PLAT-CTR`：Platform 技术原语。
- `DATA-CTR`：Data 公开数据与质量。
- `NEWS-CTR`：News 证据查询与授权。
- `QNT-CTR`：Quant 指标、参数与结果。
- `RSC-CTR`：Research 研究对象和证据消费。
- `FLOW-CTR`：Researchflow 执行和结果传播。
- `LLM-CTR`：模型请求、响应和流。
- `NTF-CTR`：通知事件和投递。
- `SRV-CTR`：Server 组合根和生命周期。
- `INT-CTR`：无法归属于单一生产方的跨模块集成协议。

编号由项目总规划登记，永久不复用。任务编号与契约编号分开维护。专项文档标题可保留旧编号作为迁移说明，但正文引用必须使用新编号。

### 3.3 目标依赖 DAG 与模块职责

**依赖方向（消费者 → 生产方）：**

| 消费者 | 允许依赖的公开生产方 | 边界 |
|---|---|---|
| Data | Platform | 仅公共技术原语；Data 自有 Provider/领域模型/Repository |
| News | Platform | 仅公共技术原语；News 自有来源授权、采集、版本和 Repository |
| Quant | Platform、Data、Notification（事件发布语义完成后） | Data 只经公开 API/DTO；不得 import Data internal |
| Research | Platform、Data、News、Notification（事件发布语义完成后） | 只消费公开数据/证据契约；不依赖 Quant/Researchflow 内部实现 |
| Researchflow | Platform、Data、News、Quant、Research、LLM、Notification | 唯一跨模块流程编排者，只调用公开 Application Port |
| LLM | Platform | 不依赖业务模块；不执行 Tool |
| Notification | Platform | 只消费版本化事件，不反向依赖事件生产方领域 |
| Server | 上述所有模块 | 仅作为唯一组合根；不承接业务规则 |


该表表达逻辑依赖，不表示所有调用都必须跨进程或按表中顺序部署。具体约束：

- Platform 是被依赖的技术原语层，不依赖 Data/News/Quant/Research/Researchflow/LLM/Notification。
- Data 拥有行情/基础数据 Provider、标准化、单位、质量、PIT 和自身 Repository。
- News 拥有来源/Provider/授权、采集、Observation、版本、身份/关系和 Evidence Query Facade。
- Quant 消费 Data 公开 DTO，拥有 Indicator/Factor/Metric/风险计算；不依赖 Research。
- Research 消费 Data/News 公开事实和 Evidence 引用，拥有 Context/Event/Claim/Hypothesis/Scenario；不依赖 Quant/Researchflow 内部实现。
- Researchflow 是唯一跨模块流程编排者，通过公开 Application Port 调用 Data/News/Quant/Research/LLM/Notification；不访问其 Domain 私有对象或 Repository。
- LLM 只提供模型协议与 Provider Adapter，不执行业务 Tool；工具授权、校验和执行由 Researchflow 负责。
- Notification 拥有事件 Schema Registry、Inbox、Subscription、Delivery 和 Channel Adapter；事件生产方拥有业务事件事实，Notification 不反向依赖业务模块。
- Server 是唯一组合根，装配各模块与共享基础设施，不拥有业务规则、Repository 或跨模块 DTO 语义。

禁止形成 Quant↔Research、Platform↔业务模块、News→Researchflow、Notification→业务模块等反向依赖。模块同进程不构成绕过公开 Port 的理由；若真实调用关系与本图不符，先登记并 Review，再调整 DAG。

### 4.1 公共数值与空值语义（字段级规则）

**Decimal string：**
- 语法为普通十进制字符串：可选负号、整数部分、可选小数部分；禁止科学计数法、前导加号、千分位、货币符号、空格和非有限值。
- 是否允许负值、最大整数位、小数位/scale、是否保留尾随零，均由字段/metric Registry 声明；不得由消费者自行格式化。
- 精确价格/金额不得经过 float64 后再格式化成 Decimal string。不能证明源精度时必须显式 degraded/unknown 或失败，不能声称无损。
- 舍入模式必须按字段/metric 显式声明；未声明时禁止自动舍入。

**Integer / number：**
- integer 表示离散计数/数量；JSON number 传输时不得超过 JavaScript 安全整数绝对值 9,007,199,254,740,991，超出必须使用专用字符串字段或拒绝。
- number 仅用于允许浮点误差的统计量；必须声明 unit、范围、精度/舍入和 tolerance。NaN/Inf 禁止序列化。
- `ratio` 与 `percentage_point` 不可混用：0.0125 ratio 表示 1.25%；1.25 percentage_point 也表示 1.25%，但两者数值不同，转换只能在显式 Adapter 边界完成。

**缺失/空值：**
- 字段缺失：仅表示 optional 字段不适用于该 DTO 版本/请求；不得用缺失表达“查询过但未知”。
- 显式 null：表示字段存在但当前无可提供值；required+nullable 字段必须输出 null，不得 omitempty。
- unknown：表示系统无法判断；必须通过该领域定义的 status/reason_code 表达，不把字符串 "unknown" 填进数值字段。
- unavailable：表示依赖/能力不可用；属于状态，不是 0 或 null 的同义词。
- 0：只有来源/覆盖证据证明真实值为零时才允许。
- 字符串字段不允许空字符串作为缺失/未知标记；数组无结果且语义已确认时使用空数组；未执行/未知时按对应状态表达。
- nil slice、空数组、null、字段缺席、零值必须分别进入 Golden。

### 4.2 公共数值规则的执行边界

- Decimal string 是精确价格/金额等字段的传输表达，不意味着所有数值字段一律转 string。
- integer 只用于计数/数量等离散量；超过 JSON/JavaScript 安全整数范围时必须改用字符串或明确的专用编码。
- number 只用于明确允许浮点误差的统计量；比例必须声明 `ratio` 或 `percentage_point`。
- 每个字段必须独立声明 currency、share、lot、volume、amount、price、ratio 等单位，不允许消费者按名称猜测。
- 公共规则不替代 Data Provider 的源精度保留，也不替代 Quant Metric Registry 的 metric-specific 精度/容差。
- Decimal 的最大整数位、小数位、scale、舍入模式必须由具体字段权威方确定；在没有明确决议前，不允许擅自指定统一小数位数。

### 4.3 时间与 PIT 规则

- 绝对时间使用 RFC3339 UTC；交易日使用 `YYYY-MM-DD` 并按 `Asia/Shanghai` 交易日历解释。
- `published_at`、`available_at`、`valid_time`、`system_observed_at`、`fetched_at`、`system_as_of`、`created_at` 各自语义独立。
- `system_as_of` 表示系统在某时点可知的信息边界，不等于交易日、发布时间或当前时间。
- Researchflow CreateRun 确定唯一 `system_as_of`；所有下游调用和重试继承，不得在 Stage 内刷新。
- 缺少来源证据的 `available_at` 必须保持 unknown/null，不能用 published_at 或 fetched_at 推导。
- PIT 能力不足时必须显式拒绝、返回 unavailable 或按字段规则降级，禁止伪造历史可见性。

### 4.4 ID 规则

- `request_id`：单次请求/执行身份；Worker 自己生成当前执行 request_id。
- `originating_request_id`：异步任务创建来源请求。
- `correlation_id`：跨模块工作链关联，不用于去重。
- `trace_id/span_id`：分布式追踪，不是业务主键。
- `event_id`：稳定事件身份，用于 Inbox 去重的组成部分。
- `idempotency_key`：一次命令/副作用意图的稳定键，必须由契约定义作用域及 fingerprint。
- `gateway_request_id` 与 `upstream_request_id` 独立保存，不得覆盖调用方 request_id。

### 4.5 Schema 版本与废弃规则

- 每个跨模块 DTO/Event 使用独立 `schema_version`，格式采用 SemVer：`MAJOR.MINOR.PATCH`。
- PATCH 只允许描述/注释/示例修正，不改变任何序列化或业务语义。
- MINOR 只允许新增 optional 字段或新增独立能力；不得新增会使 exhaustive switch 失效的必需枚举值。
- MAJOR 用于 required/nullable/type/unit/precision/enum meaning/ordering/state transition/authorization/PIT semantics 等破坏性变化。
- 消费者必须按明确支持的 schema_version 解析；未知 MAJOR 或未知必需枚举 fail-safe 拒绝，不得回退到“最新可用”或旧 Schema 猜测。
- Event Schema 注册后不可原地修改；相同 event_type + schema_version 的 schema_digest 必须永久稳定。
- 废弃必须声明 deprecated_since、replacement、迁移说明和 removal_after；至少保留两个兼容发布周期，并在所有直接消费者迁移且 Contract Test 通过后才可删除。

### 6.1 Data v1 兼容与精度保真 v2 决议

Data 当前 `services/market-data/openapi.yaml` 的 v1 Quote/DailyBar 将价格、金额表达为 JSON number，Go Model 使用 float64；成交量使用 int64。该形态继续作为既有 API 兼容契约，不在本轮静默改类型，但**不能作为精确 Decimal 已保证的证据**。尤其金额/价格经过 float64 中转后，不能通过格式化重新声称无损。

跨模块精度敏感消费统一采用版本化 v2 DTO：

- 首批精确接口仅覆盖国内 A 股个股日线：`GET /api/v2/bars/{symbol}/daily`；指数/板块/分时暂不纳入 v2 首批。v2 OpenAPI 与 Go Model 独立定义，不改变 v1。请求显式携带 start_date、end_date（YYYY-MM-DD，首尾包含且 start_date<=end_date）、limit（1..2000，无默认值）、adjustment_basis（none/forward_adjusted/backward_adjusted）和 system_as_of（RFC3339Nano UTC）；所有参数必填，范围与复权口径不得隐式默认。

**响应 Envelope：** `DailyBarsV2Response` 必须包含 schema_version、symbol、period=1d、adjustment_basis、point_in_time=true、system_as_of（与请求完全一致）、quality_status、warnings、bars。所有数组均为 non-null；无数据时 bars=[]，不得返回 null 或补零。每条 Bar 的 system_observed_at 必须非 null。

**错误语义：** 400 表示参数/日期范围/复权枚举/limit 非法或 system_as_of 晚于服务端当前 UTC 时间；401 表示 Data API Key 缺失或无效；404 表示 system_as_of 前无可证明的一致历史版本；503 表示 PIT 版本存储不可用。该历史查询只读取持久化版本，不调用实时 Provider，因此不得返回 502/504 或回退当前 Provider 值。
- `open/high/low/close`：必填 non-null decimal string，单位 CNY/share；禁止科学计数法、千分位和货币符号。缺少任一 OHLC 主字段时该 Bar 不得伪造为完整有效记录，应返回明确质量/数据错误。
- `amount`：required nullable decimal string，单位 CNY；`volume`：required nullable integer，单位 shares。缺失使用 null + quality_reasons，不得填 0；整数必须在 JSON/JavaScript 安全整数范围内，超界拒绝或使用后续专门字符串字段版本，不得静默舍入。
- `change_percent`：required nullable number，unit=`percentage_point`，1.25 表示 1.25%；无来源值时 null + quality_reasons，不填 0。`volume_ratio` 等比例字段必须标记 unit=`ratio`，不得混用。
- `trade_date`：YYYY-MM-DD；时间戳 RFC3339 UTC；`adjustment_basis` 只能是 none/forward_adjusted/backward_adjusted，响应不得用 unknown 伪装请求参数。
- 响应和每条记录保留 schema_version、symbol、trade_date、system_as_of、source/source_version、fetched_at、normalized_at、system_observed_at、adjustment_basis、adjustment_reference_date、adjustment_method、adjustment_factor_source/version、adjustment_factor_available_at、adjustment_factor_system_observed_at、quality_status、quality_reasons、normalization_version。
- `quality_status` 沿用 valid/degraded/stale/invalid/unknown；质量状态与请求状态分离。MA 等历史不足派生字段可 nullable，但 OHLC 主字段不得用 0 代替缺失。

复权字段条件约束：`adjustment_basis=none` 时 adjustment_reference_date、adjustment_method、adjustment_factor_source、adjustment_factor_source_version、adjustment_factor_available_at、adjustment_factor_system_observed_at 必须显式 null；forward_adjusted/backward_adjusted 时全部必填 non-null，且 adjustment_factor_available_at、adjustment_factor_system_observed_at 均不得晚于 system_as_of。任一因子时间证据缺失或超出截止时间，整条复权查询失败，不允许退回当前因子或其他复权口径。

空结果时 bars=[]、quality_status=unknown、warnings 至少包含稳定 no_data reason；不得将空结果标为 valid。

**精度无损要求：**
1. Provider 原始 JSON 数字必须在进入 float64 前以原始数字词法或 decimal 类型解析；可使用等价于 json.Number 的保真路径。
2. Provider 原始数据若本身是 binary float、文本精度不明或缺少源精度声明，不得标记为精确；返回明确 precision-unverifiable 失败，或仅在允许的非精确展示路径标记 degraded。
3. Data 内部 Decimal → v2 JSON decimal string 必须保持数值和 scale 规则；禁止 float64 → decimal string 的伪无损转换。
4. Quant Adapter 只接受 v2 decimal string；v1 number/float64 输入只能用于非精确展示/探索，不得进入精确指标计算或风险决策。v2 的 system_as_of 必须原样回显并用于 Provider 观察版本过滤；Data 不能用当前时间覆盖。
5. 单位转换（例如 percentage_point → ratio）必须在明确 Adapter 边界完成并有 Golden：1.25 percentage_point → 0.0125 ratio；禁止消费者按字段名猜测或重复转换。

本决议保持 v1 兼容，新增 v2 精确输入边界，不要求 WebUI 全部迁移 v2。v2 Schema、Decimal Model、Provider 精度 Fixture 尚未完成，故 DATA-CTR-005 为 `accepted`，证据完成前不能标记 `frozen`。



### 6.2 Research 消费 Data 的公开边界（DATA-CTR-007）

- Research 可以直接消费 Data 的公开 Application/API DTO，但只能通过 Research 自己的 Data Adapter；不得 import Data 的 Domain、Repository、SQL Model 或 Provider Adapter。
- Research 的 Data Adapter 必须传递 Run 的 `system_as_of`，保存返回的 `snapshot_ref/source_ref/source_version/schema_version/system_observed_at/quality_status` 和单位信息；不允许以当前最新数据回填历史查询。
- 价格/金额/数量等精确数值进入 Research Evidence、Claim 或 Scenario 时，必须使用 DATA-CTR-005 的 v2 Decimal DTO。Data v1 float64 仅允许作为明确 degraded 的描述性材料，不得作为精确数值结论、Quant 计算输入或风险门禁证据。
- Research 不能自行换算单位、复权口径或精度；必须由 Data Adapter 按 DATA-CTR-002 显式映射，并将转换规则/版本保留在 Evidence limitations 或来源元数据。
- Data API 认证使用 DATA-CTR-006 的独立 Data API Key，由 Server 通过 Secret 注入 Adapter；Research Domain 不持有明文 Key。
- 首批需要的 Data API/use case 清单（Security Master、Calendar、Daily Bars、Fundamentals 等具体哪些进入 Research Context）、各字段 required/nullable、质量门槛和是否使用 v2，仍需结合真实 Research Context Section Registry 决策。未决期间只阻断对应 Data Adapter，不阻断 Research Domain 和本地 Fixture。

### 7.1 NewsEvidenceQuery Port 语义

**调用方式：** 根 Go Module 内同进程 Application Port。当前不建设 News 独立 HTTP API，也不允许 Research 直接依赖 News Repository/SQL/Adapter。

**用例：**
- `GetEvidence`：按 `news_id` 查询指定新闻版本；未指定 `version_id` 时，只允许按明确的查询时点选择版本，不得默认取数据库当前最新版本冒充历史版本。
- `ListEvidence`：按受控过滤条件、system_as_of、业务时间和内容级别查询已持久化新闻证据；不得隐式触发 Provider 搜索或抓取。

**请求字段语义：**

| 字段 | JSON 类型 | 必填/nullable | 语义与约束 |
|---|---|---|---|
| caller_ref | string | 必填 / non-null | 可信调用主体引用，由上层可信调用上下文传入；不得接受客户端自行声明的身份作为授权事实 |
| purpose_code | enum | 必填 / non-null | 首期仅允许 research_analysis/risk_review/user_display；未知值拒绝；新增用途必须更新 News Policy Registry 与 Schema |
| requested_content_level | string enum | 必填 / non-null | 首期枚举 metadata/summary/snippet/full，与 Research EvidenceAuthorizationRef.content_level 一致；未知值拒绝。请求 full 但当前授权不允许时返回拒绝，不得静默降级成 snippet |
| system_as_of | RFC3339 UTC string | 必填 / non-null | 本次查询知识截止时间；必须 <= 服务端可信 UTC 当前时间；Researchflow Run 必须原样传递，不得由 News 使用当前时间覆盖 |
| filters | object | 必填 / non-null | 首期只允许 news_ids（最多 100）、source_refs（最多 50）、canonical_symbols（最多 100）、published_at_from/to、quality_statuses（valid/degraded/stale/invalid/unknown）；数组元素唯一。禁止任意 SQL、动态字段名、任意 URL 和任意排序表达式 |
| business_time_from / business_time_to | RFC3339 UTC string? | optional / nullable | 业务时间范围；与 system_as_of 独立解释；两者同时存在时 from 必须不晚于 to |
| page_size | integer | 必填 / non-null | 范围 1..100；调用方必须显式传值，不设隐式默认值。超过范围返回 validation Fault |
| cursor | string? | 首屏省略；后续页必填 / non-null | 不透明、防篡改的分页令牌；不得由调用方拼装或修改 |

**响应字段语义：**

| 字段 | JSON 类型 | 必填/nullable | 语义与约束 |
|---|---|---|---|
| items | array | 必填 / non-null | 当前页证据记录；无结果返回空数组，不返回 null |
| next_cursor | string? | 无后续页时 null | 下一页游标；不能通过空字符串表示结束 |
| snapshot_ref | string | 必填 / non-null | 固定本次分页会话的不可变结果集快照；首屏创建，后续页必须复用 |
| system_as_of | RFC3339 UTC string | 必填 / non-null | 回显实际使用的知识截止值，必须与请求一致 |
| diagnostics | array | 必填 / non-null | 查询执行诊断引用；无诊断时为空数组，不混入业务证据内容 |

每个 Evidence Item 至少提供稳定的 `news_id`、`version_id`、`source_ref`、`content_level`、`published_at`、`available_at`、`system_observed_at`、`system_as_of`、`content_fingerprint`、`authorization_ref` 和质量摘要。`system_observed_at` 由 News 将该版本关联 Observation 的 observed_at 投影而来；不能使用 news_items.first_observed_at 代替。字段的 required/nullable 与载荷访问策略必须由 News DTO Schema 固定；无来源证据的 available_at 保持 unknown/null。

**错误与部分结果：**
- 参数结构/枚举非法：`news.evidence.invalid_query`，class=validation，retryable=false。
- caller 无权访问请求内容级别：`news.evidence.access_denied`，class=forbidden，retryable=false；不得降级返回更高敏感级别内容。
- 历史时点不可证明：`news.evidence.pit_unavailable`，class=unavailable，retryable=false；不得用当前版本替代。
- Cursor 签名/过滤指纹不匹配：`news.evidence.cursor_invalid`，class=validation，retryable=false。
- Cursor 过期：`news.evidence.cursor_expired`，class=conflict，retryable=false；调用方必须从第一页重新查询。
- 快照缺失：`news.evidence.snapshot_unavailable`，class=unavailable，retryable=false；不得静默重建快照。
- 查询存储依赖失败：使用 PLAT-CTR-001 Fault，按幂等只读查询和 deadline 策略决定是否可重试。
- 本 Port 查询持久化证据，不承担实时 Provider 部分成功语义；Provider 采集失败由 News 采集用例和 Observation 单独表达。

**分页一致性：** Cursor 必须绑定 caller_ref、purpose_code、requested_content_level、规范化 filters 指纹、system_as_of、snapshot_ref、排序版本和稳定唯一排序键。首屏创建不可变结果集快照；后续页沿用同一快照。首期固定排序版本 `news-evidence-v1`，排序为 system_observed_at DESC、news_id ASC、version_id ASC；快照与 Cursor TTL 均为 15 分钟。游标过期、篡改、过滤条件不一致或快照不可用时明确失败，不得静默回退到 offset/current snapshot。

**尚待证据：** Go DTO required/nullable 的 JSON Schema、Cursor token 的 HMAC-SHA256 签名与 key_id 轮换实现、15 分钟 TTL 的存储/过期 Golden、错误码注册和真实 Facade Contract Test。语义参数不再留待决：purpose_code=research_analysis/risk_review/user_display；requested_content_level=metadata/summary/snippet/full；filters 仅 news_ids(≤100)、source_refs(≤50)、canonical_symbols(≤100)、published_at_from/to、quality_statuses(valid/degraded/stale/invalid/unknown)；page_size=1..100 且无默认值。以上证据缺口阻断 Research/Researchflow 真实查询 Adapter 的 L2，不阻断 News 内部 Domain 和采集流程。

### 7.2 AuthorizationRef 与当前授权复核

`AuthorizationRef` 是不透明、不可变的审计快照引用，不是访问令牌，不授予未来持续访问权。

快照记录至少包含（与 Research EvidenceAuthorizationRef DTO 统一）：

| 字段 | 类型 | 语义 |
|---|---|---|
| authorization_ref | string | 不透明稳定引用 |
| policy_owner | enum | data/news/quant/research；实际拥有授权决策权的模块 |
| policy_version | string | 不可变策略注册版本；decision_fingerprint 覆盖本次判定采用的 Provider Output Policy、Source Policy、Endpoint Policy 等具体版本 |
| decision | enum | allowed/denied/conditional/unknown；表示本次请求的决策结果，不与来源策略状态 approved/restricted/pending/revoked 混用 |
| purpose_code | enum | research_analysis/risk_review/user_display；当时获准/拒绝的受控用途 |
| content_level | enum | metadata/summary/snippet/full；决策覆盖的内容级别 |
| subject_ref | string | 被授权调用主体（caller_ref）的稳定引用 |
| resource_ref | string | 本次授权决策覆盖的内容/来源/Endpoint 资源引用 |
| decided_at | RFC3339 UTC | 决策时间 |
| expires_at | RFC3339 UTC/null | 必填字段 / nullable；null 表示策略未设置固定过期，不代表永久授权 |
| conditions | array<string> | 稳定 condition_code 列表；无条件为空数组，不承载任意策略 JSON |
| decision_fingerprint | string | 决策输入和策略版本的稳定指纹 |

授权判定必须同时考虑 Provider Output Policy、Source Policy 和 Endpoint Policy 的适用交集；更严格的限制优先。历史 AuthorizationRef 用于解释“当时为何允许/拒绝”，每次当前内容读取仍必须检查策略是否撤销、过期、用途是否匹配、内容级别是否仍允许。当前授权 denied/unknown 或授权服务不可用时，受限内容默认拒绝；conditional 仅在 News 验证全部 condition_code 均满足后允许，否则拒绝；不得因历史 allowed 放行。

News 负责产生并验证授权事实；Research 只保存不透明引用和必要审计元数据，不复制授权策略、不签发引用、不自行推断权限。Research 派生内容仍需保留原始来源授权链。

Schema/Golden 尚未生成，故本契约为 `pending_evidence`；decision 枚举与 conditions 的结构必须在 News Schema 中固定后才可冻结。

### 7.3 News PIT 与 Cursor 过滤顺序

对查询知识截止时间 `T = system_as_of`：

1. 先过滤 `news_observations.observed_at <= T` 的 Observation；只允许使用这些 Observation 能证明在 T 时已存在的 news_item/version/identity。对每个 Evidence Version，将其最早一条符合条件的 Observation.observed_at 投影为 system_observed_at。不得用 news_items.first_observed_at 为后续版本补出历史可见性，也不得先读取当前 Identity/Classification/Relation 再回填历史状态。
2. 再检查内容 `available_at`。严格 PIT 仅允许 available_at 非 null 且 available_at<=T 的记录；available_at>T 或 unknown/null 均不得作为 T 时点已公开可得的事实返回；不得从 published_at、provider_time、fetched_at 或 system_observed_at 推导。
3. 在 T 时可见的版本集合中按业务时间过滤/排序；published_at 是来源声明时间，不等于系统可知时间。Identity/Classification/Relation 必须按各自追加式断言和 observed/valid time 重建 T 时状态。
4. 同一 news_id 多版本时，选择 T 时已观察到且符合业务查询条件的版本；不得以当前最新版本覆盖历史版本。
5. Cursor 固定 caller_ref、purpose_code、requested_content_level、规范化 filters 指纹、system_as_of、snapshot_ref、排序版本和稳定唯一排序键；首屏创建不可变结果集快照，后续页只读取该快照。首期排序版本 news-evidence-v1：system_observed_at DESC、news_id ASC、version_id ASC。page_size 范围 1..100 且无默认值；快照与 Cursor TTL 均为 15 分钟。过期、篡改、过滤条件不一致或快照不可用必须明确失败。
6. 后续页必须读取相同 snapshot_ref；快照失效时返回明确 cursor_expired/snapshot_unavailable，不得静默创建新快照继续翻页。

排序主键和次级唯一键由 News 实现定义并写入排序版本；不允许消费者传入任意 sort 字段。

### 8.1 Quant Registry 与首批计算语义

每个 `metric_code` / `indicator_code` / `factor_code` 必须在 Quant Registry 注册，注册记录至少声明：

- `code`、`schema_version`、`value_type`、`unit`；
- `precision`：最大整数位、小数位/scale、舍入模式、误差容忍；
- `minimum`、`maximum` 或明确无界；
- `algorithm_version`、输入字段/窗口/复权要求；
- 参数 Schema、required/default/range；
- 缺失样本策略、minimum_coverage、quality_status 规则；
- 是否支持 lower_bound/upper_bound，以及区间语义。

Registry 是指标解释的唯一权威。Researchflow 只按 code + schema_version 验证和保存，不推断单位、精度或算法。Research 不直接重算 Quant 指标，也不得自行将 ratio 乘 100 或将 decimal string 转 float64 后宣称精确。

### 8.2 首批 Factor 决议

首批 Factor 固定为：

| factor_code | 定义 | 输入与边界 |
|---|---|---|
| momentum_20d | 最近 20 个有效交易日收益动量 | 需要 21 个连续有效复权收盘价；`close_t / close_(t-20) - 1`；unit=ratio |
| momentum_60d | 最近 60 个有效交易日收益动量 | 需要 61 个连续有效复权收盘价；`close_t / close_(t-60) - 1`；unit=ratio |
| volatility_20d | 最近 20 个 simple daily return 的波动 | 需要 21 个连续有效复权收盘价；样本标准差 ddof=1；不年化；unit=ratio |

统一边界：
- 首批按单证券时间序列输出，不做横截面排序或行业中性化。
- 复权口径必须固定并写入输入快照；同一窗口不得混合不同 adjustment_basis/reference_date。
- 不填充缺失交易日，不把缺失样本当 0；有效样本不足返回 `insufficient_data` / `unknown`，不返回可参与排序的数值。
- 首批不设置隐式默认值；factor_code + schema_version 固定参数 Schema。无参数的因子也必须使用显式空参数对象或专属无参 DTO，不允许任意 map。
- 横截面 universe_ref、trade_date、证券主数据版本、行业分类版本、winsorize/zscore/rank、中性化属于后续扩展，登记为 `deferred`，不阻断首批三个时间序列因子。
- 首批算法实现必须提供固定 Golden：正常窗口、缺失日、停牌、复权基准不一致、零/负无效价格、边界样本不足。

此决议不代表算法代码或 Schema 已实现；QNT-CTR-003 保持 `pending_evidence`，证据完成前不进入 `frozen`。

### 8.3 Metric Registry 与首批 Indicator 规则

**Registry 结构：**

每个指标注册项必须有稳定的 `code` 和 `schema_version`，至少定义：

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| code | string | 是 | 模块命名空间内唯一且永久稳定；不得因算法升级改名复用 |
| schema_version | string | 是 | 参数/结果 Schema 版本，与模块软件版本分离 |
| value_type | enum | 是 | decimal_string / integer / number，固定该 code 的 JSON 类型 |
| unit | string | 是 | 明确 currency/share/price/ratio/percentage_point 等单位；不允许空值或靠名称推断 |
| precision | object | 是 | max_integer_digits、max_fraction_digits/scale、rounding_mode、tolerance |
| range | object | 是 | min/max 与 value_type 一致；无边界必须显式声明 unbounded |
| algorithm_version | string | 是 | 算法语义版本；算法改变不得静默复用旧版本 |
| input_requirements | array | 是 | 字段、周期、复权、PIT、质量和快照要求 |
| parameters_schema | object | 是 | typed 参数 Schema；明确 required/default/range/enum |
| quality_policy | object | 是 | minimum_coverage、缺失处理、质量状态和不可用条件 |
| supports_interval | boolean | 是 | true 时 lower_bound/upper_bound 类型与 value 一致；false 时专属 Schema 省略区间字段 |

`precision.tolerance` 的 JSON 类型必须与 value_type 匹配。Decimal string 禁止科学计数法、千分位和货币符号；number 必须声明舍入和 Golden 容差；NaN/Inf 不得序列化。Registry 缺失或版本未知时，调用方必须收到 unsupported_metric/unsupported_schema，不得猜测单位或按旧版本解析。

**Indicator 首批范围：**

首批固定八项：`sma`、`ema`、`return`、`volatility`、`rsi`、`macd`、`atr`、`bollinger`。所有参数均由调用方显式传入；v1 不设置隐式默认值。整数窗口范围 1..1000；涉及多个窗口时必须满足对应大小关系。参数缺失、越界或枚举未知均返回 validation Fault。

| indicator_code | v1 参数 | v1 算法约束 |
|---|---|---|
| sma | window | 最近 window 个有效 close 的算术平均；不足返回 insufficient_data |
| ema | window、seed_method | seed_method 固定枚举 sma；首个 EMA 使用首 window 个 close 的 SMA，之后 alpha=2/(window+1) |
| return | window、return_basis | return_basis=simple/log；simple 为 close_t/close_(t-window)-1，log 为 ln(close_t/close_(t-window))；unit=ratio |
| volatility | window、return_basis、annualization_factor | window 范围 2..1000；基于指定收益序列的样本标准差 ddof=1；annualization_factor 为正整数且必须显式传入，表示年交易周期数，年化结果乘 sqrt(factor) |
| rsi | window、smoothing_method | smoothing_method 固定 wilder；初始平均涨跌幅取首 window 个变化的算术平均，之后按 Wilder 平滑 |
| macd | fast_window、slow_window、signal_window | fast_window < slow_window；EMA seed 使用 SMA；DIF=EMA_fast-EMA_slow，DEA=EMA_signal(DIF)，histogram=2*(DIF-DEA) |
| atr | window、smoothing_method | true_range=max(high-low, abs(high-prev_close), abs(low-prev_close))；smoothing_method 固定 wilder，初始值用 SMA |
| bollinger | window、multiplier、stddev_method | middle=SMA；stddev_method 固定 population(ddof=0)；upper/lower=middle±multiplier*stddev，multiplier>0 |

所有价格输入必须声明相同 adjustment_basis/reference_date；ATR 的 high/low/close 必须使用相同复权口径。缺失交易日不补零、不前向/后向填充；窗口有效样本不足返回 insufficient_data。每项指标提供正常、边界、缺失、异常、复权切换 Golden。

此处算法决议为 `accepted`；Registry JSON Schema、指标专属参数/结果 Schema、Golden 和 Contract Test 尚未形成，因此 QNT-CTR-001/002 仍为 `pending_evidence`。

### 10.1 FLOW-CTR-004 Stage 结果分层决议

跨模块 Stage 执行结果采用三层表达，禁止将执行状态、业务结论和诊断状态塞入同一个 status：

1. **Orchestrator-owned envelope**：由 Researchflow 在执行边界写入 `run_ref`、`stage_ref`、`attempt_ref`、`stage_code`、`template_version`、执行时间和状态。Provider 不得自行生成或覆盖这些字段。
2. **Typed domain payload**：由 Stage Provider 所属领域模块定义，必须带 `schema_version` 与稳定 `output_type`；其字段、单位、精度、业务枚举由对应生产模块唯一维护。Researchflow 只验证注册类型并持久化引用，不解释领域字段。
3. **Quality/diagnostic sidecar**：质量摘要使用领域质量契约；诊断引用使用 Platform Diagnostics 的 Observation/evidence_ref 规则。诊断失败不得伪装成业务拒绝，质量 degraded 不得改写 Stage 执行状态。

执行失败通过 Platform Fault/稳定错误映射返回；有效业务结果（例如 RiskDecision=reject/unknown）必须作为领域 payload 保存，不能转成技术 Fault。最终报告通过 run_ref/stage_ref/attempt_ref 和 typed output_ref 追溯，不复制或重定义领域事实。

**Retry Policy 的硬约束**

- `max_attempts` 为正整数且包含首次执行；`retryable_reason_codes` 必须是稳定白名单，不支持通配符。

### 12.2 NTF-CTR-002 幂等键与 Delivery 唯一性

- Inbox 唯一键：`(source_module, event_id)`。
- Publish 幂等唯一键：`(source_module, idempotency_key)`；同一 source_module 范围内 idempotency_key 全局唯一，不按 event_type 分桶，生产方不得跨发布意图复用。
- 两项唯一约束都必须与 payload fingerprint 比较；相同键且相同 fingerprint 返回原结果，不重复 fan-out；相同键不同 fingerprint 返回 idempotency_conflict。
- Delivery 唯一键固定为 `(source_module, event_id, subscription_id, subscription_version, channel_ref, channel_config_version, template_id, template_version, recipient_ref)`；event_id 仅在 source_module 范围内唯一。上述版本均为计划快照的一部分，不允许在原版本上原地修改。
- delivery_idempotency_key 在同一 Delivery 全部 Attempt 间保持稳定；其作用域为 channel_ref + recipient_ref + delivery_id。只有 Channel Capability 声明支持幂等且完成验证时才发送该键。
- Subscription、Channel、Template 任何影响匹配/目标/渲染/发送行为的变更都必须产生新版本；历史 Delivery 始终引用原版本。
- Outbox/Inbox 只保证业务事件到 Notification 的本地可靠接收，不代表外部渠道 exactly-once。

### 12.3 NTF-CTR-003 投递状态与重试边界补充

- 状态迁移必须以 Delivery.version CAS 为准；每次成功迁移递增 version，并追加不可变状态事件。
- `sending -> skipped` 仅在可证明渠道调用尚未发出时允许；一旦请求可能到达渠道，必须进入 `unknown` 或等待明确渠道回执，禁止以退订/取消覆盖外部副作用不确定性。
- `unknown -> retry_wait` 仅在对账证明未接受，或 Channel 支持且已验证同一幂等键安全重放时允许；否则保持 unknown。
- `max_attempts` 包含首次发送，必须为正整数；`max_elapsed`、`per_attempt_timeout`、总 deadline 必须显式配置且为正值；不设置隐式全局重试默认值。
- 自动重试仅针对渠道明确 rejected 且 reason_code 在该 Channel 的 retryable 白名单内；Retry-After 只能延后 next_attempt_at，不得越过总 deadline。ambiguous、timeout-after-write、连接中断且无法证明未发送均为 unknown，不计作可自动重试失败。
- 渠道能力必须逐 Channel 注册：supports_idempotency、supports_delivery_lookup、supports_retry_after、max_payload_bytes；未验证能力按 false/unknown 处理，不能按供应商宣传默认开启。
- `sent` 仅表示渠道明确接受，不代表送达终端用户；各渠道若有 delivered/read 回执，必须使用独立 DeliveryReceipt 事实，不反向改写 sent 的含义。

### 13.1 Server Bootstrap 与资源生命周期

Server 是唯一资源所有者和组合根。启动顺序固定为：

1. 读取并校验各模块配置/Secret；此阶段不得启动 Worker 或接受请求。
2. 初始化日志与公共 Platform 配置快照。
3. 创建共享 SQL/Redis/HTTP Client 等基础资源，每种共享资源由 Server 只创建一个实例并明确 Close 所有权。
4. 显式执行各模块 Migration；按依赖顺序和 namespace 注册，不由模块启动函数自行重复执行。
5. 构造各模块 Repository、Adapter、Application Service 和公开 Port；模块只接收依赖，不自行 new 共享 DB/Redis/HTTP Client。
6. 注册 HTTP Handler、访问策略和中间件；所有路由显式声明 anonymous/owner/service 权限。
7. HTTP Listener 与 Worker Manager 启动；Worker 在全部依赖和迁移就绪前不得 claim 任务，readiness 在两者达到可服务状态后才成功。

任一步骤失败，按已创建资源的逆序释放；不得留下部分运行的 Worker。

关闭顺序固定为：

1. readiness 置为不可服务，停止接收新的业务请求和新的任务派发。
2. 停止 Scheduler/Worker claim，向运行中任务发出取消信号并在配置的 drain deadline 内等待。
3. 超过 drain deadline 的 Attempt 必须按 Researchflow fencing/写入撤权规则处理；不能仅关闭进程就宣称 Attempt 已安全终结。
4. 关闭 HTTP Server 并等待在途请求结束。
5. 按创建逆序关闭模块持有的资源句柄及共享 Redis/SQL/HTTP Client；共享资源只由 Server 关闭一次。
6. 完成日志 flush/进程退出。

资源职责：
- Server 拥有共享连接实例；模块 Repository 仅借用连接，不得 Close 共享连接。
- 每个模块拥有自己的 SQL Schema、Repository、Migration 内容；Server 只负责集中注册和执行。
- Redis 是可选共享基础设施；没有明确跨进程协调/缓存需求的模块不得为了统一而强制依赖。
- HTTP Client 按 Platform 安全 Policy 统一创建；业务模块只提供逻辑 Dependency 和 DestinationPolicy，不创建绕过安全边界的裸 Transport。
- 配置启动后为不可变快照；模块不得在 Handler/Domain 中直接读取环境变量或创建第二份全局配置。

本契约语义已接受，但 SRV-CTR-001 状态为 `pending_evidence`；真实启动失败回滚、重复实例检查、Worker drain、数据库/Redis 故障和进程关闭测试属于模块级证据与 L3 集成验收。

## 17. 每项契约达到 frozen 的最低证据

每项契约必须在登记行补齐证据路径，至少满足；第一批场景矩阵见 [跨模块契约样例与 Golden 验收矩阵](./跨模块契约样例与Golden验收矩阵.md)：

1. 机器可校验 Schema：请求、响应、事件或持久化边界适用的 Schema。
2. Golden：正常、边界、异常、兼容样例；明确 null、缺失、零值、空数组。
3. Contract Test：生产方序列化/反序列化与消费者解析一致；断言语义，不只断言能解析。
4. 状态机契约：合法转换、非法转换、重复命令、并发竞态、终态不可逆（适用时）。
5. 时间/PIT：system_as_of 前后边界、available_at unknown、历史版本可见性（适用时）。
6. 幂等：相同键同 fingerprint 返回同结果，不同 fingerprint 冲突；外部 ambiguous outcome 不盲目重试（适用时）。
7. 安全：Secret 脱敏、授权拒绝、SSRF、内容级别限制（适用时）。
8. 消费者映射：每个直接消费者的 DTO/Adapter 字段映射与未知字段策略。
9. 版本兼容：当前版本、向前/向后兼容边界和废弃策略。
10. 可复现执行记录：测试命令、结果、提交 SHA 和证据文件路径。

任何一项缺失，状态保持 `pending_evidence`；如果语义仍不明确，必须回到 `pending_decision`。
