1. 当前材料已经覆盖主要模块职责和目标依赖方向，但尚未形成可逐条追踪的完整契约登记簿。

7. 本次登记不依赖其他分支编译或 CI，也不宣称已对所有模块分支的最新源码完成复核。生产实现的 L3 状态必须由各模块实际环境验收记录证明。

## 2. 契约状态口径

| 状态 | 本目录使用标准 | 开发影响 |
|---|---|---|
| `pending_decision` | 关键语义、生产责任或边界尚未决定 | 只阻断需要猜测该语义的调用点 |
| `accepted` | 项目统一决策已确定语义和责任边界 | 可按该语义设计/实现；不能声称已冻结 |
| `pending_evidence` | 语义已确定，缺 Schema、Golden、消费者映射或必要 Contract Test | 可开展实现和测试；依赖该契约的调用点不得宣称 L2 |
| `frozen` | 版本、Schema、Golden、消费者映射、边界测试和必要兼容性测试均通过 | 可作为稳定实现基线 |
| `deferred` | 明确延期、目标批次和不阻断范围 | 仅阻断延期项明确列出的调用点 |
| `rejected` | 已否决并记录替代方案 | 禁止继续作为有效契约引用 |

**禁止将状态混用：**
- `closed` 是某次设计决策已结束的工作流描述，不替代契约状态。
- `implemented` 不是契约冻结状态。
- CI 通过不自动使契约 frozen；CI 失败也不自动使无关契约失效。
- `frozen` 必须有可定位的 Schema、Golden、测试文件和通过记录，不能只凭文档自述。

### 4.1 公共数值规则的执行边界

- Decimal string 是精确价格/金额等字段的传输表达，不意味着所有数值字段一律转 string。
- integer 只用于计数/数量等离散量；超过 JSON/JavaScript 安全整数范围时必须改用字符串或明确的专用编码。
- number 只用于明确允许浮点误差的统计量；比例必须声明 `ratio` 或 `percentage_point`。
- 每个字段必须独立声明 currency、share、lot、volume、amount、price、ratio 等单位，不允许消费者按名称猜测。
- 公共规则不替代 Data Provider 的源精度保留，也不替代 Quant Metric Registry 的 metric-specific 精度/容差。
- Decimal 的最大整数位、小数位、scale、舍入模式必须由具体字段权威方确定；在没有明确决议前，不允许擅自指定统一小数位数。

### 4.2 时间与 PIT 规则

- 绝对时间使用 RFC3339 UTC；交易日使用 `YYYY-MM-DD` 并按 `Asia/Shanghai` 交易日历解释。
- `published_at`、`available_at`、`valid_time`、`observed_at`、`fetched_at`、`system_as_of`、`created_at` 各自语义独立。
- `system_as_of` 表示系统在某时点可知的信息边界，不等于交易日、发布时间或当前时间。
- Researchflow CreateRun 确定唯一 `system_as_of`；所有下游调用和重试继承，不得在 Stage 内刷新。
- 缺少来源证据的 `available_at` 必须保持 unknown/null，不能用 published_at 或 fetched_at 推导。
- PIT 能力不足时必须显式拒绝、返回 unavailable 或按字段规则降级，禁止伪造历史可见性。

### 4.3 ID 规则

- `request_id`：单次请求/执行身份；Worker 自己生成当前执行 request_id。
- `originating_request_id`：异步任务创建来源请求。
- `correlation_id`：跨模块工作链关联，不用于去重。
- `trace_id/span_id`：分布式追踪，不是业务主键。
- `event_id`：稳定事件身份，用于 Inbox 去重的组成部分。
- `idempotency_key`：一次命令/副作用意图的稳定键，必须由契约定义作用域及 fingerprint。
- `gateway_request_id` 与 `upstream_request_id` 独立保存，不得覆盖调用方 request_id。

## 17. 每项契约达到 frozen 的最低证据

每项契约必须在登记行补齐证据路径，至少满足：

1. 机器可校验 Schema：请求、响应、事件或持久化边界适用的 Schema。
2. Golden：正常、边界、异常、兼容样例；明确 null、缺失、零值、空数组。
3. Contract Test：生产方序列化/反序列化与消费者解析一致；断言语义，不只断言能解析。
4. 状态机契约：合法转换、非法转换、重复命令、并发竞态、终态不可逆（适用时）。
5. 时间/PIT：system_as_of 前后边界、available_at unknown、历史版本可见性（适用时）。
6. 幂等：相同键同 fingerprint 返回同结果，不同 fingerprint 冲突；外部 ambiguous outcome 不盲目重试（适用时）。
7. 安全：Secret 脱敏、授权拒绝、SSRF、内容级别限制（适用时）。
8. 消费者映射：每个直接消费者的 DTO/Adapter 字段映射与未知字段策略。
9. 版本兼容：当前版本、向前/向后兼容边界和废弃策略。
10. 可复现执行记录：测试命令、结果、提交 SHA 和证据文件路径。

任何一项缺失，状态保持 `pending_evidence`；如果语义仍不明确，必须回到 `pending_decision`。
