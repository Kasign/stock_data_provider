## 1. 盘点结论

本轮核对 repair_all 的九份模块卡点文档、RepairAll 跨模块修复记录、模块文档目录及远端分支。

- 所有模块分支均已存在，不新建分支。
- 模块分支负责模块自身实现和文档；repair_all 负责依赖协调、跨模块集成、冲突处理和完整验收。
- 卡点不等于模块代码任务。必须区分模块内可执行、上游/下游协作、项目契约决策、真实外部环境证据。
- 不把 repair_all 的代码盲目复制到模块分支；先比对双方实现和提交差异，只回迁目标模块职责内的改动。
- 本轮只建立任务拆分计划，未修改生产代码。

## 4. 模块任务包细化

### 4.1 Data（feat/data）

**D-01 DailyBars v2**
1. 复核 D1/D2 记录和 Provider 代码，不重复 CalendarRef Application Port、PIT 日历读取及已有精确值路径。
2. 对 ChangePercent 来源/派生规则、原始 lexical scale、QFQ/HFQ 精确调整、Amount 单位、ProviderTime/provider_data_version 缺失语义逐字段建立证据表。
3. 只有证据充分的字段才进入版本化 DTO、Schema、Golden；不修改 v1，不将 float64 或 DB DECIMAL scale 反推为来源精度。
4. Application Port 与 HTTP DTO 同步版本；CalendarRef 必须与同次质量评估绑定。

**D-02 DATA-CTR-007**
1. 复用已有交易日历 Snapshot Repository。
2. 明确 DailyBars Snapshot Payload、内容寻址 SnapshotRef、Manifest/Payload 绑定、AuthorizationRef 和精确读取语义。
3. 明确 Data 到 Research Evidence 的 source_ref/version/locator 映射字段；Data 只提供数据事实，Research 负责自身 Evidence 映射。
4. 增加内容损坏、幂等、并发和质量门禁测试。
5. 项目登记簿只能由契约 Owner 按准入条件更新，Data 不自行冻结项目契约。

**D-03 Provider 证据**
- DATA-003 AvailableAt、DATA-004 估值公式/ProviderReportDate、DATA-005 Freshness、DATA-006 Go/Python parity、DATA-007 多 Provider 样本只补明确缺口。
- 权限未变、样本相同、日期相同的探测不重复执行。
- 缺供应商数据、权限或固定 Python 基线时标记 EXTERNAL/NOT_COMPARABLE。

退出条件：每个字段有来源、语义、版本、样本、测试和精确 SHA；未满足准入条件的契约继续 deferred。

### 4.2 Platform（feat/platform）

**P-01 公共原语复核**
- 对 Fault、Diagnostics、HTTP Client、Secret、Storage/Migration、Time、Request ID 做定点审查。
- PLAT-BLK-01/02/03/04/05/06/07 多数属于 Server、领域 Owner 或部署运维，不得机械转成 Platform 开发。
- PLAT-BLK-08 项目级验收清单状态由 feat/design_doc / 项目规划 Owner 修订，Platform 只提供事实。
- 只有可复现公共缺陷、冻结契约实现偏差或多个真实消费者共同缺口才修改代码。

退出条件：明确给出 NO_LOCAL_TASK 或具体缺陷证据；不新增重复抽象。

## 6. 分支执行与合并规则

1. 各模块先在自己的分支复核当前 HEAD、模块任务规划、当前状态、卡点文档和契约。
2. 对照 repair_all 记录，区分“模块分支已有”“仅 repair_all 已有”“双方实现不同”“均未实现”。
3. 只回迁目标模块职责内的改动；不得整分支覆盖、盲目 cherry-pick 全部 repair_all 提交或把无关提交带入模块分支。
4. 一个任务包只有一个主责模块。跨模块工作拆成生产者契约/实现、消费者适配、Server 装配、repair_all 集成四个交付。
5. 生产者先合并到共同集成基线，消费者再适配，Server 最后接线。
6. 模块分支各自执行专项 CI；跨模块批次合并后执行完整 Integration CI。
7. 记录源分支 SHA、提交 SHA、冲突处理、目标分支 SHA、CI Run 和精确被测 SHA。文档提交不冒充代码 CI。
8. 代码 CI 与真实 Provider/Gateway/生产环境证据分开判定。

## 8. 模块交付标准

模块任务包完成时，更新模块自己的当前任务状态、模块总任务规划（任务范围变化时）和对应卡点文档。交付必须记录任务编号、问题证据、代码路径/调用链、修改文件、契约编号/版本、上下游依赖、测试命令、CI Run、精确 SHA、外部证据和未完成条件。

本计划建立后，执行方式调整为：模块分支完成模块任务，repair_all 管理依赖、合并和集成。跨模块问题不会消失，但每段代码均有唯一 Owner、明确前置和验收责任。
