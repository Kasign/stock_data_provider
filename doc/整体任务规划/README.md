## 过期文档处理原则

- 历史 Review、验收快照和旧方案保留为审计材料，不作为当前代码状态、当前分支拓扑或模块任务进度的依据；若其中存在与现行架构冲突的结论，以项目总览、doc/contract 登记簿和现行治理规范为准。
- Data 与 Root Server 模块化单体目标以架构方案为准；契约差异和跨模块裁决以 doc/contract/decisions/ 中的最新决议为准。
- Platform 当前实施状态以 `doc/platform/` 的 README 和路线图为准；本目录旧平台建设方案只保留历史背景。
- 契约编号迁移台账尚有未完成的删除门槛，不得提前删除。
- 旧路径兼容入口已删除；发现旧路径引用时应直接修正为分类目录中的正式路径，不再恢复重复文档。

## 维护规则

1. 整体目标与模块边界只在项目总览维护。
2. 契约状态、冻结范围和版本只在 `doc/contract/` 维护；字段定义由契约生产模块专项文档维护。
3. 模块实施进度以各模块自己的 `doc/<module>/` 为准。
4. 新文档按主题进入分类目录，不再直接堆放在本目录根层。
5. 分类文档路径是唯一正式路径；新增、移动或删除文档时，必须同步检索并修复全仓链接。
