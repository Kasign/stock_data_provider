## 过期文档处理原则

- 历史 Review、验收快照和旧方案保留为审计材料，不作为当前代码状态或当前分支拓扑的依据。
- Data 与 Root Server 模块化单体决策以架构方案和契约目录中的最新决议为准。
- Platform 当前实施状态以 `doc/platform/` 的 README 和路线图为准；本目录旧平台建设方案只保留历史背景。
- 契约编号迁移台账尚有未完成的删除门槛，不得提前删除。
- 本次迁移保留旧路径兼容入口；后续确认全仓链接完成迁移后，再考虑移除兼容文件。

## 维护规则

1. 整体目标与模块边界只在项目总览维护。
2. 契约状态只在契约目录维护；字段定义由契约生产模块专项文档维护。
3. 模块实施进度以各模块自己的 `doc/<module>/` 为准。
4. 新文档按主题进入分类目录，不再直接堆放在本目录根层。
5. 任何删除兼容入口或历史材料的操作，必须先检索并修复全仓链接。
