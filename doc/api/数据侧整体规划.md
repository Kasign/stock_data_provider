## 1. 总体目标

完成国内 A 股数据服务的 Go 原生化和可验证交付，使数据能力不仅“代码存在”，还具备可解释的数据质量、明确的时间与单位语义、可追溯的 Provider 来源、稳定的持久化行为和可重复的真实环境验收证据。

最终交付必须满足：

1. 国内 A 股主要数据域的服务能力和 Provider 能力边界明确。
2. 数据标准化不伪造缺失值、不混淆单位、复权口径和时间语义。
3. 统一诊断体系能够发现并结构化呈现数据问题，且不重复建设已有框架。
4. 财务、估值、公司行动、历史成分等时点数据满足可证明的 PIT 约束；不能证明时明确降级或标记未知。
5. API、数据库、Provider 原始响应和标准化结果之间可追溯、可对账。
6. 通过代码测试、真实 Provider 请求和部署验收分别提供证据，不互相替代。

### 阶段 B：DailyBar 复权与交易边界质量收尾（P0）

**目标：** 使日 K 数据的复权口径、日期边界、交易状态和诊断计数可验证。

任务：
1. 按 Provider 核对 none / forward_adjusted / backward_adjusted 的请求参数、实际响应证据、AdjustmentBasis、AdjustmentMethod、AdjustmentRefDate、SourceVersion 和因子/公司行动来源。
2. 不支持复权的 Provider 返回 not_supported；不把请求参数伪装成源端回显；没有参考日证据时保持 unknown。
3. 跨 Provider 比较仅限相同证券、日期集合、复权口径、参考基准、单位和可比较质量状态。
4. 结合交易日历、证券交易状态及公司行动，区分停牌、临停、非交易日、新股上市初期、正常无数据和 Provider 漏数。
5. 审核日期区间包含语义、Asia/Shanghai 日期、未来日期、自动回溯区间和当前日 Partial。
6. 明确解析拒绝、重复交易日、规范化丢弃、越界数据和 limit 截断的计数口径，防止重复计数。
7. 补足真实样例和回归测试；不改动已正确的 Provider 复权算法，不放宽质量门禁。

**完成标准：** 各 Provider 能力矩阵有代码/测试/真实请求证据；交易边界状态可解释；问题计数无重复或遗漏的已知缺陷；不可比较数据明确 not_comparable。

**当前状态：** 多复权口径 Probe 参数和结果字段已有实现；复权元数据、交易日历和 Partial 基础已存在；逐 Provider 真实复权证据及交易边界/计数审计仍需完成。

## 5. 统一状态定义

所有阶段和子任务只使用以下状态：

- `未开始`：尚未核对或实施。
- `进行中`：已有明确执行批次，尚未达到完成标准。
- `代码完成`：实现和对应自动化测试已提交；不代表真实 Provider 或部署通过。
- `CI通过`：指定 SHA 的相关工作流全部完成且通过；必须记录 SHA 和 Run。
- `真实验收通过`：真实 Provider/数据库/部署环境按验收标准执行并留有证据。
- `降级可接受`：存在已知缺失或限制，但符合明确契约并有原因记录。
- `阻塞`：缺少权限、凭据、环境或外部能力，写明解除条件。
- `不支持`：Provider/数据源明确不具备该能力，不等同于失败。
- `未执行`：没有实际执行证据，不得推断为通过。
