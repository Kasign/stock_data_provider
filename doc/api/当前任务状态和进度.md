## 2. 当前任务：DATA-001

**目标：** 建立 Provider × 数据域覆盖矩阵，逐项核实代码接口、具体实现、默认/实际配置、Bootstrap 注册和真实数据证据，识别缺口与错误的能力宣称。

**本轮已完成的静态核对：**
- Bootstrap 当前创建 11 个主 Provider：Eastmoney、Hithink、BaoStock、Tencent、Sina、Yahoo、NetEase、Tushare、TickFlow、Pytdx、Xueqiu。
- MiaoXiang 作为独立补充 Provider，由 `MXEnabled` 控制，不在主 ProviderPriority 列表。
- 默认配置启用 Eastmoney、BaoStock、Tencent、Sina、NetEase、TickFlow、Pytdx；默认关闭 Hithink、Tushare、Yahoo、Xueqiu。
- 默认配置与 Bootstrap 的能力接口检查不等于真实数据可用；SourceStatus 根据实际注册能力生成，也不代表质量通过。
- 已读取主要实现：Eastmoney（`eastmoney.go`、`eastmoney_announcements.go`、`eastmoney_dragon_tiger.go`、`eastmoney_capital_flow.go`）、Hithink（`hithink.go`）、BaoStock（`baostock.go`、`baostock_fundamentals.go`、`baostock_calendar.go`、`baostock_adjustment_factors.go`）、Tencent（`tencent.go`、`tencent_search.go`）、Sina、NetEase、TickFlow、Pytdx、Yahoo、Tushare、Xueqiu 和 MiaoXiang 主实现文件。\n- Eastmoney/Tencent/BaoStock 的部分能力实现位于独立文件；不能只读单一 Provider 文件就断定接口不存在。\n- 详细静态能力矩阵见 [架构/01-Provider与数据域能力边界](./架构/01-Provider与数据域能力边界.md)。

**尚未完成：**
- 继续将 Runtime Acceptance Log 中真实请求记录逐项映射到 Provider × 数据域矩阵；当前已整理 BaoStock、Pytdx、Hithink、Tushare、TickFlow、Eastmoney/Tencent 的有限样本结论。
- 核实可选 Capability Interface 是否有具体实现、注册路径和实际消费者。
- 对缺少证据的格子标记未执行/不可比较，不推断通过。

**本任务禁止事项：**
- 不新增 Provider、API、DTO、字段或数据库表。
- 不为 WebUI 展示扩展数据接口。
- 不重建 Probe/Validator/Reporter/Freshness 框架。
- 不修改其他模块、项目级契约或 Server/Platform 代码。
