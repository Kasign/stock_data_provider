### RepairAll D1 Provider 版本与交易日历证据补充（2026-11-19）

- DailyBars Provider SourceVersion 当前为适配器/接口常量：Tushare `tushare-pro-daily-v2-adjustment-factor`、BaoStock `baostock-public-tcp-v1`、Hithink 使用适配器版本常量；`IsIdentifiableSourceVersion` 仅检查非空和非 `unknown`。它们不能作为 DEC-PLAT-002-020 所要求的 Provider 数据修订版本。
- DailyBars Service 会拒绝同一次 Provider 响应中混合 SourceVersion，并按单一 Provider 响应处理；该机制有助于保持批次来源一致，但不补足数据修订版本语义。
- TradingCalendar 当前按区间从 Provider 读取并仅缓存 Redis 12 小时，未发现 MariaDB 不可变日历版本 Repository；当前 SourceVersion 同样是 Provider/Adapter 版本。多来源冲突和反推非交易日均会降级。
- 因此 D1 已确认两个真实实现缺口：Provider Adapter 版本与 Provider 数据版本尚未分离；交易日历缺少可精确读取的不可变内容版本。后续设计必须分开建模，不得复用现有 SourceVersion 字段冒充。
