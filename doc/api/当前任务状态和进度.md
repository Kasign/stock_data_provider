## 2. 当前任务：DATA-001

**目标：** 建立 Provider × 数据域覆盖矩阵，逐项核实代码接口、具体实现、默认/实际配置、Bootstrap 注册和真实数据证据，识别缺口与错误的能力宣称。

**本轮已完成的静态核对：**
- Bootstrap 的 available 映射构造 11 个 Provider Adapter 候选；默认 ProviderPriority 列出 10 个（不含 Yahoo），其中默认启用 7 个：Eastmoney、BaoStock、Tencent、Sina、NetEase、TickFlow、Pytdx。
- MiaoXiang 作为独立补充 Provider，由 `MXEnabled` 控制，不在主 ProviderPriority 列表。
- 默认配置启用 Eastmoney、BaoStock、Tencent、Sina、NetEase、TickFlow、Pytdx；默认关闭 Hithink、Tushare、Yahoo、Xueqiu。
- 默认配置与 Bootstrap 的能力接口检查不等于真实数据可用；SourceStatus 根据实际注册能力生成，也不代表质量通过。
- 已逐个读取 11 个主 Provider 候选和 MiaoXiang 的主要实现文件，并补齐 Tushare 的复权因子、公司行动、证券交易状态、市场资金流实现文件。
- Eastmoney、Tencent、BaoStock、Tushare 的部分能力实现位于独立文件；不能只读单一 Provider 文件就断定接口不存在。
- 已核实 StockUniverse 由 StockSearchProvider 列表动态断言，并由 `DataService.StockUniverse` 供 `MarketStocks` 用例消费；此前“未发现独立 Service 消费者”的判断已纠正。
- 已核实 AdjustmentFactors/CorporateActions 遍历已启用 Provider 动态发现；HistoricalIndexConstituents 在 IndexCatalog 列表按需断言；Metric/Directional SectorRanking 复用 SectorRankingProvider 列表按需断言。
- PriceLimitEventProvider 当前只有接口和装配槽位，Provider 目录未发现具体实现，Bootstrap 自动收集结果为空。
- 详细静态能力与默认注册矩阵见 [架构/01-Provider与数据域能力边界](./架构/01-Provider与数据域能力边界.md)。

**真实证据映射已完成第一轮，仍未关闭：**
- 已将 Runtime Acceptance Log 中现有真实样本按 Provider/能力映射：BaoStock（复权因子、停牌/复牌/ST）、Pytdx（日 K、GBBQ 事件、停牌/临停）、Hithink（估值、财报披露日、日 K 分页/成交量）、Eastmoney/Tencent/Sina/NetEase/Yahoo（公共源日 K）、TickFlow（报价和日 K 成交量单位）、Tushare（部分接口权限错误）。
- 仍需逐个检查实现能力是否都有明确证据状态；没有真实记录的格子统一标记未执行，不能留空或推断通过。
- 仍需核对历史证据的代码 SHA 是否与当前实现兼容；旧分支/旧 SHA 只能作为历史样本，不得自动继承当前代码验收。
- 已初步对照历史 Provider 实现与当前代码基线：TickFlow 发生旧目录到 `internal/marketdata/provider/` 的迁移；BaoStock、Hithink、Eastmoney、Tencent 的对应实现文件 Blob 也与历史证据 SHA 不同。历史真实请求仍保留为样本事实，但不能直接当作当前代码 SHA 的验收通过；需先审查差异是否影响请求/解析/质量逻辑，再决定是否需要最小化复验。
- 方法级差异初审：BaoStock、Hithink 日 K、Eastmoney、Tencent 日 K 的已核对方法差异集中于统一时钟注入；TickFlow 日 K 另增加逐字段诊断、数组长度/日期/OHLC/数值校验，手转股逻辑仍保留。该结果缩小了差异范围，但仍不能将历史 Run 升级为当前 SHA 的验收通过。
