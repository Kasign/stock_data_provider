# 数据侧文档索引

本文是 `doc/api/` 的分类入口。数据侧开发顺序、优先级和状态只由 [数据侧整体规划](数据侧整体规划.md) 维护；本目录其他文档均为专项设计、契约、规则或验收证据，不独立启动整体任务。

## 阅读入口

| 目录/文档 | 内容 | 使用边界 |
|---|---|---|
| [数据侧整体规划](数据侧整体规划.md) | 唯一任务主计划、阶段顺序和状态 | 任务排期与完成状态以此为准 |
| [architecture/](architecture/) | 服务职责、架构边界和运行说明 | 解释当前服务能力，不替代代码事实 |
| [contracts/](contracts/) | API 清单、OpenAPI、数据质量与状态契约 | 接口字段以权威 OpenAPI 和实现为准 |
| [quality/](quality/) | 字段校验、诊断、Freshness、样例管理 | 规则与诊断专项，不重复建立通用框架 |
| [acceptance/](acceptance/) | 阶段验收计划、黄金样例、对账记录 | 只记录有证据的验收状态 |
| [migration/](migration/) | Market Data 并入 Root Server 的迁移计划与唯一进度 | M0 已进入收敛阶段；只剩参数差异最终核对、Provider 请求安全证据、生产 DDL 和 integration 验收；未关闭不得进入 M1 |
| [provider-migration/](provider-migration/) | Provider 扩展、Go 迁移和 Python/Go 差分 | 历史专项状态不替代整体主计划 |

## 维护规则

1. 新文档先归入对应职责目录，不再默认放在本目录根部。
2. 只有数据侧唯一主计划保留在根目录；新增领域主计划须先明确是否应并入现有主计划。
3. 同一事实只保留一个权威来源；其他文档使用相对链接引用，避免复制维护。
4. 迁移计划记录工程迁移状态；Provider 数据质量验收与模块迁移验收分开管理。
5. 移动文档时同步修复相对链接和 `doc/README.md` 索引。
