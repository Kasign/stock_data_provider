## 1. 模块目标与边界

Data 负责 A 股数据 Provider、原始字段映射、标准化、质量校验、PIT、Freshness、数据持久化、数据 API 和真实数据验收。每项数据必须能够说明来源、单位、口径、覆盖范围、时间语义、质量状态和版本。

- Provider Adapter 负责上游协议和原始字段映射。
- Normalize 负责代码、日期、单位、精度和复权口径标准化。
- Validation 只判断，不修改输入；不把缺失值补零。
- Probe/Diagnostics 复用已有统一校验与诊断能力，不重复建设框架。
- Data 拥有领域模型、Repository、SQL、Data Migration 内容和质量规则。
- Server 负责共享资源、组合根、路由、Migration 总注册和生命周期。
- Platform 负责公共 HTTP Client、Fault、Storage、Diagnostics 等基础能力。
- Web 只消费真实 API，不推断数据质量或构造虚假字段。
- Python 仅作为迁移对照基准，不作为生产业务运行时。

## 4. 核心数据规则

1. 缺失、NULL、0、空字符串必须保持不同语义；禁止为了通过校验补零。
2. 复权模式 none/forward/backward 必须记录实际请求参数、参考日期、因子来源和版本。
3. 交易日历、停牌、上市/退市、ST 和盘中临停不可混为一种状态。
4. 财务/估值修订必须保留报告期、披露/可用时间、版本和来源。
5. PIT 无法证明时标记不可比较/不可用，不推导或回填时间。
6. Provider 部分失败、空结果、跳过、未配置和真实失败分开表达。
7. Provider 探针、Go 测试、Python parity、MariaDB PIT 和生产部署是不同验收面。
8. 不重复建设已有 Probe、Validator、Reporter、Freshness Evaluator 或统一诊断框架。
9. 绝对时间输入接受 RFC3339 的 `Z` 或明确 UTC offset，不接受无时区时间；进入模块后统一为 UTC Instant，跨模块 JSON 输出使用 RFC3339Nano UTC `Z`。A 股报告期、披露日和交易日等市场日期保持 `YYYY-MM-DD`，按 `Asia/Shanghai` 日历解释，不追加 `Z`。MariaDB `DATETIME(6)` 按 UTC 存取。

## 5. 依赖与责任

权威责任矩阵见 [依赖/01-跨模块依赖与责任边界](./依赖/01-跨模块依赖与责任边界.md)。关键边界如下：

- Platform：HTTP Client/BoundDoer、Fault、Storage、Diagnostics、Time。
- Server：共享 DB/Redis、配置/Secret 注入、Migration 注册、Root 路由、Readiness 和生命周期。
- Research：稳定 Security/Industry 引用和 PIT Data Snapshot。
- Quant：DailyBars、PIT/复权/交易日历、质量和 Metric 输入。
- Researchflow：通过公开 Application Port 消费数据快照。
- Web：消费真实 API，不决定数据质量。
