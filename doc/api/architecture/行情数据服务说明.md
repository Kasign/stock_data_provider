# 行情数据服务说明

更新日期：2026-11-10

## 1. 服务职责与边界

Go 行情数据模块负责 A 股行情、证券目录与搜索、日 K、指数、板块、市场宽度、涨跌停池、龙虎榜、交易日历、证券交易状态、财务、估值、公告、资金流、筹码分布、复权因子和公司行动等数据域。

本模块采用 Provider Adapter + 细粒度能力接口 + 统一领域模型 + Service 编排。Provider 负责数据商协议请求、响应解析和来源特有语义；Service 负责按能力组织来源、优先级、fallback、缓存、质量门禁和持久化；Application Port 向模块外消费者暴露窄化用例，不暴露 Provider、Repository、Cache 或 HTTP 传输类型。

## 3. Provider 能力矩阵

以下矩阵依据当前分支代码中的方法实现、Module 注册路径和默认配置静态核对。它描述的是代码能力与默认配置，不代表数据商当前在线、凭证有效、接口权限可用或数据质量达标。

状态口径：
- **已实现**：当前 Adapter 有对应方法实现。
- **默认启用**：`providers.json` 对应 Provider 与能力开关为 true，且进入默认优先级。
- **默认关闭**：代码实现存在，但默认配置关闭。
- **独立补充**：不进入普通 Provider 优先级链，由独立开关装配。
- **条件接入**：实现由其他能力列表动态识别，不单独配置开关。
- **未实现**：当前代码未找到该能力的 Provider 实现。

### 3.1 非独立配置能力的注册方式

以下能力不是 `ProviderSettings` 的独立开关，不能仅看配置文件判断是否接入：

- **StockUniverse**：Service 从已注册的 StockSearchProvider 中动态断言 StockUniverseProvider。当前东方财富实现完整证券目录；腾讯搜索实现不等于腾讯提供完整证券目录。
- **HistoricalIndexConstituent**：作为 IndexCatalogProvider 的可选扩展能力，由指数目录服务动态断言；Tushare 实现历史成分查询。
- **AdjustmentFactor / CorporateAction**：Service 遍历已启用的通用 Provider 列表，动态识别对应接口。当前 BaoStock、Tushare 有复权因子实现，Tushare 有公司行动实现；但 Tushare 默认关闭。
- **PriceLimitEvent**：Module 会从已启用 Provider 中动态收集该能力；当前 Provider 源码中未发现 FetchPriceLimitEventEvidence 的实现，因此目前没有可注册来源。
- **MiaoXiang**：独立装配为 SupplementProvider，不进入普通 Provider 列表和常规优先级链。

## 4. 默认装配与优先级语义

默认配置文件中的 ProviderPriority 顺序为：

`eastmoney → baostock → hithink → tushare → tickflow → tencent → sina → netease → pytdx → xueqiu`

实际注册时还会同时检查 Provider 的 `enabled` 和具体能力开关。默认配置下：
- 普通 Provider 列表中启用：eastmoney、baostock、tencent、sina、netease、tickflow、pytdx。
- 默认关闭：hithink、tushare、xueqiu；Yahoo 虽有 Adapter 和配置项，但不在默认优先级列表。
- Quote 能力默认来源：eastmoney、tencent、sina、netease、pytdx。
- DailyBars 能力默认来源：eastmoney、baostock、tencent、sina、netease、tickflow、pytdx。
- StockSearch 使用独立顺序：优先 tencent，其次 eastmoney，再追加通用 ProviderPriority 中其他已启用且打开 StockSearch 的来源。
- MiaoXiang 通过独立开关装配为补充源，不与普通行情/日 K fallback 混用。

环境变量可以覆盖配置文件，因此以上是仓库默认配置结论，不是运行环境的实时状态。启动日志中的 ProviderSummary 目前只汇总全部 Provider、Quote 和 DailyBars 名称；其他能力应以数据源状态接口及实际运行诊断为准。

## 5. 统一协议边界

当前已经有运行时统一边界，不建议再新增一个万能 Provider 或重复 DTO 转换层。统一协议应作为现有接口和 Adapter 的约束规范：

1. **能力声明**：一个 Provider 只实现自己真实拥有的能力；能力接口保持细粒度，不能要求所有数据商实现同一组方法。
2. **请求语义**：明确证券代码空间、市场范围、日期区间是否包含边界、分页/limit、复权口径和 as_of 语义。不同数据商参数必须在 Adapter 内转换。
3. **输出语义**：统一返回 `model` 领域结构；原始字段映射、代码映射、单位换算和来源特有枚举由 Adapter/Normalize 完成。
4. **来源与时间**：保留 source、source_version、provider_time 及其语义、fetched_at、available_at、system_observed_at；不得用采集时间冒充首次公开时间。
5. **缺失与质量**：未知值使用 nil/unknown，不用 0 代替；空列表不自动解释为“没有事件”；质量状态和质量原因必须能表达 valid、degraded、stale、invalid、unknown。
6. **拒绝与诊断**：请求失败、Provider 拒绝、解析失败、字段校验失败和结果不完整应区分阶段、原因码与行索引；不得将可诊断的拒绝路径静默吞掉。
7. **Fallback**：由 Service 按能力分别组织候选源。fallback 必须保留来源和降级原因；不同口径、时间语义或覆盖范围的数据不能仅因字段形状相同而无条件互换。
8. **持久化与 PIT**：历史修订必须保留来源版本、系统观察时间和可证明的可用时间；缺少 PIT 证据时 fail-closed，不得推断为历史可见。

推荐调用结构：

```text
业务 Application Port
        ↓
MarketData Service（能力选择、优先级、fallback、质量门禁）
        ↓
细粒度 Provider 能力接口
        ↓
Provider Adapter（数据商请求与原始响应解析）
        ↓
统一 Model
        ↓
Normalize / Validation
        ↓
质量结果与 Reporter / Repository
```

注意：Normalize/Validation 是统一数据边界的一部分，不应由 WebUI 或各业务消费者重复实现；Provider Adapter 仍需承担来源特有协议解析和原始字段语义识别。

## 6. 当前可确认的缺口与限制

1. 静态能力矩阵不等于真实可用性。Tushare、同花顺、雪球等默认关闭来源，必须经过凭证、权限、限流、覆盖率和字段质量验收后才能启用。
2. 默认配置只开启部分能力。不要因为 Adapter 已实现就认为 Service 当前会调用该能力。
3. PriceLimitEventProvider 接口已有定义，但当前未发现实际 Provider 实现；它是明确的能力缺口，不应通过其他字段推断事件。
4. 启动 ProviderSummary 只列出全部/Quote/DailyBars，其他能力的完整接入状态应从 SourceCapabilities/数据源状态诊断读取；若需要更易审计的启动摘要，可作为独立的小任务评估，不在本次增加运行时代码。
5. 本次为静态代码与默认配置审查，未执行构建、测试、真实 Provider 请求或 MariaDB 持久化验收。

## 8. Application Port 复权证据完整性

Application DTO 必须保留影响下游分析结论复现与审计的来源证据。DailyBar 的复权信息不止是复权方式、参考日期和因子来源，还包括：

- `AdjustmentFactorRevisionHash`：本次计算使用的因子修订版本指纹。
- `AdjustmentFactorSetHash`：参与计算的因子集合指纹。
- `AdjustmentFactorReferenceRevisionHash`：参考日期对应的因子修订指纹。
- `AdjustmentAlgorithmVersion`：复权计算算法版本。

这些字段必须从领域 Model 原样映射到 Application DTO，不得在 Port 适配时丢弃。否则下游虽能读取复权价格，却无法完整识别复权计算依据。

本次已补齐 `app.DailyBar` 和 `application.mapDailyBar` 的四项字段，并在 Reader 映射测试中增加非空值断言。此修改只补齐现有日线 Port 的证据传递，不扩展新的业务接口。

## 9. 协议边界 Review 结论与冻结范围

### 已确认合理的设计

- Provider 能力接口保持细粒度，数据商只实现真实支持的能力。
- 原始协议解析留在 Adapter；统一领域语义由 Model、Normalize 和 Validation 承担。
- Provider 选择、优先级、fallback 与质量门禁留在 Service。
- Application Port 隔离内部 Provider、Repository、Cache 和 HTTP 类型。
- PIT 读取通过显式 SystemObservedAtCutoff 进入历史修订重建路径。

### 已登记、暂不扩大处理的事项

1. Quote 的旧式错误校验与结构化 Report 校验仍并存。当前兼容包装以旧式校验错误作为返回错误依据；后续应在有明确调用方迁移证据后统一，不能直接删除旧校验。
2. DailyBar 日期越界在结构化 Validation Report 中为 Warning，但 Normalize 会将越界行剔除。需要后续明确“可保留并降级”还是“拒绝并记录”的统一策略；本轮不改变既有数据筛选行为。
3. Application Port 目前只向消费者公开 Quote 和 DailyBars。这是当前明确的消费边界，不代表所有 Data 能力都必须暴露。新增 Port 必须由实际跨模块用例驱动。

### Review 范围结论

本轮协议边界 Review 只确认现有 Quote/DailyBars 读取 Port、复权证据映射、校验与标准化职责边界。未对所有领域模型、所有 Provider 方法或所有业务端点做全量审计。新增发现必须有具体调用链或数据丢失证据，不因“尚未逐个检查”而自动扩张任务范围。

构建、测试及真实数据验收由 integration 分支统一执行；本分支本次不运行 gofmt/build/test。
