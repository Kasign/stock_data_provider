# DATA-CTR-005 / DATA-CTR-007 解阻方案

- 维护范围：Data 对外日线数据事实、精度与 Snapshot；Research 负责 Evidence 映射；Server 负责可信身份注入和组合装配。
- 工作分支：`repair_all` 聚合协调；不代表 `feat/data` 已同步。
- 当前状态：`IN_PROGRESS_DESIGN_REVIEW`；本文是实现方案建议，不将 deferred 契约擅自标为 frozen。
- 基线：`repair_all` SHA `740e7e37e876d77b1d24ade93f426d21346a8201`。
- 依据：DEC-PLAT-002-020、DEC-PLAT-002-038、DEC-PLAT-002-047；PLAT-002 登记簿中 DATA-CTR-005/007 均为 deferred。

## 1. 真实问题和现状证据

DATA-CTR-007 不能直接在当前 `DailyBarsSnapshot` 上增加一个 `snapshot_ref` 字段解决。当前实现存在四个独立缺口：

1. **数值精度在 Provider 入口已丢失。**
   - `internal/marketdata/model.DailyBar` 的 OHLC、Amount、ChangePercent、MA 字段为 `float64`。
   - `internal/marketdata/app.DailyBar` 同样以 `float64` 暴露，`DailyBarsSnapshot` 只有 Symbol、AdjustmentBasis、QualityStatus、Warnings、SystemObservedAtCutoff、Bars。
   - Tushare、BaoStock 的日线数值解析使用 `strconv.ParseFloat`；Hithink 日线 JSON 结构直接解码为 `*float64`。
   - 因此不能把现有 float64 格式化成字符串并宣称恢复了 Provider 原始十进制精度。

2. **数据库有固定精度，但不等于来源精度契约。**
   - `market_data_daily_bars` 与 revision 表的 OHLC 使用 DECIMAL(20,8)，Amount 使用 DECIMAL(24,2)，ChangePercent 使用 DECIMAL(16,8)。
   - 这些是当前存储列定义，不证明所有 Provider 的原始精度、调整后价格精度或字段舍入语义均已得到供应商证据。
   - v2 必须明确源值保真、存储精度、派生计算精度三者的区别，不能把数据库 scale 当作源端精度。

3. **现有 Snapshot 不是不可变内容资源。**
   - 当前 Application Reader 每次调用 DataService，映射实时返回的 DailyBar 列表；没有独立的不可变 Snapshot Payload、内容寻址存储或精确 Snapshot 读取。
   - 当前 DTO 没有实际 interval、不可变交易日历版本、SnapshotRef、Payload fingerprint 或 AuthorizationRef。
   - 当前 DailyBars PIT 是按历史修订重建查询结果，不等于该次结果已物化为可长期复用的不可变输入。

4. **现有 source_version 不是 Provider 数据版本。**
   - Tushare 日线写入常量 `tushare-pro-daily-v2-adjustment-factor`，BaoStock 写入 `baostock-public-tcp-v1`，Hithink 使用适配器版本常量；它们描述的是 Provider/Adapter 接口或映射版本，不是某证券某交易日的上游数据修订版本。
   - `validation.IsIdentifiableSourceVersion` 只拒绝空字符串和 `unknown`，不验证该值是否为 Provider 数据版本。
   - DailyBars Service 要求一次 Provider 响应中的所有 Bars 使用同一个 SourceVersion，且不会混合不同 Provider 的行；这可作为查询批次来源身份，但不能把 Adapter 版本升级为数据版本。
   - v2 必须区分 `adapter_version` / `normalization_version` 与可选的 `provider_data_version`。上游没有提供可验证数据版本时必须显式缺失，不得将 adapter 常量或 fetched_at 填入。

5. **交易日历当前没有不可变版本资源。**
   - `DataService.TradingCalendar` 每次从 Provider 获取完整日期区间，结果仅以 `md:v1:trading-calendar:...` 写入 Redis，TTL 为 12 小时；未发现对应的 MariaDB 历史 Repository 或精确版本读取。
   - 当前 `TradingCalendarSnapshot.SourceVersion` 也是 Provider/Adapter 版本，不是某一份不可变日历内容的版本。
   - 多 Provider 日历内容冲突时会降级为 degraded；由交易日反推非交易日的 Provider 也会降级。快照必须保留这些质量事实，不能直接作为 Quant 的完整交易日历。

6. **DATA-CTR-008 Manifest 不能单独代表 Payload。**
   - 已冻结的 Manifest Schema 1.0.0 目前只包含 caller/purpose、证券、日期范围、复权、system_as_of 和 sources 等元数据。
   - Schema 没有行情 Payload 字段，也没有 Payload Schema/内容指纹字段。
   - DEC-PLAT-002-020 要求 Snapshot 身份绑定不可变行情内容；Research Evidence 的 source/version/locator 还必须分别指向 Snapshot、可验证 Provider 数据版本和具体记录定位。

结论：DATA-CTR-005 的 v2 精度保真 DTO、interval/交易日历元数据是 DATA-CTR-007 的前置；DATA-CTR-007 再提供不可变 Payload、Manifest 绑定和授权读取。QNT-CTR-003 Factor 依赖这两个能力，不能先做生产 Factor Stage。

## 2. 推荐的目标边界

### 2.1 DATA-CTR-005：DailyBars v2

保持现有 v1 HTTP/Application DTO，不做静默改型。新增版本化的 v2 DTO，统一以规范化十进制字符串表达精确数值：

- OHLC、Amount、ChangePercent、移动均线等数值字段使用 Decimal String；Volume 使用整数 shares。
- 字符串必须是规范化十进制格式，不允许指数形式、NaN、Infinity、前导加号或无意义前导零；负零归一化规则明确。
- 不设全项目统一 scale。每个字段定义单位、允许 scale/范围、来源保真规则和缺失语义；没有来源精度证据时标记 unknown/degraded，不补位、不舍入伪造精度。
- Provider Adapter 在首次解析时保留原始十进制词法值：字符串响应直接按十进制解析；JSON number 使用保留原始 number token 的解码方式。不得先转 float64 再转字符串。
- 现有 float64 v1 由同一内部权威值投影生成；v1 投影允许按既有行为输出，但不能反向成为 v2 的数据来源。
- DTO 显式包含 interval（首批只允许已验证的 `1d`）、交易日历不可变版本引用、adjustment_basis、adjustment_method/reference_date、source/source_version、provider_time（仅来源明确支持时）、fetched_at、system_observed_at、quality_status 和 reasons。
- 交易日历版本必须来自 Data 自己已持久化、可精确读取的日历版本；缺失时明确 unknown，不能用当前日历版本覆盖历史事实。
- Quant 对具体指标的样本连续性、停牌、缺失和精度误差策略仍由 Quant Registry 决定；Data 只提供事实。

### 2.2 DATA-CTR-007：不可变 Snapshot Payload

采用 Data-owned 的单一 Snapshot 资源，不建设通用文件/对象存储平台：

1. 以一次明确查询为边界，物化一个证券、一个 interval、一个日期范围、一个 adjustment basis/reference 和一个 system_as_of 的完整结果。
2. Payload 包含 Payload Schema 版本、查询边界、v2 Bars、交易日历版本、每条记录的来源/版本/观察时间/质量和完整性信息；按交易日升序、字段规范化后生成 canonical JSON。
3. Payload fingerprint = SHA-256(JCS(canonical payload))。同一 Payload fingerprint 必须对应字节语义完全相同的内容；相同身份不同内容不得覆盖。
4. Manifest 继续复用 DATA-CTR-008 已冻结的职责和字段，不把行情正文塞进 Manifest。Manifest fingerprint 独立计算。
5. SnapshotRef 必须绑定 Manifest 与 Payload 两者，而不能仅由 Manifest 元数据计算。建议定义为对 `manifest_fingerprint + payload_fingerprint` 的规范化组合计算 SHA-256；具体公式写入 DATA-CTR-007 新版契约和 Golden。现有 DATA-CTR-008 Golden 中两个 fingerprint 暂时相等只是旧样例，不能被误当成 Payload 已被绑定的实现证据。
6. Snapshot 读取按不透明 SnapshotRef 精确定位，重新校验 Manifest/Payload 指纹和请求主体；内容寻址不替代授权。
7. 每次受保护读取由 Data 复核当前策略。AuthorizationRef.resource_ref 精确绑定 SnapshotRef；Manifest.caller_ref 与 AuthorizationRef.subject_ref 完全一致，主体必须来自 Server 可信 Principal Context，不能来自请求体或 API Key。
8. Snapshot 只保存本次研究需要的行情和追溯元数据，不复制 Provider 全库；保留策略必须覆盖引用它的 Run deadline、重试、恢复和审计需要，具体 TTL 由部署/业务保留策略提供，不在代码里硬编码猜测值。

### 2.3 Research Evidence 映射

- `source_owner=data`。
- `source_ref` 指向不可变 SnapshotRef。
- `source_locator` 指向 Payload 内精确证券、交易日和记录/字段范围。
- `source_version` 只填可由对应记录证明的 Provider 数据版本；没有 Provider 版本时显式缺失。一个 Evidence locator 跨越多个 Provider 版本时，不得任选一个版本冒充整体版本；应按来源版本拆分 Evidence 或在契约中定义可验证的组合版本引用。
- `authorization_ref` 由 Data 签发，Research 每次消费仍需通过 Data Owner 当前授权复核。
- Research 不解析 Data SQL、不复制 Data Model、不自行拼接 SnapshotRef；Researchflow 通过公开 Application Port 组合输入。

## 3. 不应采用的方案

- 不将当前 float64 用 `FormatFloat` 转字符串后称为 Decimal v2。
- 不直接把 `Bundle.snapshot_id`、查询 Request ID、数据库主键或 revision hash 当 SnapshotRef。
- 不仅对 Manifest 元数据做 Hash，却声称 Snapshot Payload 已被内容寻址。
- 不把 `FetchedAt`、`SystemObservedAt` 或当前 Provider 时间写成 `AvailableAt`。
- 不把数据库 DECIMAL(20,8)/DECIMAL(24,2) 的列 scale 当成所有 Provider 源端精度证明。
- 不由 Quant 实现 Data Snapshot/交易日历，不由 Research 自己读取 Data Repository。
- 不在 DATA-CTR-005/007 仍 deferred 时开放 QNT-CTR-003 Factor 生产输入。

## 5. 当前可立即执行的事项

1. Data 先完成 D1 字段证据盘点，不等待 Provider 新权限；从当前 Provider 解析代码、历史 Live Probe Artifact、Golden 和数据库定义整理已有证据。初步确认 Tushare/BaoStock/Hithink 的现有 SourceVersion 是 Adapter/接口版本，不是上游数据修订版本；交易日历目前仅 Redis 12 小时缓存，没有不可变持久化版本。
2. 同时核对现有交易日历 Repository 是否支持不可变版本读取；若只有当前视图，单独列出实际缺口，不预建第二套 Calendar。
3. 对现有 `source_version` 是否能逐条日线稳定追溯进行代码核对；若仅是 Provider 常量/请求时间，不得冒充数据版本。
4. D1 产出后再冻结 v2 DTO 字段级映射；没有原始精度证据的字段保持 unknown，不猜 scale。
5. DATA-CTR-007 在 D2 之后定义最终 SnapshotRef/Manifest/Payload 关系；在此之前不新增生产 Adapter 或表。

## 6. 关闭条件

DATA-CTR-005/007 只有在以下证据全部具备时才能从 deferred 重新进入冻结审查：

- DailyBars v2 的每个字段均有来源、类型、单位、scale/精度依据、缺失语义和 Golden。
- interval、不可变交易日历版本、复权参考和质量完整性被 Snapshot 身份覆盖。
- SnapshotRef 能验证 Manifest 与 Payload 内容，且不可变读取通过真实 MariaDB 集成测试。
- AuthorizationRef 与可信 Principal 完全绑定，读取时重新授权并 fail-closed。
- Research Evidence 与 Quant 输入消费者契约/测试对齐。
- Root Server Migration/装配和完整 Integration CI 对精确 SHA 通过。

在以上条件未全部满足前，DATA-CTR-005/007 与 QNT-CTR-003 保持 deferred；不以设计文档完成替代实现完成。
