# Data 跨模块依赖与责任边界

更新时间：2026-11-18  
维护分支：`feat/data`

## 1. 责任边界

| 能力 | Data 责任 | 外部责任方 | 约束 |
|---|---|---|---|
| Provider 协议、原始字段解析 | Data | 无 | Provider 行为和领域语义归 Data |
| 标准化、质量规则、PIT、Freshness | Data | Platform 提供通用诊断运行基础 | 不将领域规则移交 Platform |
| Repository、Data 表结构、Migration 内容 | Data | Server 负责总注册与执行 | 不在 Data 重建全局 Migration Runner/Lock |
| HTTP Client、Fault、Diagnostics 基础设施 | 使用公共能力 | Platform | 不重复实现公共原语 |
| DB/Redis 连接池、配置聚合、Secret 装配 | 接收注入并定义领域配置 | Server | Data 不创建 Root 级共享资源 |
| Root 路由、认证、Readiness、生命周期 | 提供 Handler/Diagnostics/MigrationRunner | Server | Data 不实现组合根 |
| TCP Provider 出站 | 提供可注入 DialContext | Server；是否公共化由 Platform 评估 | 没有多模块真实消费者前不新增泛化接口 |
| Research/Quant/Researchflow 数据消费 | 提供公开 Application Port | 对应消费者 | 消费者不得依赖 Provider、Repository、SQL 或内部 Model |

## 2. 已有公共能力与禁止重复建设

- Platform `storage.ApplyMigrations` 已提供 namespace 级 Migration Lock；Data Store.Migrate 已调用。
- Platform HTTP BoundDoer 已存在；Data Provider 通过依赖注入使用，不自建平行公共 HTTP Client。
- Platform Fault、Diagnostics、Time 等能力按项目契约使用。
- Server 是唯一组合根，负责共享 DB/Redis、配置/Secret、路由、Migration Registry、Readiness 和 Lifecycle。

## 3. 当前集成事实

- Data 的 Go Module 代码位于根 `internal/marketdata/**`。
- Data Application Port、Bootstrap Module、InProcessHandler、Diagnostics 和 MigrationRunner 已存在。
- 当前 Data 分支 `90871455b282d6124d3c25fb9189fbd274894e67` 的 Root Bootstrap 仍使用旧 `internal/adapters/marketdata` 与 `service.NewRunnerWithMarketDataStores`；尚未构造 Data Module、注册 Data MigrationRunner 或挂载 Data InProcessHandler。
- 因此 Integration 全量 CI 通过不能等同于 Data M3/M4 生产装配完成。Server 任务 SRV-009 负责该装配；Data 不在本分支复制 Server 代码。
- BaoStock/Pytdx TCP DialContext 由 Data Module 暴露注入点；Root 仍需提供受控实现。公共 TCP BoundDialer 是否建设，须先证明跨模块复用场景。

## 4. 依赖变更准入

新增依赖或公共接口前，必须同时说明：
1. 真实调用方和调用场景；
2. 当前公共能力为什么不能满足；
3. 所有权、超时、取消和错误语义；
4. 测试与验收证据；
5. 是否已有其他模块消费者。

没有真实消费者时，不新增预留接口。
