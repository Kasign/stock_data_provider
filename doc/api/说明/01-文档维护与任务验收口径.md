# Data 文档维护与任务验收口径

更新时间：2026-11-18  
适用分支：`feat/data`

## 1. 文档唯一性

- `模块总任务规划和进度.md` 是 Data 任务状态唯一权威来源，所有任务使用唯一编号。
- `当前任务状态和进度.md` 只描述一个当前执行任务，不创建并行当前任务文档。
- `任务历史/` 保存已完成任务的完整执行记录，不删除、不覆盖旧证据。
- `依赖/` 记录跨模块输入、Owner 和阻塞边界。
- `架构/` 记录当前架构事实、数据流和模块责任边界。
- `说明/` 记录验收口径、操作约束和文档维护规则。
- `其他/` 作为专项资料入口；契约、质量、验收、Provider 迁移和历史证据按原始内容保留。

## 2. 任务状态

只允许使用：`NOT_STARTED`、`IN_PROGRESS`、`BLOCKED`、`DONE`、`DEFERRED`。

`DONE` 必须同时具备：
- 代码/文档交付物；
- 与当前任务相关的自动化或真实数据验收；
- 精确代码 SHA 和 Run/Artifact（适用时）；
- 未覆盖范围和不可外推范围；
- 总规划、当前状态、历史记录三处状态一致。

代码已提交但 CI 未完成时，不得标记 DONE。真实 Provider 无证据时，不得标记真实数据通过。

## 3. 诊断判定

- **通过**：数据、字段、时间、单位和口径均满足该检查规则。
- **降级**：已知限制可控且不会污染可信数据，原因可定位。
- **失败**：真实违反契约或执行失败。
- **不可比较**：样本、时间、参考基准、来源或口径不等价。
- **跳过**：未配置、无凭据或不支持；不能计为通过。

## 4. 开发准入

先核对已有代码与公共服务；已有能力只修缺陷。新增接口必须绑定调用场景；新增字段必须写明来源与语义。WebUI 展示需求不能单独构成 API 新增理由。
