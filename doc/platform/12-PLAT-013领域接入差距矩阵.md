## 1. 结论

PLAT-013 进入设计阶段，跨分支静态盘点已完成，但三个领域都没有形成完整的平台能力接入闭环：

1. **Data** 已有独立、成熟度较高的领域诊断体系，平台不得重建 Probe、Reporter、Freshness、Coverage、Cross-Provider 或历史存储。Data 是独立 Go Module，只能通过 HTTP 契约和本地 Adapter 对接，不能 import 根模块 `internal/platform`。
2. **News** 位于根 Go Module，具备复用平台 package 的模块条件；Provider 已采用注入式 `HTTPDoer`，可承接 `httpclient.BoundDoer`，但尚未看到组合根按 Provider/Source endpoint 绑定策略的接入。News 业务代码也尚未进入当前 Analysis API 组合根。
3. **Research** 当前运行代码位于独立 `go-core` Go Module，不能 import 根模块 `internal/platform`。现有 HTTP transport 自带 Token、Request ID 和 Recovery；需通过独立模块本地 Adapter/HTTP 契约保持语义一致，不能跨 Module 引用内部包。

**重要门禁：** PLAT-002 当前仍为待评审，v1.0.0-review 尚未冻结。正式接入前必须完成契约评审和冻结；在此之前可以继续领域自身的纯业务实现和适配设计，不得把未冻结的内部 API 当成稳定依赖。PLAT-013 不要求三个领域同时接入，也不要求为了统一而引入无真实调用方的公共包。

## 3. 领域接入矩阵

### 3.1 Data

| 平台能力 | 当前情况 | 接入策略 | 验收要求 |
|---|---|---|---|
| Security / Route Policy | Data HTTP Server 使用单一 API Key，支持 X-API-Key / Bearer 并做常量时间比较；尚非 owner/service + Scope 路由策略 | 保留 Data 独立 Module；由 Server/Gateway 集成层定义服务身份和访问矩阵。若 Data API 继续独立暴露，需在其自身 Module 内按冻结契约实现等价认证 Adapter，不 import 平台 internal | 匿名、错误凭证、身份越权、重复 Authorization、未知路由和直连入口测试；区分服务身份与 Provider Key |
| Config / Secret | Data 使用自身 `services/market-data/internal/config`；Provider 凭证由领域配置装载 | 保留 Data Config struct 和 Provider 配置所有权；遵守平台 Secret 不回显/不落日志约定，不强行依赖根模块 config 包 | 非法配置不回显输入；Secret 不进入日志/错误/诊断；缺少可选 Provider Key 表达 skipped/not_configured |
| Request ID / Fault | Data 有自己的 Request ID、错误响应和 slog 路径 | 保持 HTTP 契约兼容；跨服务传播 X-Request-ID，服务端入口校验并生成；将稳定错误码映射到平台 Fault 语义，不复制平台 Fault 实现 | 重复/非法/超长 ID 处理；错误响应不泄漏 SQL/DSN/上游原始文本；调用链 ID 可关联 |
| Diagnostics | 已有 Provider Probe、被动熔断器观测、Validation/Reporter、Freshness、Coverage、Cross-Provider、Storage 检查和 MariaDB Probe 历史 | **保留 Data 现有体系**。仅在服务端摘要 API 需要时增加只读 Adapter，将 Data 的维度/结果映射为摘要和 evidence_ref；不让平台 Runner 重新执行 Data 的复杂 Probe | 每个 Data 领域状态与公共 Observation 映射有文档；保留 connectivity/contract/quality/freshness/cross_provider/storage 逐维度结果及 Provider 能力状态；历史查询仍由 Data Repository 负责 |
| HTTP Client | Provider 访问由 Data 自己的 Provider Adapter 管理；平台 HTTP Client 位于根 Module | 不跨 Module 引用平台 internal/httpclient。Data 继续使用自己的 Provider 网络策略；若将来抽公开 Module，必须由独立决策批准，当前不做 | Provider 超时、重试、限流、代理、DNS/出口策略由 Data 自身验收；平台只消费其 API，不绕过 Data 直接访问 Provider |
| Storage / Migration | Data 有自己的 MariaDB/Redis Adapter、Repository 和 Migration | 领域表、SQL、Repository、Migration 继续归 Data；平台连接生命周期契约作为行为标准，不搬迁领域存储 | 真实 MariaDB/Redis、Migration 升级/重复执行/失败恢复、缓存降级与业务事实持久化分别验收 |

**Data 结论：** 诊断体系不缺平台 Runner，缺的是边界清晰的服务间摘要契约和整体部署认证/日志语义核对。不能把 Data 既有诊断“接入平台”误做成重写诊断系统。

### 3.2 News

| 平台能力 | 当前情况 | 接入策略 | 验收要求 |
|---|---|---|---|
| Security / Route Policy | News 当前是根模块内 Application，不需要独立 Service Key；现有 Analysis API 组合根尚未装配 News 路由 | 若 News 操作通过根 Server 暴露，由 Server 统一认证授权；News Application 不再增加第二套认证 | 所有暴露的 News 路由进入受保护 Router；内部同进程调用不重复认证；Provider Secret 不得充当服务身份 |
| Config / Secret | Provider Adapter 构造配置当前持有普通 string API Key；根 Analysis bootstrap 只部分使用平台 dotenv，未统一使用 Config/Secret loader | 由根组合根装载 News Config，将 Provider 凭证以 Secret 或等价安全类型注入；领域配置仍由 News 定义 | 配置缺失/非法时启动失败；Secret 格式化和日志脱敏；业务层不直接读取环境变量 |
| Request ID / Fault | News 有自己的 ProviderError（Code/Retryable/Skipped），没有平台 Fault Adapter 证据 | 保留 ProviderOutcome/部分成功和 News 错误码；在 transport/组合边界映射 Fault，不把多个 Provider 部分成功压成一个错误 | ProviderError 与 Fault 的映射表；retryable 只作候选，不自动重试；Cause 不进入响应 |
| Diagnostics | News 有领域 Observation（身份发现/匹配/冲突），不是平台 Check Observation；未见平台 Runner 注册和受保护诊断路由 | News 定义 Source/Provider/Fetch/Parse/Normalize/Deduplicate/Persist Check；平台 Runner 只负责只读执行、超时、并发和聚合；新闻 Ingestion Run/证据仍由 News 持有 | 明确领域状态到公共 Status/reason_code 的映射；保留 quality、freshness、authorization、ProviderOutcome；evidence_ref 不透明且由 News 授权 |
| HTTP Client | Provider Adapter 接受窄 `app.HTTPDoer`，可由 BoundDoer 实现；当前构造函数仍接收抽象 Doer，未见组合根固定策略绑定 | 根组合根为每个 Provider endpoint 建立独立 BoundDoer；未来 Feed/Source endpoint 使用另一个独立 BoundDoer。禁止裸 http.Client 生产注入；Provider endpoint allowlist 不等于 Source URL 授权 | 每个 endpoint 精确 Host/Port/Dependency；默认禁止重定向；DNS/IP 与实际拨号绑定；私网/保留地址和 DNS rebinding 拒绝；生产出口演练通过后才开放在线抓取 |
| Storage / Migration | 当前新闻 Domain/Application Port 已形成；未据此确认生产 SQL Repository、新闻 Migration 已接入根 Store | News 自己实现 Repository、SQL、表与 Migration；根 Server 集成层提供 DB 生命周期/事务资源并统一 Migration 注册，不建设第二套连接池或私有 Migration Runner | MariaDB 事务/唯一约束/幂等写入/版本记录/失败恢复；Redis 不列为首期必需依赖 |
| Task / Run | 纯同步 Application 不强制异步；真实长任务需求未成为公共队列抽象的依据 | 只有定时采集、长耗时和崩溃恢复需求明确时再设计 News Ingestion Run/Worker；任务模型归 News | 幂等键、取消、重启恢复和副作用策略；不复用历史 Analysis 专属 taskqueue |

**News 结论：** 优先完成根组合根接线前的安全配置和 BoundDoer 注入准备。当前不开放任意来源在线抓取；PLAT-002 冻结、News 来源授权、平台生产 DNS/出口 SSRF 验收缺一不可。
