## 4. 每项任务的交付定义

### PLAT-001：公共能力现状盘点（P0）

目标：避免重复建设，确认已有能力是否可以抽象复用。

盘点范围：
- 根 Go module：internal/platform、internal/adapters、internal/service、cmd。
- 行情独立 module：配置、HTTP Middleware、Provider Probe、DB/Redis、Migration。
- 新闻和分析分支：认证、配置、日志、HTTP、诊断、存储、任务和启动装配。
- 部署层：环境变量、Compose、反向代理、Secret 注入和 CI。

每项记录：路径、导出 API、调用方、依赖方、测试、运行状态证据、重复实现、可复用结论和改造风险。

交付物：能力盘点矩阵、跨分支 HEAD 记录、重复实现清单、暂不抽象清单。详细证据见《07-公共能力现状盘点.md》。

验收：每项结论有代码/测试证据；未知运行状态明确标记未知；不能只按文件名判断。当前静态盘点已完成，真实部署状态和 CI/live probe 未验证，故暂列“待验收”。

### PLAT-002：公共平台契约与依赖边界（P0）

冻结：模块目录、包命名、依赖方向、身份上下文、错误分类、诊断状态、配置装载接口、HTTP Policy 和版本策略。

交付物：契约文档、依赖图、接口示例、契约测试计划。

验收：平台包不依赖业务包；跨模块调用不引用未冻结的内部实现。

### PLAT-003：安全认证中间件（P0）

交付：认证主体、身份上下文、路由策略、认证和授权 Middleware、默认拒绝、公开路由显式白名单。

验收：无凭证、无效凭证、过期凭证、Scope 不足、身份 Header 伪造、路径绕过和错误方法均有测试。

### PLAT-004：Service Key 生命周期（P0）

交付：Key 生成、Key ID、摘要存储、一次性明文展示、启停、过期、轮换、撤销、双 Key 过渡和审计事件。

验收：DB 不存明文；日志和错误不泄露 Key；撤销生效时间和缓存行为有测试。

### PLAT-005：Config / Secret（P0）

交付：类型化配置、默认值、环境覆盖、必填项校验、Secret Provider 接口、脱敏展示和启动校验。

验收：配置错误快速失败；普通日志/诊断不泄露 Secret；不在业务代码散落读取环境变量。

### PLAT-006：Logger / Error / Trace（P0）

交付：结构化 Logger 接口、稳定错误类别/错误码、Request ID、Trace Context 提取和传播、敏感字段过滤。

验收：同一请求日志可关联；错误可分类；Header、Cookie、Token、DSN 和 Provider Key 不进入日志。

### PLAT-007：Diagnostics（P0）

交付：Check 接口、Registry、Runner、Result、聚合状态、超时和并发限制、公开/管理查询边界。

验收：区分 healthy、degraded、unavailable、skipped、failed；检查项不配置时为 skipped/not_configured，而非 failed；数据质量由领域 Check 负责。

### PLAT-008：HTTP Client（P1）

交付：统一 Client Factory/Policy、总 Deadline、连接/响应超时、响应体上限、幂等重试、并发限制、错误分类、Trace 和脱敏。

验收：重试不超过预算；非幂等请求默认不重试；慢响应、大响应、断连、429、5xx 均有测试。

### PLAT-009：DB / Redis / Migration（P1）

交付：连接配置、连接池、Ping/Close 生命周期、健康检查、Key Prefix、TTL、Repository 约束、Migration 命名和注册约定。

验收：DB/Redis 故障分类清晰；Redis 丢失不导致任务事实丢失；领域表归属明确；迁移可重复执行或安全拒绝重复。

### PLAT-010：异步任务与幂等（P1）

交付：任务状态机、唯一幂等键、请求摘要、Worker 租约/心跳、超时、取消、失败重试策略、恢复和事件记录。

验收：并发重复请求只创建一个有效任务；Worker 崩溃后状态可恢复；不重复执行不可重入副作用。

### PLAT-011：Metrics（P1）

交付：统一指标命名、低基数标签、HTTP/依赖/任务/诊断指标和 exporter interface。

验收：不把用户 ID、股票代码、URL、Key ID 等高基数字段作为默认标签；指标不暴露敏感信息。

### PLAT-012：安全审计（P1）

交付：主体、动作、资源、结果、拒绝原因、关联 ID、时间、保留和访问策略。

验收：Service Key 创建/轮换/撤销和管理操作有审计；审计内容不含密钥材料。

### PLAT-013：业务接入验收（P1）

交付：Data、News、Research 三类接入清单、接入示例、契约测试和差异报告。

验收：各业务使用平台正式 API；不保留重复实现；领域诊断和领域数据所有权不被平台接管。

### PLAT-014：故障演练与治理收口（P2）

交付：Key 泄露/撤销、DB 不可用、Redis 不可用、HTTP 超时/限流、Worker 中断、诊断超时和审计不可写演练。

验收：故障结果符合 fail-open/fail-closed 约定；恢复路径和证据可复查。

## 6. 本轮执行纪律

- 每轮先读取 feat/platform-foundation 最新 HEAD 和本清单。
- 只做当前授权任务，不跨分支修改业务代码。
- 新增公共接口先更新对应设计文档和契约测试。
- 不为兼容未上线的临时接口保留双套实现；在无生产使用前优先采用清晰的最终设计。
- 每个任务完成必须具备代码提交、测试、文档、必要的真实集成证据。
- 任务未达到全部验收标准时保持未完成。
