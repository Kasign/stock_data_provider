| 状态 | 含义 |

## 4. 任务交付与验收

### PLAT-001：现状盘点

历史静态盘点见《07-公共能力现状盘点》。其运行状态和 CI 未核验项继续保留，不以本轮设计调整代替验收。开发前重新核对当前代码基线。

### PLAT-002：最小公共契约

目标：定义真正需要跨模块共享的稳定接口，不一次性冻结所有未来能力。

必须冻结：
- package 依赖方向和 Go Module 边界；
- 服务身份、管理身份边界和最小路由策略；
- 稳定错误类别；
- Request ID 与日志字段；
- Config/Secret 装载；
- Diagnostics Check/Result；
- HTTP Client 的超时、响应体上限和有限重试；
- DB/Redis 生命周期和 Migration 约定；
- 长任务需要的平台原语边界。

明确不冻结为首期实现：
- 用户/组织/租户 IAM；
- W3C Span SDK、Baggage 和 Trace 后端；
- 通用 Metrics/Exporter 平台；
- 分布式任务调度、通用工作流和 Outbox 框架；
- 动态配置中心、插件注册系统；
- 全量业务审计。

交付：《08-公共平台契约规范》及最小契约测试矩阵。跨分支评审完成后才能开始依赖该契约的正式实现。

### PLAT-003：最小身份认证与路由授权

交付：明确 anonymous、owner、service 三类访问模式；owner 使用独立 PLATFORM_ADMIN_TOKEN，service 使用各调用方独立环境凭证。凭证从部署 Secret 注入，使用 Bearer 传递和常量时间比较；不建凭证数据库、不提供动态 Key API。路由显式声明；未声明默认拒绝。

验收：匿名访问受保护路由失败；伪造身份 Header 无效；owner 与 service 不可互相冒充；错误/缺失凭证拒绝；健康路由不泄露内部信息；轮换部署 Secret 后旧凭证失效。

### PLAT-004：动态 Service Key 管理（条件任务）

首期不执行。只有出现多个独立调用方需要动态创建、独立撤销、到期管理或无停机轮换时才启动。届时再评估 Key ID、摘要存储、权限、生命周期 API 和撤销传播，不预先建设表结构和管理界面。

### PLAT-005：Config / Secret

交付：每个服务自己的类型化 Config、集中装载、默认值和启动校验；环境注入 Secret；统一脱敏行为。

验收：错误配置启动失败并指出键名，不回显值；业务代码不散落读取环境变量；不建设远程配置中心。

### PLAT-006：日志、错误和 Request ID

交付：标准 slog、稳定错误类别、X-Request-ID 生成/校验/响应/跨服务传播。首期不要求 Span/Trace SDK。

验收：给定 Request ID 能查到请求入口、依赖调用和任务关联日志；公网入口对外部 Request ID 的信任边界明确；错误有稳定 Code 和固定安全摘要，Cause 不进入响应；敏感值不落日志；access log 使用路由模板且不记录 Query/Body/凭据。

### PLAT-007：通用 Diagnostics Check/Result 执行与聚合

交付：基础 Check 执行能力、统一 Observation/Fault 结果适配、有限并发、单项超时、总 Deadline、结果聚合和访问保护。

边界：不实现 Data Provider Probe、Validation/Reporter、Freshness、Coverage、Cross-Provider；不实现 News 来源规则、Research Stage 规则或 Notification 渠道规则；不建设通用诊断历史数据库。Data 已有诊断体系继续由 Data 所有，其他领域各自实现领域检查。

验收：healthy/degraded/unavailable/skipped/failed 语义明确；非 healthy 有稳定 reason_code；safe_message 脱敏；evidence_ref 为可选不透明引用；单项失败不阻断其他检查；required/optional 聚合规则正确；领域 Adapter 保留领域细节。

### PLAT-008：安全 HTTP Client（含 SSRF 防护）

交付：可直接调用的安全 HTTP Client，而非仅提供接口钩子；缓冲式请求与流式请求使用明确分离的入口。流式入口复用同一 Transport、DestinationPolicy、DNS/IP 校验和受控 Dial；具备响应头/Body 上限、流生命周期 Context、单次阻塞 Read 空闲超时、独立流并发额度、幂等关闭和 Fault/终态统计。缓冲式请求保留有限幂等重试；流式请求不自动重试。对不可信 URL 执行精确 host/port 策略、默认禁止重定向及逐跳校验、禁用隐式代理。

验收：不发生无限重试；非幂等请求不自动重试；慢响应、大响应和依赖失败有可定位错误；覆盖私网/保留 IP、DNS rebinding、重定向到不可信地址、代理绕过等 SSRF 测试。未通过安全测试前不得开放任意来源抓取。首期不做通用熔断/自适应限流平台。

### PLAT-009：DB / Redis / Migration

交付：连接池配置、Ping/Close、资源生命周期、Redis 缓存故障策略、版本化 Migration 和显式执行方式。

验收：连接失败可诊断；Redis 清空不丢任务/业务事实；Migration 有唯一版本、失败记录和人工恢复说明。首期按单实例迁移，不做多集群编排。

### PLAT-010：长任务可靠性

当前状态：待评审，不进入通用队列扩建。

合并后的 Research 方案将 `go-core` 作为独立 Go Module，并明确首期不引入分布式队列。现有 `internal/platform/taskqueue` 直接依赖 `internal/analysis/domain`，包含分析 Runner、RunRequest/RunResult、StageEvent 和分析专属表，因此属于历史分析领域实现，不是合格的平台公共实现。

执行顺序：
1. 由 Research/Analysis 分支确认 Analysis Run/Task/Stage 的领域状态机、持久化、Worker 生命周期和启动恢复策略。
2. 验证是否存在第二个真实领域调用方，以及是否确实需要平台级可复用原语。
3. 只有出现真实跨领域复用时，Platform 才提供不含领域 DTO/状态/表名的最小技术原语；否则由领域独立实现并维护。
4. 在多实例部署未成为事实前，不增加租约、fencing、分布式锁或通用工作流。

验收：领域归属明确；重复请求幂等；进程中断后状态可恢复或明确终结；失败可定位；不安全副作用不会自动重放；平台包不依赖任何领域包。若无跨领域调用方，PLAT-010 以边界评审和接入约定收敛，不为抽象而抽象。

### PLAT-011：Metrics 与运行可观测性（按需）

首期不引入独立 Metrics 存储。只有出现真实展示或告警需求后，才补充低基数指标和导出。

### PLAT-012：必要安全审计

仅覆盖身份认证/授权、凭证轮换和管理操作等必要安全事件，不建设全量业务审计平台。

### PLAT-013：领域接入验收

Data/News/Research 按各自领域边界接入平台公共契约。Data 复用既有诊断实现；News/Research 不复制平台组件。跨分支差距、Go Module 边界、接入顺序和验收清单见《12-PLAT-013领域接入差距矩阵》；提交图、冲突路径和合并准备结论见《13-跨分支合并准备审查》。PLAT-002 未冻结前只进行只读盘点和适配准备，不将平台内部 API 当作稳定依赖。

### PLAT-014：跨模块故障演练

覆盖认证失败/撤销、DB 不可用、Redis 不可用、Provider 超时、任务进程中断、诊断超时。每项记录预期行为、实际结果和恢复步骤。

### Go Module 边界最终确认

本阶段不新增独立 `platform/go.mod`：

- News 运行时代码位于根 Go module，可直接复用 `internal/platform`。
- Data 行情服务是独立 Go module，但其 Provider Probe、质量校验和诊断历史继续归 Data 所有，通过服务 API/Adapter 对接，不直接依赖平台 Go 包。
- `go-core` 是独立的历史/迁移路径，不作为首期公共平台的强制依赖方。
- 根模块与独立 Module 不跨边界 import `internal` 包。
- 只有未来出现多个独立 Go Module 必须共享同一份可执行公共实现时，才重新评估提取公开 Module，并明确版本发布策略。

因此，平台代码集中在根模块 `internal/platform`，不创建第二套公共实现，也不修改 Data、News、Research 业务分支。


## 9. PLAT-008 首批实现进度（2026-11-05）

- 每个请求必须提供精确 host allowlist 和 dependency 标识。
- 默认仅 HTTPS/443；HTTP 和非默认端口必须显式授权。

## 11. PLAT-006 首批实现进度（2026-11-05）

已新增 `internal/platform/observability`：

- Request ID 入口校验/生成、Context 读写、响应 Header 返回。
- 后台任务不得通过 `WithRequestID` 恢复创建时的 Request ID 作为当前请求上下文；任务应由领域层持久化并恢复 `correlation_id`，可将 `originating_request_id` 作为来源元数据保存。Worker 自身没有原 HTTP Request 生命周期。
- 内部 HTTP 请求可通过 `PropagateRequestID` 传播；平台 HTTP Client 已在发出请求前自动传播 Context 中的 Request ID。
- Request ID 不承担认证和授权；非法/超长/包含空白或控制字符的值会重新生成。
- `config.Secret` 实现 slog.LogValuer，结构化日志中固定输出脱敏标记。

平台只提供 Request ID 原语和标准 slog 的安全字段约定，不包装 Logger Interface。当前尚未把所有服务入口和后台 Worker 接入该能力，任务状态仍为开发中。

- `claim` 在事务中锁定 queued 任务并更新 running，完成后再执行 Runner；没有跨进程租约语义，不能把数据库行锁当作长任务执行期间的所有权证明。
