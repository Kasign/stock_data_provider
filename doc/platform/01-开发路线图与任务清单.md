# 公共平台开发路线图与任务清单

## 1. 任务状态口径

| 状态 | 含义 |
|---|---|
| 未开始 | 尚无可验收实现 |
| 设计中 | 正在调整设计或契约 |
| 开发中 | 当前分支已有实现提交 |
| 待评审 | 文档/契约已形成，等待相关方确认 |
| 待验收 | 实现已形成，测试或集成证据未齐 |
| 阻塞 | 缺少依赖、权限或环境 |
| 已完成 | 代码、测试、文档和必要验收全部满足 |

个人使用不降低正确性、安全和可靠性要求；只减少不必要的规模化机制。

## 4. 任务交付与验收

### PLAT-001：现状盘点

历史静态盘点见《07-公共能力现状盘点》。其运行状态和 CI 未核验项继续保留，不以本轮设计调整代替验收。开发前重新核对当前代码基线。

### PLAT-002：最小公共契约

目标：定义真正需要跨模块共享的稳定接口，不一次性冻结所有未来能力。

必须冻结：
- package 依赖方向和 Go Module 边界；
- 服务身份、管理身份边界和最小路由策略；
- 稳定错误类别；
- Request ID 与日志字段；
- Config/Secret 装载；
- Diagnostics Check/Result；
- HTTP Client 的超时、响应体上限和有限重试；
- DB/Redis 生命周期和 Migration 约定；
- 长任务需要的平台原语边界。

明确不冻结为首期实现：
- 用户/组织/租户 IAM；
- W3C Span SDK、Baggage 和 Trace 后端；
- 通用 Metrics/Exporter 平台；
- 分布式任务调度、通用工作流和 Outbox 框架；
- 动态配置中心、插件注册系统；
- 全量业务审计。

交付：《08-公共平台契约规范》及最小契约测试矩阵。跨分支评审完成后才能开始依赖该契约的正式实现。

### PLAT-003：最小身份认证与路由授权

交付：明确 anonymous、owner、service 三类访问模式；owner 使用独立 PLATFORM_ADMIN_TOKEN，service 使用各调用方独立环境凭证。凭证从部署 Secret 注入，使用 Bearer 传递和常量时间比较；不建凭证数据库、不提供动态 Key API。路由显式声明；未声明默认拒绝。

验收：匿名访问受保护路由失败；伪造身份 Header 无效；owner 与 service 不可互相冒充；错误/缺失凭证拒绝；健康路由不泄露内部信息；轮换部署 Secret 后旧凭证失效。

### PLAT-004：动态 Service Key 管理（条件任务）

首期不执行。只有出现多个独立调用方需要动态创建、独立撤销、到期管理或无停机轮换时才启动。届时再评估 Key ID、摘要存储、权限、生命周期 API 和撤销传播，不预先建设表结构和管理界面。

### PLAT-005：Config / Secret

交付：每个服务自己的类型化 Config、集中装载、默认值和启动校验；环境注入 Secret；统一脱敏行为。

验收：错误配置启动失败并指出键名，不回显值；业务代码不散落读取环境变量；不建设远程配置中心。

### PLAT-006：日志、错误和 Request ID

交付：标准 slog、稳定错误类别、X-Request-ID 生成/校验/响应/跨服务传播。首期不要求 Span/Trace SDK。

验收：给定 Request ID 能查到请求入口、依赖调用和任务关联日志；错误有稳定 Code 和安全摘要；敏感值不落日志。

### PLAT-007：通用 Diagnostics Check/Result 执行与聚合

交付：基础 Check 执行能力、统一 Observation/Fault 结果适配、有限并发、单项超时、总 Deadline、结果聚合和访问保护。

边界：不实现 Data Provider Probe、Validation/Reporter、Freshness、Coverage、Cross-Provider；不实现 News 来源规则、Research Stage 规则或 Notification 渠道规则；不建设通用诊断历史数据库。Data 已有诊断体系继续由 Data 所有，其他领域各自实现领域检查。

验收：healthy/degraded/unavailable/skipped/failed 语义明确；非 healthy 有稳定 reason_code；safe_message 脱敏；evidence_ref 为可选不透明引用；单项失败不阻断其他检查；required/optional 聚合规则正确；领域 Adapter 保留领域细节。

### PLAT-008：安全 HTTP Client（含 SSRF 防护）

交付：可直接调用的安全 HTTP Client，而非仅提供接口钩子；复用 Transport、连接/请求总超时、响应体大小限制、有限幂等重试、按 dependency 的并发上限；对不可信 URL 执行来源 host/port 策略、DNS/IP 校验与实际 Dial 绑定、默认禁止重定向及逐跳校验、禁用隐式代理。

验收：不发生无限重试；非幂等请求不自动重试；慢响应、大响应和依赖失败有可定位错误；覆盖私网/保留 IP、DNS rebinding、重定向到不可信地址、代理绕过等 SSRF 测试。未通过安全测试前不得开放任意来源抓取。首期不做通用熔断/自适应限流平台。

### PLAT-009：DB / Redis / Migration

交付：连接池配置、Ping/Close、资源生命周期、Redis 缓存故障策略、版本化 Migration 和显式执行方式。

验收：连接失败可诊断；Redis 清空不丢任务/业务事实；Migration 有唯一版本、失败记录和人工恢复说明。首期按单实例迁移，不做多集群编排。

### PLAT-010：长任务可靠性

只针对实际需要后台执行的研究/分析长任务。交付持久化状态、幂等键、有限 Worker、执行超时、启动恢复策略和失败详情。首期按单实例设计；若确认多实例部署再增加租约/fencing。

验收：重复请求不会重复创建任务；进程中断后任务状态不会永久悬空；失败可定位；不安全的副作用不会自动重放。

### PLAT-011：Metrics 与运行可观测性（按需）

首期不引入独立 Metrics 存储。只有出现真实展示或告警需求后，才补充低基数指标和导出。

### PLAT-012：必要安全审计

仅覆盖身份认证/授权、凭证轮换和管理操作等必要安全事件，不建设全量业务审计平台。

### PLAT-013：领域接入验收

Data/News/Research 按各自领域边界接入平台公共契约。Data 复用既有诊断实现；News/Research 不复制平台组件。

### PLAT-014：跨模块故障演练

覆盖认证失败/撤销、DB 不可用、Redis 不可用、Provider 超时、任务进程中断、诊断超时。每项记录预期行为、实际结果和恢复步骤。

## 5. 执行顺序

PLAT-001 -> PLAT-002 -> PLAT-003/005/006（可并行） -> PLAT-007 与 PLAT-008（可并行开发，真实抓取受 PLAT-008 安全门禁） -> PLAT-009 -> PLAT-010 -> PLAT-011/012（按需） -> PLAT-013 -> PLAT-014。

并行只限独立 package 和文档；涉及启动入口、路由总表、DI、Migration 总入口时由集成分支统一装配。

## 6. 执行纪律

- 每轮先读取最新分支 HEAD 和任务文档。
- 只在 feat/platform-foundation 修改平台实现和平台文档。
- 不为了兼容未上线的临时接口保留双套实现。
- 一批任务围绕一个完整交付目标集中提交。
- 测试只覆盖实际承诺的语义，不为了覆盖率引入无调用方的抽象。
- 没有真实部署证据时明确标记未知，不声称运行通过。


## 7. Data 既有诊断体系复用说明（2026-11-05）

Data 领域诊断不是平台待重建能力。数据分支已具备 Provider Probe、被动熔断器诊断、Validation/Reporter、Freshness、Coverage、Cross-Provider、交易上下文和 Probe 历史。PLAT-007 只提供公共执行原语和结果契约，不接管这些领域能力。

Data 现有诊断接口、状态模型、字段问题、质量报告和历史记录由 Data 分支继续维护。后续接入通过 Adapter 映射 Observation/Fault；不能为统一字段而删除 Data 专有质量维度、Provider 状态或历史明细。
