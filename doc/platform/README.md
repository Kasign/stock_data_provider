## 文档权威规则

1. 本目录的 01 文档是公共平台任务状态的唯一权威清单。
2. 模块技术细节以对应专项设计文档为准；代码行为以当前分支实际实现和测试为准。
3. 本目录文档描述目标设计，不代表代码已经实现；状态必须有提交、测试和验收证据。
4. 当设计发生变化时，先更新对应设计文档，再实施代码；涉及公共契约的变化必须记录版本和受影响模块。
5. 旧的项目级公共平台方案保留为历史入口和总体摘要，后续细节逐步链接到本目录，不再在多份文档维护同一份详细设计。

## 当前代码基线观察

在 0351862c6b07ed9e4786fd0fb753831d5d0eb 基线上，根 Go module 已有少量 platform 代码：配置 dotenv 加载、分析 HTTP API、异步分析任务队列；MariaDB/Redis 连接和分析存储位于 storage adapter。行情服务位于独立 Go module，拥有自己的配置、HTTP 路由、API Key 校验、Provider 诊断和 MariaDB/Redis 访问。

这说明仓库已有可复用基础，但尚未形成跨服务统一的 Security、Config、Logger、Error、Trace、Diagnostics 和 HTTP Client 公共契约。PLAT-001 必须继续逐项盘点真实调用方、测试和运行状态，不能把“已有同名代码”直接认定为平台能力完成。

## 开发约束

- 只在 feat/platform-foundation 分支开发公共平台代码和本目录文档。
- 本阶段不修改 Data、News、Research、WebUI 的领域实现。
- 不擅自改服务端集成分支的启动入口、全局路由、DI、Migration 总入口。
- 不为了抽象而搬迁已有代码；优先建立契约和 Adapter，完成验收后再决定是否迁移。
- 不新增不必要的微服务、消息中间件、配置中心或可观测性存储系统。
- 一批任务围绕一个完整交付目标，按功能批次集中提交。
