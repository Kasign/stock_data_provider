## 1. 审查目标与结论

本轮目标是确认 Data、News、Research 及可能的 Server/组合根分支当前有哪些可合并提交、提交图如何分叉、哪些路径存在内容差异、合并前后由谁验收。其他分支仍在持续开发，因此所有 HEAD 和 Compare 结果均为本轮快照。

**结论：当前不执行合并。**

1. Data 有 8 个独有提交，变更集中且与 Platform 自共同祖先以来的变更路径无交集，是下一批最适合优先集成的领域分支；但最新实时 Provider Probe 检查存在一次 success 和一次 failure，且 Commit Status 为 pending，需先由 Data 维护方解释。
2. News 有 96 个独有提交、64 个变更文件；与 Platform 共同修改 27 个路径，其中 10 个当前 Blob 不同。News 的 Provider/Source 传输仍缺少生产组合根注入 BoundDoer 的证据，暂不适合合并。
3. Research 当前没有领先于 Platform 的独有提交，HEAD 是较早合并 Platform 后的祖先快照，不需要合并。
4. 远端没有独立 Server/组合根分支。当前 cmd/analysis-api 是历史 Analysis API 入口，不是完成了平台安全、News、Diagnostics 装配的组合根。不能把 Data 分支当作 Server 分支。
5. Design 与 WebUI 的提交分别属于规划文档和前端，不纳入本轮 Platform 后端合并批次。

## 4. Server/组合根缺口

远端分支列表只有 main、feat/design_doc、feat/full-go-data-providers-api-switch、feat/platform-foundation、feat/research-analysis-flow-native-go、feat/research-news-ingestion、feat/webui-market-data-console。

现有 cmd/analysis-api/main.go 只装配 Market Data、存储、Analysis Runner、历史 taskqueue 和 internal/platform/httpapi。当前没有 News 装配，也没有统一 Security/Scope 和 Diagnostics 路由。internal/platform/httpapi.Server.Handler() 只注册健康、Analysis Run/Task 路由，并使用 Request ID/日志/Recovery 中间件；未见平台认证授权中间件接入。因此不能将其标记为完整 Server 组合根。

## 5. 建议的集成顺序与门禁

1. **明确 Server Owner 与组合根基线**：确定根启动入口、Security/Scope、Config/Secret、Request ID/Fault、Diagnostics 聚合、Storage/Migration 注册和部署文件的唯一所有者。
2. **Data 优先**：Data 分支稳定后，重新核验提交图；因当前路径无交集，预计可作为低冲突首批集成。合并后分别完成 Data Module 验收与平台契约核对。
3. **News 后续**：先解决 10 个差异路径，确认根 Config/Secret 装载、Provider 与 Source 独立 BoundDoer、授权策略与 SSRF 门禁，再集成。
4. **Research 按需**：当前没有独有提交，不做合并；未来有实际新提交后重新审查独立 Module 契约。
5. **Server 组合根**：由 Server Owner 统一装配根 HTTP 路由、DI、Worker、Migration 总注册及部署，不让 Platform 反向依赖业务 Module。
6. **PLAT-014**：按参与分支精确 SHA 做跨模块认证、超时、故障、恢复、DB/Redis、Provider 和诊断演练。

### 合并前必须重新执行

其他分支仍在开发期间，本文件中的 SHA、冲突路径和 CI 状态都是时间点快照，不构成后续合并授权。
