# Platform 模块总任务规划和进度

任务前缀：PLAT

## 1. 模块目标与边界

Platform 为个人使用、单一所有者、少量服务和低并发的 A 股研究系统提供最小可靠公共原语。目标是安全、性能可控、故障可定位，不建设通用 SaaS 底座。

Platform 拥有通用 Config/Secret、Fault/Request ID、Security 原语、HTTP Client/BoundDoer、Storage/Migration Runner、Diagnostics Runner、Time 等基础能力。它不拥有业务 DTO、领域 Repository、业务状态机、跨模块编排、根 HTTP 宿主、Server Bootstrap 或领域 Adapter。

Server 创建并装配共享资源、路由、模块依赖、Migration 注册和生命周期；各领域模块实现自己的 Repository、SQL、Migration 内容和业务 Check。

## 2. 当前能力基线

| 能力域 | 已有实现 |
|---|---|
| Config/Secret | 类型化配置、Secret 安全输入和脱敏边界 |
| Fault/Request ID/Logging | 公共 Fault、错误投影基础、结构化日志和请求关联原语 |
| Security | Principal/AuthMethod、Authenticator、Scope 与可信 Context 原语 |
| Owner Security | Password/CredentialStore、Session/Cookie、CSRF、Login RateLimit、Security Audit Event/Writer 原语 |
| HTTP Client | 固定 DestinationPolicy、DNS/IP/SSRF、受控 Dial、逐跳重定向、响应体限制、缓冲和流式传输 |
| Storage | SQL/Redis 生命周期、Migration Runner、事务基础能力 |
| Diagnostics | Check/Observation/Report Schema、Runner、并发/超时/取消和聚合 |
| Time | UTC 时间源、IANA 时区、MariaDB 权威时钟适配器与统一时间 API |

能力实现和 Platform L1 测试不代表消费者 A2 接入或生产部署 A3 验收完成。

## 4. 验收层级

- **Platform L1**：公共原语、Schema/Golden、单测、Race/Vet、必要 MariaDB/Redis 集成。
- **Consumer A2**：Server/领域模块真实调用、依赖注入、Fault/Diagnostics 映射、资源所有权和生命周期。
- **Production A3**：部署 DNS/egress、凭据、真实依赖、运行安全、故障演练和恢复。

任何一层通过不自动代表其他层通过。缺少当前精确 SHA 证据时标记 NOT_COMPARABLE。

## 5. 依赖与责任

| 能力 | Platform 负责 | Server 负责 | 领域模块负责 |
|---|---|---|---|
| Config/Secret | 解析和安全原语 | 服务配置 Bootstrap、Secret 装载注入 | 定义本模块配置 Schema |
| HTTP Client | SSRF/DNS/Dial/重定向/流式安全 | 创建共享 Client、固定 BoundDoer、生命周期 | Provider/模型协议和来源授权 |
| Security | Principal/Authenticator/Scope/Session/CSRF 等原语 | 路由认证策略、Session Handler、Cookie 与登录流程 | 资源级授权与 AuthorizationRef |
| Storage/Migration | 连接生命周期和通用 Runner | 创建资源、汇总并注册 Migration | Repository、SQL、领域 Migration |
| Diagnostics | Schema/Runner/聚合 | 注册 Check、Required/Readiness 和 HTTP | 领域 Check 与 reason/evidence |
| Time | UTC/IANA/MariaDB 时钟原语 | 注入时钟和配置 | 业务时间语义与 PIT 规则 |

跨模块剩余责任以《16-公共平台剩余开发任务与跨模块接入责任清单》为补充，不将 Server/消费者任务移入 Platform 本地任务。
