## 1. 实施原则与范围

1. 先按 PLAT-CTR-001～007 做现有代码的契约符合性核对，再补缺失实现和证据；不以新增 package 数量作为进度。
2. Platform 只提供技术原语。领域 DTO、业务错误语义、领域授权策略、诊断规则、Repository、领域表和历史记录由领域模块拥有。
3. Data 是独立 Go Module，不得 import 根模块 `internal/platform`；通过 HTTP/JSON 与自身 Adapter 接入。
4. News、Quant、Research、Researchflow、LLM、Notification 在根 Go Module 内按冻结后的窄接口依赖 Platform；不允许 Platform 反向依赖这些领域。
5. GOV-CTR-003 的 request_id 由 Platform 提供运行时原语；originating_request_id、correlation_id、event_id、idempotency_key 的生成、持久化和业务作用域由领域 Owner 负责。
6. GOV-CTR-006 的 AuthorizationRef 是审计引用，不是 bearer token。Data/News/Quant/Research 分别签发和复核；Platform 不建设通用授权策略引擎，不替 Owner 作授权决策。
7. 仅 A1：允许模块内部实现和模块级测试。跨模块联调、契约 frozen、生产可用必须分别提供 A2/A3 证据。
8. 通过 GitHub API 在本分支提交；更新文件使用当前 SHA/expected head；按完整功能批量提交，不拆成零碎提交。

## 3. 按契约拆分的实施任务

### 3.1 PLAT-CTR-001：Fault 结构与分类

**Platform 内任务**
- 核对 Class 枚举、Fault 字段边界、Cause unwrap 和直接 JSON 禁止序列化。
- 补 Class 合法性/稳定 Code 的边界测试，验证未知 Class、空 Class、nil Fault 不会被误分类为 4xx。
- 增加内部 Fault 结构 Golden 或等价契约 Fixture，明确 Dependency 不属于默认公开响应字段。
- 不在 `fault` 包引入 `net/http`，不把历史 `internal/platform/httpapi`（其依赖 Analysis domain/Store）包装成通用 transport。

**服务 Transport 接入方任务**
- 按唯一映射表将 Class 映射为 400/401/403/404/409/503/504/500。
- 生成独立公开 DTO：`error.class/code/message/retryable`；不输出 Cause、Dependency、堆栈或任意原始错误。
- 缺少 SafeMessage、非法 Fault、普通未知 error 和未知 Class 使用固定 internal 摘要。
- 401 challenge 由认证中间件负责；Retryable 不改变状态码，也不自动生成 Retry-After。

**退出条件**
- Fault 包单测通过；公开 DTO Golden/映射测试由真实服务 Transport 所有者提交。
- 不把 Platform 内部 Fault 单测通过记为 PLAT-CTR-001 全链路完成。

### 3.2 PLAT-CTR-002 + GOV-CTR-003：Request Context 与 ID 语义

**Platform 内任务**
- 补齐 X-Request-ID Header/Context/出站传播 Golden。
- 组合测试覆盖：缺失、非法、多值 Header 时重新生成；响应回显；出站覆盖调用方 Header；Context 无值时删除预置 Header。
- 确认 1..128 ASCII 字符范围和默认 16 随机字节生成语义。

**领域/部署接入方任务**
- 公网直连服务入口重新生成 Request ID；仅可信 Gateway 且网络不可绕过时才可接受 Gateway 注入值。
- 异步任务保存 originating_request_id；领域生成并持久化 correlation_id；Worker 不复用来源 Request ID。
- event_id 与 idempotency_key 保持各自 Owner 作用域和 fingerprint 规则。

**退出条件**
- Platform 的 Request ID Contract Test 通过；Worker/事件 Envelope Golden 由相应领域模块提供。
- 不在 Platform 新增通用 Task/Correlation/Event/Idempotency 模型。

### 3.3 PLAT-CTR-003：身份、授权、Service Secret

**Platform 内任务**
- 对照 token 32..256 字节 URL-safe 约束、owner/service 凭证分离、常量时间比较、重复 Authorization Header 拒绝、Scope 固定 allowlist 和路由显式策略。
- 补充凭证轮换行为的 Authenticator 快照测试：新配置生效后旧凭证拒绝；调用方修改输入配置切片不得改变已构建认证器。
- 补充路由策略矩阵和 401/403/匿名白名单测试。

**服务/部署接入方任务**
- 每条路由显式声明 anonymous/owner/service；未注册路由不放行。
- Owner Token 与每个 Service Secret 独立注入；Provider Token、Data API Key 不得复用。
- Secret 轮换、旧值撤销、日志脱敏和网络入口保护属于部署/集成证据。

**非目标**
- 不做用户/租户体系、动态 Key CRUD、Redis 凭证缓存或策略引擎。

### 3.4 PLAT-CTR-004：Diagnostics Observation 与 Runner

**Platform 内任务**
- 新增 Observation Draft 2020-12 Schema 和 Golden，字段严格遵守契约：status、reason_code、safe_message、checked_at、duration、evidence_ref、attributes。
- Schema/Validator 与 Go `Observation.Validate` 做正反向一致性测试；校验 UTC 时间、非负纳秒 duration、长度、控制字符、attributes 数量/总字节数。
- 建立 Summary 聚合真值表：required failed > required unavailable > degraded/optional failure > healthy；全 skipped/空检查为 skipped；required skipped 转 failed。
- 覆盖结果顺序稳定、重复 ID/非法 Check/并发上限/单项超时/总 Deadline/取消/单项 panic。
- 保留 Runner 的边界：只读、有界、可取消；不能安全终止忽略 Context 的 goroutine。

**领域/服务接入方任务**
- 各领域 Adapter 负责稳定 reason_code、固定 safe_message、attributes 白名单和 evidence_ref 授权。
- 诊断 HTTP 路由由服务组合根注册到 Security Router；公开 liveness 只返回最小状态，详细诊断要求 owner/service Scope。
- 不把 Data Probe、News Ingestion、Research Run、Notification Delivery 的质量规则/历史迁入 Platform。

**退出条件**
- Schema、Golden、Validator 和 Runner 聚合/边界测试进入 Platform CI。
- 至少有一个服务级受保护路由组合 Fixture；各领域 Adapter 证据仍由领域分支完成。

### 3.5 PLAT-CTR-005：HTTP Client、SSRF 与出口安全

**Platform 内任务**
- 按契约逐项核对默认超时、响应体上限、重试次数、依赖并发、精确 Host/Port、代理禁用、自定义 Host 拒绝、DNS A/AAAA 全量校验、受控 IP Dial、同源重定向和 HTTPS 降级限制。
- 补充表驱动契约测试，确保配置边界和默认值不漂移。
- 验证 Retry 仅在显式 Idempotent 且 Body 可重放时发生；总 Deadline 覆盖并发等待、DNS、连接、响应头和响应体读取。
- 生产网络出口、真实 DNS 和部署 Go Runtime 版本单独记录，不以本地 Resolver/Dial 测试替代。

**领域接入方任务**
- News/Data Adapter 提供固定 DestinationPolicy；News 来源授权仍由 News 持有。
- 不接受用户/Provider 响应推导的任意目标 URL；不绕过 BoundDoer 使用裸 Transport。

### 3.6 PLAT-CTR-006：Storage、Repository、Migration

**Platform 内任务**
- 复核 OpenSQL/OpenRedis 资源 Close 责任、Ping Fault、Migration namespace/version、完整有序注册清单、已应用版本有序前缀、checksum 漂移、advisory lock 物理连接和 RowsAffected。
- 通过可复现 MariaDB/Redis 服务完成真实连接池、关闭顺序、Migration 并发/锁超时、DDL 部分执行和恢复演练。
- 明确真实服务不可用时记录 SKIPPED，不把模拟驱动测试写成真实数据库 PASS。

**领域接入方任务**
- 各模块拥有 Repository、SQL、业务表、事务边界和 Migration 内容；Platform 只提供连接生命周期与 Migration Runner。
- 组合根显式执行 Migration；Open 连接不自动迁移。

### 3.7 PLAT-CTR-007：Typed Config 与 Secret

**Platform 内任务**
- 补齐 Env 类型解析、非法 key、缺失/空值、默认值、Secret fmt/GoString/slog/JSON/Text 脱敏、dotenv 不覆盖进程环境变量的测试。
- 配置错误只包含 key 与期望格式，不包含原始值。
- 验证 Secret 明文仅能通过显式 Value() 访问。

**服务接入方任务**
- 每个服务定义自己的 Config struct、默认值和跨字段 Validate。
- Bootstrap 一次性读取并校验，之后使用不可变配置快照；缺少必填配置必须启动失败。
- Provider/业务配置不迁入 Platform；不建设远程配置中心或热更新。

### 14.2 发现并移交的 Analysis TaskQueue 可靠性问题

审查 `internal/analysis/app/runner.go` 与 `internal/platform/taskqueue/queue.go` 后确认：

- `Runner.Run` 先调用 `Store.Begin`，成功后才注册终态 defer。因此 `Store.Begin` 失败并 panic 时，Run 记录可能不存在；此时 Queue panic 恢复事务中 Run UPDATE 影响 0 行是合法情形。
- 若 Run 记录已经存在，Queue 的 `finishPanic` 必须确保 Run 终态更新恰好影响 1 行；当前实现未读取 Run UPDATE 的 `RowsAffected()`。如果更新意外影响 0 行，Task 更新仍可能成功并提交，导致 Run/Task 终态不一致。
- 建议 Analysis/Server 领域接入方在同一事务内先确认 Run 是否存在：不存在时允许跳过 Run 更新；存在时必须要求 Run UPDATE 恰好影响 1 行。Task 仍必须恰好更新 1 行，任何异常均回滚整个事务。
- 该队列直接依赖 Analysis domain 和 Analysis 表，不属于可复用 Platform 原语；按 PLAT-010 领域归属决议，本分支只记录发现，不修改队列实现或 API。
