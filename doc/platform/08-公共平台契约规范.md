# 公共平台契约与依赖边界（PLAT-002）

- 契约版本：v1.0.0-review
- 状态：平台分支评审稿，待 Data / News / Research / Server 集成方确认
- 所属分支：`feat/platform-foundation`
- 创建基线：`1a11d78956c3015f901144364d809509647b9ccc`
- 适用范围：根 Go module 内的公共平台 package，以及通过 HTTP 接入的独立服务
- 原则：本文件定义跨模块可依赖的稳定语义；具体实现和存储细节不属于公共契约

> 本文的接口示例用于冻结 API 形状和语义，不代表这些 package 已经实现。契约评审完成后，代码实现必须以此为准；若实现中发现契约缺陷，先更新版本和影响范围，不允许各模块自行扩展出不兼容语义。

## 1. 契约总览

### 1.1 公共能力包边界

首期在根 Go module 的 `internal/platform` 下实现，不创建独立公共服务，也不提前拆独立 Go module。

建议的基础包：

| 包 | 契约职责 | 允许依赖 | 禁止依赖 |
|---|---|---|---|
| `platform/identity` | Principal、Scope、身份上下文 | 标准库 | security 实现、业务领域 |
| `platform/fault` | 稳定错误类别、错误码和安全错误包装 | 标准库 | HTTP、业务领域 |
| `platform/observability` | Request ID、Trace Context、日志字段/脱敏 | 标准库、slog | 业务领域、HTTP Handler |
| `platform/security` | Credential 认证、Principal 建立、路由授权策略 | identity、fault、net/http | 业务领域 Repository |
| `platform/config` | 类型化配置装载、校验、Secret Provider | 标准库 | 业务配置实体、业务 Repository |
| `platform/diagnostics` | Check、Registry、Runner、Result、状态聚合 | fault、标准库 | Data/News/Research 质量规则 |
| `platform/httpclient` | Client Policy、Deadline、Retry、响应限制 | fault、observability、net/http | Provider 解析和业务 API |
| `platform/storage` | DB/Redis 生命周期接口与通用健康能力 | 标准库、database/sql | 领域 SQL、Repository |
| `platform/migration` | Migration 元数据、注册、执行协调接口 | 标准库、database/sql | 领域表结构和业务 Model |
| `platform/servicekey` | Service Key 生成、摘要校验、生命周期 | identity、fault、Repository 接口 | Provider Token、用户登录 |
| `platform/audit` | 审计事件与 Writer 接口 | identity、observability、fault | 普通业务日志和业务历史 |
| `platform/task` | 通用任务生命周期契约 | identity、observability、fault | 分析流程步骤和领域结果 |

包可以按实现需要拆分内部文件，但不得通过合并包来模糊以上职责。首期不要求一次创建所有目录。

### 1.2 依赖方向

```
cmd / bootstrap / transport
       |
       +------> platform/*
       |
       +------> application
                    |
                    +------> domain
                    |
                    +------> ports
                                 ^
                                 |
                              adapters

platform/* -X-> Data / News / Research / Notification
platform/* -X-> WebUI
```

约束：

1. `identity`、`fault` 是底层类型包，不依赖其他 platform 子包。
2. `security` 可以依赖 `identity` 和 `fault`；`identity` 不得反向依赖 security。
3. `diagnostics` 可以依赖 `fault`，不能依赖任何领域诊断 DTO。
4. `observability` 不依赖 HTTP Handler；HTTP Middleware 负责把请求上下文接入日志字段。
5. `httpclient` 可以使用 fault 和 observability，但不能依赖 Provider 包。
6. platform 不直接创建业务 Repository，不读取业务表。
7. 不允许循环 import；公共类型不得为了方便放进 `internal/service` 或某个业务 package。

### 1.3 Go Module 边界

| 模块 | 使用方式 |
|---|---|
| 根服务 `example.com/stock-analysis-flow` | 直接依赖 `internal/platform/**` |
| News 根模块实现 | 在根 module 内直接依赖冻结后的 platform package |
| Research 最终根模块实现 | 在根 module 内直接依赖冻结后的 platform package；当前独立 go-core 代码只作为行为参考 |
| 行情服务 `services/market-data` | 独立 go.mod，不得 import 根 module 的 internal 包；通过 HTTP 身份/诊断契约和本模块 Adapter 接入 |
| WebUI | 只消费服务端 API，不依赖 Go package |

若未来多个独立 Go Module 确实需要共享同一份 Go 源码，必须单独评估提取公开的 platform module；不使用复制粘贴、相对路径或跨 module internal import 解决。

## 2. Identity 契约

### 2.1 Principal

身份类型固定为：

- `user`：外部用户主体。
- `admin`：平台管理主体。
- `service`：通过 Service Key 认证的内部服务主体。
- `job`：可信任务执行主体，必须保留创建任务时的 Actor 快照。

Provider 凭证不是 Principal，不进入身份上下文。

建议 API：

```go
package identity

type Type string

const (
    TypeUser    Type = "user"
    TypeAdmin   Type = "admin"
    TypeService Type = "service"
    TypeJob     Type = "job"
)

type Scope string

type Principal struct {
    Type      Type
    ID        string
    ServiceID string
    Audience  string
    Scopes    []Scope
    ExpiresAt time.Time
}

func (p Principal) HasScope(required Scope) bool

func WithPrincipal(ctx context.Context, p Principal) context.Context
func PrincipalFromContext(ctx context.Context) (Principal, bool)
```

语义要求：

1. `ID` 是主体稳定标识；service 主体必须同时具有非空 `ServiceID`。
2. `Scopes` 在建立 Principal 时复制并规范化，外部调用方不能通过修改原始 slice 改变已认证身份。
3. Scope 精确匹配；首期不支持通配符和隐式父子继承。
4. Principal 不保存原始 Credential、Key Secret 或 Authorization Header。
5. `WithPrincipal` 只允许可信认证层调用。客户端 Header、Query、Body 中的 user/service/admin ID 均不能直接构造身份。
6. job 主体只能从服务端持久化的任务 Actor 快照恢复，不接受 Worker 请求自行声明身份。
7. 身份上下文缺失时按匿名主体处理，不能默认视为内部服务。

## 3. Security 契约

### 3.1 认证和授权接口

```go
package security

type Authenticator interface {
    Authenticate(ctx context.Context, r *http.Request) (identity.Principal, error)
}

type Authorizer interface {
    Authorize(ctx context.Context, principal identity.Principal, required []identity.Scope) error
}

type AccessMode string

const (
    AccessPublic  AccessMode = "public"
    AccessUser    AccessMode = "user"
    AccessService AccessMode = "service"
    AccessAdmin   AccessMode = "admin"
)

type RoutePolicy struct {
    Mode   AccessMode
    Scopes []identity.Scope
}
```

认证器只负责验证凭证并建立可信 Principal；授权器只负责主体类型和 Scope 判定。路由策略由服务端显式注册，不根据 URL 前缀推断权限。

### 3.2 固定规则

- 未声明策略的业务路由默认拒绝；只有 liveness 等明确列出的路由可匿名。
- `AccessPublic` 是显式匿名白名单，不代表绕过请求体、速率、超时等安全限制。
- `AccessService` 只接受 service Principal；`AccessAdmin` 只接受 admin Principal；不得互相替代。
- `AccessUser` 只接受 user Principal。未来用户登录系统未接入前，不伪造用户认证实现。
- 配置了 Scope 的路由必须全部满足；空 Scope 不等于匿名。
- 认证失败不透露 Key ID 是否存在、凭证状态或摘要匹配情况。
- 授权失败不返回主体内部元数据。
- 客户端提供的身份 Header 一律视为不可信输入。
- 安全中间件不能通过 path contains、大小写变形、尾斜杠或 HTTP method fallback 绕过路由策略。

### 3.3 Scope 命名

Scope 使用 `资源:动作`，统一小写、稳定、不可由 URL 自动生成。首批候选：

- `platform:diagnose:read`
- `platform:service-key:read`
- `platform:service-key:manage`
- `platform:audit:read`
- `data:read`、`data:diagnose`
- `news:read`、`news:search`、`news:ingest`
- `research:run`、`research:read`
- `notification:send`、`notification:manage`

业务分支应在接入时给出实际操作矩阵；未被使用的 Scope 不提前实现成宽泛授权。

## 4. Fault 契约

### 4.1 错误类别

```go
package fault

type Class string

const (
    ClassInvalid       Class = "invalid"
    ClassUnauthenticated Class = "unauthenticated"
    ClassForbidden     Class = "forbidden"
    ClassNotFound      Class = "not_found"
    ClassConflict      Class = "conflict"
    ClassRateLimited   Class = "rate_limited"
    ClassUnavailable   Class = "unavailable"
    ClassTimeout       Class = "timeout"
    ClassInternal      Class = "internal"
)

type Error struct {
    Class   Class
    Code    string
    Message string
    Cause   error
}

func (e *Error) Error() string
func (e *Error) Unwrap() error
func IsClass(err error, class Class) bool
```

### 4.2 语义与映射

| Class | 语义 | 默认 HTTP |
|---|---|---:|
| invalid | 请求或配置格式不合法 | 400 |
| unauthenticated | 缺少或无效身份凭证 | 401 |
| forbidden | 身份已建立但权限不足 | 403 |
| not_found | 目标资源不存在 | 404 |
| conflict | 状态冲突、幂等键冲突 | 409 |
| rate_limited | 超出限流/并发策略 | 429 |
| unavailable | 依赖或能力暂不可用 | 503 |
| timeout | 操作超过 Deadline | 504 |
| internal | 未分类内部错误 | 500 |

规则：

1. `Code` 是稳定机器可读标识，使用 `<domain>.<reason>`，例如 `platform.key_revoked`、`data.provider_unavailable`。
2. 不同领域可定义自己的 Code，但不能重新定义 Class 的语义。
3. 对客户端的 `Message` 必须安全，不得包含 DSN、SQL、Token、Key、Provider 原始响应或内部堆栈。
4. Cause 只用于内部错误链；序列化响应不输出 Cause。
5. HTTP 映射由 transport adapter 完成，领域层不能依赖 HTTP 状态码。
6. 未知错误统一映射 internal，不把任意字符串错误自动映射为客户端错误。

## 5. Observability 契约

### 5.1 Request ID

- Header：`X-Request-ID`。
- 入口接受长度 1–128、字符集 `[A-Za-z0-9._-]` 的值；无效或缺失时生成新的随机 ID。
- 内部调用必须传递当前 Request ID；外部调用传入值仅用于关联，不代表身份或权限。
- 响应必须返回最终 Request ID。
- Request ID 不作为 Metrics 标签。

### 5.2 Trace Context

首期采用 W3C Trace Context 的 `traceparent` 格式作为跨服务传播契约；不自研 Span SDK，不接受它作为安全身份。

```go
package observability

type TraceContext struct {
    TraceID    string
    SpanID     string
    TraceFlags byte
}

func ParseTraceParent(value string) (TraceContext, error)
func FormatTraceParent(value TraceContext) string
func WithTraceContext(ctx context.Context, value TraceContext) context.Context
func TraceContextFromContext(ctx context.Context) (TraceContext, bool)
```

- 只接受规范格式和非全零 ID；非法值丢弃并记录安全的解析结果，不回显原始 Header。
- 当前服务若创建子 Span，必须更新 Span ID 并保留 Trace ID/Trace Flags。
- 首期不传播任意 Baggage，避免将未验证的高基数或敏感值带入内部链路。

### 5.3 Logger 与脱敏

- 使用标准库 `log/slog` 作为首期日志 API，不再自建一层仅转发 slog 的 Logger Interface。
- 业务依赖通过构造参数注入 `*slog.Logger`；禁止平台 package 依赖可变全局 Logger。
- HTTP Middleware 统一附加 `request_id`、`trace_id`、`service`、`environment`；主体字段仅记录稳定主体类型/ID，且按日志级别和隐私策略决定是否记录。
- 必须脱敏：Authorization、Cookie、Set-Cookie、API Key、Service Key、Provider Token、密码、DSN、数据库连接串和 Secret 配置。
- 不记录请求/响应 Body，除非某个领域明确评审字段白名单、大小上限和脱敏方式。
- 错误堆栈只进入受控内部日志，不进入 API 响应。

## 6. Config / Secret 契约

### 6.1 配置装载

```go
package config

type Source interface {
    Lookup(key string) (value string, ok bool)
}

type Loader interface {
    Load(ctx context.Context, dst any) error
}

type Validator interface {
    Validate() error
}
```

约定：

1. 配置在启动阶段一次装载，解析为类型化结构，完成默认值和 Validate 后作为不可变快照注入。
2. 环境变量名由应用配置结构明确映射；业务配置归业务模块，不把 ProviderSettings、新闻采集参数等放入 platform。
3. 缺少必填配置或格式错误必须启动失败，错误指出配置键和原因，但不回显值。
4. 不提供首期动态配置中心或自动热更新。
5. dotenv 仅为本地开发辅助，不能覆盖进程已有环境变量，也不能成为生产 Secret 的唯一来源。

### 6.2 Secret

```go
type SecretRef struct {
    Name string
}

type SecretProvider interface {
    Resolve(ctx context.Context, ref SecretRef) (Secret, error)
}

type Secret struct {
    value string
}

func (s Secret) Reveal() string
func (s Secret) String() string
func (s Secret) GoString() string
```

- `String` 和 `GoString` 必须输出固定脱敏占位，不输出明文。
- 只有实际建立数据库连接、Provider Client 或签名校验的边界代码可以调用 Reveal。
- 首期 SecretProvider 可由环境变量实现；接口保留未来接入部署 Secret Manager 的空间，但不建设配置中心。
- 不提供 Secret 的 JSON/Text Marshal 明文实现。

## 7. Diagnostics 契约

### 7.1 状态定义

| 状态 | 含义 | 示例 |
|---|---|---|
| healthy | 检查成功，满足要求 | DB Ping 成功 |
| degraded | 检查可运行但能力受限/质量未达目标 | 可选 Provider 缺失、覆盖率偏低 |
| unavailable | 依赖或目标能力当前不可访问 | DB 连接失败、远端服务不可达 |
| skipped | 明确未执行或不适用 | 未配置可选凭证、功能未启用 |
| failed | Check 自身执行异常或违反检查契约 | Panic、内部实现错误、结果无效 |

`skipped` 不是失败；可选项 skipped 不单独使总体状态降级。必需项不能以 skipped 隐藏缺失配置，必须在注册描述中声明 required。

### 7.2 接口形状

```go
package diagnostics

type Status string

const (
    StatusHealthy     Status = "healthy"
    StatusDegraded    Status = "degraded"
    StatusUnavailable Status = "unavailable"
    StatusSkipped     Status = "skipped"
    StatusFailed      Status = "failed"
)

type Descriptor struct {
    ID       string
    Category string
    Required bool
    Timeout  time.Duration
}

type Observation struct {
    Status    Status
    Summary   string
    CheckedAt time.Time
    Duration  time.Duration
    Attributes map[string]string
}

type Check interface {
    Descriptor() Descriptor
    Run(ctx context.Context) (Observation, error)
}

type Registry interface {
    Register(check Check) error
    Checks() []Check
}

type Runner interface {
    Run(ctx context.Context, ids ...string) Report
}
```

### 7.3 执行与聚合规则

- Check ID 全局唯一；重复注册必须返回错误，不能覆盖旧 Check。
- 每个 Check 有独立 Timeout；Runner 有总 Deadline 和最大并发数。
- Runner 负责 panic recovery、超时、结果时间和错误分类。
- Check 不应在内部无限重试；需要重试时由 Check 明确声明且必须受总 Deadline 约束。
- 必需 Check 未配置：返回 failed 或 unavailable，并标记明确 Code（不能 skipped）。
- 非必需 Check 未配置/未启用：skipped。
- 返回未知 Status、空 ID 或非法结果：failed。
- 聚合优先级：failed > unavailable > degraded > healthy；skipped 不参与降级计算。
- 若所有 Check 都 skipped 或无适用 Check，总体为 skipped，而不是 healthy。
- Report 同时返回每项结果和总体状态；不能只返回一个布尔值。
- Details/Attributes 仅允许低敏感、低基数信息；不得输出凭证、连接串或完整 Provider 原始响应。
- 平台只提供执行框架；Data 的 Freshness/字段质量、News 的正文质量、Research 的 Evidence 完整性由领域 Check 实现。

## 8. HTTP Client Policy 契约

### 8.1 Policy

```go
package httpclient

type RetryMode string

const (
    RetryNever       RetryMode = "never"
    RetryIdempotent  RetryMode = "idempotent"
)

type RetryPolicy struct {
    Mode       RetryMode
    MaxAttempts int
    BaseDelay  time.Duration
    MaxDelay   time.Duration
}

type Policy struct {
    TotalTimeout          time.Duration
    ConnectTimeout        time.Duration
    ResponseHeaderTimeout time.Duration
    MaxResponseBytes      int64
    MaxIdleConnsPerHost   int
    Retry                 RetryPolicy
}

type Doer interface {
    Do(req *http.Request) (*http.Response, error)
}

type Factory interface {
    New(policy Policy) (Doer, error)
}
```

### 8.2 固定语义

- 每个请求有总 Deadline；DNS、连接、TLS、响应头、Body 读取和重试共同消耗预算。
- 非幂等请求默认 RetryNever；不能仅根据 HTTP 方法推断业务幂等性。
- RetryIdempotent 必须由调用方明确声明，并对 429、部分 5xx、网络瞬时错误使用有限退避；不重试认证/授权/参数错误。
- 重试次数、退避和 Retry-After 都受总 Deadline 约束。
- 响应 Body 必须限制最大读取字节数；超限返回明确错误并关闭 Body。
- Client 必须复用 Transport/连接池；禁止每个请求新建 Transport。
- 请求上下文中的 Request ID/Trace Context 自动传播；禁止传播身份 Header 或 Provider 凭证到不匹配的目标 Host。
- 不在公共层自动记录 URL Query、请求 Body 或响应 Body。
- 业务 Provider 自己负责数据解析、业务限流配额和错误语义；平台只负责通用传输治理。

## 9. Storage / Migration 契约

### 9.1 所有权

- MariaDB 是持久化事实源；Redis 是缓存和短期协调。
- 领域模块拥有自己的 SQL、Repository、表结构和数据保留策略。
- 平台只定义连接生命周期、通用健康接口和 Migration 执行治理。
- 不创建万能 Repository，不把 Data/News/Research 表迁入 platform schema。

### 9.2 Migration 元数据

建议稳定标识为 `<namespace>/<version>`，例如 `platform/0001`、`data/0042`。namespace owner 负责 Migration 内容，统一 Runner 负责校验唯一性、排序、执行记录和并发互斥。

契约要求：

- 注册阶段拒绝空 ID、重复 ID、非法版本和空 Up 实现。
- 执行顺序确定且可重复得到相同结果。
- 记录状态至少区分 running、succeeded、failed；失败保留安全错误摘要。
- 并发启动只能有一个 Runner 执行同一数据库的 Migration。
- MariaDB DDL 可能隐式提交，不能假设整批 Migration 可以事务回滚；Migration 必须设计为可检测、可重入或提供明确前向修复。
- 生产迁移由显式部署步骤执行，不允许每个服务实例启动时无协调地自动改表。
- 平台分支不修改服务端集成分支的 Migration 总入口；由集成分支负责最终装配。

## 10. 任务 / Audit 的契约预留

PLAT-002 只冻结边界，不实现 Task Runner 和 Audit：

- Task 只存执行生命周期元数据，业务输入/结果由领域存储。
- Task 创建时固化 Actor/Scope/Request ID/Trace 快照；Worker 不接受客户端重建身份。
- 状态转换受控，终态不可被普通 Worker 覆盖。
- 租约、心跳、恢复和副作用幂等由 PLAT-010 冻结细节。
- Audit 记录主体、动作、资源、结果、拒绝原因、关联 ID、时间；不保存密钥明文或凭证摘要。
- 审计写入失败时，敏感管理操作默认 fail-closed；普通业务日志不替代审计事实。

## 11. 契约测试计划

平台实现必须提供可独立运行的契约测试。测试不依赖真实外部 Provider。

| 契约 | 必测场景 |
|---|---|
| Identity | 匿名上下文、Principal 复制隔离、Scope 精确匹配、job Actor 恢复 |
| Security | 无凭证、错误凭证、主体类型不匹配、Scope 不足、伪造身份 Header、未声明路由默认拒绝、路径/方法绕过 |
| Fault | Class/Code 稳定、Unwrap、未知错误映射、响应不泄露 Cause |
| Request ID | 缺失生成、合法透传、非法重建、响应回写、跨服务传播 |
| Trace | 合法/非法/全零 traceparent、Span 更新、与身份完全隔离 |
| Logger/Redaction | Authorization/Cookie/DSN/Provider Key/Service Key 不泄露 |
| Config | 默认值、环境覆盖、必填项、非法格式、Secret 脱敏、dotenv 不覆盖既有环境变量 |
| Diagnostics | 重复注册、并发上限、单项超时、总超时、panic、skipped 语义、聚合优先级、敏感属性过滤 |
| HTTP Client | 总 Deadline、非幂等不重试、幂等有限重试、429/5xx、Retry-After、响应体超限、连接复用、Body 关闭 |
| Migration | 重复 ID、排序稳定、并发互斥、失败留痕、DDL 部分完成后的恢复 |
| Module Boundary | 平台 package 不 import 业务 package；根 module 与行情独立 module 不发生 internal 跨模块引用 |

## 12. 版本、兼容与变更治理

- 本契约评审版本为 `v1.0.0-review`；评审通过后冻结为 `v1.0.0`。
- 新增可选字段/接口方法、增加可选状态或扩展错误 Code，按兼容性评估决定次版本。
- 删除字段、改变状态含义、放宽默认权限、改变错误映射、改变重试默认值均属于破坏性变更，必须升主版本并同步所有接入分支。
- 公共 DTO 的 JSON 字段采用 snake_case；Go 字段采用 PascalCase。
- 时间统一 UTC RFC3339Nano；超时使用 Go duration 配置，不在 JSON 中传裸纳秒。
- Scope、Status、Error Class 和 Migration ID 均为稳定机器标识，不依赖展示文案。
- 未冻结的内部实现类型不得出现在业务模块的函数签名中。
