# 公共平台最小契约规范（PLAT-002）

- 契约版本：v1.0.0-review（个人使用范围收敛稿）
- 状态：平台分支设计稿，待 Data / News / Research / Server 集成方评审
- 所属分支：feat/platform-foundation
- 适用范围：根 Go module 内的公共平台 package；独立服务通过 HTTP 契约和领域 Adapter 接入

本文只冻结当前真实需要的跨模块语义，不代表所有 package 均需立即创建。接口以 Go 标准库和现有依赖为优先；不为理论上的高并发预留分布式组件。

## 1. Package 与依赖边界

首期按需创建以下 package，不预建空目录：

| Package | 稳定职责 | 首期不包含 |
|---|---|---|
| security | 访问模式、认证结果、可信身份上下文、路由授权 | 用户中心、组织/租户、动态策略引擎 |
| security | 基于配置 Secret 验证 owner/service 身份并建立上下文 | 动态凭证 CRUD、用户中心、策略引擎 |
| config | 类型化配置装载、校验、Secret 脱敏 | 远程配置中心、热更新 |
| fault | 稳定错误类别、Code、安全摘要 | HTTP Handler、领域错误规则 |
| observability | Request ID、slog 字段和敏感信息过滤 | Span SDK、Trace Collector |
| diagnostics | Check 执行、结果、有限并发和简单聚合 | 插件系统、复杂历史分析 |
| httpclient | Transport 复用、超时、响应上限、有限重试 | 通用熔断/自适应限流平台 |
| storage / migration | 仅在有多个调用方时抽取连接生命周期和 Migration 约定 | 万能 Repository、多集群编排 |
| task | 仅在多个领域真实共享长任务生命周期时抽取 | 通用工作流、分布式调度 |
| audit | 先以必要管理事件记录为准，不要求独立框架 | 全量业务审计平台 |

依赖方向：

    cmd / transport / bootstrap
       -> platform/*
       -> application -> domain / ports
    adapters -> ports

platform 不得 import Data、News、Research、Notification 或 WebUI；不得访问领域表和领域 Repository。根 module 与行情独立 module 不允许 internal 跨模块引用，行情服务通过 HTTP 契约和本地 Adapter 接入。

## 2. 身份与访问模式

首期只区分：
- anonymous：明确白名单的 liveness 等接口；
- owner：单一所有者管理操作，由部署环境注入独立 PLATFORM_ADMIN_TOKEN；
- service：调用方独立环境 Secret 认证的服务间调用。

不实现 user 注册/登录、组织、租户和 job Principal。后台任务保存创建来源与 Request ID，不允许客户端在执行时声明可信身份。

所有路由必须显式声明访问模式；未声明默认拒绝。公开路由不代表绕过请求体限制、超时和安全日志。

## 3. 服务凭证与最小授权

首期采用部署 Secret 注入：owner 使用独立 PLATFORM_ADMIN_TOKEN；每个 service 调用方使用独立环境 Secret。Secret 至少 256 bit 随机熵，通过 Bearer 传递，服务端常量时间比较验证。不建凭证表、不提供动态 Key CRUD API，不依赖 Redis 缓存认证结果。

凭证通过部署 Secret 更新轮换；更新后旧值拒绝。Provider Token 与内部服务 Secret 完全分离。只有动态撤销、无停机轮换或大量调用方管理成为真实需求时，才另行设计 Key ID、摘要存储和生命周期管理。

首期权限采用少量固定权限组，不做通配符、隐式继承和动态策略。身份与 Scope 分离：凭证确认调用方，路由 Scope 决定可执行能力。

## 4. Fault 契约

错误至少包含：
- Class：validation、unauthenticated、forbidden、not_found、conflict、unavailable、timeout、internal；
- Code：稳定机器标识，如 platform.key_revoked、data.provider_unavailable；
- SafeMessage：可对调用方展示的安全摘要；
- Dependency：可选的稳定逻辑依赖标识（如 news.provider.tavily、storage.mariadb），不得填写完整 URL、IP、凭证或用户输入；
- Retryable：布尔提示，表示该错误在技术上可作为重试候选，默认 false；
- Cause：仅内部错误链，不序列化。

HTTP 状态码由 transport 映射。Retryable 不是“调用方必须重试”的命令：实际重试仍必须同时满足请求幂等、HTTP Policy 允许、剩余重试预算和总 Deadline；Provider/News 领域策略可以进一步禁止重试。认证/授权、参数校验、内容质量拒绝等错误不得标记为可重试。Dependency 用于定位逻辑依赖，不是错误类别，也不替代 Code/Class。错误不得泄露 SQL、DSN、Token、Key、原始 Provider 响应和堆栈。

## 5. Request ID 与日志

首期使用 X-Request-ID 贯穿同步请求和内部 HTTP 调用：
- 入口缺失/非法时生成随机 ID；
- 响应返回最终 ID；
- 内部服务调用传播当前 ID；
- 后台任务保存创建时 ID，并记录 task_id；
- Request ID 不承担认证和授权。

日志使用标准库 slog。必要字段包括 service、environment、request_id、task_id、route、status、duration、dependency、operation、attempt、error_code。禁止记录凭证、密码、DSN、请求/响应 Body 和完整上游响应。

首期不要求 traceparent、span_id、baggage 或 Trace SDK。未来如 Request ID 不足以定位跨服务并行调用，再单独升级契约。

## 6. Config / Secret

每个服务拥有自己的 Config struct。平台统一启动装载、默认值、校验和脱敏。配置启动后作为不可变快照使用。Secret 首期由部署环境变量注入；Secret 类型的 String/日志格式必须脱敏。不得将业务配置集中到平台。

## 7. Diagnostics

### 7.1 所有权与范围

Platform 提供公共 Observation/Fault 契约、轻量 Check 执行、超时/并发限制和基础聚合；不实现 Data/News/Research/Notification 的领域诊断规则，不接管领域诊断历史或证据存储。

- Data 已有 Provider Probe、被动熔断器诊断、Validation/Reporter、Freshness、Coverage、Cross-Provider、交易上下文和 Probe 历史，继续由 Data 所有。
- News 负责来源授权、来源可用性、搜索/抓取/解析/标准化/去重/证券关联/持久化诊断。
- Research 负责 Analysis Run/Stage、输入质量、Dependency、Context 和 Evidence 诊断。
- Notification 负责渠道和 Delivery Run 诊断。
- WebUI 只消费各领域 API，不在前端计算健康度或数据质量。

### 7.2 Check 执行契约

Check 定义至少包含 ID、名称/类别、是否必需、Timeout 和副作用等级；执行结果字段统一为：

| 字段 | 类型/约束 | 语义 |
|---|---|---|
| status | enum，必填 | healthy/degraded/unavailable/skipped/failed |
| reason_code | string，条件必填 | 稳定、可机器处理的原因标识；非 healthy 结果必须提供，使用领域命名空间，如 news.source.fetch.blocked_private_ip |
| safe_message | string，必填 | 面向诊断调用方的脱敏摘要，不包含正文、snippet、URL Query、凭证或完整上游响应 |
| checked_at | timestamp，必填 | 本次检查完成时间（UTC） |
| duration | duration，必填 | 本次检查耗时 |
| evidence_ref | string，可选 | 不透明、受权限保护的证据引用；只引用领域拥有的 Observation/证据，不内嵌证据内容，不保证平台可直接读取 |
| attributes | object，可选 | 仅允许有界、低敏感的结构化标量；限制字段白名单和总大小，不放任意 JSON/原始响应 |

reason_code 与 evidence_ref 不是新闻专属字段；所有领域可以按同一规则使用。reason_code 由产生该 Check 的领域维护稳定词汇，平台不维护跨领域的大枚举。evidence_ref 由证据所有者解释和授权，平台只透传，不解析、不自动访问。没有持久化证据时可省略 evidence_ref。

状态：healthy、degraded、unavailable、skipped、failed。

- 可选 Provider 未配置：skipped/not_configured；
- 必需依赖缺失：failed 或 unavailable，不得 skipped；
- 单项超时/异常不能阻断其他检查；
- 总执行时间和并发有上限；
- 公开接口只返回总体最小状态，详细诊断需要 owner/service 授权；
- Data/News/Research 保留自己的质量规则，平台只负责执行和聚合。

首期以实时检查为主，不要求诊断历史库。

### 7.3 状态与聚合规则

平台状态只用于 Check 执行和基础能力摘要。领域可保留更细状态，例如 Data 的 ProviderOutcome、Quality、Freshness；Adapter 映射时不得丢失领域状态和质量维度。平台不将 HTTP 200 等同业务健康，也不把质量异常误标为 Check 执行器失败。

- 每项 Check 独立执行；单项失败/超时不阻断其他项。
- 总 Deadline 和最大并发必须有上限。
- optional 未配置/不适用为 skipped，必须提供 reason_code；required 依赖缺失不能 skipped。
- 诊断默认只读；真实写入、通知或高成本全量探测必须显式授权。
- 公开 Liveness 仅返回最小状态；详细诊断受 owner/service 保护。

### 7.4 历史与证据所有权

首期不建设通用诊断历史数据库。Data Probe Run、News Ingestion Run、Research Analysis Run、Notification Delivery Run 和各自证据由领域保存。平台只透传可选 evidence_ref、run_id/task_id 等关联标识，不解析 evidence_ref、不访问领域表、不替代领域历史 API。

## 8. HTTP Client

Policy 至少包含总 Timeout、连接/响应头超时、MaxResponseBytes、有限 Retry、逻辑 Dependency 和 MaxConcurrent 配置。Source Fetch 还必须提供 DestinationPolicy；其安全语义不得通过关闭校验或默认代理绕过。

- 复用 Transport 和连接池；
- 所有请求支持 context 取消；
- 非幂等请求默认不重试；
- 只有调用方明确声明幂等的请求才允许有限重试；
- 重试次数和退避不能超过总 Deadline；
- 不记录请求/响应 Body 或敏感 Query；
- Provider 配额和领域限流由 Data/News Adapter 管理；
- Redirect 默认禁止，允许时必须逐跳校验 URL 与来源策略；
- DestinationPolicy 必须校验 host/port 和 DNS/IP，且受控 DialContext 必须连接已校验的 IP，防止 DNS rebinding；
- 不可信 URL 默认禁用环境代理；
- Source Fetch 不允许任意 URL 输入，必须使用已登记 source/endpoint 并执行领域授权策略；
- 每个逻辑 dependency 可设置并发上限。

## 9. Storage / Migration

MariaDB 是持久化事实源，Redis 是缓存和短期辅助状态。领域拥有自己的表、SQL 和 Repository。平台只提供连接生命周期、健康检查和 Migration 版本/执行约定。

Migration 使用唯一 namespace/version，显式执行并记录成功/失败。首期按单实例执行，不设计多集群锁和分布式迁移编排。

## 10. 长任务边界

PLAT-002 只冻结原则，不定义完整通用 Task Runner。只有长耗时且需要后台执行的业务使用持久化任务；快速查询直接同步返回。MariaDB 保存状态和幂等事实，Worker 并发有上限。首期按单实例运行；多实例、租约、fencing 和 Outbox 在真实需要出现时重新评审。

## 11. 契约验收

- 平台包不依赖领域包，根 module 与行情 module 无 internal 跨模块引用；
- 路由默认拒绝，owner/service/anonymous 不能互相冒充；
- owner/service 使用独立部署 Secret；缺失凭证默认拒绝，伪造 Header 无效，Secret 不进入日志；
- Request ID 可关联请求、内部调用和后台任务；
- 配置错误快速失败且不泄露 Secret；
- Diagnostics 能区分必需依赖失败、可选能力 skipped 和数据质量异常；
- HTTP 超时、响应大小、取消、幂等重试、SSRF/DNS rebinding/重定向逐跳校验和按依赖并发限制有测试；
- Diagnostics 结果字段统一包含 reason_code、safe_message，可选 evidence_ref；
- Fault 统一包含 Retryable 与可选 Dependency，实际重试仍受幂等和 Retry Policy 约束；
- DB/Redis 故障行为明确，Migration 有版本和失败记录；
- 不要求 OAuth/OIDC、Trace 后端、Metrics 存储、消息队列或分布式任务调度。


## 12. 跨模块诊断契约补充

- Data 既有 Probe/Validation/Freshness/Coverage 等领域模型继续保留；平台只提供适配目标，不强制重写。
- Observation 的 reason_code 按领域命名空间维护；平台不建立全领域原因大枚举。
- evidence_ref 是不透明引用，由领域证据所有者解释、授权并决定保留期限。
- Fault.Dependency 是稳定逻辑依赖标识，不得包含 URL/IP/Secret；Retryable 仅为技术候选提示。
- 领域诊断历史不集中写入平台库；平台摘要不得成为领域事实来源。


## 13. 首期 Go Module 落点补充

首期公共实现位于根 Go Module 的 `internal/platform`，不新增独立 `platform/go.mod`。

- 根服务和根 Module 内的 News 等领域可以直接依赖平台 package。
- Data 的行情服务是独立 Module，其诊断规则、Probe、质量报告和历史仍由 Data 自己维护；通过 HTTP API/Adapter 对接，不跨 Module 引用根模块 `internal`。
- `go-core` 当前作为历史/迁移路径，不要求接入首期公共平台。
- 平台公共契约以稳定 HTTP/JSON 字段表达跨服务语义；Go package 复用仅发生在同一 Module 内。
- 当多个独立 Module 确实需要共享同一份可执行实现时，再独立评审公开 Module 和版本治理，不提前承担发布成本。


## 14. PLAT-007 首期聚合语义

- 必需 Check 执行失败时，总体状态为 `failed`；必需 Check 不可用或超时时，总体状态为 `unavailable`。
- 任意 Check 为 `degraded`，或可选 Check 执行失败/不可用，总体状态为 `degraded`。
- 可选 Check 主动返回 `skipped` 不降低总体状态；全部 Check 均为 `skipped` 时总体状态为 `skipped`。
- 因总 Deadline/取消而未启动的 Check 属于 `unavailable`，不能伪装成 `skipped`；可选项未执行同样会使总体状态降级。
- 必需 Check 返回 `skipped` 属于契约错误，按 `failed` 处理。
- 总体状态优先级：必需失败 > 必需不可用 > 降级/可选失败 > 健康；全跳过单独返回 skipped。
- Check 按输入顺序返回结果，执行并发不改变结果顺序。重复 ID、缺少执行函数和非法超时在启动前整体拒绝。
- 单项执行超时和总 Deadline 均通过 context 传递。Check 实现必须响应 context 取消；Go 不能安全地强制终止不遵守取消约定的函数。


## 15. HTTP Client 首期安全实现约束

- DestinationPolicy 必须逐请求传入，Dependency 使用稳定逻辑标识；AllowedHosts 为精确匹配，不支持通配符。
- AllowedPorts 未显式配置时仅允许 HTTPS/443；显式启用 HTTP 后才允许 HTTP/80。非默认端口必须列入 allowlist。
- DNS 任一 A/AAAA 结果落入禁止地址段时，整个目标拒绝；IPv4-mapped IPv6 一律拒绝。
- 受控 DialContext 在每次新建连接时重新解析和校验，并直接连接通过校验的 IP；不能在校验后再由默认 Dialer 解析 hostname。
- 环境代理关闭；请求自定义 Host 头拒绝；重定向默认关闭，显式开启最多 3 跳并逐跳重新验证，禁止 HTTPS 降级。
- 响应体默认上限 2 MiB，配置最大 16 MiB；依赖并发默认 4，最大 32；请求总超时覆盖并发等待、DNS、连接、响应头和响应体读取；重试最多 2 次且必须显式声明幂等。
- 这些实现约束不替代 News 来源授权；平台只负责网络目标安全和通用执行策略。
