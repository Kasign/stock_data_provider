# 服务接入统一验收清单

## 1. 目的与适用范围

本文是平台公共原语交付给 Server、Data、News、Research 集成方的统一接入清单。它不替代各领域自己的业务验收，也不授权平台分支修改其他分支。

平台包级 CI 通过只证明公共原语在其测试边界内符合约定，不代表服务入口、真实路由、领域 Adapter、生产网络或部署配置已经接入。

## 2. 接入责任边界

| 集成方 | 必须负责的工作 | 不应做的事 |
|---|---|---|
| Server / Data 集成分支 | 根服务 bootstrap、Config 组合、DI、全局路由、服务级认证装配、Migration 总入口 | 不复制一套平台 security/config/diagnostics 实现 |
| Data 领域 | Provider Probe、质量校验、Freshness、Coverage、Cross-Provider、Probe 历史与领域 API | 不将领域质量规则迁入 Platform |
| News 领域 | 来源授权、Provider endpoint 配置、新闻采集诊断、Ingestion Run；根 Module 内按契约注入 BoundDoer | 不把 Provider endpoint allowlist 当作来源授权；不注入裸 http.Client 绕过平台网络策略 |
| Research 领域 | Analysis Run/Stage/Task/Worker、Context/Evidence 和领域诊断；独立 Module 通过 HTTP 契约对接 | 不将 Analysis 领域状态机和表结构迁入 Platform |
| Platform | 稳定公共原语、包级测试、契约文档和接入差异评审 | 不修改其他分支启动入口、全局路由、领域 Repository 或 Migration 总入口 |

根 Go Module 内的领域可按 Go internal 规则直接复用 `internal/platform`。独立 Go Module（如 Data 服务、历史 go-core）不得跨 Module import 根模块的 `internal` 包，应通过 HTTP/JSON 契约和本地 Adapter 对接。

## 3. Bootstrap 与 Config（PLAT-005）

- [ ] dotenv（如启用）只在 bootstrap 最早阶段加载；生产 Secret 由部署环境注入。
- [ ] 每个服务有自己的类型化 Config struct，不建立平台全局业务配置。
- [ ] 通过 `config.Env` 一次性读取配置；业务 handler、domain、use case 和 Worker 不直接调用 `os.Getenv`。
- [ ] Config loader 负责默认值、类型解析、必填项、数值范围和跨字段校验。
- [ ] 所有配置校验完成后再初始化 DB、Redis、HTTP Client、Provider 和 Worker；失败时服务启动失败。
- [ ] 错误只指出配置键和错误类型，不回显输入值。
- [ ] Secret 使用 `config.Secret` 保存；只在构造认证客户端等必要位置显式调用 `Value()`。
- [ ] 禁止把 Secret 转成普通字符串写入日志、错误、诊断、响应或配置快照。
- [ ] 配置加载后作为不可变快照使用；不在业务流程中重新读取环境变量。
- [ ] dotenv 测试覆盖：缺失文件、进程环境优先、引号/注释、非法键/值、文件解析失败不产生部分环境变量写入。

**验收测试：**
1. 缺失必需配置、非法类型、非法范围和跨字段冲突均启动失败。
2. 错误输出不包含输入值或 Secret。
3. Secret 经 fmt、slog、JSON/Text 序列化均脱敏。
4. 服务业务代码不存在绕过 Config loader 的环境变量读取。

## 4. Authentication 与 Route Policy（PLAT-003）

- [ ] 服务启动时通过部署 Secret 构造 Authenticator；owner 与每个 service 使用独立高熵 Token。
- [ ] Token 至少 32 字节；部署侧使用密码学安全随机数生成，不把长度检查当作随机熵证明。
- [ ] 路由统一注册到 security.Router；每条路由必须显式声明 Anonymous/Owner/Service/OwnerOrService 策略。
- [ ] 不保留绕过认证 Router 的第二套 ServeMux、裸 Handler 注册或调试路由。
- [ ] 只有最小 liveness 路由匿名；readiness 不公开依赖明细，按部署边界或 owner/service 策略保护。
- [ ] 业务读取、写入、研究任务、管理和诊断明细分别声明最小身份与 Scope。
- [ ] owner 不自动继承 service Scope；service 必须满足路由声明的全部 Scope。
- [ ] 只接受 Authorization: Bearer；拒绝重复 Header、错误 scheme 和无效 Token。
- [ ] 不信任 X-Identity、X-Principal 等客户端身份 Header；Principal 只从认证 Context 获取。
- [ ] 错误语义固定：缺失/无效凭证 401；已认证但身份或 Scope 不足 403。
- [ ] 未注册路由保持 404；不得通过 catch-all 将未知路径意外暴露。
- [ ] Authorization、Token 和 Secret 不进入访问日志、应用日志或错误响应。

**验收测试：**
1. 匿名 liveness 可访问；匿名访问受保护路由返回 401。
2. 错误 Token、错误 scheme、重复 Authorization Header 返回 401。
3. owner 不能冒充 service；无 Scope 或 Scope 不足返回 403。
4. 伪造身份 Header 不改变 Principal。
5. 未注册路径返回 404；零值/非法 RoutePolicy 无法注册。
6. 所有业务路由均经过受保护 Router；测试应枚举路由清单，防止漏保护。

**凭证轮换：**
- 首期按部署 Secret 更新和服务重启执行；轮换后旧 Token 必须失效。
- 记录调用方、被调用服务、变更顺序和回滚方式。
- 当前不支持同一 service 主体同时配置新旧两个 Token；如未来要求无停机轮换，必须重新评审双凭证过渡能力，不得在集成层私自绕过。

## 5. Request ID、日志与 Fault（PLAT-006）

- [ ] HTTP 入口使用统一 Request ID Middleware，响应返回最终 Request ID。
- [ ] 公网入口若不信任客户端 Request ID，由可信 Gateway 覆盖/清理后再传入；Request ID 不用于认证、授权或主体识别。
- [ ] Request ID 恰好一个且格式合法时才可保留；缺失、重复、非法或超长 Header 必须重新生成，不能从重复值中任选一个。
- [ ] Request ID Middleware 位于 Recovery、Access Log 和业务 Router 外层，使错误响应和日志都能关联请求。
- [ ] 内部 HTTP 调用从 Context 传播 Request ID。
- [ ] 任务可将 `originating_request_id` 作为创建来源元数据持久化；Worker 执行和重试通过独立 `correlation_id` 关联，并恢复 task_id/run_id；不得把来源 Request ID 恢复为 Worker 当前 Request ID。
- [ ] Access log 使用路由模板，不记录原始 Query、Body、Authorization、Cookie 或完整 URL。
- [ ] Fault 对外只返回稳定 Class/Code/SafeMessage；Cause 仅供内部受控诊断，不序列化给客户端。
- [ ] SafeMessage、Code、Dependency 由生产者按白名单构造；禁止直接放入 err.Error()、SQL、DSN、Token、URL 或原始上游响应。
- [ ] 日志采用结构化字段白名单；不能依赖 Fault 或 Secret 类型自动清洗任意普通字符串。
- [ ] Recovery 不向客户端输出 panic 内容/堆栈；日志只保留必要关联元数据。

**验收测试：**
1. 单个 Request ID 能关联入口、出站依赖请求和后台任务。
2. 非法/超长 Request ID 被重新生成；外部有效格式 ID 的信任边界符合部署策略。
3. 注入包含 DSN、Token、SQL 的底层错误，响应 JSON 和受控日志不出现秘密。
4. Access log 不包含 Query、Body、凭据和任意用户输入路径参数。
5. Panic 响应不泄露 panic 内容或堆栈。

## 6. Diagnostics（PLAT-007）

- [ ] Platform Runner 只执行只读、可取消的 Check；Check 必须遵守 Context 取消约定。
- [ ] 每个服务由集成层创建领域 Adapter，并明确 Required、Timeout 和总 Deadline。
- [ ] Data 保留 Provider Probe、Validation/Reporter、Freshness、Coverage、Cross-Provider 和 Probe 历史。
- [ ] News 保留来源授权、抓取/解析/标准化/去重和 Ingestion Run 诊断。
- [ ] Research 保留 Analysis Run/Stage、Dependency、Context、Evidence 和可复现性诊断。
- [ ] Adapter 将领域状态映射到 Observation 时，不得丢失 ProviderOutcome、Quality、Freshness 等领域维度。
- [ ] 每个领域 Adapter 有独立映射说明，列出源状态、公共 Status、reason_code 和 Required/Optional 语义；不把不同质量维度压成单一健康状态。
- [ ] Adapter 只调用领域只读诊断接口，不跨领域查表、不触发任务/通知/写入型探测。
- [ ] dependency 使用逻辑名称白名单；safe_message 为固定脱敏摘要；attributes 按字段白名单逐项构造。
- [ ] evidence_ref 保持不透明并由领域授权；公共 Report 不携带原始证据、响应正文、snippet、模型上下文或错误堆栈。
- [ ] Adapter 测试注入 Token、DSN、URL Query 和原始上游错误，断言 Observation/Report JSON 不泄漏。
- [ ] 无法可靠映射的领域状态不得猜测为 healthy 或 skipped，应返回固定失败摘要并保留受控内部 Cause。
- [ ] optional 未配置/不适用返回 skipped + reason_code；required 依赖缺失不得 skipped。
- [ ] Check 超时/失败不得阻断其他独立检查；总 Deadline 触发时未启动项不得伪装为 skipped。
- [ ] 公开接口只返回最小存活/就绪摘要；详细诊断路由必须由 security.Router 显式保护。
- [ ] 写入、通知、高成本全量探测不作为普通 Runner Check 暴露，必须由领域侧显式授权和编排。
- [ ] evidence_ref 由领域拥有和授权；Platform 只透传，不解析、不访问领域存储。
- [ ] 不建设 Platform 通用诊断历史数据库。

**验收测试：**
1. 覆盖 healthy/degraded/unavailable/skipped/failed 及 required/optional 聚合。
2. 单项超时、异常、总 Deadline 和 Context Cancel 均有确定结果。
3. 详细诊断无凭证返回 401、权限不足返回 403。
4. 诊断结果不含 Secret、URL Query、正文、snippet 和原始 Provider 响应。
5. Data/News/Research 领域状态和证据引用可追溯。

## 7. 安全 HTTP Client（PLAT-008，适用于真实外部抓取）

- [ ] 每个固定 Provider endpoint 由组合根创建独立 BoundDoer，绑定精确 Host/Port 和 Dependency。
- [ ] 不使用裸 http.Client 绕过 DestinationPolicy。
- [ ] Provider API endpoint allowlist 与 News 来源授权 allowlist 分开维护。
- [ ] DNS/IP 校验、实际 Dial 绑定、私网/保留地址拒绝、代理禁用和重定向逐跳校验均通过测试。
- [ ] 请求 Context、总 Deadline、响应体上限和有限幂等重试生效。
- [ ] 非幂等请求不自动重试；重试不突破总 Deadline。
- [ ] 真实生产抓取开放前，完成部署 DNS/网络出口策略和来源授权验收。

## 8. 集成顺序与交付证据

推荐顺序：

1. 服务 Config loader 与启动失败校验；
2. Authenticator 构造和全量路由策略登记；
3. Request ID、Recovery、Access Log 和 Fault 响应统一；
4. 领域 Diagnostics Adapter 与受保护路由；
5. HTTP Client/BoundDoer 按 endpoint 注入；
6. 契约测试、部署验证和凭证轮换/故障演练。

每个集成方交付：
- 变更文件与负责模块；
- 路由访问矩阵（method、route、identity、scope）；
- Config 字段清单及 required/optional；
- Diagnostics Check 清单和 required/optional 说明；
- 自动化测试结果及精确 CI commit SHA；
- 尚未完成的生产环境验证项，不得将静态测试描述为部署验收。

## 9. 当前平台基线

本清单对应平台分支当前实现方向。包级验证记录必须以各自提交 SHA 和 Actions Run 为准：

- Security：缺失凭证 401、身份/Scope 不足 403 的回归测试已加入。
- Config：Secret 脱敏、类型解析和 dotenv 先解析后应用的回归测试已加入。
- Observability/Fault：Request ID 格式边界、Context 传播和 Cause 不序列化已实现；真实入口/Worker/日志接入待验收。
- Diagnostics：Runner 与聚合原语已实现；领域 Adapter 和 HTTP 路由授权待验收。
- HTTP Client：平台安全网络执行和 BoundDoer 已实现；生产 DNS/出口与 News 真实注入待验收。

本清单不是“全部已完成”的声明。平台原语、领域接入、服务装配和生产运行验证必须分别记录状态。

## 11. PLAT-007 诊断路由权限矩阵与验收要求（2026-11-05）

- [ ] liveness 仅允许返回最小存活状态，使用 `AnonymousAccess()`。
- [ ] readiness 默认受保护；若部署探针必须匿名访问，需单独记录原因，并测试响应不含依赖名、错误摘要、地址、耗时明细和 evidence_ref。
- [ ] Platform 基础设施详细诊断使用 `OwnerAccess()`。
- [ ] Data 领域诊断使用 `OwnerOrServiceAccess(ScopeDataDiagnose)`，并保留 Data 原有 Probe/Quality/History。
- [ ] Research 只读诊断使用 `OwnerOrServiceAccess(ScopeResearchRead)`，不得借此获得 Research Run 权限。
- [ ] News/Notification 在专属 Scope 尚未由真实调用方需求确认前使用 owner-only；禁止借用无关 Scope。
- [ ] 所有详细诊断路由显式注册到 `security.Router`；无凭证 401、Scope 不足 403、未注册路径 404。
- [ ] 诊断 GET 路由不得触发写入、真实通知或高成本全量探测；此类动作须由领域侧另行授权和编排。

当前平台仅提供 Runner/Observation 和 Security 路由策略原语，尚无证据表明上述服务路由及领域 Adapter 已接入。该矩阵是后续集成要求，不是完成声明。


## 12. PLAT-006 Recovery / Access Log 接入补充门禁（2026-11-05）

本轮平台审查基线：`8806593e78ce54917492c6427b1ab90746681cb3`。

- [ ] 不得把历史 Analysis HTTP transport 内的私有 Request ID、Recovery、Access Log 视为 Platform 公共能力。
- [ ] Request ID 统一使用平台 Middleware；重复、非法、缺失值必须重新生成。
- [ ] Access Log 记录 ServeMux 路由模板，不记录任意原始 Path、RawQuery、完整 URL、请求/响应 Body、Authorization 或 Cookie；未匹配路由使用固定占位值。
- [ ] Recovery 只记录 request_id、route pattern、method、panic 类型等受控元数据，不输出 panic 原文或堆栈，不将其写入客户端响应。
- [ ] Recovery 必须识别响应是否已经提交：未提交时返回固定安全 500；已提交时不得二次写入状态或追加错误 JSON。
- [ ] ResponseWriter 包装不得静默丢失 Flush/Hijack/Pusher/ReaderFrom 等可选能力；若明确不支持流式/升级连接，必须在接口契约和测试中限制。
- [ ] Access Log 与 Recovery 使用显式注入的结构化 logger，不依赖可变全局 Logger。
- [ ] 中间件顺序为 Request ID 最外层、Access Log 次外层、Recovery 包裹业务 Handler，确保 panic 后仍记录请求完成信息。
- [ ] Fault 的 Cause 只用于内部错误链；响应只输出稳定 Class/Code/SafeMessage。生产者不得直接把 err.Error() 填入公开字段。
- [ ] 对 readiness、领域调用失败、Store 读取失败和 JSON 输入错误分别注入含 DSN、Token、SQL、URL Query 的错误标记，断言响应不泄漏。
- [ ] 在当前仅有一个历史 transport 消费方时，不为抽象而提前固化通用中间件；由 Server/Analysis 集成方先完成真实接入评审。出现第二个独立消费者后，再评估公共 Recovery/Access Log 原语。

**当前审查结论：** Platform 只提供 Request ID/Fault 原语；Recovery/Access Log 平台实现待真实多服务需求确认。历史 Analysis transport 的重复 Request ID、原始 Path 日志和错误响应脱敏问题由对应集成分支修复，本 Platform 分支不越界修改。


## 13. PLAT-006 Fault → HTTP 映射与公开响应验收（2026-11-05）

- [ ] HTTP transport 只按 Fault Class 映射状态码：validation 400、unauthenticated 401、forbidden 403、not_found 404、conflict 409、unavailable 503、timeout 504、internal 500。
- [ ] 未知/空 Class、nil Fault、非法 Fault 和普通未知 error 统一兜底为固定 internal/500；不得猜测成 4xx。
- [ ] 401 的 `WWW-Authenticate` 由认证中间件负责，Fault mapper 不自行推断或覆盖认证挑战。
- [ ] timeout 只用于同步等待下游/网关超时；客户端取消/断开时停止工作，不伪造 504。
- [ ] Retryable 不改变状态码，不自动生成 Retry-After；只有接口明确掌握重试时间和策略时才可设置该 Header。
- [ ] 使用独立公开 Error DTO，不直接序列化内部 Fault；公开字段仅为 Class、Code、固定 SafeMessage、Retryable。
- [ ] Dependency 默认不公开；确需公开时必须经过独立公开枚举映射，不能透传内部逻辑依赖名。
- [ ] Cause 永不进入响应、公共日志字段、诊断 Attributes 或错误 DTO。
- [ ] 缺少 SafeMessage 时使用 Class 固定默认摘要，不回退到 Cause.Error()。
- [ ] Code/SafeMessage 不得包含动态 ID、用户输入、URL、SQL、DSN、Token、上游响应或堆栈。
- [ ] 普通未知 error、非法 Fault、未知 Class 的响应保持相同安全兜底结构；内部日志通过受控字段保留错误类型和 Cause。
- [ ] 对每个 Class 验证状态码、响应 JSON 和 Header；额外覆盖未知 Class、空字段、nil、Cause 含 DSN/Token/SQL、Dependency 含内部主机标识。
- [ ] 验证领域 Handler 不自行决定同类 Fault 的 HTTP 状态码；认证中间件与 Fault mapper 不重复写响应。

**实现边界：** Platform Fault 包不依赖 `net/http`。当前只有一个历史 HTTP transport 消费方，先由 Server/Analysis 集成方实现 DTO 和映射；第二个独立消费者出现后再评估公共 transport 抽取。


## 14. PLAT-006 异步任务关联标识验收（2026-11-05）

- [ ] 明确区分 request_id、correlation_id、task_id、run_id；如接入 tracing，再独立管理 trace_id。
- [ ] 每次 HTTP 请求使用独立 request_id；不得把长期 correlation_id 填入 `X-Request-ID`。
- [ ] correlation_id 由可信服务端入口/业务编排生成或从可信上游 Context 继承；不直接信任任意客户端 `X-Correlation-ID`。
- [ ] 创建任务时持久化 correlation_id 和 originating_request_id，并与 task_id/run_id 建立稳定关联。
- [ ] 幂等命中返回原任务的 correlation_id 和来源 request_id；新 HTTP 请求的 request_id 不覆盖原任务来源。
- [ ] Worker 从持久化任务记录恢复 correlation_id/task_id/run_id/originating_request_id；日志、阶段事件和失败记录可关联回任务来源。
- [ ] 重试保持原 correlation_id 和 task_id；执行 attempt 标识由领域模型按需管理。
- [ ] Worker 不将 originating_request_id 冒充当前 HTTP request_id；Worker 发起的新 HTTP 请求使用自身 request_id。
- [ ] Worker 出站传播 correlation_id 使用明确的独立协议/字段，不复用 `X-Request-ID`。
- [ ] 不把 Task/Run Schema、队列状态机或任务持久化字段迁入 Platform；Research/Analysis 领域负责其数据模型和恢复语义。
- [ ] 不在缺少第二个独立异步消费者时新增通用 TaskContext/CorrelationID 中间件；先完成领域接入验证。
- [ ] 不以 correlation_id 替代 tracing SDK/traceparent；未来接入分布式追踪时单独评审。

**审查结论：** 当前平台 Request ID 原语不需要扩展。异步任务关联缺口属于 Research/Analysis Task/Worker 领域接入，由对应领域分支实现；Platform 分支只维护跨服务契约与验收要求。


## 15. PLAT-006 Request ID 信任边界与出站传播验收（2026-11-05）

- [ ] Request ID 只作为可观测性元数据，不用于认证、授权、用户身份、幂等或防重放。
- [ ] 公网入口由可信 Gateway 覆盖/清理外部 `X-Request-ID`；应用服务不能被绕过 Gateway 直连，或必须在入口重新生成 ID。
- [ ] 内部服务只在调用方身份和网络路径可信时继承上游 Request ID；不可信来源一律重新生成。
- [ ] 合法格式不等于可信来源；日志不得根据 Request ID 推断调用方身份。
- [ ] 出站 Request ID 只从服务端 Context 读取；有 Context 值时覆盖所有调用方 Header 值并只发送一个值。
- [ ] Context 没有 Request ID 时删除请求上已有的 `X-Request-ID`，不得将未经验证的值继续传给下游。
- [ ] Request ID 不作为指标标签；高基数关联字段只进入受控日志/追踪。
- [ ] Access Log 使用 request_id、route pattern、method、status、duration、response bytes 等固定白名单字段。
- [ ] 不记录原始 URL/Query、Body、Authorization、Cookie、Secret、API Key、用户输入或未经白名单处理的 Cause。
- [ ] Request ID 只关联同步请求链；异步任务通过独立 correlation_id 关联。
- [ ] 对公网 Gateway 覆盖、绕过 Gateway 直连、内部可信传播、Context 缺失、调用方预置 Header 和重复出站 Header 分别进行集成测试。

**实现边界：** Platform 负责格式校验和 Context 出站传播；Gateway 覆盖、网络隔离、日志落地和真实服务入口接入由 Server/部署集成方负责。


## 16. PLAT-007 Runner Panic 安全边界补充（2026-11-05）

- [ ] Runner 捕获 Check panic 后只返回固定安全摘要；不得保留 panic payload、堆栈或将其写入 Fault.Cause。
- [ ] 回归测试使用包含 Token/DSN 标记的 panic payload，断言 Fault.Cause 和 Report JSON 均不包含该标记。
- [ ] Check 返回的 Fault.SafeMessage、Code、Dependency 由领域 Adapter 按白名单构造；Runner 不替代领域脱敏责任。
- [ ] HTTP transport 不得直接序列化内部 Fault；必须按独立公开 DTO 和字段白名单输出。

该补充只收紧 Runner 对 panic payload 的处理，不改变领域 Fault 字段的所有权，也不增加 Diagnostics API 字段。


## 17. PLAT-008 同源重定向与凭据隔离验收（2026-11-05）

- [ ] 默认禁止重定向；启用后首期仅允许 scheme、规范化 hostname、有效 port 均一致的同源跳转。
- [ ] 即使多个 host 都在 AllowedHosts 中，跨 host/子域跳转也必须拒绝，避免 Authorization、Cookie 或自定义 Provider 凭据被带到其他主机。
- [ ] 同源路径变化允许；HTTPS 降级、端口变化、主机变化、循环和超限均拒绝。
- [ ] 未来如需跨主机 CDN 跳转，必须设计独立凭据剥离/重建策略，不能只依赖标准库敏感 Header 清理或 Host allowlist。


## PLAT-008 并发隔离与重试退避补充验收（2026-11-05）

- [ ] 依赖级 semaphore 在网络请求、响应体读取期间生效；所有成功、失败、超时、取消路径均释放。
- [ ] 可重试传输错误和 502/503/504 响应触发退避前释放 semaphore；退避结束重新竞争槽位。
- [ ] 同一依赖并发上限为 1 时，一个请求处于退避期间，另一个请求仍可获得该槽位并完成。
- [ ] 退避期间 Context 取消后立即退出；不得重新获取槽位或泄漏并发容量。
- [ ] DNS/IP 校验的语义明确为新建连接时执行；不得宣称复用连接的每个请求都会重新解析 DNS。
- [ ] 若新增按策略区分的 IP allowlist/出口范围，重新评审 Transport 连接池隔离与连接复用策略。
