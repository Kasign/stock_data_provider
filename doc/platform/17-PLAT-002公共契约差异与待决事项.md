## 1. 总体结论

1. `08-公共平台契约规范.md` 是 Platform 候选技术契约，不是全局冻结源。项目级登记簿将 PLAT-CTR-001～007 全部标记为 `pending_evidence`；Platform package 已实现或单测通过，均不能自动升级为 `frozen`。
2. Platform 负责 Fault、Request Context、Security 原语、Config/Secret、Diagnostics Runner、受控 HTTP Client、Storage/Migration Runner 等技术能力；领域模块负责自己的 DTO、业务授权、诊断规则、Repository、Migration 内容和业务状态。
3. Server 是唯一组合根，但这只确定责任归属，不构成本分支的开发范围。本分支只交付 Platform 可被组合根调用的稳定原语、接口说明和测试证据。
4. 项目级契约登记簿于 2026-11-06 更新了 Market Data 迁入 Root Server 同 Go Module/同进程的目标架构。Platform 文档中仍有“Data 独立 Go Module”的旧表述，必须修正为“迁移目标与当前迁移阶段分开表达”，不能继续把旧 Module 边界写成永久契约。
5. 现有跨分支矩阵和 GOV-004 文档包含旧 SHA、旧目录/模块边界快照；它们只能作为历史审查证据，不能作为 2026-11-09 的最新代码状态。

## 2. 已确认一致的公共边界

| 主题 | 当前一致结论 | 权威归属 | Platform 本分支动作 |
|---|---|---|---|
| 依赖方向 | Platform 不依赖任何业务模块；领域模块只依赖 Platform 技术原语，不依赖 Platform 私有实现 | 项目契约目录 + Platform package | 保持 package 无领域反向依赖 |
| Fault | 内部 Fault 保留 class/code/safe_message/dependency/retryable/cause；cause 不序列化；retryable 不是重试命令 | PLAT-CTR-001；领域错误码由领域 Owner 维护 | 补齐/核对统一映射与安全边界，不定义领域错误码 |
| Request ID | X-Request-ID 是单次请求关联标识，不是身份、授权或幂等键；异步关联由 originating_request_id/correlation_id 承担 | GOV-CTR-003、PLAT-CTR-002 | 只提供 Context/传播原语；信任入口由服务接入方配置 |
| 身份 | anonymous/owner/service 是首期技术身份类型；业务资源授权仍归领域；凭证由部署配置注入 | PLAT-CTR-003 | 不建设用户中心、租户、动态 Service Key 或领域授权引擎 |
| Config/Secret | 每个服务拥有自己的 Config；Platform 只做基础解析和 Secret 脱敏；启动装配由组合根负责 | PLAT-CTR-007 | 不集中定义业务配置，不实现远程配置中心/热更新 |
| Diagnostics | Platform 执行 Check、限制并发/超时并聚合；reason_code、evidence_ref 和质量含义归领域 | PLAT-CTR-004 | 不建设领域诊断历史库，不将 Observation 等同业务质量 |
| HTTP Client | DestinationPolicy、DNS/IP 校验、受控 Dial、重定向逐跳验证和并发约束由 Platform 提供；来源授权和业务重试归领域 | PLAT-CTR-005 | 保持受控缓冲/流式能力；不解析 SSE/业务协议 |
| Storage | Platform 提供连接、Ping、Close、事务/迁移执行原语；表、Repository、事务业务边界和 Migration 文件归领域 | PLAT-CTR-006 | 不建设万能 Repository，不注册领域 Migration |
| 长任务 | Run/Stage/Attempt 和工作流状态属于 Researchflow 等领域；旧 Analysis taskqueue 不是新领域通用框架 | 项目架构基线 | PLAT-010 暂缓，不扩建通用队列/工作流 |

## 4. 当前可执行的 Platform 工作

以下事项可在本分支独立完成，不依赖 Server 实现：

1. 修正 Platform 公共契约文档中的 Data Module 过期描述，明确目标架构与当前迁移事实。
2. 按 PLAT-CTR-001～007 对照真实 Platform Go API，逐项核对方法/字段/错误语义/默认值/上限和测试。
3. 补齐平台可独立验证的 Fault 安全映射辅助能力、Request ID 多值 Header/传播边界、Secret 脱敏、Diagnostics Schema/聚合、HTTP Client 流式生命周期和 Storage Migration Runner 测试。
4. 将 A1 包级测试与 A2 消费者接入、A3 生产网络/Secret/资源生命周期验收分开记录。
5. 只读跟踪领域分支的消费者实际调用需求；发现缺口时仅新增最小平台原语，不复制领域 DTO 或业务规则。

## 5. 明确不在当前分支执行

- Server Bootstrap、DI、HTTP 路由总表/Middleware 装配、服务身份注入、Worker 启动、Migration 总注册、Shutdown 生命周期。
- Data 迁入 Root Server 的代码移动、API/Adapter 切换和部署变更。
- News/Research/Quant/Researchflow/LLM/Notification 的领域 Adapter、业务规则、Repository、Schema 和测试。
- 项目级 GOV-CTR 决议、全局契约状态和模块依赖 DAG 的直接修改。
- 通用 Task Queue/Workflow、动态 Service Key 管理、Metrics 平台、通用诊断历史数据库和万能 Repository。

上述任务由各自 Owner 在对应分支或 Integration 完成。Platform 分支只提供可被调用的技术原语和文档，不替代其工作。

## 6. 验收口径

- 文档差异项有明确权威归属、Owner、状态和阻断范围。
- Platform API 不依赖业务模块，且没有通过内部包泄露领域模型。

- 契约状态仍由 `feat/design_doc` 登记簿维护；本文不得自行宣布 frozen。
