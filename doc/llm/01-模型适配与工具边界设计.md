# LLM 模型适配与工具边界设计

## 1. 目标

提供可替换、可测试的 Go 模型 Adapter，连接现有独立模型服务。模型推理由外部/本地服务承担；本分支不建设推理运行时或第二个 Gateway。

## 2. 职责

Provider/Model Adapter、协议转换、模型参数、超时、限流、错误分类、有限重试、结构化输出支持、流式事件解析、Usage/Latency/Request ID/版本元数据、输入脱敏和资源限制。

## 3. 明确不属于 LLM

- Run/Stage、模板、失败恢复：Researchflow。
- Tool Registry、白名单、权限、调用预算和工具执行：Researchflow。
- Context/Evidence/Event/Hypothesis：Research。
- 指标、策略、概率和风险门禁：Quant。
- 研究业务表写入：领域模块/Researchflow。
- 模型权重、推理部署和 GPU 调度：独立模型服务。

## 4. 接口

当前首批协议以 OpenAI Responses API 为准。ModelRequest 包含 request_id、model、instructions、受控 input、max_output_tokens、明确支持的 sampling/reasoning parameters、response_schema、受控 tool definitions、deadline 和 metadata；不把 Chat Completions messages 作为默认内部结构。ModelResponse 包含解析后的 output text/structured payload、response_id、actual_model、response status、usage（可空）、incomplete/error details、request ID 和 timing。

OpenAI Responses JSON DTO 只存在 Adapter 内部。Adapter 必须按 output item 类型解析，不能假设首个 output 一定是 message/text。Structured output 必须在本地按调用方 Schema 再校验；usage 缺失保持 unknown/null。Stream 使用 Responses SSE 事件模型，不把 Chat Completions delta 结构当作通用事件。

LLM Adapter 不依赖 Researchflow 类型；调用方负责把领域上下文转换为模型协议请求，并对输出做业务 Schema、引用和数值来源校验。现有 Gateway 的静态协议证据与未验证能力见《03-现有模型Gateway协议盘点》。

## 5. 安全与可靠性

不记录 API Key、Authorization、Cookie 或完整敏感上下文。总 deadline 由调用方传递；只对安全幂等请求有限重试。429/5xx/timeout/invalid response 分类。工具调用只作为待校验请求，不由 Adapter 执行。完整 Prompt/Response 不默认持久化。

## 6. 可观测性

记录 provider、model、model_version、parameters_hash、schema_version、latency、usage、finish_reason、error_code 和 trace/request IDs。元数据不得泄露凭证或高敏上下文。


## 7. 当前 Gateway 协议基线

- 当前部署客户端采用 OpenAI Responses（wire_api=responses），请求路径为 POST /v1/responses；真实主机名和凭据不得进入仓库。
- Gateway 支持 Responses 路径转发与 SSE 透传，但本地 llama.cpp/Qwen 的真实端到端能力仍需验证；Gateway 的 OpenAI-compatible 标签不是完整能力承诺。
- 本地 Gateway 会合并 instructions 与 input 中 system/developer 项，并在流式请求缺少时注入 stream_options.include_usage；这些改写必须纳入 Adapter Fixture 和在线验收。
- Tool Call 仅作为模型输出意图，Researchflow 负责授权和执行；LLM 不执行工具。
- 结构化输出不因请求携带 text.format 就视为通过，Adapter 必须本地 Schema 校验。
- 详细源码依据、错误矩阵和 E2E 缺口见《03-现有模型Gateway协议盘点》。


## 8. 首批 Provider Port 与 DTO

首批内部 Port 采用 OpenAI Responses 语义，内部 ModelRequest/ModelResponse 不暴露 OpenAI JSON DTO。当前建议首批只支持单轮文本 input，复杂多轮、多模态和后台响应列为 deferred。ToolDefinition 可以作为受控声明传入，但能力未知时不得发送，LLM 不执行工具。Usage 缺失保持 nil，Structured Output 由 Adapter 本地 Schema 校验。完整字段、Stream event、Error Contract 和 Owner 未决项见《04-ProviderPort与DTO字段级契约》。
