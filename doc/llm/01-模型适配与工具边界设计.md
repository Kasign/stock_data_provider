# LLM 模型适配与工具边界设计

## 1. 目标

提供可替换、可测试的 Go 模型 Adapter，连接现有独立模型服务。模型推理由外部/本地服务承担；本分支不建设推理运行时或第二个 Gateway。

## 2. 职责

Provider/Model Adapter、协议转换、模型参数、超时、限流、错误分类、有限重试、结构化输出支持、流式事件解析、Usage/Latency/Request ID/版本元数据、输入脱敏和资源限制。

## 3. 明确不属于 LLM

- Run/Stage、模板、失败恢复：Researchflow。
- Tool Registry、白名单、权限、调用预算和工具执行：Researchflow。
- Context/Evidence/Event/Hypothesis：Research。
- 指标、策略、概率和风险门禁：Quant。
- 研究业务表写入：领域模块/Researchflow。
- 模型权重、推理部署和 GPU 调度：独立模型服务。

## 4. 接口

ModelRequest 包含 request_id、model、input/messages、parameters、response_schema、deadline 和受控 metadata。ModelResponse 包含 content/structured payload、finish_reason、usage、provider/model、request metadata 和时间。

LLM Adapter 不依赖 Researchflow 类型；调用方负责把领域上下文转换为模型协议请求，并对输出做业务 Schema、引用和数值来源校验。

## 5. 安全与可靠性

不记录 API Key、Authorization、Cookie 或完整敏感上下文。总 deadline 由调用方传递；只对安全幂等请求有限重试。429/5xx/timeout/invalid response 分类。工具调用只作为待校验请求，不由 Adapter 执行。完整 Prompt/Response 不默认持久化。

## 6. 可观测性

记录 provider、model、model_version、parameters_hash、schema_version、latency、usage、finish_reason、error_code 和 trace/request IDs。元数据不得泄露凭证或高敏上下文。
