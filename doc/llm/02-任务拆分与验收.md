所有任务初始完成：否。先核实现有独立模型服务协议，不预建多模型复杂路由。

| 编号 | 优先级 | 任务 | 依赖 | 验收 |
|---|---|---|---|---|
| LLM-001 | P0 | 现有模型服务协议盘点（OpenAI Responses） | GOV-001/004 | URL、认证、请求/响应、流式、超时和错误行为；静态盘点完成，在线验收待执行 |
| LLM-002 | P0 | Provider/Adapter 接口 | LLM-001 静态协议结论；Platform HTTP Adapter 单独验收 | 不依赖 Researchflow 或具体业务模型；可先完成 Port/Fixture，真实部署接入另验 |
| LLM-003 | P1 | 超时/限流/错误/重试 | LLM-002 | deadline、错误分类、有限重试和取消 |
| LLM-004 | P1 | 结构化输出支持 | LLM-002 | 本地 Schema 校验、非法 JSON、截断、Schema 和引用缺失；Gateway text.format 透传不等于上游能力已验证 |
| LLM-005 | P1 | Responses SSE 流式响应适配 | LLM-001/002 | 事件顺序、结束状态、断连和取消；本地 llama.cpp 端到端验证前不标记完成 |
| LLM-006 | P1 | 用量和调用元数据 | LLM-002 | 模型/参数/耗时/用量/错误可追踪且不泄密 |
| LLM-007 | P1 | 脱敏和资源限制 | LLM-002/003 | Secret 不入日志、输入输出大小受限 |
| LLM-008 | P2 | 多模型路由/降级 | 真实需求评审 | 明确场景、策略和验收后才实施 |

## 验收门禁
- 与现有模型服务完成真实协议调用，不只用 Mock。
- 超时、取消、限流、错误分类和 Schema 校验覆盖。
- 模型工具调用只作为待校验请求，不由 Adapter 执行。
- 不把自由文本当业务事实；不保存完整敏感 Prompt。

### LLM-001 交付物

必须提交协议调查记录，而不是只写“兼容 OpenAI”：
1. 实际 Base URL、Path、HTTP Method 和 wire protocol。
2. 认证方式与 Secret 注入位置（文档中不得写明文密钥）。
3. 请求字段支持矩阵、默认值和被忽略字段。
4. 普通响应与结构化输出的完整脱敏样例。
5. 流式事件序列、结束标记、usage 位置和断连行为；不支持项明确记录。
6. 错误矩阵：HTTP 状态、Gateway 错误体、超时、取消、限流和连接异常。
7. 最大请求/响应大小、并发和超时限制。
8. 协议调查所用 Gateway 版本/观察日期；协议变化需可复核。

LLM-001 可以先通过配置、现有调用代码和脱敏请求样本完成静态盘点；在线调用无凭据时记为 blocked，不得把静态盘点写成真实调用验收通过。

## LLM-002 字段级设计基线（历史评审建议，2026-11-05）

- MVP 输入固定单轮 instructions + input_text；复杂 input item、多轮和多模态 deferred。
- ToolDefinition 纳入受控可选字段；默认 tool_choice=none，只有 function_tool_calls=supported 才允许 auto。LLM 不执行工具。
- reasoning_effort 保留 typed optional，但默认关闭，只有当前 Provider/Model/Gateway 版本明确 supported 才发送。
- 本地 Schema 语义建议固定 Draft 2020-12；上游 strict 子集兼容性单独验证，validator 库仍待选择。
- Usage.total_tokens 上游优先；缺失时仅在 input/output 均明确且无溢出时派生，标记 source=derived。
- SSE sequence_number 若提供则连续递增；缺号、重号、倒退均不得标记 completed；全流缺失可继续并标记 unavailable。
- ID 分为 request_id、correlation_id、gateway_request_id(X-Request-ID)、upstream_request_id(Request-Id)，不混用。
- Generate/Stream 返回 (ModelResponse,error)；Stream 返回最终聚合 Response，合法 incomplete/failed 状态不与 Go error 重复表达。
- 上述内容属于字段级设计基线；当前契约编号和状态以项目级目录为准。LLM-CTR-001～003 仍为 pending_evidence，缺少 Schema/Golden/Contract Test；真实 Gateway E2E 与能力验证仍未执行，不以个人 Owner 签字作为门槛。


## LLM-002 Fixture 设计基线（2026-11-05）

- JSON Golden 覆盖 completed 文本、function_call、refusal、incomplete、failed、unknown output item、usage 缺失/不一致、Schema 校验失败和非法响应结构。
- SSE Golden 覆盖完整文本流、tool call item、completed/incomplete/failed/error terminal、未知事件、sequence 连续/缺号/重复/倒退/混合缺失、无 terminal EOF、callback error 与 Context cancel。
- 每个 Fixture 同时断言原始 wire payload、归一化 DTO、终态/typed error、Usage 来源和是否允许作为成功结果。
- 详细 Fixture 名称、原始 JSON/SSE 样例和预期结果见《05-JSON与SSE契约Fixture清单》。这些是测试设计样例，不代表当前本地模型真实行为。
