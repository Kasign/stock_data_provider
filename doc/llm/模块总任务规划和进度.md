## 1. 模块目标与边界

LLM 模块负责 Go 侧模型服务协议适配：Provider Port、Responses 请求/响应转换、JSON/SSE 解析、结构化输出 Schema 校验、Usage/延迟元数据、错误归一化、取消和资源生命周期。

- 复用现有独立模型 Gateway，不重建推理服务。
- Platform 提供受控 HTTP Client、BoundDoer、Fault、Secret 等公共原语。
- Server 负责 SecretRef 解析、固定目标 BoundDoer、Gateway 版本/Capability Evidence、资源生命周期及向 Researchflow 注入 Provider。
- Researchflow 负责工具权限、调用预算、业务重试和研究流程；LLM Adapter 只执行单次调用，不自动重试。
- LLM 不复制 SSRF、DestinationPolicy、HTTP Client，不执行模型工具调用。

## 4. 生产装配边界

Server 必须：

1. 创建共享 Platform HTTP Client，为 Gateway 配置固定 DestinationPolicy/Dependency。
2. 构造固定目标 BoundDoer，注入非流式 HTTPDoer。
3. 将 BoundDoer.OpenStream 返回值包装为 LLM HTTPStreamResponse，保留 Body 所有权和原始错误。
4. 解析 SecretRef 并注入 config.Secret；不得混用 Web Session、Admin Key 或 Provider 上游 Key。
5. 注入 ProviderConfig、CapabilityState 和生产 Clock；能力快照绑定真实 Gateway 版本、验证时间、有效期和 evidence_ref。
6. 将 LLM Provider 注入 Researchflow 对应 Stage Adapter；关闭时先停止消费者，再关闭共享 HTTP Client。

LLM 不负责 Server 组合根，不读取环境变量，不自建网络客户端，不决定业务重试。

## 5. 诊断和验收门禁

| 状态 | 判定标准 |
|---|---|
| PASS | 指定 Gateway/模型版本有真实运行证据，行为符合预期 |
| DEGRADED | 部分能力可用，限制范围明确且调用侧有约束 |
| FAIL | 已声明支持的能力违反协议，或出现安全/资源生命周期缺陷 |
| NOT_COMPARABLE | 缺少真实证据、版本不匹配、证据过期，或只有 Mock/Fixture |

验收必须区分：

- 模块代码测试：精确 SHA 的 gofmt、go test、Race、Vet。
- 协议契约测试：Schema、Golden、Validator、Contract Test。
- Gateway A2：真实 Gateway Generate、Structured Output、SSE、取消、超时、超限和错误响应。
- 生产装配 A3：Server 的 DNS/egress/Secret/BoundDoer/生命周期与 Researchflow 注入。

任何一层通过都不能替代其他层。

## 6. 执行顺序

1. LLM-009 文档治理。
2. LLM-010 现有代码专项 Review，形成缺陷清单并只修复确认缺陷。
3. LLM-011 对当前准确 SHA 执行自动化验收。
4. LLM-012 在具备真实环境和凭据后完成 Gateway 验收。
5. Server 生产装配由 `feat/server` 负责；接线暴露 LLM 自身缺陷时回到本分支修复。
6. LLM-008 保持延期，不作为当前主线。
