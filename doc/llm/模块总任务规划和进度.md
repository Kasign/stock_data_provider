## 1. 模块目标与边界

LLM 模块负责 Go 侧模型服务协议适配：Provider Port、Responses 请求/响应转换、JSON/SSE 解析、结构化输出 Schema 校验、用量/延迟元数据、错误归一化、取消和资源生命周期。

- 复用现有独立模型 Gateway，不重建推理服务。
- Platform 提供受控 HTTP Client、BoundDoer、Fault 和 Secret 等公共原语。
- Server 负责解析 SecretRef、固定目标 BoundDoer、Gateway 版本/Capability Evidence、资源生命周期和向 Researchflow 注入 Provider。
- Researchflow 负责工具权限、调用预算、业务重试和研究流程；LLM Adapter 只执行单次调用，不自动重试。
- 不在 LLM 复制 SSRF、DestinationPolicy、HTTP Client 或业务工具执行。

| Test Assets | JSON/SSE Fixture、Schema、Golden 和错误边界测试 |

以上表示模块实现资产存在，不代表真实 Gateway 版本、能力或生产请求已验证。

## 4. 生产装配边界

Server 必须：
1. 创建共享 Platform HTTP Client，并为 Gateway 固定 DestinationPolicy/Dependency。
2. 构造固定目标 BoundDoer，注入非流式 HTTPDoer。
3. 将 BoundDoer.OpenStream 的返回值包装为 LLM HTTPStreamResponse，保留响应 Body 所有权与错误。
4. 解析 SecretRef 并注入 config.Secret；不得混用 Web Session、Admin Key 或 Provider 上游 Key。
5. 注入 ProviderConfig、CapabilityState、生产 Clock；能力快照必须绑定真实 Gateway 版本、验证时间、有效期和 evidence_ref。
6. 将 LLM Provider 注入 Researchflow 对应 Stage Adapter；关闭时先停止消费者，再关闭共享 HTTP Client。

LLM 不负责上述 Server 组合根工作，不读取环境变量，不自建网络客户端，不决定业务重试。

## 5. 验收门禁

- 精确 SHA 的 gofmt、测试、Race、Vet。
- 真实 Gateway Generate、Structured Output、SSE、取消、超时、超限和错误响应 E2E。
- 验证 Gateway 版本和能力证据，未验证能力保持 unknown/unsupported，不以配置开关代替实测。
- Secret 不入日志；Body 在成功、错误、取消和提前退出路径均正确关闭。
- Fixture/Mock 和模块 CI 不替代真实 Gateway A2 验收；A2 不替代生产 DNS/egress/Secret A3 验收。
