# 国内 A 股数据源扩展计划

- 适用分支：`feat/full-go-data-providers-api-switch`
- 更新日期：2026-10-30
- 依据：当前分支 Provider 接口、实现、启动注册、默认配置及 Python/Go 迁移矩阵。
- 范围：国内 A 股；海外数据源暂缓。

## 1. 执行原则

1. 优先验证已有 Go 实现但默认关闭的 Provider，不重复实现相同能力。
2. 只有确认代码缺失、字段覆盖不足或质量不满足需求后，才新增 Provider/接口。
3. 启用 Provider 前必须核实权限、限流、字段、单位、复权、时间、分页和覆盖率。
4. 质量不达标的来源不能仅为增加覆盖率而进入可信回退链。
5. Go 内部标准单位、null/zero、复权和质量门禁保持不变。
6. 海外数据、交易下单和非当前目标能力不纳入本阶段。

## 阶段三开发顺序与状态（2026-10-30）

1. [已实现] 市场情绪快照与历史持久化：复用市场宽度、涨跌停/炸板池，按源端报告交易日对齐；缺失计数保持 null，历史查询只读已采集记录。
2. [已实现，待真实负载验收] 全市场批量股票概览：分页读取证券池并做并发受控行情与 MA 汇总，覆盖不足时只返回 lower-bound/degraded。
3. [待开发] 市场级资金流及历史序列：仅使用证券范围、方向、单位和报告日期可证明一致的上游数据；禁止将部分个股资金流求和冒充全市场值。
4. [部分实现] 板块多维排行：已支持今日涨幅、成交额、近 5 日涨幅；资金净流入维度等待可信字段和完整候选集证据。
5. [已实现，待 MariaDB 环境验收] Provider 主动诊断与诊断历史：Provider/capability 两级状态，主动探测与业务流量隔离，并持久化安全摘要。

## 3. 第二批：真实缺失的数据能力

### P1 全市场批量股票概览

目标字段需先冻结：
- 证券代码、名称、交易状态；
- 最新价、涨跌幅、成交量、成交额、换手率；
- MA5、MA10、MA20、MA60；
- 最后有效交易日、行情源、质量状态；
- 分页、证券范围、总数/下界、覆盖率。

现有 `GET /api/v1/market/quotes` 只接受调用方指定的最多 50 只股票，不等于全市场扫描。不能把逐只请求包装成全市场完整快照。

### P1 市场情绪历史快照

候选指标：上涨/下跌/平盘家数、涨停/跌停、炸板、连板高度、涨停封板率等。

必须先明确：
- 分子、分母和证券池范围；
- ST、停牌、新股、退市整理期等排除规则；
- 交易日和采集时间；
- 上游分页完整性；
- 历史快照的持久化、重复采集和修正策略。

当前市场宽度接口是市场快照，不代表已有完整历史情绪序列。

### P1 市场级资金流

必须明确主力/超大单/大单等统计口径、净流入公式、币种单位、覆盖范围、交易日、数据时间、来源和质量。个股资金流不能直接相加后冒充市场资金流，除非证券范围和口径可证明一致。

### P1 板块多维排行

分别定义：
- 当日涨幅；
- 当日成交额；
- 近 5 个交易日涨幅；
- 资金净流入。

每种排序都必须明确候选板块全集、缺失值处理、分页、排名并列和覆盖率。仅对截断样本排序不能声明为全市场 Top。

### P1 Provider 主动诊断

现有诊断主要记录实际 quote/daily_bars 请求形成的熔断状态。扩展时需要：
- Provider 与 capability 两级状态；
- 主动探测超时和并发限制；
- 冷却、限频和探测频率；
- 最近成功/失败时间及安全错误摘要；
- 探测结果与真实业务请求结果分开；
- 诊断历史持久化。

## 4. 第三批：历史可用性和 PIT

- 财务报告版本、公告时间、修订记录和 available_at。
- 指数成分历史生效区间，而不是把当前成分当作历史成分。
- 公司行动和复权因子版本。
- 历史 ST、停复牌、退市及涨跌幅规则证据。
- 资金流、筹码等快照的源端时间和历史留存边界。

不能确认历史可用时间的数据不得进入严格历史回测。

## 5. 单项开发准入条件

新增/启用任一数据能力前，先提交一份简短能力说明：
1. 对应 API/Provider 接口。
2. 当前代码是否已有实现。
3. 目标来源及权限前置条件。
4. 字段和单位契约。
5. 时间、分页和覆盖率语义。
6. fallback 顺序与质量门禁。
7. 单测样本和真实运行验收方式。

满足准入条件后再开发，避免重复造轮子和默认打开未经验证的数据源。
