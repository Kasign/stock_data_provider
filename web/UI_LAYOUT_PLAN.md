# WebUI 产品信息架构与页面排版计划

更新时间：2026-10-27
状态：主导航已调整为平铺结构；设置中心作为独立页面；浏览器与部署验收待完成
适用分支：`feat/webui-market-data-console`
范围：`web/**`。本计划定义页面职责、排版顺序、状态呈现和数据依赖；不改变既有 Provider 数据口径，不将未实现的后端能力当成现有功能。

## 1. 产品原则

1. **保留并扩大数据能力**：优先利用真实行情、日 K、财务、估值、筹码、资金流、公告、龙虎榜、交易日历、Provider 能力和质量信息。
2. **按用户任务组织页面**：首页看市场；个股研究看单股；自选股看跟踪状态；分析任务看执行与结果；数据中心看服务与数据能力健康。
3. **UI 可先做，数据缺失要诚实**：市场情绪历史、全市场资金流、多维板块排行、全球市场等模块可先布局；无真实接口时显示“规划中/接口待接入”，禁止 mock 行情或假成功。
4. **状态语义分离**：服务健康、Provider 配置、实际探测、请求成功、数据质量是不同概念。null、0、空集合、unknown、degraded、stale、unavailable 不得互相替代。
5. **保持技术栈**：继续使用原生 HTML/CSS/JavaScript ES Modules、Nginx 同源代理和 Docker；不为了模仿参考项目而迁移框架。
6. **同一股票上下文贯通**：榜单、自选、研究列表、任务和结果链接到统一标的；更换标的时必须隔离/清除旧结果。

## 2. 主导航目标

1. **首页**：A 股市场总览与研究入口。
2. **个股研究**：股票列表与专业详情页。
3. **自选股**：跟踪清单、今日分析状态和快捷分析。
4. **分析任务**：新建、任务列表、结果详情；运行流放在任务详情内部。
5. **条件选股**：保留规划入口；策略、扫描和候选 API 接入后启用。
6. **数据中心**：服务状态、Provider 能力、数据质量和“立即检查”。
7. **设置**：服务连接、密钥和界面偏好。
8. **后续扩展**：问股、通知、告警等在真实后端 API 接入前保留明确的规划/不可用状态。

不再让“个股分析”和“个股研究”职责重复。行情查询、技术分析、财务和补充数据统一进入个股研究；分析任务的执行过程和结果在分析中心查看。

## 3. 首页：市场总览

页面从上到下按全局到局部排列。桌面端使用两列布局，小屏改为单列；每个模块独立加载、显示状态和错误。

### 3.1 顶部市场状态栏
显示交易日/市场阶段（必须可由真实交易日历确定）、数据更新时间、质量提醒和刷新操作。不能把浏览器当前时间冒充为 Provider 行情时间。

### 3.2 指数与市场广度
核心指数、最新价、涨跌额/幅、源端时间、来源、质量；上涨/下跌/平盘/未分类数量、证券覆盖情况。复用现有 `/api/v1/market/indices` 与 `/api/v1/market/breadth`。成交额汇总必须展示覆盖范围，不能把不完整覆盖包装成全市场数据。

### 3.3 市场情绪
先展示可以由真实即时数据支持的原子指标：涨跌家数/比例、涨停/跌停、炸板、连板高度等（只展示 Provider 实际返回字段）。每个指标说明统计口径、交易日和覆盖情况。
情绪历史曲线需要真实的定时快照和历史查询接口。能力未接入时显示占位状态，不得把当前快照重复画成历史曲线。初期不急于给不透明的 0–100 综合分；先把指标组成及口径定义清楚。

### 3.4 市场成交与资金
必须把“成交额/成交活跃度”与“资金净流入”分开。现有市场广度的 `total_amount_cny` 是成交额，不是净流入；个股资金流也不能直接相加冒充全市场流向。市场级净流入需真实 Provider、明确口径/单位/时间/覆盖/质量；历史趋势需要快照存储。

### 3.5 热点板块与轮动
用 Tab/分段控件切换：
- **今日涨幅**：复用现有行业/概念排行、涨跌幅、领涨股与质量。
- **成交额排行**：要求后端保证完整候选范围、排序和分页，不能只重排现有 Top N。
- **近 5 日涨幅**：需要有稳定身份的板块历史日线、明确交易日窗口及服务端聚合。
- **资金净流入**：需要板块级资金流 Provider 和 API，接入前显示“接口待接入”。
榜单必须声明排序口径、时间、覆盖和是否为完整榜单。点击个股进入统一研究详情。

### 3.6 市场活动与全球联动
保留涨跌停池、人气/飙升榜、龙虎榜和交易日历。另预留全球市场联动模块，初始为“数据源待确认/接口待接入”。后续接入需定义海外资产标识、币种、时区、市场交易时段、当地日期、报价时间与质量。不同市场不同时间的数据不能被无说明地横向比较；海外数据暂不阻塞国内 A 股主线。

## 4. 个股研究：列表 + 专业详情

### 4.1 列表页
用于搜索、筛选和比较，不塞入全部研究细节。数据来源优先为搜索结果、自选股和最近研究；未来再扩展服务端分页清单。
默认字段：股票名称/代码、最新价、涨跌额/幅、成交额、成交量、换手率、量比、MA5/MA20、数据时间/质量。市值、PE/PB/PS/PCF、ROE、MA60 等可以通过可配置列或详情页查看。
当前没有核实到全市场统一批量股票概览 API。首版只展示搜索、自选和最近研究，不允许通过逐只高并发请求伪造全市场列表。

### 4.2 技术指标口径
MA5/20/60 基于有效日 K 收盘价，要求足够的有效窗口，明确复权口径和最后有效交易日；数据不足显示不可用而非 0。换手率、量比优先使用真实行情字段，不随意估算。列表和详情复用统一计算逻辑；规模化后由批量概览 API 提供统一口径。

### 4.3 专业详情页

当前实现记录（2026-10-27）：研究列表的“查看详情”在个股研究页面内切换标的；页面顶部集中呈现当前匹配行情、来源/时间/质量与 MA5/MA20，下面按需读取公司资料、行业概念、财务、估值、资金与筹码、公告。完整图表与历史日 K 仍在独立行情视图，避免重复维护图表渲染器。列表来源限于本地自选与已查询标的，并非全市场批量行情。
页头固定显示股票名称/代码、价格、涨跌、报价时间、来源与质量。主操作为“加入自选”“发起分析”“查看历史结果”。内部区块：
1. 概览；
2. 走势与技术分析；
3. 财务与基本面；
4. 估值；
5. 资金与筹码；
6. 公告；
7. 数据质量与来源。
每一分区独立显示 loading、empty/unconfirmed、error、unavailable 与质量状态。切换标的须清除旧快照并阻止旧请求覆盖新标的。

## 5. 自选股
定位为长期跟踪，不是通用搜索结果列表。每行显示现价/涨跌、关键指标、今日分析状态、活动任务、最新结果和下一步动作；支持打开详情、单股/批量分析。当前数据保存在浏览器 localStorage，必须标识“当前浏览器本地”，不声称跨设备同步。今日状态 unknown 不能解释成未分析。

## 6. 分析任务与详情内运行流
分析任务页提供“新建分析任务”、筛选和任务列表。字段包括标的/类型、任务状态、数据质量摘要、开始/更新时间、异常摘要和详情入口。当前已有创建 Task、查询单个 Task、阶段事件和单个 RunResult，但没有核实到分页服务端任务列表 API；浏览器最近任务引用不是服务端历史。

任务详情建议分为“结果摘要”“运行流”“数据与诊断”。默认先看真实结果摘要、质量门禁、风险/阻断原因和缺失数据；运行流显示真实 StageEvent 时间线、序号、时间、状态与异常详情。只有后端提供可信 flow snapshot 与依赖边后才绘制 DAG；禁止推断虚假依赖、百分比或取消状态。

## 7. 条件选股
保留规划状态的页面骨架，但不展示虚构策略、候选或扫描历史。目标分区为策略与参数、扫描任务、候选与命中解释、历史扫描。启用前需有服务端能力声明、策略 schema、扫描创建/状态、候选解释和历史分页契约。

## 8. 数据中心：服务状态 + 立即检查

### 8.1 服务卡片
目标展示 WebUI/Nginx、`stock-analysis-server`、`stock-analysis-data`、MariaDB、Redis。每项显示状态、最近检查时间、耗时和安全错误摘要。数据库/Redis 只能在后端提供独立证据时标记健康/故障；无证据显示 unknown。

### 8.2 立即检查行为
- 一个明确的“立即检查”按钮，显示进行中、完成摘要、防重复点击和重试入口。
- 先检查 WebUI、行情服务 `/health/live` 与 `/health/ready`，分析服务 `/healthz` 与 `/readyz`。
- `/readyz` 当前能报告 MariaDB/Redis 的依赖子状态；行情 ready 是整体状态，不足以单独诊断每个底层依赖。
- `/api/v1/data-sources` 只代表 Provider 配置/能力声明，不代表实时健康。
- 逐 Provider/能力真实检查必须由新的受保护后端诊断 API 执行，浏览器不能自行对所有上游发起高并发探测。
- 状态分成服务存活、服务就绪、依赖状态、Provider 配置、实际探测、数据质量。
- 需要超时、并发上限、总时限和安全错误摘要；一个 Provider 失败不能阻止其他检查。不能暴露密钥、Cookie、数据库凭据或内部敏感 URL。

### 8.3 Provider/数据集分组
按行情/日 K、证券主数据与搜索、指数/广度、行业/概念、涨跌停与龙虎榜、交易日历、财务/估值、公告、筹码/资金流分组。每项区分配置能力、最近探测、数据质量、检查/源端时间与可用诊断。关闭/未配置/不支持不是失败。

## 9. 设置与扩展页面
设置按服务连接、界面偏好、数据偏好和诊断分组。浏览器偏好可本地保存；服务器配置、密钥写入、认证与服务器 `.env` 管理需要权限、安全和审计契约。问股、通知、告警等先保留规划状态，后端资源接入前不启用写操作。

## 10. 统一视觉规则
- 标题/描述、主操作和状态徽标位置统一；首屏强调 3–5 个核心指标。
- 共用卡片、表格、筛选控件、状态组件和可折叠诊断区。
- 深浅主题走共享 tokens；不写死新模块的状态颜色。
- 默认正文和表格字号可读；诊断细节逐层展开。
- 小屏可单列、表格局部横向滚动，页面整体不得水平溢出。
- 所有模块都需定义加载、空但未确认、确定空、不可用、失败、部分数据、质量降级和重试状态。

## 11. 实施顺序
1. **P0 UI 重排**：首页、个股研究列表/详情、自选股、分析任务/详情内运行流、数据中心、设置；缺数据的模块先做准确占位。
2. **P0 基础服务检查**：使用现有 health/readiness 与 Provider 能力声明显示真实状态，明确哪些尚未逐 Provider 实测。
3. **P1 国内数据能力**：情绪历史、市场/板块资金流、完整多维板块排名、股票批量概览、逐 Provider 实际诊断。
4. **P2 全球市场**：先选数据源与资产范围，定义时区/交易时段/币种/质量契约后接入。
