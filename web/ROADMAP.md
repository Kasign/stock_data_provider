# stock_analysis_web 功能规划

> 本文是 WebUI 的功能路线图和接口协作约定。参考项目：  
> - [Kasign/daily_stock_analysis](https://github.com/Kasign/daily_stock_analysis)  
> - [完整配置与部署指南中的 WebUI 说明](https://github.com/Kasign/daily_stock_analysis/blob/main/docs/full-guide.md#本地-webui-管理界面)  
>
> **前端约束：只使用原生 HTML、CSS、JavaScript（ES Modules）。不使用 React、Vue、Svelte、TypeScript 或前端框架，不引入需要打包的前端构建链。** 现有静态页面、Nginx 代理和 Docker 部署方式继续保留。

## 1. 产品定位与原则

`stock_analysis_web` 是个人股票研究与数据质量工作台，负责把行情服务、Go 分析服务的能力清楚地呈现在浏览器中。它不替代后端分析逻辑，不直接执行交易，也不在缺少真实数据时伪造结论。

1. **接口优先**：显示后端返回的字段、来源、时间、质量和错误；未接入的能力标为“待后端接口支持”，不使用 mock 冒充已完成。
2. **质量优先**：数据缺失必须显示“未知/缺失”，不能当作 0、不能用过期报告悄悄补当前结果；行情和分析报告要展示来源、时间、降级原因与警告。
3. **任务可恢复**：耗时工作由后端创建和保存，前端可刷新、重新进入、查看最终结果；状态以服务端为准，不虚构进度百分比。
4. **模块隔离**：前端仅在 `web/` 开发；不把 JS/CSS 混入 Go 或 Python 业务目录。需要新增 API 时先确认契约，由后端任务独立实现。
5. **轻依赖、可维护**：按 API、状态、页面渲染、图表、格式化拆分原生 JS 模块；优先采用 HTML 表格和原生 SVG/CSS 图表，不引入 React 或重型构建系统。
6. **安全默认**：不硬编码密钥；页面默认通过同源反向代理访问 API。公网访问前必须有 HTTPS 和身份认证/访问控制，不能把 localStorage 当作密钥保险箱。

## 2. 参考项目中值得吸收的能力

| 参考能力 | 规划吸收方式 | 注意事项 |
| --- | --- | --- |
| 首页「历史 / 自选 / 今日」工作区 | 统一首页，查看关注标的、今日分析状态和最近报告 | 需要后端提供自选股与历史列表接口；未提供前可用本地最近查询记录，不冒充跨设备同步 |
| 异步任务面板、阶段进度与恢复 | 任务列表、阶段事件、刷新后恢复、失败原因和重试入口 | 只展示后端真实状态；取消、重试操作必须有对应 API |
| 手动分析与策略选择 | 选择标的、市场、分析阶段和后端支持的策略后提交任务 | 策略列表由后端提供或有明确的静态契约，不能把没有实现的策略做成可选项 |
| 历史报告、完整报告和回放 | 列表筛选、详情阅读、报告复制/下载，不重新触发分析 | 报告必须读取持久化记录；Markdown/富文本渲染须转义不可信内容 |
| 大盘复盘与独立历史 | 市场概览、复盘任务状态、复盘历史回放 | 指数、市场宽度、板块及资金数据均需真实 API 支持，缺字段显示“暂无数据” |
| 报告中的数据上下文与诊断 | 展示来源、质量、缺失原因、降级状态、关键输入摘要 | 只展示后端提供的诊断摘要，不暴露 Prompt、密钥或内部敏感信息 |
| 技术面工具、个股对比、选股 | 逐步增加指标图、对比表和筛选任务 | 计算规则和指标口径必须文档化并测试，批量筛选需后端支持 |
| Agent 问股和会话 | 规划多轮问答、会话恢复、上下文切换与导出 | 依赖后端 Agent/Chat API；模型密钥留在服务器，浏览器不直连模型厂商 |
| 回测、持仓和组合风险 | 作为后续独立功能页 | 需要历史数据、交易成本、持仓账本及回测 API，不能只用前端公式生成“准确率” |
| 告警规则与触发历史 | 创建/启停规则、查看触发和通知结果 | 监控必须由后端持续执行；仅靠打开着的浏览器不能实现可靠告警 |
| 智能导入、语言和主题 | 先支持文本/CSV 导入；再根据后端能力扩展 Excel/图片解析；主题与中英切换 | 不为导入而引入重型前端框架；图片识别由后端接口负责 |

## 3. 分期计划

### P0：可靠的行情与分析主流程（当前阶段）

**现有基础能力（已有代码）**
- [x] 原生 HTML/CSS/JavaScript 页面与响应式基础布局。
- [x] 实时行情查询、日 K 图表与表格、复权口径选择。
- [x] Provider 能力列表、服务健康状态、行情质量等级及警告展示。
- [x] 创建 Go 分析任务、轮询任务状态、加载阶段事件。
- [x] 任务结束后获取持久化分析结果，展示质量门禁、候选信号概要、警告和 JSON。
- [x] API 路径和行情 API Key 配置；`stock_analysis_web` Docker 服务、Nginx 同源代理和独立 WebUI CI。

**接下来优先完善**
1. **页面体验与状态一致性**
   - 加入清晰的加载、空数据、请求失败、部分成功、超时和重试状态。
   - 防止较早发出的请求覆盖新查询结果；页面切换或新查询时取消过期请求。
   - 在刷新或重新进入后恢复可恢复的任务；区分 pending、running、completed、failed、cancelled 等真实状态。
2. **近期标的和自选列表**
   - 先支持最近查询、固定常用标的、粘贴多只股票代码。
   - 自选列表跨会话持久化优先使用后端 API；只有 API 未就绪时才提供明确标记的浏览器本地模式。
   - 后端支持后再加入股票名称/代码/拼音搜索补全，避免前端维护一份易过期的全量证券列表。
3. **历史任务与报告入口**
   - 增加最近任务列表与运行结果入口，按股票、状态、时间过滤。
   - 后端提供历史 API 后，支持历史报告分页、详情回放和 Markdown/JSON 下载；回放不得重新触发分析。
4. **结果透明度**
   - 将数据来源、行情时间、复权口径、数据质量、缺失字段、警告和降级原因放在容易找到的位置。
   - 任务失败显示后端错误和请求 ID（若有）；不能只显示“失败”。
5. **连接与安全诊断**
   - 分开显示行情服务与分析服务的健康状态、最后检查时间和错误详情。
   - 增加连接配置校验、密钥显隐、清除本地配置能力；继续默认只通过同源代理访问后端。

**P0 验收标准**
- 查询成功、仅部分接口成功、空数据、API Key 错误、后端不可用和任务失败均有明确界面反馈。
- 刷新页面后，存在后端持久化状态的任务可以恢复；已完成任务可以直接查看结果。
- 任何质量缺失或降级状态均不会被 UI 隐藏或转成正常状态。
- 原生 JS 模块有自动化测试，CI 检查语法、格式化/状态逻辑并构建 Docker 镜像。

### P1：日常投研工作台

1. **首页总览**
   - 今日任务统计、正在运行的任务、最近完成报告、关注标的摘要、服务状态。
   - 支持“今日 / 自选 / 历史”视图和折叠任务面板；今日日期、交易日期和时区语义以 API 为准。
2. **手动分析增强**
   - 多标的批量提交、分析阶段/市场选择、后端支持策略的显式选择。
   - 幂等提交、防重复点击、失败后重试；仅在后端支持时显示取消。
3. **报告详情与数据诊断**
   - 结构化报告区块：核心结论、趋势与信号、风险、催化、警告、输入数据摘要。
   - 显示数据块状态、来源、缺失原因和降级摘要；支持复制报告、复制脱敏诊断信息、下载 Markdown/JSON。
4. **大盘复盘**
   - 指数、市场宽度、涨跌分布、板块/题材排名、资金信息和新闻摘要。
   - 复盘任务有状态和失败原因；复盘历史与个股报告分开筛选并可回放。
   - 每项数据均按真实可用字段显示，不能把缺失的市场宽度或资金流展示为 0。
5. **技术面工作区**
   - K 线范围切换、成交量、MA/EMA、RSI/MACD 等常用指标、区间涨跌幅和波动统计。
   - 统一指标周期、数据窗口、复权口径及计算测试；不足以计算时显示原因，前端指标明确标注口径。
6. **个股对比**
   - 支持 2–3 只股票同步比较报价、区间收益、波动、技术指标、质量状态和数据覆盖差异。
   - 统一比较时间范围；标的交易日不同或字段缺失时显式说明，不能直接比较不一致区间。
7. **国际化与显示偏好**
   - 支持简体中文/英文界面切换，与报告正文语言分开保存。
   - 增加浅色/深色主题；保留窄屏、键盘操作和可读对比度。

### P2：分析工具与自动化能力

1. **条件选股 / 筛选任务**
   - 多条件筛选、排序、候选列表、任务阶段、结果回看；复用成功的市场快照须由后端明确返回缓存信息。
   - 过滤条件与硬性风险限制由服务端执行，前端不得把 UI 筛选等同于正式策略评分。
2. **新闻与舆情**
   - 按标的聚合新闻、发布时间、来源、原文链接和情绪/事件摘要。
   - 标注新闻时间与数据来源；区分来源事实和模型摘要，保留检索失败及来源不足状态。
3. **Agent 策略问股**
   - 多轮会话、明确当前主标的、切换会话恢复上下文、选择后端支持的策略、导出对话。
   - 使用后端流式接口呈现增量内容与真实任务状态；前端不持有模型厂商 API Key。
4. **智能预警**
   - 管理价格、涨跌幅、成交量及后端已实现技术指标规则；展示启停状态、触发记录、冷却状态和通知结果。
   - 触发条件、去重和通知必须由服务器执行；规则创建成功与触发结果分开呈现。
5. **智能导入**
   - 首先支持从文本、剪贴板和 CSV 导入股票清单，先预览、校验、去重，再确认保存。
   - Excel、图片识别等能力只在后端解析 API 稳定后接入；必须展示无法识别的行和可修正错误。
6. **回测验证**
   - 展示历史信号的方向胜率、买卖条件命中率、模拟收益和样本数量，支持股票和日期范围筛选。
   - 明确交易成本、滑点、信号时点及可用样本；区分历史分析评价与未来收益，不能把回测显示为收益保证。
7. **通知与任务中心**
   - 查看任务完成/失败、告警及推送结果，支持通知通道测试（仅当后端提供接口）。
   - 真实发送动作必须显示服务端结果，不能在前端点击后直接提示“发送成功”。

### P3：持仓与组合风险（需独立后端能力）

- 账户、持仓、交易/现金流水、公司行动录入，支持 CSV 预览导入及错误行修正。
- 展示市值、盈亏、仓位与行业集中度、持仓价格来源/日期/过期状态。
- 在后端提供可信的历史估值序列和风险 API 后，再展示回撤、波动率、Sharpe、VaR 等组合风险数据。
- 缺少可靠现价或汇率时，明确标记不可用，不以成本价当现价，也不把缺价资产静默计入汇总。

## 4. 后端接口依赖和前后端边界

### 当前前端已有的接口调用

- 行情服务健康检查：`/health/ready`
- 分析服务健康检查：`/readyz`
- Provider 列表：`GET /api/v1/data-sources`
- 实时行情：`GET /api/v1/quotes/{symbol}`
- 历史日 K：`GET /api/v1/bars/{symbol}/daily`
- 创建分析任务：`POST /api/v1/analysis/tasks`
- 查询任务/事件/分析结果：`GET /api/v1/analysis/tasks/{task_id}`、`/events`、`GET /api/v1/analysis/runs/{run_id}`

实际路由和字段以代码与 API 契约为准。新增功能实施前，先确认对应后端端点、字段、分页、错误、鉴权、时间范围和持久化语义。

### 后续建议的 API 契约组

| 功能 | 所需契约（建议方向，不代表已实现） |
| --- | --- |
| 自选/最近标的 | `/api/v1/watchlist`、股票搜索/补全接口 |
| 历史报告 | 分页 history 列表、报告详情、Markdown/JSON 导出 |
| 大盘复盘 | 创建复盘任务、任务状态/事件、结构化结果与历史查询 |
| 筛选任务 | 创建筛选任务、任务状态/阶段事件、候选结果、筛选条件快照 |
| 个股比较 | 批量报价/日 K 读取或可复用的多标的查询接口 |
| Agent 会话 | 会话 CRUD、消息/流式响应、当前主标的与策略状态 |
| 告警 | 规则 CRUD、启停、dry-run、触发历史、通知尝试结果 |
| 回测 | 创建回测、任务状态、结果分页和整体/单股统计 |
| 持仓与风险 | 账户、交易账本、导入预览/确认、持仓快照和风险摘要 |

在接口不存在时，UI 应显示“后端能力尚未接入”，不可使用静态示例结果模拟真实业务。后端 API 需要变更时先提出契约和测试要求，不直接在本 WebUI 任务中侵入修改 Go 核心逻辑。

## 5. 原生前端目录约定

继续留在独立的 `web/` 目录，可逐步把代码组织为：

- `index.html`：应用骨架、导航、语义化页面结构。
- `styles.css`：布局、响应式、浅/深主题和公共组件样式。
- `src/api.js`：统一 fetch、鉴权头、超时/取消、错误解析和 API 路由。
- `src/state.js`：跨视图状态、任务状态和请求序列管理。
- `src/app.js`：应用启动、路由/视图切换和事件绑定。
- `src/pages/*.js`：行情、首页、任务、报告、复盘等独立页面渲染模块。
- `src/components/*.js`：表格、状态标签、确认框、通知提示等无框架组件。
- `src/chart.js`：原生 SVG 图表和指标可视化。
- `src/format.js`：数字、时间、质量状态和输入格式化。
- `tests/*.test.mjs`：不依赖浏览器 UI 框架的单元测试。

目录调整按功能批量进行，不为了拆文件而频繁提交。暂不需要的目录无需提前创建；避免单一 `app.js` 随功能持续膨胀。

## 6. 开发顺序与避免冲突

1. **先完成 P0 稳定性**：错误/空状态、请求竞态、任务恢复、结果来源与诊断。
2. **再完成 P1 的首页/历史/报告**：开始前先确认后端历史、自选、市场复盘接口哪些已落地；按契约分批实现，不做假接口。
3. **每组功能单独检查**：先写接口契约及验收用例，再写 UI；单元测试、静态检查、Docker 构建通过后再合入。
4. **保持分支隔离**：WebUI 代码只改 `web/` 和 WebUI 专项 CI/文档。Go 数据源、分析服务、Python bridge 等逻辑在各自任务或 PR 实现；避免为了页面需求直接改动并行开发中的核心文件。
5. **集成测试后再启用入口**：在 Docker 同一网络验证代理、认证头、真实返回字段与后端错误；CI 构建成功不等于生产 API 已联通。

## 7. 非目标与禁止事项

- 不使用 React/JSX，也不引入 Vue、Svelte、TypeScript、Vite 或需要编译的前端框架链。
- 不在浏览器中直连模型厂商，不把服务端密钥写入前端代码、HTML、镜像或仓库。
- 不提供真实交易下单，不把任何技术指标/回测结果包装为收益保证。
- 不使用 mock 数据冒充线上行情、市场统计、持仓、筛选结果或回测数据。
- 不隐藏数据质量降级、不用 0 填补未知值、不把任务错误吞掉。
- 不在 WebUI PR 中重构 Go 核心服务；有接口缺口时先提出契约与后端独立任务。
