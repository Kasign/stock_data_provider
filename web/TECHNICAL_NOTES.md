# WebUI 技术说明

更新日期：2026-10-26

本文记录 WebUI 的分层方式、请求生命周期、市场人气榜的数据契约与边界。目标是便于后续功能开发、代码审查和部署联调；它不替代 Go 服务的 OpenAPI 定义。

## 1. 前端分层与请求路径

- `web/index.html` 承载页面结构及稳定的 DOM 锚点。
- `web/styles.css` 负责布局、主题及桌面/窄屏适配。
- `web/src/api.js` 统一拼接同源代理路径、发送 API Key，并处理 HTTP 错误。
- `web/src/market-overview.js` 按市场模块处理请求状态、回包渲染、质量信息和请求取消。
- `web/src/app.js` 负责跨模块导航、共享股票选择与行情查询流程。

浏览器使用同源代理路径，例如 `/market-api/api/v1/market/hot-stocks`。不要在 UI 模块中直接访问上游域名、读取环境变量或复制 API Key 管理逻辑；服务地址和密钥由连接设置与 Nginx 代理统一管理。

## 2. 人气榜与飙升榜契约

请求：

```http
GET /market-api/api/v1/market/hot-stocks?type=popular&limit=20
X-API-Key: <由现有设置提供>
```

`type` 为 `popular`（人气榜）或 `surge`（飙升榜）；`limit` 为 1–100，WebUI 当前请求 20 条。前端表格展示：

| 字段 | UI 语义 |
|---|---|
| `rank` | Provider 原始排名 |
| `symbol` / `code` / `name` | 个股身份信息；可选名称缺失时退回代码 |
| `latest_price` | Provider 增补的最新价格，单位为人民币元/股；缺失时显示“—” |
| `change` | Provider 返回的价格变化，单位为人民币元/股；缺失时显示“—” |
| `change_percent` | 涨跌幅，按百分比数值展示；例如数值 10 表示 10%，不再乘 100 |
| `rank_change` | 原样展示源端数值，不自行推断正数/负数的排名方向 |
| `source` / `fetched_at` | 来源与本服务采集时间 |
| `quality_status` / `quality_reasons` | 由后端提供的质量状态与解释 |

### 必须保留的数据边界

1. **榜单覆盖范围有限。** `total` 表示本次有界响应中的记录数，不是全市场证券数量或覆盖率。
2. **采集时间不是行情时间。** 上游没有可独立核验的市场快照时间，后端可能将响应标记为 `degraded`。UI 不把 `fetched_at` 当作报价发生时间，也不自行把质量升级为 valid。
3. **排名变化不推导方向。** `rank_change` 的符号含义依赖上游，不应渲染成未经证明的“上升/下降”箭头或做投资结论。
4. **空字段不是零。** 缺失价格和涨跌字段显示为 “—”；空数组表示接口没有返回记录，并不能单独证明整个市场没有符合条件的股票。
5. **榜单不是投资建议。** 排名、涨跌幅和人气变化是描述性数据，不构成买入/卖出信号。

## 3. 状态、并发与取消策略

市场总览的每个模块独立维护请求控制器和 generation 计数。启动新请求前会取消同模块旧请求并增加 generation；响应返回后必须同时确认未取消且 generation 未变化，才允许更新 DOM。这样，用户快速切换人气榜与飙升榜时，较慢的旧响应不会覆盖当前选择。

共享的市场刷新操作可以并行刷新模块，但每个模块独立展示错误。某项榜单接口失败不会阻止指数、市场广度、行业排行或涨跌停池的数据继续显示。

点击榜单股票时，模块将 `symbol` 与名称交给 `app.js` 的统一股票选择回调。回调复用已有行情查询流程，并在查询进行中拒绝重复启动；它会同步输入框、清理旧搜索状态并请求实时报价和日 K。不要在榜单模块内再实现一套 quote 请求或缓存。

## 4. 错误处理与部署兼容

- `401/403`：提示检查现有行情 API Key。
- `404`：当前部署版本可能尚未提供该 API，需要更新 market-data 服务。
- `503`：没有启用相应 Provider 或服务暂不可用，应按后端错误提示处理。
- `502` 或网络错误：显示请求错误和 API 返回的状态/请求标识（如有），不生成本地示例记录来填充榜单。
- 用户切换榜单或再次刷新时，旧请求会被 AbortController 取消；被取消的旧请求不得覆盖当前结果。
- Provider 能力列表只在数据源回包将 `hot_ranking_capable` 显式标记为 true 时显示支持。数据分支的 `services/market-data/openapi.yaml` 已在提交 [`5bcc05f`](https://github.com/Kasign/stock_data_provider/commit/5bcc05f1db5114828dbbce947841cbc521e079a9) 中补上该字段，保持 JSON 响应与 OpenAPI Schema 一致。字段缺失不等于 true，也不等于整个服务不可用。

## 5. 扩展约定

- 页面状态与真实接口结果分开建模；加载、空结果、错误和质量降级应明确区分。
- 新字段必须先核对 Go 模型与 OpenAPI 的单位、缺失语义和时间含义，再决定格式化方法。
- 数值统一通过现有格式化函数显示；百分比字段先核对后端是否采用百分点口径，避免重复乘以 100。
- 事件监听使用委托时，应限定到稳定容器并校验目标元素；动态内容使用 `textContent`，不得把源端字符串拼成 HTML。
- 保持页面原生 ES Modules 结构，不新增框架或模拟接口来绕过数据层缺口。

## 7. 本地日 K 技术指标计算

技术指标由 src/chart.js 从当前已加载的标准化日 K 计算，不在 Go Provider 中新增指标 API，也不会把本地计算结果冒充后端分析因子。行情请求失败时日 K 被清空，指标面板随之清空，防止把上一只股票的指标留在新标的上。

- MA5 / MA20 / MA60：最近 5 / 20 / 60 个有效收盘价的简单平均。缺失收盘价不作为 0，而是跳过该条有效观测；日期仍保留在行结果中，供曲线按日期定位。
- RSI(14)：使用 14 个收盘价变化的初始平均涨幅/跌幅，后续采用 Wilder 平滑。至少 15 个有效收盘价才形成首个 RSI。RSI 触及 30 / 70 参考线只做描述，不自动生成买卖提示。
- MACD(12,26,9)：EMA12、EMA26 分别以首个 12 / 26 个有效收盘价的 SMA 初始化，随后按 alpha=2/(period+1) 更新；DIF 为 EMA12−EMA26，DEA 对首 9 个 DIF 做 SMA 初始化后继续 EMA 平滑，柱值按 A 股常见显示口径取 2×(DIF−DEA)。首个完整 DEA/柱值一般需要 34 个有效收盘价。
- 叠加均线：均线按日期对齐到收盘线或 OHLC K 线；用户可独立启用/关闭 MA5、MA20 和 MA60。绘制范围包含选中的均线值，缺失值不会连接成伪造的连续点。
- 数据边界：结果依赖当前 Provider 的复权口径、缺失值、日期范围与质量状态。WebUI 不补数据、不重采样、不校正后端价格、不计算成交信号，也不宣称这些计算具备严格的 PIT 可复现性。
- 验证状态：本批添加计算和 SVG 绘图回归测试源码，但按照统一测试安排未运行测试、未启动 CI。真实浏览器视觉、不同日期范围/复权口径下的呈现仍待集中验收。


## 8. 任务事件状态归一化与 Provider 能力清单

- Provider 能力清单以字段名为唯一键。某个后端能力只对应一个 UI 标签；例如 capital_flow_capable 在前端统一标注为“个股资金流”，不能因为不同功能批次的文案差异而重复渲染。
- 阶段事件列表与事件详情复用相同的状态归一化规则：先 trim、转小写，再将连续非字母数字/下划线/连字符转换为连字符；例如 IN PROGRESS 与 in-progress 归到相同展示状态。未知的非空状态保留后端原文，缺失状态显示“状态未报告”。
- UI 标签映射只用于可读性，不覆盖原始事件 JSON，也不根据事件顺序推断依赖。成功状态使用成功色调；失败、异常、阻断、拒绝使用错误色调；降级与部分完成使用警告色调；其余状态保持中性。
- 自动诊断焦点优先选择真实的失败、阻断、降级或运行中事件，状态匹配同样经过归一化。若服务端没有对应事件，则仍按既有逻辑选择最新事件。
- 本次改动仅影响浏览器中的展示规则，不更改 Go API、数据库字段、事件序号或轮询策略；测试源码已补充，但未运行测试或触发 CI。


## 9. 阶段事件读取异常与诊断导出

- 阶段事件采用增量读取且在临时请求失败时保留此前已知事件。为避免用户误以为这些事件是本次刷新结果，读取错误通过独立的 aria-live 状态提示展示，并在事件数量摘要中标明读取异常。
- 事件 API 恢复成功时，现有错误提示随状态重置自动隐藏。事件读取失败不抹掉成功取得的 Task 状态，也不把已有事件清空来掩盖错误。
- “复制诊断”包含客户端采集时间、Task 的服务端错误摘要、轮询提示、Run 结果读取提示、事件读取是否完成/暂停、最近读取错误、已知事件数量、after_sequence 游标和选中事件序号。该信息用于定位数据读取故障，不代表服务端权威日志。
- 诊断导出不复制浏览器连接配置、API Key 或请求头。事件/Run JSON 仍由用户主动触发复制；分享诊断信息前应检查其中的任务 ID、股票代码和服务端返回消息是否适合外发。
- 本次为前端展示和诊断导出改动，不新增接口或持久化字段；测试源码已更新但按协作约定未运行。


## 10. 市场活动列表的请求状态与旧快照边界

- 交易日历按日期范围加载，任何开始的新请求都把页面切到明确的加载态；校验失败、缺少 API Key 或请求失败时，不能继续保留上一日期范围的日历格子、质量原因或来源/采集时间。
- 交易日历失败提示中的请求范围来自本次输入；失败时的元数据显示“本次未返回数据”，不把上一成功响应的来源时间用于解释当前筛选条件。
- 龙虎榜整页刷新与加载下一页使用不同的失败语义：整页刷新失败应移除旧记录与旧摘要；追加页失败保留之前已成功取得的记录，并以错误提示说明追加失败，不修改之前记录的质量状态。
- 每个模块继续使用独立 AbortController 与 generation，旧请求的完成/失败均不能改写新的筛选状态。
- 本次仅规范现有 UI 的状态清理，不更改服务端字段、分页参数或接口请求；已补充 UI 契约测试源码，未运行测试或触发 CI。


## 11. 个股研究快照失效与错误状态

- 个股研究的各模块使用统一面板配置记录内容容器、标的、来源时间、质量原因、质量状态与错误提示容器。切换股票、修改行情 API Key/路径或主动重新加载时，旧快照不能继续被解释为当前请求结果。
- 单项加载开始前清除该模块的旧内容、元数据和质量原因，并切换到“读取中”状态；请求失败则保留本次失败提示，不回退显示上一轮成功结果。此规则适用于财务、估值、筹码分布、资金流、公司档案和板块资料。
- API Key 缺失不是普通的请求错误：需先中止所有进行中的个股研究请求，再清理全部研究面板并统一标记“需配置 Key”。连接设置变更后主动触发失效，防止因旧请求较晚返回而覆盖空状态。
- 公告整页刷新开始时清除旧列表和旧摘要；请求失败不保留旧时间戳或旧质量原因。追加下一页时已成功的公告属于可用快照，因此追加失败保留原列表/摘要并单独提示错误。
- 财务报告期参数无效时同样中止财务请求并清空上一报告期结果，避免过期结果与当前选择不一致。
- 目前只处理浏览器状态和已有接口，不新增服务端接口或数据库字段。测试源码已补充，但按统一安排未运行自动化测试或触发 CI。


## 12. 主行情请求与页面筛选条件一致性

- 主行情、日 K 与 Bundle 快照使用统一的请求 generation 和 AbortController。每个响应在写入页面前都必须属于当前 generation；取消请求后即使底层 fetch 较晚结束，也不得再渲染。
- 股票输入、日期区间、日 K 上限、复权口径改变时，旧行情、旧日 K、技术指标、Bundle 来源/时间摘要和个股研究补充快照都不再视为当前结果。筛选条件不合法时同样清除旧结果，并在提示中显示本次问题。
- 查询开始前清空上一份 K 线与技术指标，不在新请求期间显示前一查询的曲线；请求结束只由当前 generation 释放加载状态，避免旧请求的 finally 覆盖新请求状态。
- 修改 API Key 或行情 API 路径时取消正在运行的行情请求并清除旧快照。新选择可以替换旧请求；重复提交相同查询条件时则避免启动第二个相同请求。
- 跨层状态语义以 [《WebUI 与数据层状态及响应契约》](https://github.com/Kasign/stock_data_provider/blob/5776313e7b50648ea0e7d741c7eb1c02b8d20758/docs/architecture/WEBUI_DATA_STATE_CONTRACT.md) 为共同约定；变更 Go DTO、Provider 字段、错误码或质量语义前，先修改/核对对应 OpenAPI 与数据契约。
- 当前为 UI 源码与契约测试源码变更，未新增接口。测试和真实浏览器验证按统一安排留待后续集中进行。


## 13. 市场总览全局刷新序号

- 市场总览每个数据面板独立维护 AbortController/generation，防止旧指数、广度、板块、涨跌停池或人气榜响应覆盖当前面板。
- 顶部“正在刷新/已尝试刷新”摘要另维护 refreshGeneration。连续刷新时，只有最新一轮 Promise.all 完成后才可写最终摘要；旧轮即使因请求取消而提前结束，也不能覆盖新轮状态。
- 全局摘要只表达刷新请求的生命周期，不代表所有 Provider 均有效或数据完整。实际质量、接口错误、来源与时间继续以各面板状态为准。
- 本次不改变 API 或数据结构；契约测试源码已补充但按协作约定未运行。


## 14. 连接变更与证券搜索建议失效

- 股票搜索请求和防抖定时器依赖当前行情 API Key 与 marketBase。连接设置的任一项发生变化时，应取消旧定时器/请求、递增搜索 generation、清除候选项并收起下拉列表。
- 被取消的旧搜索即使随后 resolve/reject，也不能更新当前候选项或错误状态。新凭据下的搜索由用户下一次输入触发，避免自动把旧查询条件与新服务混用。
- 本次只处理 UI 异步状态，不修改搜索接口、缓存或数据结构；契约测试源码已更新但按约定未运行。


## 15. 无数据情况下的筛选状态失效

- 筛选条件变化本身就是一次状态失效事件，与当前是否有行情值、K 线数组是否为空无关。即使前一次请求失败或返回空集合，也要清理旧错误/旧元数据并明确提示当前条件需要重新查询。
- 此处理仅清理 WebUI 当前主行情视图，不要求后端为纯 UI 筛选变更增加 API；响应是否真实为空仍以共享数据契约为准。
- 测试源码已补充，但按统一安排未运行自动化测试或触发 CI。


## 16. 服务健康与 Provider 清单的请求序号

- `refreshServices` 和 `refreshSources` 分别维护请求 generation，并在任何 DOM 写入前检查当前 generation。连接设置切换、初始加载与手动检查重叠时，只允许最新一次刷新修改全局健康灯、连接摘要和 Provider 能力列表。
- 健康检查返回 `stale=true` 表示该次结果已被更晚的检查替代；设置页应提示已忽略旧结果，不能把旧连接的成功/失败状态展示为当前连接。
- Provider 清单在缺少 Key 时立即清空；若此前已发出的请求晚到，generation 校验可防止它重新填回旧清单。
- 当前只增加 UI 请求状态保护，不改变服务端健康端点、数据源 endpoint 或响应格式。测试源码已更新但按统一安排未执行。


## 17. 统一 Compose 部署与服务名约定

- 根目录 `docker-compose.yml` 是整套系统唯一的常规部署入口，统一定义 `stock-analysis-data`、`stock-analysis-server`、`stock-analysis-web` 三个服务，并使用同一个外部网络 `1panel-network`。

- Compose 服务名和 `container_name` 按以上名称一一对应。行情服务只在容器网络暴露 `8091`；分析 API 使用宿主机回环映射 `127.0.0.1:8092`；WebUI 默认使用 `127.0.0.1:8093`，避免后端 API 直接监听公网接口。

- `MARKET_DATA_BASE_URL` 默认指向 `http://stock-analysis-data:8091`；`MARKET_DATA_SERVICE_NAME` 与 `ANALYSIS_SERVICE_NAME` 默认分别为 `stock-analysis-data` 与 `stock-analysis-server`。已有 `.env` 不会随模板自动升级，需要显式调整旧服务名。

- WebUI 的 `/market-api/`、`/analysis-api/` 同源代理仍由 `web/default.conf.template` 生成；`NGINX_ENVSUBST_FILTER` 只替换两个上游主机变量，不替换 `$host`、`$uri` 等 Nginx 内置变量。

- 旧 `docker-compose.go.yml` 与 `web/docker-compose.yml` 已被统一配置取代；部署脚本和工作流现在引用根目录 Compose 文件。旧 Go 应用容器升级前应按 README 指引停用/移除，避免旧 `8092` 端口映射与旧 DNS 别名干扰新部署。

- 这次是配置与文档变更；按协作约定未运行自动化测试、未解析 Compose、未构建镜像或触发 CI。


## 18. Task/Run 与分析 API 地址隔离

- 每条活动 Task/Run 和最近任务记录都绑定其原始 `analysis_base`。任务 ID 只在生成它的分析服务地址范围内解释，不能因为 API 设置改变就把旧 ID 发给新服务。
- `pollTask` 与 `loadTaskRunResult` 在请求开始时捕获 API base 与 connection generation；写入 Task 状态、事件、运行结果前，两者必须仍与当前状态一致。
- 修改分析 API 路径会先保存当前活动任务引用及其原始地址，再递增 connection generation、停止轮询并使进行中的 Run 结果读取失效；活动详情的旧事件/报告随之清理，但本地最近任务引用保留。
- 最近任务以 `task_id + analysis_base` 区分。对没有 `analysis_base` 的旧版本地记录，按当前连接地址解释并在再次保存时迁移；已知来自另一个地址的记录会被标记，且不会发起请求。
- 如果创建请求在连接变更前发出、变更后才返回，成功回包只入原地址的历史记录，不覆盖新连接的活动任务；失败回包明确提示无法确认旧服务是否已创建，避免盲目重复提交。
- 当前只改变浏览器的请求上下文和本地历史元数据，不新增 API 或数据库字段。测试源码已补充，但按统一安排未运行自动化测试或触发 CI。


## 19. 通知、Chat、选股、告警与设置的契约边界

- web/API_CONTRACT.md 的“未接入功能的后端契约需求”章节列出通知收件箱、Agent Chat、条件选股、告警和服务端配置的最小资源/状态要求。该章节是后端需求草案，不是已注册路由；前端不得按草案猜 URL 或启用写操作。
- 通知列表未读数必须来自服务端；收件箱状态与告警投递尝试分开持久化。
- Chat 的会话、消息和流式生成必须由服务端标识并保持会话上下文隔离。没有真实 Chat API 时，不能把普通分析报告或固定文案作为模型回答。
- 选股策略 schema、扫描任务、候选集合和历史是分离的后端资源；多股票分析 Task 不是选股引擎，候选评分/解释也不能由页面捏造。
- 告警规则 CRUD、评估结果、触发历史、投递尝试分别设计状态与持久化；评估错误/缺数据不能映射为“未触发”，触发也不代表通知送达。
- 服务端设置要定义字段权限、秘密字段回显规则、版本冲突和审计。部署 .env 是运维配置，不应从普通 WebUI 字段中回传明文。
- 新资源上线时需同步 Go Handler/领域行为、OpenAPI、契约测试和错误/空数据语义；浏览器 UI 只有在实际路由/权限/回包可用后才从 unavailable 转为真实加载态。


## 20. 最近任务本地迁移与抑制状态的 endpoint 作用域

- Task ID 的本地生命周期以 task_id + analysis_base 为身份。移除一条历史引用或清空列表时，抑制标记也必须同时保存 analysis_base；否则同一 ID 若由另一个分析服务返回，可能会被旧服务的移除状态误抑制。
- 旧的单任务引用迁移到历史列表时，必须用 task_id 和 analysis_base 定位记录，并把 analysis_base 纳入可比较字段。legacy 记录缺少 base 时按当前连接解释；已知不同 base 的记录不得参与迁移判断。
- 在同一分析服务重复轮询时，若本地历史字段未改变，应避免反复 upsert；这减少无意义的 localStorage 写入并使 updated_at 仍表示引用最后实际更新时刻。
- 本次仅更正浏览器端本地任务历史，不更改服务端数据或 task 状态。契约测试源码已补充但按用户安排未运行。

## 21. 设置页连接测试使用未保存草稿

- 设置页的“检查连接”直接对表单中的行情/分析 API 地址发起健康检查，不再复用全局 `refreshServices()`，因此不会把已保存地址的状态误当成新地址测试结果，也不会覆盖全局健康指示灯。
- 健康检查只读、不保存连接配置。若请求尚未返回时用户再次修改了任一地址，将丢弃该次检查结果并提示重新检查；只有通过“保存”才会修改浏览器本地配置。
- 本轮同步更新设置契约测试源码与进度记录；按协作约定未运行测试或触发 CI。
